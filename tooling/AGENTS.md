# tooling/ — 공유 개발 도구 설정

workspace 패키지가 공유하는 설정 패키지. 런타임 코드는 두지 않는다.

## 현재

- `scripts/sdk-api-snapshot.mjs` (`pnpm sdk:api`) — 다섯 SDK 패키지의 빌드된 선언과 CSS/JSON export 경로를 스냅샷으로 관리한다(#520). 각 항목은 `name | kind | definition`을 적고(`kind`는 런타임 값에 대한 `export type`이면 `type-only <kind>`), 이어지는 `# reachable types`에는 시그니처가 참조하지만 export 항목은 없는 SDK 타입을 기록한다. SDK 참조는 `dist` 경로 대신 `@ap/<pkg>[/<entry>]#Name`으로 출력한다. `--update`는 스냅샷을 갱신하고 `--self-test`는 fixture를 검사한다.
- `scripts/check-lazy-chunks.mjs` (`pnpm check:lazy-chunks`, `--self-test`) — 빌드된 `apps/platform-web/dist`에서 `index.html`의 진입 스크립트와 그 정적 import 폐쇄를 읽어, 지연 화면만 쓰는 무거운 엔진의 표식 문자열(`LAZY_ENGINES`: Dockview, 리치 텍스트 편집기 두 부품, echarts, tanstack virtual, 엑셀 내보내기, 분석 보드 화면, FeedbackOps 알림 패널 — #706·#821·#820)이 든 청크가 있으면 실패한다. 어느 청크에도 표식이 없으면 검사가 아무것도 증명하지 못하므로 그것도 실패다. 새 엔진은 `LAZY_ENGINES`에 더한다. CI `platform-workspace`가 `pnpm build` 바로 뒤, `sdk:pack`이 `dist`를 비우기 전에 돈다.
- `tsconfig/` (`@ap/tsconfig`) — `base.json`. 모든 패키지·앱의 `tsconfig.json`이 `extends` 한다.
- `eslint/` (`@ap/eslint-config`) — 패키지 경계·계약 lint(ESLint flat config). 패키지별 프리셋(`contracts`·`kernel`·`menu`·`app`·`httpAdapter`·`foBridge`·`foBridgeMenu`·`hostModule` 등; `hostModule`은 다른 저장소 모듈 패키지용으로 `@ap/contracts`·`@ap/ui`만 허용하며 이 저장소 패키지에는 적용하지 않고, 셸의 고정 모듈 fixture 디렉터리에만 `hostModuleDir(dir)`로 쓴다, ADR-0053)을 각 consumer가 `eslint.config.js` 한 줄로 가져다 쓴다. `@fops/*` import는 `@ap/ui`를 포함해 모든 패키지에서 금지한다(ADR-0046). 예외는 다리(`@ap/fo-bridge`의 `foBridge`, 다리 메뉴의 `foBridgeMenu`) 하나다(규칙 8). 경계 규칙 원본은 [패키지 경계 §3](../docs/integration/platform-packages.md#3-패키지-구성)이다. 접두사 상수와 규칙 원본은 `tooling/eslint/src/`에 있다. UI를 그리는 프리셋(`ui`·`components`·`shell`·`menu`·`app`)은 `@shadcn/lint` 6개 규칙을 error로 켠다(#228). 테마는 루트 `components.json`의 `tailwind.css`(앱 `style.css` — 패키지에는 Tailwind 진입 CSS가 없어 이것이 없으면 플랫폼 유틸리티 `t-mono` 등을 모른다), 컴포넌트는 `@ap/ui`·`@ap/components` import로 알아본다. 규칙 옵션은 공유 디자인 시스템의 원본인 FeedbackOps `.oxlintrc.json`(FO ADR-0062)을 따른다 — 화면은 컴포넌트에 layout만, 컨테이너(`*Content`·`*Header`·`*Footer` 등)에는 spacing도 더할 수 있고, 50px 헤더(`DetailPanelHeader`·`ShellHeader`·`ListToolbar`)에는 높이를 줄 수 없다. arbitrary 값은 layout만 허용하고, `no-raw-colors`·`no-arbitrary-values`는 상수 문자열도 읽는다(`scanAllStrings`). primitive를 정의하는 `packages/ui`만 FeedbackOps `packages/ui`처럼 `no-restyle`·`require-static-classes`를 끈다. `packages/components`는 primitive 위에 조립하는 층(06 §13)이라 가져온 primitive의 모양을 덮어쓰지 못한다 — 자기 마크업은 상대 import라 컴포넌트로 보지 않으므로 토큰으로 자유롭게 꾸민다(`boundaries.test.ts`가 고정). 클래스가 아닌 문자열 오탐이나 의도한 일회성 처리는 그 줄에 `eslint-disable-next-line shadcn/<rule> -- <이유>`로 표시한다. FeedbackOps 설정이 바뀌면 `tooling/eslint/src/index.js`의 `RESTYLE_CONTRACTS`·`DESIGN_SYSTEM_RULES`를 같이 맞춘다. FeedbackOps에 없는 플랫폼 contract는 접근성 하한 넷이다(ADR-0023 개정). 소비자 덮어쓰기를 허용하는 lint `RESTYLE_CONTRACTS`는 기존 셋이다: `Input`·`SelectTrigger`·`Checkbox`의 `border-border-control`, `Button`의 `aria-disabled:` 비활성 모양, `DropdownMenu*Item`의 `focus-visible:ring-*` 키보드 포커스 링. 네 번째인 탭 선택 표식은 `packages/ui`가 정의하므로 소비자 lint contract를 추가하지 않는다. 디자인 시스템 규칙은 테스트 파일(`**/*.test.{ts,tsx}`)과 생성 파일(`**/*.generated.ts`)을 검사하지 않는다.
- `gen-menu/` (`@ap/gen-menu`, `pnpm gen:menu`) — 이미 앱의 `GROUPS`(`apps/platform-web/src/menus.ts`)에 있는 그룹의 메뉴 패키지 스켈레톤(`src/endpoints.ts`·`src/mock/`·`useMenuQuery` 페이지 — menu-query 패턴)을 만든다. Management·Analysis 뼈대는 레이아웃 슬롯 컴포넌트를 쓰고, 나머지 archetype은 점선 슬롯을 쓴다. `GROUPS` 행의 `space`로 `menus/<space>/<group>/` 위치를 정하며 `null`은 `_global`이다. `repo-invariants`가 폴더 소속과 선언의 일치를 검사한다. 사이드바 그룹은 추가하지 않는다. 앱 배선 여섯 줄(`menus.ts` import/spread, `style.css`, 앱 `package.json` 의존, `dev/mock-assembly.tsx`의 `<gen:menu-mock-*>` 마커)은 생성기가 쓰고 `--remove`가 바이트 단위로 되돌린다 — 마커 영역은 손으로 고치지 않는다. 생성기를 바꾸면 깨끗한 트리에서 `node tooling/gen-menu/scripts/probe.ts`를 coordinator가 1회 돌린다. `--page-type` 슬롯(`PAGE_SLOTS`)은 06 §12와 함께 고친다.
- `css-selectors/` (`@ap/css-selectors`) — 빌드된 CSS 파일에서 selector 집합을 추출하고 두 집합의 added/removed를 비교하는 CLI(#58). CI(`.github/workflows/css-selectors.yml`)가 PR head 빌드와 병합 기준(merge-base) 빌드를 비교해 Job 요약에 마크다운 리포트를 쓰고, selector가 제거되면 실패한다. 의도된 제거 PR은 `css-removal-ok` 라벨을 단다(라벨 on/off 시 이 워크플로만 재실행). 로컬 실행: `node tooling/css-selectors/src/cli.ts <base.css> <head.css> [--summary <file>] [--allow-removal]`, 단위 테스트는 `pnpm --filter @ap/css-selectors test`.
- `scripts/sdk-pack.mjs`·`sdk-consumer-check.mjs`·`sdk-finalize-dist.mjs` (`pnpm sdk:pack --version X.Y.Z --out <dir>`, `pnpm sdk:consumer-check <dir>`) — SDK 릴리스 tarball 다섯 개의 빌드·pack과 깨끗한 외부 소비자 게이트(ADR-0056, #519). `sdk-pack`은 repo 밖 임시 폴더에 `dist`와 릴리스 manifest를 두고 `pnpm pack`한다(추적 파일은 건드리지 않는다). `--out`은 없거나 빈 폴더여야 하고(아니면 아무것도 지우지 않고 실패), 모든 단계가 끝난 뒤에야 tarball 다섯 개와 `SHA256SUMS`가 그곳으로 옮겨진다. tarball 안 형제 `@ap/*`는 정확 버전 `peerDependencies`이고 `dependencies`에 있으면 pack이 실패한다(#806). `sdk-consumer-check`는 tarball 폴더를 `127.0.0.1` HTTP로 서빙해 실제 소비자처럼 URL 직접 의존으로 설치하고(`@ap/*` overrides 없음, `blockExoticSubdeps: true` — `file:` 설치는 #806을 숨긴다), 패키지마다 tarball이 둘 이상이면 실패하고, 브라우저 `tsc`는 앱 소스만 보며(자기 검사로 Node 전용 선언을 거부하는지 확인) 빌드 산출 JS에 Button 개발용 throw가 남지 않았는지 확인한다. `sdk-finalize-dist`는 각 패키지 `build`의 둘째 단계(CSS·JSON 복사, 상대 import에 `.js`). 루트 `turbo.json`의 `build`는 `^build`에 의존해 형제 `dist`가 먼저 만들어진다. ESLint 프리셋은 `dist/**`를 전역 ignore한다(빌드 산출물에는 소스 주석의 인라인 지시어가 복사돼 있다).

## 규칙

- 설정 변경은 모든 패키지에 퍼진다. 바꾼 뒤 루트 검사(루트 `AGENTS.md`)를 돌린다(생성기는 `pnpm --filter @ap/gen-menu test`로 먼저 좁힌다).
- 패키지 접두사(`@ap/`, 임시)를 설정에 쓸 때는 상수 한 곳에만 둔다(패키지 경계 §8).
- 루트 workspace 파일(`package.json`, `pnpm-workspace.yaml`, `turbo.json`)과 CI(`.github/workflows/ci.yml`의 `platform-workspace` Job)는 여기 규칙과 함께 바꾼다. CI 단계 순서의 원본은 [패키지 경계 §6](../docs/integration/platform-packages.md#6-경계-강제와-도구) CI 행이다.

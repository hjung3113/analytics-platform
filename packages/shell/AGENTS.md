# @ap/shell

App Shell(06 §8–9, 화면 설계 [07](../../docs/07_app_shell_wireframe.md)). 메뉴 목록은 주입된 Registry에서, 선택지·세션은 어댑터에서 읽는다.

## 파일

- `QueryBar.tsx` / `QueryHistoryControl.tsx` — Apply 메뉴에서 `GlobalContextBar`가 기존 metadata effect보다 먼저 `QueryBar`를 마운트한다. Kernel 초안/선택 포트와 components의 요약·확장 메타데이터를 쓰며 메뉴 축·파서를 import하지 않는다. 본 화면 편집은 인라인, 보드 칸 편집은 기존 48px 행 안의 고정 패널이다. `historySlot`은 이력 컨트롤을 연결하고, 검증된 행의 실제값만 요약한다. 최근 조건 선택은 초안만 복원하고 삭제·모두 지우기 확인·키보드 포커스를 제공한다(06 §11). 검증 `QueryBar.test.tsx`; live fixture를 유지한다.
- `AppShell.tsx` — 레일(52px)·밝은 사이드바(240/56px)·스크롤 main·전체 높이 오른쪽 상세 aside 배치(06 §13, ADR-0013). `/board`(플랫폼 화면)에는 사이드바를 붙이지 않는다. 공간 밖 Registry 화면(`space: null` — 홈·내 활동·공지)에는 업무 사이드바 대신 `PlatformSidebar`를 붙인다(ADR-0070). 접힘 상태·저장 키·`[`는 둘이 하나를 쓴다. `[` 단축키와 `platform:sidebar-collapsed` 저장 키·1440px 미만 기본 접힘 유지. 상단 바 없음.
- `AppRail.tsx` — 맨 위 `SystemSwitcher`, 구분선, 현재 시스템의 섹션 버튼(`systemSections.ts`의 `useSystemSections` — `currentSpace`가 사이드바 공간과 같을 때만, 그룹당 하나, 현재 메뉴의 그룹에 `aria-current="true"`, 현재 섹션 클릭은 아무 일 없음, 다른 섹션은 그 그룹 첫 보이는 메뉴로 Kernel 링크 이동), 명령 팔레트, `분석 보드`(메뉴 검색 바로 아래 — 보드 지원을 선언한 열 수 있는 메뉴가 있을 때만, `board/boardMenus.ts`), 레일 아래 `slots.notifications`가 있고 그 메뉴를 열 수 있으면 `알림` 종(`NotificationsBell.tsx` — 버튼·팝오버 틀·배지·접근 이름은 셸이, 건수와 본문은 슬롯이 준다. 열면 포커스는 대화상자, Esc는 종, `모두 보기` 이동은 도착 제목이 갖는다, #652)과 같은 건수를 전환기 플랫폼 링크·플랫폼 사이드바 `NavItem`에 배지로 다는 `unread.tsx`의 `MenuUnread`, 그 아래 `slots.topBarTools`, 구분선, 도움말·사용자 메뉴. `언어` 전환과, `feedbackOps.overall`이 있고 사용자가 그 `permission`을 가질 때만 보이는 `FeedbackOps 전체`(새 탭)는 사용자 메뉴 항목이다(#595 전까지, ADR-0070). 언어 항목은 메뉴를 닫지 않는다. 공간 마지막 화면 복원 규칙은 여기 복사하지 않는다 — [06 §9.1](../../docs/06_platform_ui_contract.md#91-워크스페이스-decided-2026-09-26), 검증은 Kernel `src/platform.space-resume.test.tsx`.
- `VocDrawer.tsx`·`vocContext.ts` — 레일 `VOC 등록`(`slots.vocCompose`가 있을 때만, `분석 보드`와 `알림` 사이)이 여는 도킹 드로어(06 §8, ADR-0070 결정 5, #655). `AppShell`이 `useVocDrawer`로 상태를 쥔다: 초안이 없을 때만 Context를 고정(`freezeVocContext` — 순수, 칩 id `menu`·`page:<key>`·`period`·`global:<필드>`, 남은 칩의 원본 Context·page 쌍으로 `href` 재구성), 숨겨도 `Compose`는 마운트 유지, 상세 슬롯 `activation`이 늘면 드로어만 숨기고(초안 유지) 상세 aside를 보인다(같은 렌더에서 — 상세의 첫 포커스가 보이는 aside에 닿는다). 숨긴 Compose의 일시 portal은 `TransientOverlayScope`로 닫는다. Kernel 세션이 바뀌거나 슬롯이 사라지면 고정 Context·초안·확인 상태를 버리고 닫힌 채 시작한다. 레일 버튼은 `VocDrawerContext`(셸 내부, 미공개)로 컨트롤러를 받아 `AppRail()` 시그니처는 무인자로 둔다. 닫기(버튼·Esc·레일·`onCancel`)는 더러운 초안이면 드로어 안 `alert`로 `작성 중인 내용을 버릴까요?`를 묻고, Esc는 aside 안 DOM 대상일 때만 받는다. 검증 `vocContext.test.ts`·`AppShell.vocDrawer.test.tsx`.
- `SystemSwitcher.tsx` — 레일 맨 위 업무 시스템 전환기(15 §3.2, ADR-0042). `@ap/ui` Popover(modal, focus trap), 카드 = `accessibleSpaces` ∧ `spaceEntry` 있는 것(보조 문구 `이어서`/`시작`은 `entry.menuId`·`resumed`), `slots.plannedSpaces` 표시 전용 행, 제목 아래 `플랫폼 메뉴` 구역(`platformMenu.ts`의 `usePlatformMenu` — `space: null` 그룹을 그룹 순서로, 각 메뉴 권한·열 수 있음만 판정, `/` 메뉴는 `홈`)은 글자 링크로 시스템 카드 위에 있고 카드 수에 들지 않으며 접근 가능한 공간이 0개여도 그려진다. 열면 현재 카드 → 첫 카드 → 첫 플랫폼 링크 → 빈 안내 순으로 포커스. 이동은 팝오버를 먼저 닫고 `onCloseAutoFocus`(트랩 해제 뒤)에서 실행해 Kernel 도착 포커스(ADR-0032)가 새 제목에 남는다. 현재 카드 재선택·Esc·바깥 클릭은 전환기 버튼으로 복귀. 팝오버가 열린 동안의 도착(뒤로/앞으로 등)은 팔레트와 같은 Kernel 포커스 게이트(`switcherSession`)로 제목 포커스를 지키고, 대기 중인 이동은 언마운트·Provider 세션 교체 때 버린다. 테스트: `SystemSwitcher.test.tsx`(실제 Provider·PlatformPage), `SystemSwitcher.entry.test.tsx`(`spaceEntry` 래핑).
- `PlatformSidebar.tsx` — 공간 밖 Registry 화면의 사이드바(ADR-0070). `usePlatformMenu`의 그룹대로 `홈`·`내 활동`(알림·설문·권한 요청 …)·`공지`를 그린다. 머리 50px(`분석 플랫폼` + 접기), 접힘은 `AppShell`이 쥔 상태를 그대로 받는다. Scope 선택기·즐겨찾기·최근·FeedbackOps 블록 없음. 항목은 `AppSidebar`의 `NavItem`을 쓴다. 검증 `AppShell.test.tsx`의 `platform sidebar (ADR-0070)`.
- `AppSidebar.tsx` — 전역 화면과 접근 가능한 공간이 0개일 때는 그리지 않는다. 공간 머리(50px: 공간 이름 + 현재 섹션 이름, 같으면 한 줄)·접기, Scope 선택기, 현재 섹션(그룹)의 권한 기반 메뉴만(그룹 제목은 섹션 이름과 같아 생략, 미등록 경로·공간 진입 거부 fallback은 모든 그룹을 그대로), 즐겨찾기·최근(펼친 모드만), 그 아래 스크롤 밖 FeedbackOps 블록(그려지는 `sidebarSpace`가 `accessibleSpaces`에 있고 라우트가 그 공간 메뉴일 때만 `entriesFor(sidebarSpace.id)`. 비어 있거나 진입 거부·미등록 경로면 그리지 않음. 접힘이면 아이콘만. 아이콘은 슬롯 항목의 `icon`(앱이 준다, `key`는 React key일 뿐이고 셸은 분기하지 않는다, ADR-0072). `href: null` 항목은 같은 행 모양의 비활성 `<span role="link" aria-disabled="true">`로 그리고 이유를 접근 이름·툴팁에 붙인다). 그룹 표시는 Registry `GroupDef`(`hideLabelWhenSingle`)만 따른다 — 그룹·메뉴 id를 코드에 쓰지 않는다(lint `ap/no-shell-id-literal-comparison`, `no-group-id-literals.test.ts`). 접근성 이름·landmark 구조는 `AppShell.test.tsx`가 고정한다. 메뉴 검색은 팔레트만.
- `ScopeSelector.tsx` — (`layout="bar"`는 분석 보드 Context 바용 32px 한 줄 변형.) Scope 선택(`session.scopes`)과 검증 상태·room 부여 수, `error`에서 현재 Scope를 다시 고르면 `retryScope()`(다른 상태에서는 Kernel 동작 없음, #183), `error`일 때 'Scope 다시 확인'(목록에 없는 Scope도). 접힌 사이드바에서도 이름과 상태·room 설명(aria-describedby) 및 Tooltip을 유지. status만 polite live region으로 알린다.
- `CommandPalette.tsx` — 메뉴 검색 이동(행 보조줄 `<시스템> › <섹션> › <메뉴>`, 연속 같은 이름은 한 번). 닫으면 연 요소로 복귀(#296), 다른 pathname 메뉴를 고르면 Kernel의 `page` 요청을 Dialog close autofocus 뒤에 넘겨 새 화면 제목에 포커스(#339, 06 §26). 세대 번호 대신 `paletteSession`의 `claim(owner)`·`release(owner)`·`isCurrent()`만 사용한다. 언마운트 해제는 FocusScope passive cleanup 뒤 `setTimeout(0)`으로 미룬다.
- `GlobalContextBar.tsx` — (보드 전용 선택 prop `label`은 바의 표시 이름·접근 이름을 칸 이름으로 바꾸고 `whenEmpty`는 바가 비는 자리에 그릴 것을 준다.) 기간·room_name·Condition·Selection·전달 Context 표시/편집. Condition은 주입된 축의 표시 이름과 기존 단일축/쌍 편집기를 사용하며, 그 밖의 맵은 요약과 전체 지우기만 제공한다. URL로 전달된 Line·PRC 그룹은 요약과 제거만 제공하며, Condition과 PRC 그룹은 소속 기준(`membershipBasis`)을 함께 전달한다. 선택지는 `useAdapterRequest`로 조회하고 실패 시 오류와 재시도를 제공한다. Selection 평가(`evaluateSelection`)는 바 수준의 한 조회 소유자가 실제·측정·인라인/넘침 편집기에 결과를 공유한다.

## 규칙

- import 가능: `@ap/contracts`, `@ap/kernel`, `@ap/components`, `@ap/ui`. 앱·mock·메뉴 화면 import 금지. 특정 메뉴 id를 코드에 쓰지 않는다.
- 도메인 선택지(설비·room·조건 목록)를 셸이 계산하지 않는다. 어댑터가 세션 권한으로 거른 결과를 표시만 한다.
- 개발 전용 도구(역할 전환, 응답 시나리오)는 셸에 넣지 않는다. 앱이 `slots.topBarTools`로 주입하고 레일 아래에 렌더한다(ADR-0009 슬롯 이름 유지).
- 레이아웃 치수·IA 변경은 07/06 §9 변경이다. 워크스페이스 층(06 §9.1)도 여기와 Registry에 얹는다.

- 상세 슬롯 aside는 셸이 소유한다. 상세가 없으면 폭 0, 열리면 공유 폭 토큰을 06 §7 범위로 clamp하며 본문을 overlay·scrim·inert로 막지 않는다(ADR-0013, 06 §13).

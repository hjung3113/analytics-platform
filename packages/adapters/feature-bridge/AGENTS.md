# @ap/feature-bridge

FeedbackOps 다리의 런타임(ADR-0071·0081, #759). 소비자 쪽 패키지이며 SDK가 아니다(`SDK_PACKAGES`에 없다). 다리 메뉴(`@ap/menu-my-activity`, 이후 `menus/feedbackops/*`)와 앱 파일이 패키지 root를 import하고, 슬롯·API 서브패스(`./fo-api`, `./*-slot`)는 앱 `main.tsx`만 import한다.

## 파일

- `src/fo-api.ts` — `setFoApi`/`foApi`: 앱이 주입하는 FeedbackOps API 슬롯. FeedbackOps를 import하지 않는다.
- `src/fo/session.ts` — `foQueryClient`(FeedbackOps QueryClient는 이 하나, ADR-0071 결정 5 — Kernel의 내부 조회 클라이언트(ADR-0086)와는 별개)와 `useFoSession`(세션 세대).
- `src/fo/FoBridge.tsx`·`links.tsx`·`survey-links.tsx`·`voc-links.tsx` — 호스트 이음매(`FoBridge`)와 FeedbackOps 경로 → 플랫폼 메뉴 링크 맵.
- `src/notifications-slot.tsx`·`voc-compose-slot.tsx`·`home-todo-slot.tsx` — Kernel 슬롯 값. 앱 `main.tsx`만 import한다. 페이지(`src/pages/`)는 첫 사용 때 lazy로 불러온다. 알림 `Recent`도 `src/pages/RecentInbox.tsx`(lazy, FO 진입 `global-screens/inbox-panel`)를 열어 패널이 시작 청크에 실리지 않는다(종·배지는 `/core`의 `useUnreadNotificationCount`로 같은 자리에 남고, Suspense는 패널 안에만 있다, #820).
- `src/scope-control.tsx` — Kernel 슬롯 `scopeControl`(사이드바 `목록 범위`, ADR-0081, #759). 앱 `main.tsx`만 import한다. `For('feedbackops')`는 모듈 수준의 한 컴포넌트를 돌려주고(호출마다 새로 만들면 사이드바가 다시 마운트된다), mock에서는 비활성 `전체` 자리표시를 직접 그리고, 준비된 세션에서만 `src/pages/ScopeControl.tsx`(lazy)를 연다.
- `src/nav-counts.tsx` — Kernel 슬롯 `navCounts`(사이드바 개수 배지, #761 p1b). 앱 `main.tsx`만 import한다. `For('feedbackops')`는 모듈 수준의 한 컴포넌트를 돌려주고, 그 컴포넌트는 mock·로딩·오류·준비 어느 때나 같은 자리에서 `children`을 부른다(사이드바 목록이 다시 마운트되지 않는다). 현재 `managedSystem`으로 FeedbackOps `fetchNavCounts`를 `useQuery`로 읽고(`foQueryClient`의 `['nav-counts', managedSystem]`, 없는 범위는 `undefined` — FeedbackOps 화면의 관찰자와 같은 쿼리를 나눠 쓰므로 `invalidateNavCounts`가 한 번 새로고침하고 범위를 떠나면 취소된다), 생략된 키는 배지 없음, 0은 0이다.
- `src/saved-views.tsx` — Kernel 슬롯 `spaceNavSection`(사이드바 `저장된 보기`, #761 p3). 앱 `main.tsx`만 import한다. `Body`는 모듈 수준 한 컴포넌트이고 mock·세션 준비 전에는 muted 한 줄(`실서버 필요`)만 그리며 요청하지 않는다. 준비된 세션에서만 `src/pages/SavedViews.tsx`(lazy)를 연다: `['saved-views','voc']` 목록·적용·삭제(#972 포커스 복구)와 수신함·Triage의 저장 폼. 적용은 `operatorHostLinks.targetOf`로 저장된 `view`가 가리키는 메뉴를 찾아 담지 않은 키와 `managedSystem`을 지운다. 실패는 Kernel 토스트.
- `src/fo/uuid.ts` — `UUID_PATTERN`·`isUuid`(루트 export): 다리·메뉴·앱의 UUID 검사는 이 하나다(`VOC_ID`·`SURVEY_ID`·경로 표의 `detailPath.pattern`도 여기서 나온다).
- `src/fo/RejectedPage.tsx` — 틀린 주소 값의 공용 거절 화면(`값 지우기`, 루트 export). 다리 메뉴 화면(`FoScreenPage`를 쓰는 모든 운영 화면, `fo-dashboard`)이 같은 문구를 쓴다(ADR-0071 결정 9).
- `src/fo/FoScreenPage.tsx` — 운영 화면 페이지 골격(루트 export): 주소 값 검사(`route.rejectedKey`) → 거절이면 `RejectedPage`, 아니면 `PlatformPage layout="fill"` + `FoBridge`(`operatorHostLinks`) + 화면 칸 + `detail` 드로어. 값을 검사하는 `isValid`(`isVocSearchValueValid` 등)는 FO 진입을 import하므로 각 메뉴가 prop으로 넘긴다. 거절이면 `children`·`detail`은 마운트되지 않아 요청도 없다. `fo-dashboard`는 골격이 달라 쓰지 않는다.
- `src/testing.tsx` — 서브패스 `./testing`(테스트 전용, 루트 export 아님): `createFoMenuHarness({ manifests, homeMenuId, group, detailSlot })` → `{ registry, mountAt(url, { registry?, extra? }) }`. 다리 메뉴의 `test-support.tsx`가 자기 manifests로 부른다. `@ap/kernel/testing`·`@testing-library/react`를 쓰므로 lint는 이 한 파일에만 `kernel/testing`을 허용한다.
- `src/pages/HomeTodo.tsx`·`VocCompose.tsx`·`ScopeControl.tsx`·`RecentInbox.tsx` — 슬롯이 lazy로 여는 FeedbackOps 화면. 전체 진입 `@ap/feature-screens/global-screens`는 여기서만 import한다. `ScopeControl.tsx`는 메뉴 그룹이 `foAdmin`이면 picker를 `disabled`로 그린다(ADR-0081 d4; 그룹으로 판단하고 메뉴 id 목록은 쓰지 않는다).
- `src/fo/voc-routes.ts`·`src/fo/task-routes.ts`·`src/fo/finding-routes.ts`·`src/fo/integration-routes.ts` — FeedbackOps `/vocs`·`/tasks`·`/findings`·`/integration…` 경로 → 플랫폼 메뉴 경로 표(`operatorRoute`). Findings 표(#762 s)는 `operatorHostLinks`에 달려 있고(#762 p1), 연동 네 표(대시보드·Evidence·커버리지·엔티티 링크)도 달려 있다(#762 p2; `/admin/*`·`#coverage`는 #764 p2에서 연결). Task 표 일곱(#763 s: Task Request·보드·Milestone·목록·내 Task·목록 별칭 둘)은 모두 `src/fo/operator-links.ts`의 `operatorHostLinks`에 달려 있다(#763 p1·p2). Surveys 표와 자식 화면 대상(`src/fo/survey-routes.ts`: `surveysRoute`·`surveyChildTarget`·`surveyOperatorTargets`와 숨은 세 화면의 `surveyBuilderRoute`·`surveyResultsRoute`·`surveyFollowUpRoute` — 경로 매개변수 `:surveyId`는 페이지 키가 아니라 `route.params`에서 읽는다, 후속 조치만 `focus`를 페이지 키로 가진다)은 `operatorHostLinks`에 달려 있다(#764 p1, 신고자 `설문` 대상이 먼저). Admin 표 다섯(`src/fo/admin-routes.ts`: 관리 시스템·분석 영역·권한 요청·권한 부여·설정, `adminOperatorTargets`; 설정은 `operatorRoute`의 `hash`로 `#coverage`를 `section`에 매핑)도 `operatorHostLinks`에 달려 있다(#764 p2, 설문 대상 뒤. 매핑 없는 `/admin/…`와 `#coverage` 밖 조각은 연결 안 함). Coverage의 `설정`(`/admin/settings#coverage`)·권한 요청 알림·복구 출처 링크가 이 메뉴로 간다. 테스트 하네스 `createFoMenuHarness`는 `permissions` 옵션(기본 `platform:view`·`feedbackops:access`)을 받고, 세션에 권한이 없는 메뉴는 셸처럼 그리지 않는다. 건수 배지 `surveys.all`은 `fo-surveys`로 간다. `FoBridge`는 비유한 알림 시간(`Infinity`)을 빼서 Kernel 기본값을 쓴다.
- `src/fo/operator-links.ts` — `operatorHostLinks`: 다리 메뉴와 대시보드가 쓰는 FeedbackOps 경로 → 플랫폼 메뉴 링크 묶음. VOC·Findings·Tasks·연동·내 VOC·설문·관리자 대상을 선언 순서대로 합친다. 각 경로 표의 허용 대상과 거절 조건은 위 항목 및 `src/fo/operator-links.ts`를 따른다(ADR-0071 결정 10).
- `src/fo/FoDetailDrawer.tsx` — FeedbackOps 상세 `DetailParts`를 셸 상세 슬롯 `DetailDrawer`에 그리는 래퍼(루트 export, `.fo-detail-body` 스타일은 `src/styles.css`). 다리 메뉴(`fo-voc`·`fo-tasks`)가 `FoBridge` 안에서 쓴다.
- `src/fo-entry-graph.test.ts` — 다리가 닿는 FeedbackOps 진입의 import 그래프와 영구 로드 모듈의 `/core` 한정을 고정한다.

## 규칙

- 루트와 슬롯 파일(`src/pages/` 밖)은 `@ap/feature-screens/global-screens/core`만 import한다. 전체 진입을 영구 로드 코드에 들이면 메인 번들에 FeedbackOps 화면이 실린다(ADR-0071 결정 1, #654).
- 화면은 재export하지 않는다. 다리 메뉴가 정확한 FeedbackOps 진입을 직접 import한다.
- 세션 싱글턴은 이 패키지에만 둔다. 다른 패키지가 `foQueryClient`나 세션을 새로 만들지 않는다.
- 슬롯·페이지 테스트는 이 패키지가 아니라 슬롯을 쓰는 메뉴 패키지에 둔다: 메뉴의 manifest·레지스트리·fixture가 필요하고 `packages/*`는 메뉴를 import하지 못하기 때문이다(`@ap/menu-my-activity`의 `src/notifications-slot.test.tsx`·`voc-compose-slot.test.tsx`·`home-todo-slot.test.tsx`, `src/fo/test-support.tsx`; `@ap/menu-fo-dashboard`의 `scope-control-slot.test.tsx`·`scope-control-page.test.tsx`; `@ap/menu-fo-voc`의 `nav-counts.test.tsx`). 이 패키지의 테스트는 메뉴 없이 도는 것(경로 표·링크·UUID·진입 그래프·`FoScreenPage`)이다. 메뉴 테스트가 쓰는 레지스트리·`mountAt` 하니스(`./testing`)는 이 패키지에 있고 테스트 본문은 메뉴에 둔다.

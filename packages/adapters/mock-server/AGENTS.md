# packages/adapters/mock-server — development server stand-in

`@ap/mock-server` imitates the server where no real backend exists. The Kernel and common components never import it. The app's mock assembly `apps/platform-web/src/dev/mock-assembly.tsx` passes the result of `createMockAdapter({ endpoints: MOCK_ENDPOINTS, registry, auditEvents: MOCK_AUDIT_EVENTS })` to `main.tsx` as `#platform-assembly`. It runs only in dev, `--mode mock` and vitest, never in a production build (ADR-0009).

## Rules

- Depend only on `@ap/contracts`. Import neither React nor any other `@ap/*`.
- Do not import apps (`apps/*`) or menus (`menus/*/*`, `platform/*`). Menu-specific mock handlers and calculations live in each menu package's `src/mock/`; this package knows no menu.
- Menu data touchpoints are each menu's endpoint declarations (`menus/<space>/<group>/src/endpoints.ts`) and its mock handlers (`src/mock/`). Productivity and cycle aggregation stays on the menu side.
- Menu `src/mock/**` handlers may import this package. `serve()` is an engine-internal step: do not export it publicly.
- In the app, only `src/dev/**` (mock assembly, `DevTools.tsx`) and the app integration tests `src/server-conformance.test.ts` and `src/published-metrics.test.ts` import this package; lint blocks `main.tsx`. Menu pages do not import mock handlers relatively; the app registers them through the menu's `/mock` subpath.
- Keep tests that look at mock and screen calculation together out of this package. Metric publication versions are split across `menus/bravo/metrics/src/mock/published-pointers.test.ts` (catalog pointer comparison), `menus/mars/analytics/src/resolve-metric.test.ts` (page default version) and `apps/platform-web/src/published-metrics.test.ts` (kernel `classifyMetricInit` + mock).
- Export explicitly from `src/index.ts`; `export *` is forbidden.

## Engine behaviour

- Decide permission and Scope re-verification from the server-side declaration copy or server-owned map, never from the request ([checklist §2-§3](../../../docs/integration/real-server-checklist.md)).
- Query order (declaration-based) follows checklist §3 (`src/query/endpoints.ts`: `MockEndpoint`, `defineMockEndpoint`, `serveEndpoint`, `MockRegistrationError`, `MockRequestError`). `mart: false` marks a non-mart source (no Trust, mart scenarios not applied).
- `createMockAdapter({ endpoints, actions?, registry, auditEvents? })` (`src/adapter.ts`) implements the port plus declaration-based `menuQuery` and `menuAction`. The seven endpoint registration checks are owned by [checklist §3 "등록 검증"](../../../docs/integration/real-server-checklist.md).
  - `auditEvents` seed menu-owned audit targets (metrics) into the same store as equipment events, read by `auditTrail` and `entityAudit`. Registration checks duplicate ids, target type (equipment excluded), metric `scopeId: null` and instants with a zone ([ADR-0048](../../../docs/adr/0048-menu-audit-seeds-join-shared-mock-audit-store.md)).
- Write order (`src/actions/actions.ts`: `MockAction`, `defineMockAction`, `serveAction`; checklist §3 `menuAction`, ADR-0054): shape → idempotency key → permission → Scope → the action's optional input-dependent `authorize` (`can(permission)`, `false` = `forbidden`, like the server's `authorize(actor, tx, input)`) → replay → input → version → handler. Only `ok` is recorded, by `(actor, key)` with no expiry. The engine writes no audit row; audit is the handler's job. `createMockAdapter({ actions? })` validates registration (duplicate id, `menuId`, permission, Scope, `invalidates`, `version` handler).
- Endpoint and action permissions are the registered menu's entry permission, or, when `permissions` (the app permission vocabulary) is passed, any permission in that vocabulary (for write permissions such as publish that are not a menu entry permission). Without a vocabulary the entry-permission rule applies; typos are rejected either way.
- Roles and permissions (`src/world.ts`): roles come from the list the app assembly passes as `createMockAdapter({ permissions: [...registry.permissions, ...modulePermissions(registry)] })` (`createUsers`: admin all, engineer without console and feature, viewer only explicit permissions). The app adds external-module permissions (e.g. `eqv:view`) through `modulePermissions(registry)`; this package knows no module. Without the list the default is the Kernel permissions plus the four sample-menu permissions (`WORLD_PERMISSIONS`, ADR-0072; no app import). Usage-instrumentation space ids are only shape-checked because the app's space list is unknown here.
- `src/server.ts`: engine-internal `serve()`, role (localStorage `platform:role`) and scenarios, `getEntity`, `recordUsage`, `reportClientError`, `usageSummary`, `usageNextScreens` (the "next screen" aggregate `aggregateUsageNext`, mask k = 3 per cell; the seed `seedUsageNext` fills only when called).
- Latency: queries default to `DEFAULT_QUERY_LATENCY_MS` (120 ms) + 0–60 ms jitter (`queryDelay`); the earlier 450 ms made the demo feel slow. Writes, audit and annotations stay 80 ms. The `slow` scenario's +2.2 s and the `latency` a call supplies (fixed by tests and E2E) stay unchanged. `createMockAdapter({ latency })` replaces every default delay with one fixed value (no jitter) for suites that send thousands of requests one at a time (server conformance uses 0, #1680); it is process-wide like the world. To see loading states use the DevTools `slow` scenario. Change the constant in one place only.
- Chart annotations (`src/audit/annotations.ts`, ADR-0041): `listAnnotations`, `saveAnnotation`, `deleteAnnotation` decide in the order permission (`analytics:view`) → scenario → validation → Site boundary.
  - Rows keep the `scopeId` of their creation and every read filters by `scopeId`, never by `chartId` alone.
  - The server stamps author and time; they are absent from the wire input (unknown keys are rejected). Trust is null (non-mart data).
  - `mine` is computed per response from the requesting role and never stored. Only the author deletes; success leaves a runtime audit row (`delete`, `annotation`) that `auditTrail` merges.
- `uploadFile` (`src/services/services.ts`, #1741): an in-memory store keyed by minted id with the real server's 32 MiB cap and closed MIME set copied, replay by `(user, idempotencyKey)` (`replayed`, other file = `conflict`). No purge or link. `resetUploads()` clears it with the other service stores.
  - A mock action reads a stored file by id through its handler argument `readUpload(id)` (`UploadContent`: the `UploadedFile` fields plus `bytes`), like a server consumer reads an unlinked upload (ADR-0140 §6): null for an unknown id or a file another user uploaded, so the handler answers both alike. Handlers that take no upload id ignore it; a direct handler call in a test may omit it.
  - A handler that must await (an async validator over the file) is defined with `defineMockAsyncAction`: same judgment order, the engine awaits it, and its sync `handle` throws, so tests drive it through the adapter. `defineMockAction` and every existing sync handler are unchanged. Proof: `src/actions/__tests__/actions.test.ts` «reading an uploaded file in a handler».
  - Async handlers are not serialized: the replay store is checked before the `await` and written after it, so the same idempotency key sent twice at once runs the handler twice, and two calls can interleave at the `await`. A handler re-reads any store it appends to after its `await` (a read taken before it may be stale). The Kernel's single-flight write keeps one screen from sending both; the engine does not add a per-key lock.
- Jobs (`src/actions/jobs.ts`): `Job.startedAt` is the start time; `Job.anchor` is a decimal sequence string unique per equipment and ascending by `startedAt` (find with `findJobByAnchor`).
- `MockEndpoint.provisional` is an optional hook for a menu to judge Trust by the target data's time. It replaces the period-length judgment only for normal, non-empty mart responses; unspecified, empty, error and malformed responses keep the existing judgment. An execution occurrence is judged by `startedAt >= DATA_THROUGH − 24h` (`anchor` is a RecordSequence, not a time, ADR-0094); the reference period does not apply.

## Layout

Group `src/` by branch folder: `access/` (permission, validation), `audit/` (audit, chart annotations), `actions/` (write actions, jobs), `query/` (endpoints, optional ports). Keep at the root only the public entry `index.ts`, `server`, `adapter`, `world` and `test-setup.ts` (the vitest `setupFiles` target). Tests go in the owning folder's `__tests__/`; integration tests belonging to no single folder go in `src/__tests__/` (ADR-0090).

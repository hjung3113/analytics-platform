# @ap/components

Platform Component 층(06 §13) + 차트 계약(§16) + 페이지 archetype 골격(§12). 메뉴가 조립하는 부품이다.

## 파일


- `LegendTree.tsx` — 도메인을 모르는 계층 범례 트리. 보이기는 소비자 소유(`visible`, 리프 id로 판정)이고 조상은 3단계 체크(체크·일부·해제)로 보인다. 선택 모드의 단일 현재 항목, controlled 정렬 표시, controlled/uncontrolled 펼침을 받는다. 행 이동은 APG 방향키, 포커스 복구를 소유한다(06 §26, ADR-0057). 모든 모드에서 Tab은 현재 행 → 펼침/접기 버튼(부모만, 읽기 전용 펼침은 건너뜀) → 조작 가능한 정렬 버튼 → 트리 밖 순서이고 Shift+Tab은 그 반대다. 현재 행의 동작 버튼만 `tabIndex=0`이고 다른 행의 버튼과 보이기 체크박스는 `-1`이다. 펼침 버튼의 Enter/Space는 펼침을 바꾸고, 행의 Enter는 선택 모드에서 선택, 그 밖에는 펼침을 바꾸며, 행의 Space는 보이기를 바꾼다.
- `PlatformPage.tsx` — 페이지 최상위. 제목·액션·`contextExtension`·`dataTrustSummary`·breadcrumb 슬롯, Scope 게이트, 전역 Context Bar는 `slots.contextBar`로 받아 렌더(셸을 import하지 않음). 본문 영역은 `data-platform-page-content` 속성으로 식별한다(헤더·전역 Context·페이지 extension 제외, Scope 게이트도 이 영역에 렌더). 계약 검사는 스타일 클래스 대신 이 안정된 hook을 사용한다. Kernel `pageNavigation`의 포커스 요청을 소비해 `drill`이면 현재 단계, 그 밖이면 제목(h1)에 포커스하고, 프로그램이 준 제목 포커스로는 제목 툴팁을 열지 않는다(06 §26). 도착으로 열린 `focus=` 상세 패널은 그 제목 포커스를 가져가지 않는다(ADR-0032). Scope 게이트의 동작 버튼이 상태 변경으로 사라지면 포커스를 main 랜드마크(셸 밖에서는 본문 요소)로 옮긴다(06 §26, #353). 머리 컨테이너 폭이 줄거나 실제로 넘치면(`scrollWidth > clientWidth`, 결정은 `headerYield.ts`) 설명·Data Trust 요약·잠정 배지 순으로 양보하고 제목은 최소 폭을 지키며, 보조 동작은 ⋯ 메뉴에 둔다(ADR-0035). 보드 지원 메뉴(`features.board`)를 열 수 있는 본 화면에서는 `secondaryActions`가 없어도 앱의 `slots.boardEntry` 항목을 ⋯에 덧붙인다(칸 안·슬롯 없음·보드 미지원은 ⋯를 만들지 않음, 16 §6). 항목의 대화상자는 `useHeaderOverflowDialog()`로 머리에 맡기면 ⋯가 닫혀도 남고, 열릴 때 ⋯가 `더보기`로 포커스를 끌어오지 않으며 이동 없이 닫으면 `더보기`로 돌아간다(`PlatformPage.board-entry.test.tsx`). 모든 양보 뒤에도 들어가지 않는 폭에서만 머리 가로 스크롤을 남겨 주 동작에 Tab 포커스나 스크롤로 닿게 하며, 정상 폭(1280px 이상 + 상세 패널)에서는 넘치지 않는다(06 §7).
- `AnalysisLayout.tsx` — 분석 화면의 KPI 띠·차트 2열·전체 폭 분해 표, 단위별 접기와 접힌 항목 칩 복원·메뉴별 기억·포커스 이동을 소유한다(06 §12.6, ADR-0022). 선택적 `density`는 regular(기본값) 또는 compact(1–4열)를 고르며, 차트의 `AnalysisSection.span: 'full'`은 활성 열 전체를 차지한다. 크기와 상속은 06 §12.6을 따른다.
- `DrillLayout.tsx` — `DrillPath`·`DrillLayout`·`ReturnLink`(06 §12.7·§13·§22, ADR-0025). 경로 바는 `useDrill()`을 읽고, 형식 오류와 결과에 없는 값은 본문 자리에 상태를 그린다. 복귀 버튼은 `returnOrigin()`의 메뉴 이름과 단계 값을 쓴다.
- `ManagementLayout.tsx` — 관리 화면의 filter/table/drawer 슬롯. 자기 폭에 따른 접을 수 있는 sticky 필터 레일과 좁은 폭 팝오버, 공통 접힘 기억·포커스 이동을 소유한다(06 §12.6, ADR-0022). `pendingFilterCount`가 있으면 접힌·좁은 `필터 · N` 버튼에 `미적용 n` 글 표식과 설명(접근 가능한 이름은 그대로)을, 레일 머리에 미적용 변경 수를 보인다(ADR-0037).
- `PageFilterBar.tsx` — consumer가 정의한 검색·텍스트·Select·custom 필드와 actions를 표시한다. field value·URL key·변경·reset/apply 의미는 consumer가 소유하며, 현재 알 수 없는 Select 값은 표시 옵션으로 유지한다(#54, 06 §13·§15). 입력·Select는 40px 기본 높이를 쓰며 덮어쓰지 않는다. 관리 화면은 `onApply`로 막대를 `<form>`으로 만든다 — submit이 유일한 적용 경로이고, 막대는 한글 조합 중(`isComposing`·keyCode 229·compositionend 직후) Enter의 암묵 submit만 막는다. 적용으로 포커스된 `적용` 버튼이 꺼지면 같은 컨테이너의 첫 필드로 포커스를 옮긴다.
- `PlatformPage` 칸 모드(`screenMode === 'pane'`, ADR-0049) — 머리(50px)와 `slots.contextBar`를 그리지 않고 자동 도착 포커스(`page`)를 하지 않는다(보드가 칸 머리·Context 바를 소유). 명시적 드릴·반환 포커스는 칸 안에서 현재 단계, 없으면 칸 루트로 간다(`DrillLayout`의 드롭다운 닫힘 포커스도 그 칸 안에서만 찾는다 — 4단계에서 가운데 메뉴로 단계를 고르면 트리거가 사라지므로 조회 범위는 사라지지 않는 경로 바 `<nav>`에서 잡는다, #497 D1). Scope 게이트와 그 복구 동작, `contextExtension`, `OutcomeScope`·`OutcomeBanners`·본문(`data-platform-page-content`)은 그대로이고 거부·검증 중에는 보호된 본문을 마운트하지 않는다. `DetailDrawer`는 칸 안이면(`paneLabel`) 제목 위에 `칸 N · 메뉴` 캡션을 보이고 그 칸의 화면(pathname)이나 분석 Context가 열린 뒤 바뀌면 `onClose`를 한 번 부른다(`DetailDrawer.pane.test.tsx`). 연 요소가 사라지면 `data-pane-id` 칸 루트(#497이 `tabIndex=-1`로 제공)로, 칸이 아니면 main으로 포커스를 돌린다. 검증 `PlatformPage.pane.test.tsx`·`PlatformPage.pane-drill.test.tsx`.
- `pageFocus.ts` — `focusPageFallback`은 가장 가까운 포커스 가능한 칸 루트(`[data-pane-id][tabindex]`)를 main보다 먼저 쓰고 공개하며 `requestReturnFocus`·`consumePageFocus`는 내부에서 쓴다.
- `useFilterDraft.tsx` — 관리 화면 필터 초안(`values`·`set`·`changedCount`·`reset`·`patch`)과 `FilterApplyButton`(`적용`/`적용 (n)`). 초안은 `ManagementLayout` 위 화면이 들고, 적용된 값(또는 명시한 `identity`)이 바뀔 때만 다시 맞춘다. 적용은 patch를 만들어 `setPage` 한 번(`page: null` 포함)으로 보낸다(ADR-0037). 같은 파일의 `useManagementFilters({ applied, identity?, clearKeys, toPatch?, onRebase? })`가 초안·적용(`toPatch`가 null이면 중단)·푸터 초기화 버튼(적용 값이 있을 때만, `focusPageFallback` 호출 없음)·`recoverButton`(경고창 안 복구 동작: 적용 값과 무관하게 항상 만들고, `type="button"`, `focusPageFallback` 뒤 `clear`)·`barProps`·`layoutProps`(`activeFilterCount`·`pendingFilterCount`)를 한 번에 배선하고, `onRebase`는 초안을 다시 맞추는 render 단계에서만 불린다. 필터 의미·URL key·초기화 키 목록·patch 검증은 화면이 준다.
- `tableUrlWarning.tsx` — `useTableUrlWarning(allowedSort)`(`sort`/`page` 원문을 코덱으로 해석해 `parsedSort`·`parsedPage`·`invalid`·ADR-0034 문장을 돌려줌)와 `TableUrlWarning`(표 자리에 그리는 danger 메시지, `초기화`는 `focusPageFallback` 뒤 `setPage({ sort: null, page: null })` 한 번; 선택 prop `filters`에 관리 화면의 `filterSlot`을 주면 메시지 위에 `gap-3`으로 함께 그린다). 허용 정렬 열은 페이지가 준다. sort/page를 페이지가 직접 읽는 표(설비·지표 카탈로그·레지스트리·활용률)는 이것을 쓴다. 감사·권한도 sort/page만 틀리면 이것을 쓰고(`filters={filterSlot}`), 필터 키가 틀리면 `FilterUrlWarning({ sentences, filters?, recover })`가 우선한다(#389, #413) — 같은 틀(제목 `invalidFilterTitle`, 문장마다 `<p>`)에 `recover`(= `useManagementFilters().recoverButton`)를 동작으로 둔다. `TableUrlWarning`은 그대로이고 틀린 키가 sort/page일 때만 이긴다.
- `StateView.tsx` — `QueryView`는 §19의 QueryState idle을 중립적인 조회 전 상태와 번역된 필수 누락 목록으로 표시한다(ADR-0061). `OutcomeScope.tsx`는 PlatformPage 본문별 위젯 응답 배너(#55, ADR-0017). Outcome 그룹 등록 훅은 상태 분기 전에 유지하고 이전 그룹을 해제한다. 검증 `StateView.test.tsx`·`OutcomeScope.test.tsx`.
- `PlatformDataTable.tsx` — 서버 페이징 표. `loadPage`는 `@ap/contracts`의 `PageQuery`·`PageResult` 모양을 쓰고, 열은 엔진 무관 `PlatformColumn<T>`(TanStack `ColumnDef` 변환은 비공개 `columnDef.ts`)만 받으며 정렬은 `PageSort[]`다. 행 영역 높이는 내용만큼이며 `tableFit.ts`가 스크롤 컨테이너·본문 영역(`data-platform-page-content`)·고정 머리(`data-page-sticky-header`)를 관찰해 남은 높이 `max(240px, R)`를 상한으로 정한다(명시한 `height`는 분석 표의 상한). 선택 열은 내보내기·복사·`bulkActions`가 있을 때만, `rowAction` 동작 열은 오른쪽 고정이며, 128px이 안 들어가고 72px이 들어가면 `rowAction(row, { compact })`가 `compact: true`로 불려 72px 아이콘 전용 형태로 계속 고정한다(ADR-0037, 06 §15). 동작 컨트롤은 `RowAction.tsx`(`RowAction` — `compact`·아이콘·접근 가능한 이름·글자, `onClick`·`link` 자식·`textLink`·`disabled`+`aria-describedby`; 메뉴 이름을 모른다)가 소유한다. 같은 요소 트리를 두 형태로 그려 compact ↔ 일반 전환에도 DOM 노드와 포커스가 유지되므로(툴팁은 compact에서만 열림) 메뉴는 `compact ? A : B`로 요소 종류를 바꾸지 않고 `<RowAction compact={compact} …/>` 하나를 돌려준다. 표는 데이터 열 정의를 동작 폭과 무관하게 메모해 폭 경계 전환이 셀 내용을 다시 만들지 않는다(#399). 정렬·페이지는 `urlState`로 제어하고 코덱 `parsePageIndex`·`parseTableSort`·`encodeTableSort`를 쓴다(키 이름·값 도메인은 페이지 소유). 표 엔진(`@tanstack/*`)은 여기 내부이고 메뉴 import는 lint가 막는다. 요청 취소 판정은 표 자신의 `controller.signal.aborted` 하나다(타임아웃 `AbortError`는 오류로 보인다). 그 밖에 `DetailDrawer.tsx`(+`Field`), `AuditTimeline.tsx`, `DataTrustIndicator.tsx`, `StatCard.tsx`, `RadioGroup.tsx`, `copyText.ts`(링크 복사용 `copyText`·`useCopyLink` — 쓰기 완료 뒤에만 성공, 비보안 컨텍스트는 제스처 안 `execCommand`, #300).
- `AnalysisChart.tsx` — `ChartSpec` 히트맵·도넛·scatter·boxPlot·pareto·topNBar 프레임과 로컬 선택·키보드 표·명시적 상세·manifest Export를 소유한다(06 §16, ADR-0058의 §24 예외). `topNBar.ts`는 전체 입력의 정렬·상위 N 제한·색상 투영을 담당한다. 선택적 `size`는 regular/compact/hero이며 공통 크기 결정·서식 있는 설명 Tooltip·compact 범례 규칙은 06 §12.6을 따른다.
- `AnalysisChartFrame.tsx`(Zoom/Brush/Reset/Compare/Annotate/Export), `EChart.tsx`(ECharts 어댑터). Compare·Annotate·Export는 현재 메뉴 manifest `features`가 켠 것만 그리고, 주석은 `adapter.listAnnotations`·`saveAnnotation`·`deleteAnnotation`(작성자만 삭제 — 응답의 `mine`으로 버튼을 그리고 인라인 확인, ADR-0041. 키 `chartId + scopeId`, `usePlatformQuery` 'session' 식별자에 Scope 포함)으로만 읽고 쓴다 — 모듈 전역 저장소를 두지 않는다(06 §16, #103). Compare 범례는 두 기간을 이름으로 연결한 그룹으로 표시하고 plot과 SVG swatch가 같은 선 패턴을 쓴다(ADR-0014). 선택적 `size`는 AnalysisChart와 같은 상속·내용 계약(06 §12.6)을 쓰며 regular 플롯의 기존 기본 높이 260px을 유지한다.
- `AnalysisChartFrame` SDK 조각 — `pointActivation`/`pointActions`는 키보드 동작도 갖춘 소비자 콜백이다. `orientation="horizontal"`은 세로 brush가 있는 범주 행을 그리고 `visibleSeriesIds`/`onVisibleSeriesChange`가 표시 시리즈를 제어한다(06 §16, ADR-0063).
- `querySummary.ts` — 전체값 기준 초안/적용 요약을 공유한다. 축 이름과 소비자 page 라벨은 입력으로 받는다. `PageFilterBar mode="draft"`는 제어 필드를 유지하고 Apply/form submit 동작을 제외한다. `PlatformPage.queryBarExtension`은 초안/적용 page 요약과 검증 문제를 제공하고, 보드의 `QueryBarExtensionsProvider`는 칸/메뉴/params/session별 본문·바 Provider가 메타데이터를 공유하게 한다. `queryResult`는 page header 없는 칸 내용까지 적용 결과 줄의 권위 있는 조회 상태/완료 시각을 제공하며 조회를 시작하거나 합치지 않는다. `QueryBarExtension.historyPageSummary(global,page)`는 임의 이력 후보의 실제값·유효 기본값을 요약하는 순수 함수로, 현재 초안 요약을 다른 행에 재사용하지 않는다(06 §11). 검증은 query-summary/result 테스트.
- `annotationLayout.ts` — note label rows and widths (#399 AC-2).
- `testing.ts` — 테스트 전용 공개 진입점 `@ap/components/testing`(`stubCompactTableGeometry`: 표 행 영역 폭 220px·페이지 1280×800 stub과 복원 함수, ADR-0040 확장). `src/index.ts`에서 내보내지 않으며 이 패키지 테스트는 `./testing`을 import한다. 행 영역 이름은 `scrollportLabel.ts`를 표와 공유한다.
- `dock/` — 호스트 전용 진입점 `@ap/components/dock`(`src/index.ts`는 re-export하지 않는다, 메뉴·모듈 import는 lint가 막는다, ADR-0067). 제어형 `DockLayout`: 호출자가 `DockNode` 트리(`schema.ts`: `group{panels,active}` | `branch{dir,sizes,children}`, 최대화는 저장하지 않음)를 주고 엔진이 그리며 사용자가 바꾼 것을 `onLayoutChange`로 알린다. `normalizeDockTree`(고쳐서 돌려줌, 던지지 않음)·`isValidDockTree`(거절용)와 키보드·메뉴 경로가 끌기와 같은 순수 명령(`commands.ts`: `movePanel`·`addPanel`·`removePanel`·`activatePanel`·`resizeBoundary`·`groupOf`·`panelOrder`)이 있다. 엔진(`dockview-react`, 정확한 고정 8.6.1)은 `DockEngine.tsx`만 import하는 lazy 청크이고(청크 실패는 `EChart`와 같은 오류 상태와 `다시 시도`), 공개 API에는 엔진 타입·JSON이 없다. **리마운트 0**: 새 `layout`은 `fromJSON(…, { reuseExistingPanels: true })`로 라이브 엔진에 맞추며 `clear()`·`close()`를 부르지 않는다. 탭에는 닫기 버튼이 없고 탭의 Delete/Backspace는 엔진 닫기로 가지 않는다(닫기는 플랫폼 명령; 선택 prop `onPanelDelete(panelId)`가 호스트에 그 키를 알린다 — 보드는 `비우기`). `onActivate`는 사용자 활성화(탭 포인터·Enter/Space/방향키, 패널 안으로 들어온 포커스)에만 불리고 엔진 활성 변화는 부르지 않는다. 보이지 않는 패널(배경 탭·다른 패널 최대화·좁은 폭 한 그룹 표시)은 `inert`이고 `TransientOverlayScope`로 열린 Radix 오버레이를 닫는다(`data-dock-panel`·`data-dock-visible`). 경계마다 포커스 가능한 `role="separator"`(방향키 5%·Home/End, docs/16 §4)를 엔진 sash 위에 겹쳐 그리고 포인터 끌기는 엔진 sash가 맡는다. 그룹 `⋯`(`renderGroupActions`)의 열기 요소에는 `data-dock-group-menu`를 달며 탭의 Shift+F10·ContextMenu가 이를 연다. Esc는 열린 메뉴·Popover가 먼저 받고, 남은 Esc가 가장 안쪽 최대화만 끝낸다. 엔진 안내 방송(영어)은 끈다. 선택 prop `currentPanelId`는 호스트의 현재 칸으로, 좁은 폭 표시가 그 칸을 보인다(없으면 첫 그룹 활성 탭·사용자 선택). 좁은 폭 탭은 `panels` 순서다. `tabA11y(panelId)`는 탭 요소에 `aria-description`·`aria-keyshortcuts`를 단다. Tab/Shift+Tab은 탭 → 그 칸 안(첫 포커스 요소, 없으면 `data-dock-panel` 자체) → 다음 그룹 탭 순서로 `DockLayout`이 옮긴다(엔진 DOM 순서 유지). 엔진이 다시 짜면서 포커스가 있던 탭이 사라지면 같은 칸의 탭에 포커스를 돌려준다. 검증은 `dock/` 테스트(jsdom은 엔진 기하가 없어 구조만 단언하고 크기는 E2E에서 본다).
- `styles.css` — Tailwind `@source`. `a11y.test.tsx` — 드로어·라디오 키보드·포커스 접근성 테스트. `xlsxTestReader.ts` — 테스트 전용 XLSX 판독기(fflate, devDependency).


## 규칙

**표 소유 내보내기·복사(#173·#174, [ADR-0008](../../docs/adr/0008-table-owned-export-fixed-toolbar.md), 06 §15).** 메뉴는 `exportRows(request, signal)`(선택 ids 또는 필터 전체 + 표의 활성 `sorting`)·`exportNote`·`exportFilterSummary`·`exportContext`만 주고, outcome 처리·CSV/XLSX 직렬화·파일·토스트·[복사]는 `PlatformDataTable`이 소유한다. 직렬화기는 내부 모듈 `src/tableExport.ts`(`index.ts` 비공개). 화면에 보이는 값만 나가며 라벨·시간 열은 `PlatformColumn.exportValue`로 같은 텍스트를 준다. 게이트는 manifest `features.export`. XLSX(`write-excel-file/browser`)는 클릭 때 동적 `import()`로만 불러 별도 청크에 둔다. 툴바 순서·거절 문구·시트 구성·클립보드 경로의 세부는 `PlatformDataTable.test.tsx`·`PlatformDataTable.copy.test.tsx`·`tableExport.test.ts`가 고정하고, 테스트가 고정하지 않는 접근성·클립보드 규칙은 06 §15 "표 내보내기·복사 구현 계약"에 있다 — 바꾸면 테스트·06 §15·ADR-0008부터 고친다.

- import 가능: `@ap/contracts`, `@ap/kernel`, `@ap/ui`와 표·차트 라이브러리. `@ap/shell`, 앱, mock, 메뉴 화면 import 금지.
- 컴포넌트는 도메인 의미(설비, 지표 이름)를 모른다. 컬럼·셀·탭 내용은 props로 주입받는다.
- 06 §19 상태, §18 Data Trust, 접근성(키보드·포커스 복귀·레이블) 의무를 컴포넌트가 소유한다. 페이지가 따로 구현하게 두지 않는다.
- 차트 클릭으로 전역 Context를 조용히 바꾸지 않는다. 명시적 콜백(`onPointClick`, "분석 구간 적용")만 제공한다.
- 새 컴포넌트는 실제 메뉴 2~3곳 반복이 확인된 뒤 올린다(06 §24). 스타일은 `@ap/ui` 토큰 유틸리티만.
- `DetailDrawer`는 셸 상세 슬롯에 portal로 내용을 넘긴다(ADR-0013, 06 §13). AppShell 또는 같은 `DetailPanelSlotProvider` 아래에서만 쓴다. URL 도착으로 `focus=`와 함께 열린 패널은 포커스를 가져가지 않고, 같은 화면에서 연 패널만 닫기 버튼으로 포커스한다(ADR-0032). 포커스를 가져가지 않은 패널은 언마운트 때 포커스가 패널 안에 있을 때만 복귀한다. 탭 전환으로 포커스된 컨트롤이 사라지면 선택된 탭 트리거(없으면 패널)로 옮긴다(06 §26, #353).

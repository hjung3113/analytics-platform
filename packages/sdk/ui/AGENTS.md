# @ap/ui

UI Primitive 층(06 §13)과 디자인 시스템 CSS. 플랫폼 개념(Context, Scope, 메뉴)을 모른다.

## 파일

- `src/styles/` — 디자인 시스템 CSS의 원본(ADR-0043·0046, FeedbackOps `a8d768b8`에서 이전): `tokens.css`·`semantic.css`(공유 값)·`theme.css`(Tailwind 테마 매핑)·`compat.css`, 그 위 `platform-tokens.css`(플랫폼 확장 값만), `index.css`(확장 Tailwind 테마 매핑·base·타이포 유틸리티 `t-page-title` 등. 진입점 = `@ap/ui/styles.css`). 기능 화면처럼 플랫폼 확장 없이 공유 파일만 받는 소비자는 `@ap/ui/styles/{tokens,semantic,theme,compat}.css`와 클래스 스캔용 `@ap/ui/styles/sources.css`를 개별로 import한다. `styles/__tests__/`는 소비 계약·토큰 충실도·상태 색 대비 검사다.
- `src/theme/` — `theme-tokens.json`·`tokens.generated.ts`는 CSS 원본에서 생성한다. 직접 수정하지 말고 색 토큰을 바꾼 뒤 `pnpm --filter @ap/ui gen:theme`을 실행한다. 새 색 토큰은 `scripts/theme-tokens.config.mjs`에서 공개 포함 또는 제외 이유를 분류한다.
- `src/components/shadcn/*` — shadcn primitive 22종의 실제 구현(원래 FeedbackOps). 공개 export는 `src/index.ts`의 명시 목록이고, `src/public-exports.test.ts`가 이름 목록을 고정한다. `DialogContentBare`·`alert-dialog`·`avatar`·`card`·`combobox`·`hover-card`·`sheet`·`textarea`·`toggle-group`은 플랫폼 화면이 쓰지 않지만 기능 `@ap/feature-ui`가 얇은 재수출로 받으므로 공개한다(`src/index.ts` 끝의 기능 소비 묶음). 같은 묶음에 `KeyboardShortcut`·`SkeletonBlocks`·`SkeletonRows`, 모션 상수·`readMotionTiming`·`useListMotion`·`isToastTarget`, 그리고 플랫폼 표식 없는 shadcn 탭 `TabsListBase`·`TabsTriggerBase`(`TabsList`·`TabsTrigger`는 플랫폼 표식 래퍼라 FeedbackOps 모양과 다르다)가 있다. 이 묶음은 소비자(FeedbackOps) 전환용이며 플랫폼 코드가 새로 쓰기 전에 06 §24 기준을 따른다.
- `src/components/PlatformTabs.tsx` — 예외: `TabsList`·`TabsTrigger`는 같은 패키지 shadcn 탭을 감싼 플랫폼 선택 표식 구현(ADR-0023 개정, #340). `Tabs`·`TabsContent`는 `shadcn/tabs`에서 내보낸다.
- `src/components/Button.tsx`·`KeyboardShortcut`·`SkeletonBlocks`·`SkeletonRows`, `src/utils/`(`cn`·`motion`·`toast-target`·`useListMotion` — 이전; `isProductionEnv`(플랫폼 환경 판단)·`platform.ts`(`isMacPlatform`·`shortcutLabel` — 단축키 표기의 OS 판정과 한 가지 표기 `⌘K`/`Ctrl+K`, #300), `copyText.ts`(일반 텍스트 복사의 성공 판정 한 벌 — 06 §15: 보안 컨텍스트는 `writeText`가 끝나야 성공·거부는 폴백 없이 실패, 비보안은 `execCommand('copy')`가 true이고 일회성 `copy` 리스너가 실제로 값을 채웠을 때만 성공. `DetailPanelHeaderActions`와 `@ap/components`의 `useCopyLink`가 쓴다, #673), `storage.ts`(`readLocalStorage(key, decode, fallback)`·`writeLocalStorage(key, value | null)` — 선택 기억값의 try/catch 한 벌, 저장소나 `decode`가 던지면 `fallback`, 쓰기 실패는 false. components·shell이 쓴다. Kernel은 `@ap/ui`를 import할 수 없어 자기 내부 사본을 둔다, #673) — 플랫폼 것), `src/internal/useHorizontalOverflow.ts`, `StatusBadge.tsx`(`Tone`: success/warning/danger/neutral/info).
- `src/{layout,panel,toolbar,forms,feedback}/` — FeedbackOps `a8d768b8`에서 옮긴 레이아웃 셸 3종(`PageShell`·`ListShell`·`WorkbenchShell`)·`ShellHeader`·`ToolbarKicker`, 상세 패널 부품(`DetailPanelHeader`·`DetailPanelSectionNav`·`FieldRow`·`Callout` 등), 목록 툴바, 폼(`DatePicker`·`FieldLabel`·`SearchInput`), 피드백(`DirtyConfirmation`·`EmptyState`·`PreviewModal`·`UndoToast` — 선택 `actionLabel`로 버튼 문구를 바꾼다)과 그 테스트(#442). sonner의 `Toaster`·`toast`는 공개 export로 남는다(#497 — 분석 보드는 #886부터 셸 토스트 스택을 쓰므로 플랫폼 코드에는 쓰는 곳이 없고, `UndoToast`도 마찬가지로 공개 SDK로 둔다). `ListToolbar`는 탭과 액션이 들어가면 한 줄(50px), 툴바 자신의 폭이 모자라면(뷰포트 아님 — 탭 블록 `basis-[22rem]`을 지키며 감싼다) 탭 줄 아래 오른쪽 정렬 액션 줄까지 두 줄(줄마다 50px)이 되고 `role="toolbar"`는 쓰지 않는다. 높이는 적지 않고 고정 표지 `data-list-toolbar`만 둔다(측정값을 읽는 곳이 생기면 그때 넣는다, #946 Q9). 아래 하단 규칙선은 border가 아니라 1px 오버레이라 한 줄이 정확히 50px(두 줄 100px)이고, 이 값을 읽는 sticky 요소는 아직 없다(#886). 공개 export는 `src/index.ts`(기능 화면 이름 그대로, 기능의 `DetailPanelSlotContext`는 옮기지 않았다). `badges/StatusBadgeFrame.tsx`는 `DetailPanelHeader`가 쓰므로 함께 옮겼고 형제 `badges`는 #443에서 옮겼다. 플랫폼 페이지는 계속 `PlatformPage`를 쓰고 이 셸을 채택하지 않는다.
- FeedbackOps `packages/ui` 전체 이전은 #441–#443(ADR-0046)에서 끝났다. ADR-0050/#479는 기능 도메인에 묶인 부품(`badges/`의 `StatusBadgeFrame` 외 전부, `entity/LinkedEntityTrail`, `components/{ChipPicker,ManagedSystemPicker,AnalyticsAreaPicker}`)과 그 테스트를 기능 소유로 되돌렸다. `rich-content/`(`RichEditor`·`RichContentRenderer`·sanitizer·allowlist 사본·tiptap 확장·`AttachButton`·`Mention`·`AttachmentRef`)는 범용 부품이라 [ADR-0052](../../../docs/adr/0052-rich-content-stays-in-the-sdk.md)가 SDK로 복원했다(`sdk-v0.5.0`). SDK 편입 기준: 부품 안에 특정 제품의 도메인 데이터·문구·권한을 박아 두지 않았으면 쓰는 곳이 없어도 둔다(제품별 매핑은 prop으로 받고 매핑은 제품이 소유). SDK에는 `data/ObjectRow`, `identity/{UserAvatar,UserChip}`, `indicators/{ProgressMeter,SeverityIndicator}`, `permissions/PermissionBlockedPanel`, `badges/StatusBadgeFrame`, `rich-content/`가 있다. 공개 export는 `src/index.ts`에 명시한다. 기능 쪽에만 남는 파일: `components.json`·기능 `AGENTS.md`.
- **rich-content allowlist 동등성(보안 관련):** `rich-content/allowlist-local.ts`·`fixtures-local.ts`는 sanitizer 허용 목록의 사본이다. `allowlist-drift`·`fixtures-drift` 테스트는 이 사본을 인라인 fixture에 고정한다. [실제 기능 소스 parity test](../../../apps/platform-web/src/rich-content-allowlist-parity.test.ts)는 기능 패키지 집합(`tooling/eslint/src/feature-packages.js`) import 없이 allowlist의 전체 규칙과 fixture corpus를 비교한다. 여기서 allowlist를 바꾸면 기능도 같이 반영해야 한다. 기록: [백로그](../../../.planning/backlog.md).

## 규칙

- 디자인 시스템 원본은 이 패키지다(플랫폼/SDK 소유, [ADR-0043](../../../docs/adr/0043-platform-sdk-is-the-app-contract-and-unified-framework.md)·[ADR-0046](../../../docs/adr/0046-design-system-source-moves-to-platform-whole-package.md)). 토큰·유틸·primitive 묶음은 #441에서 FeedbackOps `a8d768b8` 값 그대로 옮겼고(이전 기록: [저장소 구조](../../../docs/integration/repository-layout.md)), 기능 `@ap/feature-ui`는 기능 쪽에 그대로 남는 별개의 사본이다. 이전된 묶음의 모양 변경은 여기서 먼저 한다.
- import 가능: 외부 라이브러리만. 기능 패키지 집합(`tooling/eslint/src/feature-packages.js`)와 `@ap/*`는 어떤 패키지에서도 import하지 않는다(경계 lint가 강제).
- 공유 토큰·폰트·반경·본문 값의 원본은 [tokens.css](src/styles/tokens.css)·[semantic.css](src/styles/semantic.css)이고 소비 계약은 [FO ADR-0058](../../../docs/adr/history/feedbackops/0058-tailwind-v4-css-first-theme.md)의 기록을 따른다(플랫폼 결정: [ADR-0011](../../../docs/adr/0011-design-direction-feedbackops-shell.md)). 플랫폼 확장의 설계 원본은 [DESIGN.md](../../../DESIGN.md#platform-extension-layer)이며 이 패키지는 구현을 소유한다. 토큰 파일 밖에서 hex 값 금지.
- 앱은 Tailwind → `@ap/ui/styles.css` 순서로 import한다. 이 진입점은 tokens·semantic(`layer(base)`) → theme → compat → `platform-tokens.css`(`layer(base)`) → `@source` 순서를 유지한다(캐스케이드 순서 변경 금지). 폰트는 앱에서 레이어 없이 import한다.
- label·vivid accent·control 경계의 역할과 허용 표면은 [DESIGN 접근성 pairing](../../../DESIGN.md#accessibility-pairing-rules)을 따른다. 새 소비자도 이 조합을 확인한다.
- `DialogContent`·`SheetContent`를 플랫폼에서 렌더링하면 `closeLabel`, `Combobox`를 렌더링하면 `listboxLabel`·`emptyText`를 i18n에서 전달한다(FeedbackOps#749).
- 명령 팔레트는 `DialogContent scrim="palette"`를 사용한다(#310, FeedbackOps #1050); 다른 `DialogContent`는 기본 모달 scrim을 유지한다.
- 모션(토큰, overlay 진입·퇴장, reduced-motion)은 `theme.css`·`compat.css`와 primitive에서 그대로 온다(FO ADR-0063, 06 §26). 플랫폼에서 덮어쓰지 않는다. `useListMotion`·모션 상수는 기능 화면 소비용으로 공개했지만 플랫폼 화면은 아직 쓰지 않는다(06 §24, #289). `prefersReducedMotion`의 첫 소비자는 EChartImpl의 Canvas reduced-motion이다(#297).
- 상태 색은 `StatusBadge`/`Tone`으로만 노출한다. 새 Tone은 DESIGN 변경이다.
- 데이터 조회, 권한 판단, 라우팅, 도메인 문구를 넣지 않는다. 그런 조합은 `@ap/components`다.
- shadcn 컴포넌트를 공개하려면 `src/index.ts`에 export하고 `src/public-exports.test.ts` 목록을 같이 고친다. `styles/index.css`의 `@source "../"`가 이 패키지 `src` 전체를 스캔한다.
- 이전한 테스트는 `vitest.config.ts`(`globals`, jest-dom setup `src/vitest.setup.ts`)로 돈다. 기능과 다른 의존 버전(vitest 3·jsdom 26·lucide 1.x)에서 다시 도는 것이므로 새로 생긴 실패는 코드를 고치지 말고 원인을 먼저 가린다.

- `DetailPanelSlot.tsx` — 셸 상세 슬롯 등록 primitive(Provider·host hook·등록 hook). 도메인·URL을 모른다(06 §13, ADR-0013). 슬롯은 하나이고 등록 방식은 둘이다([ADR-0047](../../../docs/adr/0047-detail-panel-slot-single-registrant-model.md)): portal 등록(`useDetailPanelSlot(options?)` — host를 받아 직접 portal, 제공자 없으면 throw; `onSuperseded`는 활성 칸 portal 등록자가 새 등록자로 바뀔 때 호출)과 내용 등록(`layout/useDetailPanelContent(node)` — 셸의 `detailPanel` prop, 제공자 없으면 no-op, `undefined`면 비움). 둘은 한 등록자 목록을 공유해 마지막 등록자가 이기고 정리 시 직전 등록자가 돌아온다. 내용 등록의 내용은 Provider가 host에 portal로 그린다(그래서 Provider 위치의 React context를 본다). `useDetailPanelContent(null)`은 슬롯만 차지하는 닫힌 등록자이고, 슬롯 내용만 `DetailPanelFullscreenContext`(Provider가 확장 상태·Escape를 소유)를 받으며 호스트 hook은 `{ ref, open, activation, expanded, toggle }`를 돌려준다(#473). `activation`은 상세가 **새로 보이게 될 때만** 1 늘어난다(새 portal 등록자, 새 비null 내용 등록자, 같은 등록자의 `null`→노드). 열려 있는 등록자의 새 노드 재렌더, 닫힌(`null`) 등록자, `clearContent`, 해제·직전 등록자 복귀는 늘리지 않는다 — 셸이 도킹 VOC 드로어를 상세에 자리 내줄 때만 쓴다(#655, 06 §13). `SurfacePauseScope paused`/`useSurfacePaused()`는 등록자를 소유한 화면이 가려졌지만 마운트가 남은 상태를 선언한다(도메인 중립, [ADR-0088](../../../docs/adr/0088-surface-pause-detail-slot.md)): 중지된 등록자는 자리를 지키되 `open` false·`activation` 불변(중지 중 내용 갱신도 불변)·`onSuperseded` 미호출이고, 재개 때 여전히 승자일 때만 다시 보이며 `activation`이 늘고, 중지된 채 새로 등록하면 목록 맨 뒤에 선다. 내용 등록자의 내용은 중지 동안 그리지 않고 portal 등록자의 서브트리는 숨은 host에 마운트된 채 남는다. `TransientOverlayScope`는 Dialog·AlertDialog·Popover·Sheet·DropdownMenu·Select의 일시 portal을 scope로 닫는다. 숨겨진 scope의 자식은 유지하며, `detached`면 부모 칸 visibility와 분리된다.

## 검증

`pnpm --filter @ap/ui test`로 좁혀 본 뒤 루트 검사(루트 `AGENTS.md`). 토큰·스타일 변경은 `pnpm dev`로 화면을 직접 확인한다.
- 이 패키지를 바꾸면 루트 `pnpm typecheck|test`가 기능 패키지도 검사한다. 기능 UI의 부품 동작을 바꾸면 `pnpm --filter @ap/feature-ui exec vitest run`으로 좁혀 보고, 커밋 뒤 `pnpm --filter @ap/platform-api-ops gate:fe-lint --base origin/main`으로 기존 Biome 변경 파일 계약을 확인한다(#676). 통합 CI는 `ci.yml`이며 ESLint 전환 #1102는 미구현이다.
- `@formkit/auto-animate@0.10.0` 패치는 `useListMotion`이 남아 있는 동안 유지한다(`patches/@formkit__auto-animate@0.10.0.patch`, 루트 `pnpm-workspace.yaml`의 `patchedDependencies`). 패치가 없으면 `useListMotion` 테스트 2건(destroy 뒤 polling 타이머)이 실패한다. 패치 변경 후에는 `pnpm install` 결과와 workspace state를 확인한다.

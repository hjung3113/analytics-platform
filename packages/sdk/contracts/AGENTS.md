# @ap/contracts

Contract types and pure functions shared by the platform, server and menus. Keep them free of runtime-environment dependencies so a backend can share them later.

## Rules

- Import nothing from React, DOM types, Node APIs, other `@ap/*` packages or external runtime libraries.
- A field addition or rename is a contract change. Update the consumers (kernel, shell, app mock implementations) in the same PR and first decide whether the change belongs in contract 06 or the package-boundary document. Most field names are Candidate.
- Contract tests live in the app integration tests `apps/platform-web/src/{url-contract,platform-inbound-link,instant,menu-query-contract,contracts-helpers,measure}.test.ts` (and `saved-view-contract.test.ts`): update them with any codec or declaration change. The package's own `test` only checks that `vocab.json` is current: after changing a vocabulary list, run `gen:vocab` and commit the result.
- Reject URLs with an error; never repair them (contract/kernel.md §6).
- When adding a method to `PlatformAdapter`, fix in the same PR every adapter implementation that `pnpm typecheck` then breaks (`testAdapter` in `@ap/kernel/testing`, mock `packages/adapters/mock-server/src/adapter.ts`, `referenceAdapter` in `@ap/server-conformance` tests), the `@ap/server-conformance` checks, and the tables in [checklist §2](../../../docs/integration/real-server-checklist.md) and [wire-format draft §1](../../../docs/integration/http-adapter-contract.md).
- The public API is `index.ts` (root), `build.ts` (`@ap/contracts/build`, build tools only) and the generated `vocab.json`; export new public API explicitly there, and keep build tooling out of the root. Moving files only changes import paths.
- Deployment output and consumer-environment rules belong to [package boundaries §3](../../../docs/integration/platform-packages.md#3-패키지-구성); `check:pack` verifies them.

## Layout

`src/` root holds the public entries `index.ts` and `build.ts`, the generated `vocab.json` (referenced by `exports`), `globals.d.ts`, and the cross-cutting `guards.ts`·`i18n.ts`. The rest are folders: `adapter/` (port, actions, audit, response, paging, selection ports, correlation ID), `menu/` (menu declaration, query declaration, required Context), `links/` (URL codec, `returnTo`, platform inbound links, applied history), `host/` (host → module contract), `values/` (period, measure, instant). File names below are inside these folders.

## Contracts by file

- `url.ts` — global Context URL codec (`parseQuery`, `buildQuery`, `isAppRelativePath`, …); implements the §6 URL contract.
- `platform-inbound-link.ts` — platform inbound deep-link codec (`PlatformHop`·`buildPlatformInboundLink`·`parsePlatformInboundLink`). The owner is [integration contract](../../../docs/integration/platform-inbound-links.md) §2; this file implements it.
- `return-to.ts` — the navigation-information rule: `RETURN_TO_KEY`, `withoutReturnTo(pairs)` before persistence/replay, `carriesReturnTo(carrySet)` for `CarrySetDef.pageKeys` (ADR-0081 UX-10). URL-string stripping stays kernel-internal (`stripReturnToFromUrl`).
- `menu.ts`:
  - `MenuMeta` (manifest declaration). Optional `aliases` are old-path aliases: the manifest writes the old path in `path` and `createRegistry` rewrites it to the canonical path (ADR-0093).
  - `ContextKey`, `Capability`, `PageType`; brand ids `GroupId`·`SpaceId`·`MenuPermission` (private brand symbol, no value list) with identity-cast constructors `groupId`·`spaceId`·`menuPermission` (they keep the literal so the app gets narrow types; shape checks are `createRegistry`'s, not the constructors').
  - `KERNEL_PERMISSIONS` and `Permission = KernelPermission | MenuPermission`. The app declares the value lists of group/space/menu permissions (ADR-0072); this package holds none. The app declares them in its assembly file with `createRegistry({ permissions })`, and `registry.permissions` is the one runtime list validators and pickers share.
  - Manifest defaults `contextCapabilities(declared?)` (undeclared keys are all `unsupported`; a new object per call) and `NO_FEATURES` (all features off), shared by menu index files and the `gen-menu` template.
  - `SpaceDef.scopePresentation?: 'default' | 'hidden'` (ADR-0108) decides only the sidebar Scope surface (absent = `'default'`). A `'hidden'` space cannot hold `requiresScope: true` menus (Registry rejects) nor use Scope-requiring endpoints/actions.
  - `SpaceDef.feedbackTracking?: true` (ADR-0110): self-registration declaration; rules in [contract/kernel.md §9.1](../../../docs/contract/kernel.md#91-업무-시스템-decided-2026-09-26).
  - `ConditionPreset`·`MenuMeta.conditionPresets`·`conditionPreset`: a Condition preset narrows only the menu query's projection and leaves global Condition and URL as they are ([ADR-0083](../../../docs/adr/0083-condition-presets.md), §6.4).
- `menu-query.ts` — endpoint declaration `EndpointSpec`·`AnyEndpointSpec`·`defineEndpoint`, wire request `MenuQuery`, declaration-based Context projection `projectContext` (pure; takes the already narrowed `g`), and pure `narrowCondition(condition, axes)` (returns `null`, not `{}`, when no axis remains). Decision [ADR-0019](../../../docs/adr/0019-menu-query-endpoint-declaration.md); server judgment order [checklist §3](../../../docs/integration/real-server-checklist.md) (field names are Candidate).
- `action.ts` — write-action declaration `ActionSpec`·`AnyActionSpec`·`defineAction`, wire request `MenuAction`, write-only answers `ActionResponse`·`ActionOutcome`·`FieldError` (do not widen `ApiResponse`). Decision [ADR-0054](../../../docs/adr/0054-write-port-declared-actions-idempotency-version.md); server judgment order [checklist §3](../../../docs/integration/real-server-checklist.md).
- `build.ts` — the second entry point `@ap/contracts/build` (ADR-0156, owner decision #1923): re-exports the snapshot emitter below; the root `index.ts` does not, so the browser-facing root API carries no build tooling.
- `declaration-snapshot.ts` — menu declaration snapshot (ADR-0156): pure emitter `menuDeclarationSnapshot` (rows sorted by id, duplicate ids refused, `sha256` digest over `canonicalJson` with an in-file SHA-256 because contracts imports no crypto), `collectDeclarations` (endpoint/action exports of declaration modules) and the Vite build plugin `menuDeclarationSnapshotPlugin` (structural plugin object; the caller injects the module loader, so no Vite or Node import). It lives here, not in `@ap/contract-schemas`, because the start kit installs only the release tarballs. The file shape is `menuDeclarationSnapshotSchema` in `@ap/contract-schemas`, whose tests pin this emitter; the core server keeps a pinned local copy.
- `query-history.ts` — applied-history store port, entries, keys, deterministic ordering/id. The store owns merge, counts, timestamps and keeping 20 entries (§11).
- `saved-view.ts` — saved-view types (condition sets, menu views, separate publish-target and approval-status fields, per-object capability, `denied` variant), menu declaration `SavedViewSupport`, store port `SavedViewStore` (`Result`: conflict·forbidden·unavailable·invalid), pure `validateSavedView`·`canTransition`. Decision [ADR-0092](../../../docs/adr/0092-saved-view-units-tiers-and-groups.md); contract §21 (kernel.md).
- `paging.ts` — server paging shape `PageQuery` (`page` from 0)·`PageResult`; `sortRows` sorts by the first sort key only and never slices (export mock handlers); `sortAndPage` = `sortRows` + slice (mock handlers). `@ap/components` re-exports the same names (§15).
- `column-filters.ts` — table filter contract (ADR-0104, ADR-0105):
  - Closed operator lists per kind (`TEXT_OPS`·`NUMBER_OPS`·`DATE_OPS`·`INSTANT_OPS`·`ENUM_OPS`) and `ColumnFilterSpec` (`text`·`number`·`date`·`instant`·`enum`; wire meaning only: `ops`·`requires`·text `caseSensitive`·enum `multiple:false`·enum `cell?: 'scalar' | 'many'`).
  - With `cell: 'many'` the row value is an array of option values: `in` = any element included; `notIn` = has elements and none included; `null`/`undefined`/`[]` are empty.
  - `ColumnFilter` is `{ id, op, value }`; date `between` is wall-clock `YYYY-MM-DD`, `to` exclusive. `TableQuery = PageQuery & { filters?; groupBy? }` (`PageQuery` unchanged).
  - Pure `filterRows(rows, filters, accessor?, { specs? })` (the mock server's one-liner; lenient: negation operators exclude empty values, `isEmpty`/`isNotEmpty` name them explicitly).
  - `betweenOrdered(kind, value)` rejects reversed/empty `between`: date and instant need `from < to`, number `min <= max`.
  - `validateFilters(filters, specs)` rejects undeclared fields/operators, bad value shapes, `:` in an id, `requires` violations and `multiple:false` violations; mock and server call it first.
  - URL codec `encodeFilterParam(s)`/`parseFilterParams(values, specs)`/`filterParamLimit`/`FILTER_PARAM_LIMITS`: `<id>:<op>[:<value>]`; sub-separator `~` for lists/ranges and `%XX` escapes for `%`·`~`·`\`·`#`·`/` and control characters (so the Kernel address check passes); limits 20 conditions, 50 list items, 2400 total `URLSearchParams` length (ADR-0105). Test: `@ap/components` `table/__tests__/filterCodec.test.ts`; behavior test `contracts-helpers.test.ts`; Zod equivalence in `@ap/contract-schemas`.
- `period.ts` — wall-clock period math `periodHours`·`bucketStart`·`Grain` and labels `formatPeriod`·`periodShort`·`periodSpan` (§7), shared by screens and server (§6.3). `@ap/mock-server` re-exports the same names.
- `instant.ts` — real-instant (epoch ms, ISO with offset) display `formatInstant`·`instantEpochMs`. Never mix with wall-clock (`formatDateTime` in `url.ts`; §6.3).
- `number.ts` — language-following number display `formatNumber(value, lang, { decimals? | minimumFractionDigits?, maximumFractionDigits? })` (`ko` → `ko-KR`, `en` → `en-US`). Menus use it instead of `toLocaleString` (#1890).
- `measure.ts` — measure re-aggregation `Reaggregation` (`sum`·`ratioOfSums`·`recomputeFromDistribution`·`none`), `MeasureMeta` and `canClientSum`. Server, export, metric catalog and charts share this vocabulary. Owner [01 §aggregation contract](../../../docs/architecture/architecture-and-data-contract.md#집계-가능성-계약); decision [ADR-0082](../../../docs/adr/0082-measure-reaggregation-contract.md).
- `required-context.ts` — required-Context judgment `CONTEXT_FIELDS` (capability → Context field), `missingRequiredContext`, `requiredContextError`; client gate and server validation share it ([ADR-0061](../../../docs/adr/0061-query-draft-applied-address-and-required-gate.md)).
- `selection-ports.ts` — input/output types of the equipment-selection metadata ports (axis options, equipment search, selection resolve) and the judgment error `PortError`·`PORT_ERROR_CODES`·`isPortError` (structural check, not `instanceof`). Decisions [ADR-0059](../../../docs/adr/0059-app-injected-equipment-axes-and-condition.md), [ADR-0074](../../../docs/adr/0074-port-failures-three-surfaces-structural-port-error.md).
- `audit-order.ts` — pure `compareAuditEvents(a, b)`: the `entityAudit` port order (newest time first, ties by `id` ascending; ADR-0085), compared with `instantEpochMs`; used by kernel, `AuditTimeline` and the mock server. It is a separate file because `scripts/vocab.mjs` reads `audit.ts` directly with Node type stripping, so `audit.ts` may hold type imports only.
- `audit.ts`, `i18n.ts` — `AuditEvent`·`AUDIT_ACTIONS`, `Text`.
- `response.ts` — response and Trust envelope (`ApiResponse`, `Trust`, `Assessment`, `Outcome`); §18–19.
- `host.ts` — host → module contract v1 ([ADR-0053](../../../docs/adr/0053-host-module-contract-v1.md)): `ModuleManifest`·`ModuleScreenMeta`·`ModuleHost`·`ModuleScreenProps`·`ModuleTarget`·`ModuleStatus`, the open vocabulary `ModuleScopedId` (`<moduleId>:<name>`), accepted versions `HOST_CONTRACTS`, optional features `HostFeature` (`query`·`detailSlot`·`write`; `write` brings `host.act` and `ActionResult`, ADR-0054). Nodes and elements are `unknown`. Only `SessionUser.permissions` also accepts `ModuleScopedId` (`Permission`·`GroupId`·`SpaceId` are the brand ids of `menu.ts`, ADR-0072).
- `adapter.ts` — the `PlatformAdapter` port and its input/output types; design in [package boundaries](../../../docs/integration/platform-packages.md) §4.
- `correlation.ts` — `clientCorrelationId()`: client-made `client-…` correlation IDs (error screens, client error reports); format constraints are in the file comment.
- `uuid.ts` — `randomUuidV4()`: a UUIDv4 in any browser context (`crypto.randomUUID`, else `getRandomValues` with the version/variant bits pinned; without Web Crypto at all it throws — there is no `Math.random` fallback). Every client-made `Idempotency-Key` (servers accept only UUIDv4) and any other client id use it instead of `crypto.randomUUID()`, which is missing outside a secure context (plain HTTP).
- `guards.ts` — `isRecord` (non-null, non-array object; prototype not inspected): the one shape check before reading fields of untrusted values (stored JSON, server responses). `@ap/ui` may not import `@ap/*`, so it keeps its own sanitizer copy; the mock-server's `isPlainObject` (prototype check) is a different judgment.
- `vocab.json` — generated: the closed vocabularies a server outside this repo or toolchain must follow (`kernelPermissions`·`USAGE_VIAS`·`AUDIT_ACTIONS`·`OUTCOMES`; the server does not know app space/menu permissions, ADR-0072). Exported as `@ap/contracts/vocab.json`. The source is each `as const` list; `pnpm --filter @ap/contracts gen:vocab` (`scripts/vocab.mjs`) generates it and `test` checks it is current. Consumers: the platform API vocabulary drift test and the `@ap/contract-schemas` release asset (`pnpm sdk:schemas` copies it as is).
- `globals.d.ts` — minimal `URLSearchParams`·`URL`·`AbortSignal`·`crypto` declarations (`crypto.randomUUID` optional) for use without the DOM lib.

## Verification

Run `lint` and `typecheck`; after `build`, run `check:pack` for the deployment bundle and the outside-repo consumer check. Root check scope follows the root `AGENTS.md`.

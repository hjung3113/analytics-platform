# @ap/components

Platform Component layer (06 §13), chart contract (§16) and page archetype skeletons (§12). Menus assemble these parts.

## Rules

- Import only `@ap/contracts`, `@ap/kernel`, `@ap/ui` and the table/chart libraries. Never import `@ap/shell`, apps, mocks or menu screens.
- Keep components free of domain meaning (equipment, metric names). Columns, cells and tab content are injected through props.
- Components own the 06 §19 states, §18 Data Trust and the accessibility duties (keyboard, focus return, labels). Pages must not reimplement them.
- Never change the global Context silently from a chart click. Offer only explicit callbacks (`onPointClick`, "분석 구간 적용").
- Put a domain-free general-purpose piece here regardless of consumer count. Promote a pattern born inside a menu only after 2–3 real menus repeat it (06 §24, root `AGENTS.md`). Style with `@ap/ui` token utilities only.
- The table engine (`@tanstack/*`) is internal; lint blocks menu imports of it.
- Verify with `pnpm --filter @ap/components test`, then the root checks (root `AGENTS.md`). Check consuming screens with `pnpm dev`.

## Layout

`src/` folders (ADR-0090): `chart/`, `table/`, `archetypes/` (PlatformPage, Analysis/Management/DrillLayout), `drawer/` (detail drawer, row actions, audit timeline), `filters/`, `state/` (state, trust, cards, focus helpers), plus `dock/`, `workspace/`, `inspector/`, `floating/`, `saved-view/`, `hierarchy/`. Tests live in each folder's `__tests__/`; `chart/__fixtures__/` holds fixed inputs; cross-folder tests (`a11y.test.tsx`) sit in `src/__tests__/`. `pageFlow`, `visibleArea`, `StateView`, `RadioGroup`, `lazyChunk` and `scrollportLabel` stay at the `src/` root because `dock/` and `workspace/` import them via `../`. Public entry points: `index.ts`, `testing.ts`, `dock/index.ts`, `styles.css` (Tailwind `@source`).

- `testing.ts` is the test-only entry `@ap/components/testing` (`stubCompactTableGeometry`: 220px row-area width and 1280×800 page stub, with a restore function; extends ADR-0040). Never export it from `src/index.ts`; this package's tests import `./testing`. The row-area name comes from `scrollportLabel.ts`, shared with the table.
- `table/__tests__/xlsxTestReader.ts` is a test-only XLSX reader (fflate, devDependency).

## Table

### `table/PlatformDataTable.tsx` — server-paged table
- `loadPage` uses `PageQuery`/`PageResult` from `@ap/contracts`; columns are the engine-neutral `PlatformColumn<T>` only (the TanStack `ColumnDef` conversion is private `table/columnDef.ts`); sorting is `PageSort[]`.
- Row-area height follows content. `table/tableFit.ts` observes the scroll container, the body (`data-platform-page-content`) and the sticky header (`data-page-sticky-header`) and caps the height at the remaining `max(240px, R)`. An explicit `height` is the cap for analysis tables.
- The selection column appears only with export, copy or `bulkActions`. The `rowAction` column is pinned right. When 128px does not fit but 72px does, `rowAction(row, { compact })` is called with `compact: true` and stays pinned as a 72px icon-only form (ADR-0037, 06 §15).
- Wheel behaviour follows [06 §15](../../../docs/contract/platform-ui-contract.md); `useInWorkspacePanel` and `screenMode` choose the implementation branch.
- `RowAction.tsx` owns the action control (`compact`, icon, accessible name, text; `onClick`, `link` child, `textLink`, `disabled` + `aria-describedby`; it knows no menu name). It renders the same element tree in both forms, so DOM nodes and focus survive compact ↔ regular switches (the tooltip opens only in compact). Menus return one `<RowAction compact={compact} …/>`; never switch element type with `compact ? A : B`.
- Memoize data-column definitions independent of action width so a width-boundary switch does not rebuild cell content.
- Optional `isRowMuted(row)` renders data cells of true rows `text-text-muted` (`text-text-secondary` on hover, selected or active) and sets `data-muted="true"`. `_select`, `_action` and cells with their own colour classes are unchanged. It is a visual effect only, so put the meaning in a visible cell such as a status badge (06 §15).
- Sort and page are controlled through `urlState` with the codecs `parsePageIndex`, `parseTableSort`, `encodeTableSort`; key names and value domains belong to the page.
- Cancellation is decided by the table's own `controller.signal.aborted` alone (a timeout `AbortError` is shown as an error).
- Privates (not exported from `index.ts`) split out of the table; the table only assembles and renders:
  - `table/usePagedRows.ts`: page query lifecycle (Context reset → fetch effect order preserved). `dataVersion` (the `refreshOn` epoch or the `rows` counter) is appended to the request identity, never the Context identity; `JSON.parse(identity)[0]`/`[1]` stay Context and page.
  - `table/useRowsSource.ts`: the `rows` input (#1672, ADR-0137): builds the table's own `loadPage` over given rows (filter, group or sort, page through the column value; `externalPagination` shows all rows) and the counter fed to `usePagedRows`' `dataVersion`; drops `filter`/`groupable`/`filterFields` with `externalPagination`.
  - `table/useTableTransfer.ts`: export/copy (cancel controller, clipboard path, shortcuts).
  - `table/useColumnPreferences.ts`: column settings storage (visibility, width, pin, order; pure order maths in `table/columnOrder.ts`).
  - `table/tableMessages.ts`: export/copy copy text.
  - Query identity (`usePagedRows`) and export header (`useTableTransfer`) take the global Context from Kernel `useQueryContext()` (narrowed by the applied Condition preset), never the raw `global` (06 §15, ADR-0083).
- Related parts: `DetailDrawer.tsx`; `AuditTimeline.tsx` (optional `more: AuditMore` takes Kernel `useEntityAudit`'s `timeline` spread and draws `이전 변경 이력 더 보기`, the end caption, failure retry, permission notice, focus move and status announcement; 06 §13·§26, ADR-0085); `DataTrustIndicator.tsx` (mixed source-logic-version badge and detail rows; yields with the provisional badge in a narrow header, 06 §18); `StatCard.tsx`; `RadioGroup.tsx`; `copyText.ts` (`useCopyLink` shows the success toast only after the write completes; `copyText` is re-exported from `@ap/ui`).

### Column filters

  - Reversed ranges and the page `validate` (`FilterValueCheck`, `urlState.validate`) are rejected with an inner sentence and a disabled `적용`.
- `table/filterLine.tsx` (`FilterLine`, `HeaderFunnel`): one slot toggling pinned button ↔ chip, other chips, `+ 필터` list → editor, clear all, focus return.
- `table/useTableFilterDeclaration.ts` (opt-in root export): one memoized field declaration derives URL filters, column props and non-column fields. Keep declarations/validators memoized on their inputs; late enum choices can be supplied to `filterColumnProps`. `table/useClearFiltersAction.tsx` returns the translated empty-result clear button or literal `null`. ### URL warnings and recovery (`table/tableUrlWarning.tsx`)
Reject invalid URL values; never repair them (06 §6). Use these for tables whose page reads sort/page itself.
- `useTableUrlWarning(allowedSort)` parses raw `sort`/`page` with the codecs and returns `parsedSort`, `parsedPage`, `invalid`, the ADR-0034 sentences and `cause` (`sortPage` default, `filter`, `both`). The page supplies the allowed sort columns.
- `useTableUrlState(allowedSort, { extraPatch?, filters? })` returns the same plus the `PlatformDataTable` `urlState`:
  - `undefined` when sort/page is invalid; otherwise page 1 is `null`.
  - `onChange` writes `sort` and `page` in one `setPage`; only `clamp` uses `replace`.
  - `extraPatch(reason)` adds page-owned keys to the same write (e.g. closing `focus`/`tab` on a user sort/page change in permission/role tables).
  - `filters` (`{ key, specs, labels?, legacy?, validate? }`, ADR-0105; `validate` is the port's `FilterValueCheck`) reads repeated/hidden page-key conditions through the `@ap/contracts` codec into `urlState.filters`. A change calls `onChange({ filters })` and writes condition and `page` in one `setPage`. Legacy keys migrate once by `replace` (two legacy keys giving both ends of one range field, e.g. `fromAt` + `toAt`, merge into one range). Invalid input makes `urlState` `undefined` and adds sentences, and `recoverKeys` clears only the bad keys (filter/legacy, or sort/page). Tables using `filters` (equipment, audit, permissions) pass both.
- `TableUrlWarning` draws the danger message in the table slot. `초기화` runs `focusPageFallback` first, then one `setPage({ sort: null, page: null })`. Title by `cause`: `invalidTableTitle`, `invalidFilterTitle`, `invalidTableFilterTitle`; `recoverKeys` narrows what is cleared. Optional `search` node (e.g. equipment quick search) is drawn above the message with `gap-3`.
- Other page keys: the menu declares `PageKeyRule[]` (`key` inside the menu's `pageKeys` so `pageParam` reads it; user-facing field `label`; `valid` check for present values) and calls `usePageKeyRules(rules)` (same shape as `useTableUrlWarning`) → `invalid`, `sentences` (ADR-0034 sentence per key), `badKeys`, `recover` (clears only bad keys in one `setPage`). `PageKeyWarning({ sentences, onRecover })` shows title `invalidFilterTitle`, one `<p>` per sentence and `초기화`.
- All three recovery paths use one `RecoverButton({ onRecover, label? })` (`RecoverButton.tsx`); it calls `focusPageFallback` first because it disappears with the message.

### Export and copy
**Table-owned export/copy ([ADR-0008](../../../docs/adr/0008-table-owned-export-fixed-toolbar.md), 06 §15).**

- Load XLSX (`write-excel-file/browser`) only through a dynamic `import()` on click, in a separate chunk.
- Toolbar order, refusal copy, sheet layout and clipboard path are pinned by `table/__tests__/PlatformDataTable.test.tsx`, `…copy.test.tsx` and `tableExport.test.ts`. Accessibility and clipboard rules those tests do not pin are in 06 §15 "표 내보내기·복사 구현 계약". When changing, fix the tests, 06 §15 and ADR-0008 first.

**Menu-declared Workbook export (06 §15).**
- `table/workbook.ts` (public `WorkbookSheet`, `checkWorkbook`, `toWorkbookXlsx`, `WORKBOOK_LIMITS`, `WorkbookError`) owns sheet-name rules, limits and cell conversion.

## Page archetypes

### `archetypes/PlatformPage.tsx` — page top level

- `ObjectLinks` is the public body placement for kind/id + link options. `RowAction.menu` keeps its trigger node across density changes. PlatformPage alone draws subjectLinks header groups, main screen only; HeaderOverflowGroup and ObjectLinkItems stay internal (06 §22).
- Slots: title, actions, `contextExtension`, `dataTrustSummary`, breadcrumb; the Scope gate. The global Context Bar arrives as `slots.contextBar` (never import the shell).
- The body is identified by `data-platform-page-content` (excludes header, global Context, page extension; the Scope gate renders inside it). Contract checks use this stable hook, not style classes.
- `contextNotes` (`ReactNode[]`; `null`/`false` entries are neither counted nor drawn) is the notice slot above `contextExtension`. With `layout="fill"`, the head area (notes + extension) is drawn as a collapsible by internal `PageContextHead.tsx` (not exported from `index.ts`; 06 §12.8, ADR-0075). Internal `useCollapsePreference.ts` shares remembered collapse, opposite-toggle focus and collapsed-summary notice with `PageFilterBar`. A flow page draws notes above the extension without collapse.
- Arrival focus: consume Kernel `pageNavigation` focus requests. `drill` → current step; otherwise optional `arrivalTarget` (domain-free `() => HTMLElement | null`, used only when connected; the host passes the module screen's registered target); otherwise the title (h1). 06 §26 owns the exception where `arrivalTarget` precedes the title on `page`/`return` arrivals. Programmatic title focus never opens the title tooltip (06 §26). A `focus=` detail panel opened by arrival does not take that title focus (ADR-0032).
- When the Scope gate's action button disappears after a state change, move focus to the main landmark (the body element outside the shell) (06 §26).
- Blocked-place request (`state/AccessRequestEntry.tsx`, layout §8 `accessRequest`, ADR-0154 decision 6): `useScopeAccessRequest()` returns the slot only while the session carries `requestableScopes`; `AccessRequestEntry` draws `권한 요청` or `요청 대기 중` + `요청 상태` from the slot's `Pending` and owns the controlled `Dialog`; `scopeRequestTarget` is the room-place target rule. `PlatformPage` uses it in the Scope `forbidden` gate (place c) and passes `OutcomeBanners forbidden` one banner for a partially granted Scope (place e; `OutcomeScope` tracks `forbidden` widgets in the same store). Without the slot every place renders as before.
- Header yield (ADR-0035): when the header container narrows or actually overflows (`scrollWidth > clientWidth`, decided in `headerYield.ts`), yield in order description → Data Trust summary → provisional badge; the title keeps its minimum width; secondary actions go in the `⋯` menu. Only when nothing more fits, keep horizontal header scroll so primary actions stay reachable by Tab or scroll. At normal width (1280px+ with a detail panel) it must not overflow (06 §7).
- Board entry (16 §6): on a main screen whose menu can open the board (`features.board`), append the app's `slots.boardEntry` item to `⋯` even without `secondaryActions`. Inside a pane, with no slot, or when the board is unsupported, create no `⋯`. The item's dialog goes through `useHeaderOverflowDialog()` so it survives `⋯` closing; opening it does not pull focus to `더보기`; closing without navigating returns focus to `더보기`.
- `density` defaults to compact (content 16/12/16px); `comfortable` is an explicit developer choice (06 §12). A nested page does not inherit the outer declaration and uses its own default.
- Return row (06 §22): in the main screen, a current menu whose carry set lists `returnTo` gets a 32px row (`data-return-row`) directly above `data-platform-page-content`. Show the return link only when `returnOrigin().accepted`; `spaceLabel` supplies the origin-system text when present. Outside a return-aware set, keep the header `ReturnLink`.
- Pane mode (`screenMode === 'pane'`, ADR-0049): do not draw the head (50px) or `slots.contextBar`, and do no automatic arrival focus (`page`); the board owns pane head and Context bar. Explicit drill/return focus goes to the current step in the pane, else the pane root. `DrillLayout`'s dropdown-close focus is looked up only inside the pane, anchored on the path bar `<nav>` (which never disappears; the trigger vanishes when a middle-menu step is chosen at step 4). The Scope gate and its recovery actions, `contextExtension`, `OutcomeScope`, `OutcomeBanners` and the body stay as is; do not mount the protected body while denied or validating.
  - `DetailDrawer` inside a pane (`paneLabel`) shows a `칸 N · 메뉴` caption above the title and calls `onClose` once when that pane's screen (pathname) or analysis Context changes after opening. If the opener disappears, focus returns to the `data-pane-id` pane root (`tabIndex=-1`), or to main when not in a pane.
- `state/pageFocus.ts`: `focusPageFallback` (public) prefers the nearest focusable pane root (`[data-pane-id][tabindex]`) over main; `requestReturnFocus` is internal; arrival reading is the Kernel host hook `useArrivalFocus`.

## Detail drawer
- `DetailDrawer` portals its content into the shell detail slot (ADR-0013, 06 §13). Use it only under AppShell or the same `DetailPanelSlotProvider`. With one tab, draw content without a tab row (06 §13).
- Focus: a panel opened by URL arrival with `focus=` takes no focus; a panel opened from the same screen focuses its close button (ADR-0032). A panel that took no focus restores focus on unmount only when focus is inside it. When a tab switch removes the focused control, move focus to the selected tab trigger (the panel if none) (06 §26).

### Detail expansion (ADR-0126)
`DetailDrawer` consumes the existing UI slot context and shared toggle/Escape handler; do not add a second expansion owner or per-menu option. Contracts: components §13 and kernel §6.4.
- Preserve DOM nodes, editor values and scroll through toggles. Undeclared content keeps the 48rem expanded reading column; the footer stays outside the scroll body.
- Optional per-tab `regions` (`DetailDrawerRegions`: required body, optional properties/activity) is exclusive with legacy content. Use the panel named container at 60rem with an 18rem sticky properties track; missing properties reserves no column. Declared regions align to the title inset without a reading-width cap.
- Preserve DOM order body/properties/activity and keyboard access to both named scroll regions; never reparent or duplicate content at a width boundary. See components §13 for scrolling and state semantics.
- A pane-owned drawer declares `localExpansion` when registering so it cannot write the main URL or pane query.
- `PlatformPage` alone marks the covered body below its sticky page header inert; leave header, rail and sidebar available.
- Restoring an expanded address must not claim toggle focus. Labels come from Kernel i18n.

## Charts
- `chart/AnalysisChart.tsx`: owns the `ChartSpec` heatmap, donut, scatter, boxPlot, pareto and topNBar frames, local selection, keyboard table, explicit detail and manifest Export (06 §16; exception to §24 per ADR-0058). `chart/topNBar.ts` sorts the full input, limits to top N and projects colours. - `chart/AnalysisChartFrame.tsx`: Zoom/Brush/Reset/Compare/Annotate/Export. Optional `size` uses AnalysisChart's inheritance and content contract (06 §12.6); regular keeps the 260px default plot height.

- `chart/LaneTimeline.tsx` + `chart/laneTimeline*.ts`: standalone Canvas 2D interval timeline (06 §16, ADR-0064). - `chart/LegendTree.tsx`: domain-free hierarchical legend tree. The consumer owns visibility (`visible`, judged by leaf id); ancestors show a 3-state check (checked/partial/off).
  - Modes: selection mode has a single current item (`onSelect`). With `onDrill`, instead `currentId`'s `aria-current` and drill separate from visibility; a node's `drillOnly` is a drill target with no checkbox or visibility leaf (ADR-0084). Also takes a controlled sort indicator and controlled/uncontrolled expansion.

  - Tab order in every mode: current row → expand/collapse button (parents only; read-only expansion skipped) → operable sort button → out of the tree; Shift+Tab reverses. Only the current row's action buttons have `tabIndex=0`; other rows' buttons and visibility checkboxes are `-1`.
  - Keys: expand-button Enter/Space toggles expansion. Row Enter, with `onDrill`, drills a drillable row (`drillOnly`, or optional `canDrill(id)` true, or with no `canDrill` a row with children) — not expand, not `onSelect` — and other rows toggle expansion or do nothing (ADR-0084 amendment); in selection mode it selects; otherwise it toggles expansion. Row Space toggles visibility (not for `drillOnly` rows).
  - The drill button (non-current drillable rows, `tabIndex=-1`; for `drillOnly` rows the always-visible `CornerDownRight` mark is the button) is not a Tab stop. The tree-head `모두 보이기` (shown with `onDrill` when all leaves are off) is a `secondary` + `Eye` button on its own row above the rows and is a normal Tab stop before the tree.
  - `aria-multiselectable` is `true` when checkboxes exist.
- `AnalysisChartFrame` SDK pieces (06 §16, ADR-0063):

  - Horizontal mode also takes controlled row highlight `activeCategory` / `onActiveCategoryChange(category, how)` / `revealActive` and a row-height viewport `rowPitch` (≥24px; scrolls inside the plot box, category `dataZoom` off, Brush kept). Pure geometry: `chart/analysisChartGeometry.ts` (`rowPitchChartHeight`, `revealScrollTop`) (ADR-0079).
    - If `activeCategory` is not among drawn categories, the selection summary (`활성 행` line) does not mention it (keep the controlled value; filter only the display).
    - When `activeCategory` changes from outside, move the selected point (selector, `지점 동작` target) to that row (selected series first, else first selectable point; `null` unchanged; focus is not moved).
    - Without `rowPitch`, category labels thin automatically; when `rowPitch` appears, re-reveal the active row.
  - Horizontal stacked bar `startAlign` changes layout only: per-series lane width = that series' maximum, 2% gap between lanes; transparent spacer series `__spacer-k` in the same `stack` are `silent` with `tooltip.show:false` and are absent from selector, table, legend and callbacks; the value axis is lane-name dividers; Brush is off (exception to `rowPitch`'s keep-Brush rule). The label is a surface-colour chip with accent border; in sort mode the max label sits inside the piece's right end, otherwise outside right, and the right grid margin is reserved.
- `chart/chartValueLabels.ts`: pure pieces for `AnalysisChartFrame`'s `valueLabels` (horizontal stacked: piece labels and row totals), `reaggregation` and `serverTotals`.

## Dock and workspace
### `dock/` — host-only entry `@ap/components/dock`
`src/index.ts` does not re-export it; lint blocks menu/module imports (ADR-0067).
- Controlled `DockLayout`: the caller gives a `DockNode` tree (`schema.ts`: `group{panels,active}` | `branch{dir,sizes,children}`; maximize is not stored); the engine draws it and reports user changes via `onLayoutChange`. `normalizeDockTree` repairs and returns (never throws); `isValidDockTree` rejects. Pure commands shared by drag, keyboard and menu paths: `commands.ts` (`movePanel`, `addPanel`, `removePanel`, `activatePanel`, `resizeBoundary`, `groupOf`, `panelOrder`).
- The engine (`dockview-react`, exact pin 8.6.1) is a lazy chunk imported only by `DockEngine.tsx` (a chunk failure shows the same error state with `다시 시도` as `EChart`; layouts after arrival draw without fallback via `lazyChunk.tsx`). The public API exposes no engine type or JSON.
- **Zero remount.** A new `layout` is fitted to the live engine with `fromJSON(…, { reuseExistingPanels: true })`; never call `clear()` or `close()`.
- Tabs have no close button, and a tab's Delete/Backspace does not reach the engine close (closing is a platform command; optional `onPanelDelete(panelId)` tells the host that key — the board maps it to `비우기`).
- `onActivate` fires only on user activation (tab pointer, Enter/Space/arrows, focus entering a panel), not on engine activation changes.
- Invisible panels (background tab, another panel maximized, one-group narrow display) are `inert` and close open Radix overlays through `TransientOverlayScope` (`data-dock-panel`, `data-dock-visible`).
- Each boundary gets a focusable `role="separator"` (arrows 5%, Home/End, docs/16 §4) overlaid on the engine sash; pointer drag stays with the engine sash. During pointer drag only pane frames and dividers update live; pane content is frozen at drag-start size and overflow is clipped (`data-dock-resizing`, `data-dock-frozen`, px inline on `[data-dock-panel-content]`); `onLayoutChange`, measurement and group strip width apply once when the drag ends. Keyboard separators apply immediately.
- Group header right slot `renderGroupActions(group, { stripWidth })`: the active tab's pane area, a sibling outside the tab list; `stripWidth` is the group strip's px width. The menu-opening element carries `data-dock-group-menu`. A tab's Shift+F10, ContextMenu key and right click first activate that tab (`onActivate`); the keyboard open focuses the first item. Closing that menu without selection returns focus to the tab, not the trigger.
- CSS hooks read by `dock.css`: slot content `data-dock-wrap`, `data-dock-selected`; host-set `data-dock-tab-compact` on background tab elements (one at a time from the back); tab content `data-dock-tab-shrinkable`, `data-dock-tab-action` (badge-only background tabs, second slot row, selection strip).
- Header is a 40px strip; the active tab of a multi-tab group has a 2px accent bottom bar + semibold. Open menus/Popovers take Esc first; the remaining Esc ends only the innermost maximize. Turn off the engine's (English) announcements.
- Optional `currentPanelId` is the host's current pane; narrow-width display shows it (else first group's active tab / user choice). Narrow-width tabs follow `panels` order. `tabA11y(panelId)` sets `aria-description` and `aria-keyshortcuts` on the tab element; re-apply after engine reconcile and after the engine moves a tab (`onDidMovePanel`).
- Tab/Shift+Tab order moved by `DockLayout`: active tab → header-slot buttons → inside that pane (first focusable; else the first `tabindex=-1` descendant; else `data-dock-panel` itself) → next group's active tab. Keep engine DOM order; groups follow `dockGroupsInReadingOrder` (top coordinate, then left). A `tabindex=0` wrapper that hands focus to an inner item (Radix radio group) counts as the first stop. Tab after the last group and Shift+Tab before the first group's tab leave directly to the next/previous focusable element outside the layout (`leave`) rather than relying on DOM order.
- The layout root is `overflow-hidden`, so overlays of invisible panels left in old places never widen the container. If the engine rebuilds and the focused tab disappears, return focus to a tab of the same pane. When the size changes while maximized, the engine returns the hidden group's px sizes at old values (skewing ratios), so `DockEngine` re-applies the stored ratios on restore.
- Panel content renders inside the internal `dock/PanelBoundary.tsx`: a render failure stays in that panel (`StateMessage` danger with Correlation ID and `다시 시도`), is reported through Kernel `reportShellError` (via `useHostPlatformOptional`; no report without a provider) and clears on a new user or revision (#2025). `lazyChunk.tsx`'s `ChunkLoadBoundary` catches chunk-load failures only (`isChunkLoadFailure` from `@ap/kernel/host`) and rethrows the rest to the nearest screen or panel boundary.
- Tests: jsdom has no engine geometry, so assert structure only; sizes are checked in E2E.

### `workspace/` — menu façade `PanelWorkspace` (root export, **Decided**, 06 §12.8, ADR-0067 decisions 18–22)
- State is pure `workspaceState.ts` (`{ v:1, preset, layout, hidden, mode?, rows? }`; `normalizeWorkspaceState` never throws; `applyPreset`, `resetLayout`, `hidePanel`, `showPanel`; `settleRows` fits rows after edits). Local preference is `workspaceStorage.ts` (key `platform:workspace:v1:<user>:<menu>:<persistKey>`, 300ms debounce, flush on unmount/`pagehide`).
- `WorkspaceToolbar` is drawn only outside `WorkspaceCommandsHost`; inside a host, the same commands (`dock/WorkspaceCommandsHost.tsx`) go to the host menu. `panelContext.ts` makes card/chart titles inside a pane `sr-only`. Chart frames and tables inside an embedded container draw no border of their own at any density, and a pane keeps its titles visible. `dock/layoutMenu.ts`'s `dockLayoutMenu` computes layout-menu items shared with the board (the caller gives the sort key).
- Wheel: table wheel contract [06 §15](../../../docs/contract/platform-ui-contract.md); tab-row wheel contract [16 §4.1](../../../docs/design/analysis-board.md); related code `panelContext.ts`, `table/PlatformDataTable.tsx`, `dock/dock.css`.

The board passes no `rows`, so it is unchanged.
  - Mode is the second radio group of `WorkspaceCommand.group: 'mode'`; `radioGroupsOf` splits per group.
  - Visible-area measurement is internal `visibleArea.ts`: nearest scroll container − `stickyChromeHeight` (same page's `[data-page-sticky-header]` plus a collapsed `[data-query-bar][data-query-bar-collapsed]`, the same sum as `PlatformPage`'s `--page-sticky-offset`; `table/tableFit.ts` shares only the scroll-container measure and subtracts only the header). Page-flow wiring is internal `pageFlow.ts` (`PlatformPage layout="fill"` receives the registration and switches to flow size while stacking is visible).
  - `PlatformPage layout="fill"` and `ChartSize 'fill'` (plot box height measured by `useElementSize`, minimum 320px) are opt-in.
- Panel `badge`: tab `PanelBadge` (`workspace/PanelBadge.tsx`, reuses `StatusBadge`, removed from the accessibility tree) and tab `aria-description` (`tabA11y`). A hidden-panel warning goes to the toolbar and board host menu through `WorkspaceCommand.description` / `warning`. Do not change the title; do not add `data-dock-tab-shrinkable`.
- Tests: jsdom asserts structure only (groups, tabs, commands, storage keys, query counts); sizes are checked in E2E (3b).

# @ap/components

Platform Component 층(06 §13) + 차트 계약(§16) + 페이지 archetype 골격(§12). 메뉴가 조립하는 부품이다.

## 파일

폴더 배치(ADR-0090, #713): 차트 갈래는 `src/chart/`, 표 갈래는 `src/table/`, 페이지 골격(PlatformPage·Analysis/Management/DrillLayout)은 `src/archetypes/`, 상세 서랍·행 동작·감사 타임라인은 `src/drawer/`, 조회 조건 부품은 `src/filters/`, 상태·신뢰·카드·포커스 도우미는 `src/state/`에 두고 각 폴더의 테스트는 `__tests__/`, 고정 입력은 `chart/__fixtures__/`다. 여러 갈래에 걸친 테스트(`a11y.test.tsx`)는 `src/__tests__/`다. `dock/`·`workspace/`·`inspector/`는 그대로이고, `dock/`·`workspace/`가 `../`로 import하는 `pageFlow`·`visibleArea`·`StateView`·`RadioGroup`·`lazyChunk`와 `scrollportLabel`은 `src/` 루트에 남는다(713s에서 정리). 공개 진입점은 `index.ts`·`testing.ts`·`dock/index.ts`·`styles.css` 그대로다.


- `chart/LegendTree.tsx` — 도메인을 모르는 계층 범례 트리. 보이기는 소비자 소유(`visible`, 리프 id로 판정)이고 조상은 3단계 체크(체크·일부·해제)로 보인다. 선택 모드의 단일 현재 항목(`onSelect`; `onDrill`이 있으면 대신 `currentId`의 `aria-current`와 보이기와 분리된 드릴 — 노드 `drillOnly`는 체크박스·보이기 잎이 없는 드릴 대상, ADR-0084), controlled 정렬 표시, controlled/uncontrolled 펼침을 받는다. 행 이동은 APG 방향키, 포커스 복구를 소유한다(06 §26, ADR-0057). 모든 모드에서 Tab은 현재 행 → 펼침/접기 버튼(부모만, 읽기 전용 펼침은 건너뜀) → 조작 가능한 정렬 버튼 → 트리 밖 순서이고 Shift+Tab은 그 반대다. 현재 행의 동작 버튼만 `tabIndex=0`이고 다른 행의 버튼과 보이기 체크박스는 `-1`이다. 펼침 버튼의 Enter/Space는 펼침을 바꾸고, 행의 Enter는 `onDrill`이 있으면 드릴 가능한 행(`drillOnly`, 선택 `canDrill(id)`가 true인 행, `canDrill`이 없으면 자식 있는 행)에서 드릴(펼침·`onSelect` 아님)이고 그 밖의 행은 펼침 토글 또는 무동작(ADR-0084 개정), 선택 모드에서 선택, 그 밖에는 펼침을 바꾸며, 행의 Space는 보이기를 바꾼다(`drillOnly` 행 제외). 드릴 버튼(드릴 가능한 현재가 아닌 행, `tabIndex=-1`; `drillOnly` 행은 항상 보이는 `CornerDownRight` 표식이 곧 이 버튼)은 Tab 정지점이 아니고, 트리 머리 `모두 보이기`(`onDrill`이 있고 모든 잎이 꺼졌을 때)는 줄들 위 자기 줄의 `secondary` + `Eye` 버튼이며 트리 앞의 일반 Tab 정지점이다. `aria-multiselectable`은 체크박스가 있으면 `true`다.
- `inspector/` — `Inspector`(루트 export, **Candidate**, 06 §13, ADR-0080): 보조 섹션(`id`·`title`·`icon`·`summary?`·`render`)을 한 번 선언하고 `form`으로 `stack`(APG 아코디언: 제목 안 버튼의 `aria-expanded`/`aria-controls`, 다중 열림 기본, 전체 스크롤, 내용 패널은 `region` 아님)과 `rail`(40 px 아이콘 버튼 + Tooltip + Popover peek, Escape는 그 버튼으로 포커스 복귀, 한 번에 하나)을 고른다. 섹션 내용은 질의를 소유하지 않는다 — 질의는 Inspector 위에 둔다. 펼침 집합은 `persistKey`로 `platform:inspector-expanded:v1:<user>:<menu>:<persistKey>`에 기억(`inspectorState.ts`, 사용자·메뉴 없으면 메모리). 검증 `Inspector.test.tsx`·`a11y.test.tsx`.
- `floating/` — `FloatingWindow`(루트 export, 06 §13, #893 893d1): 도메인을 모르는 비모달 창 틀. 제어형 `geometry`·`area`(호출자가 측정, 좌표는 area 기준)·`mode`(`window`/`fill`/`off` — 모드가 바뀌어도 children은 같은 자리라 재마운트되지 않는다). 끌기·핸들 중 좌표는 내부 상태이고 `onGeometryChange`는 pointerup·키·메뉴 확정 때만 부른다. 표시값은 `clampGeometry`가 계산할 뿐 저장값을 고치지 않는다. 키(8px, Shift 48px, Alt=크기)와 `⋯` 메뉴(`modal={false}`)가 끌기의 대체 경로(WCAG 2.5.7). 문구는 전부 `labels`(기본값 없음). 판정 `fitsArea`는 호출자가 `fill`을 고르는 데 쓴다. 레이어 `z-40` + `isolate`. 검증 `floating/__tests__/`.
- `saved-view/` — 도메인을 모르는 저장된 뷰 조각(06 §21, ADR-0092, #1011d): `ViewSelector`(현재 체크와 `내 기본` 표식 분리, 검색·공개 대상 필터·로딩·실패·빈 상태, 저장 메뉴 `현재 뷰에 저장`/`새 뷰로 저장`(편집 권한이 없으면 `내 복사본으로 저장`)/`저장본으로 되돌리기`, 변경이 사라지는 뷰 전환(수정됨·미적용·저장 안 됨, `discardsChanges`) 전 저장(편집 가능이면 현재 뷰, 아니면 복사본·새 뷰, `onSaveAs`가 `false`로 풀리면 전환 안 함)/버리기/취소, 행과 ⋯ 별개 Tab 정지, 자세히 보기)와 `SaveViewDialog`(단위·이름·새 저장/갱신, 초안이면 `적용 뒤 저장` 안내, 포함 내용·패널 조건·제외값 읽기 전용, 저장 단위가 메뉴 뷰일 때만 패널 요약, 닫힘 시 `returnFocusRef`(없으면 연 요소)로 포커스 복귀, 실패 시 입력 보존, 공개 대상은 최종 저장에서만 전달)·`ShareTargetPicker`(사람·그룹 공개 대상 선택)·`GroupEditor`(그룹 멤버 편집)·`ViewManagement`(저장 뷰 관리)·`ApprovalQueue`(공식 승인 요청)·`summarizeSavedViewContext`. 데이터·콜백은 props로만 받고 저장소·Kernel 훅을 모른다(`text.ts`는 사용자 문구, `viewInfo.ts`는 표시용 타입·시간·승인 tone). 검증 `saved-view/*.test.tsx`.
- `archetypes/PlatformPage.tsx` — 페이지 최상위. 제목·액션·`contextExtension`·`dataTrustSummary`·breadcrumb 슬롯, Scope 게이트, 전역 Context Bar는 `slots.contextBar`로 받아 렌더(셸을 import하지 않음). 본문 영역은 `data-platform-page-content` 속성으로 식별한다(헤더·전역 Context·페이지 extension 제외, Scope 게이트도 이 영역에 렌더). 계약 검사는 스타일 클래스 대신 이 안정된 hook을 사용한다. `contextNotes`(`ReactNode[]`, `null`·`false` 요소는 세지 않음)는 `contextExtension` 위의 안내 슬롯이고, `layout="fill"`이면 머리 영역(안내 + 확장)을 `PageContextHead.tsx`(내부, `index.ts`로 내지 않음)의 접기로 그린다(동작은 06 §12.8, ADR-0075). 접힘 기억·반대 토글 포커스·접힘 요약 안내는 내부 훅 `useCollapsePreference.ts`가 `PageFilterBar`와 나눠 쓴다. flow 페이지는 접기 없이 안내를 확장 위에 그린다. 검증 `PlatformPage.head.test.tsx`. Kernel `pageNavigation`의 포커스 요청을 소비해 `drill`이면 현재 단계, 그 밖이면 선택 prop `arrivalTarget`(도메인을 모르는 `() => HTMLElement | null`, 연결된 요소일 때만 — 호스트가 모듈 화면의 등록 대상을 넘긴다, #804) 아니면 제목(h1)에 포커스하고(`page`·`return` 도착에서 `arrivalTarget`이 제목보다 앞서는 예외는 06 §26이 소유), 프로그램이 준 제목 포커스로는 제목 툴팁을 열지 않는다(06 §26). 도착으로 열린 `focus=` 상세 패널은 그 제목 포커스를 가져가지 않는다(ADR-0032). Scope 게이트의 동작 버튼이 상태 변경으로 사라지면 포커스를 main 랜드마크(셸 밖에서는 본문 요소)로 옮긴다(06 §26, #353). 머리 컨테이너 폭이 줄거나 실제로 넘치면(`scrollWidth > clientWidth`, 결정은 `headerYield.ts`) 설명·Data Trust 요약·잠정 배지 순으로 양보하고 제목은 최소 폭을 지키며, 보조 동작은 ⋯ 메뉴에 둔다(ADR-0035). 보드 지원 메뉴(`features.board`)를 열 수 있는 본 화면에서는 `secondaryActions`가 없어도 앱의 `slots.boardEntry` 항목을 ⋯에 덧붙인다(칸 안·슬롯 없음·보드 미지원은 ⋯를 만들지 않음, 16 §6). 항목의 대화상자는 `useHeaderOverflowDialog()`로 머리에 맡기면 ⋯가 닫혀도 남고, 열릴 때 ⋯가 `더보기`로 포커스를 끌어오지 않으며 이동 없이 닫으면 `더보기`로 돌아간다(`PlatformPage.board-entry.test.tsx`). 모든 양보 뒤에도 들어가지 않는 폭에서만 머리 가로 스크롤을 남겨 주 동작에 Tab 포커스나 스크롤로 닿게 하며, 정상 폭(1280px 이상 + 상세 패널)에서는 넘치지 않는다(06 §7).
- `PlatformPage` return row (#760, 06 §22): in the main screen, a current menu whose carry set lists `returnTo` gets a 32px row (`data-return-row`) immediately above `data-platform-page-content`. Show the return link only when `returnOrigin().accepted`; `spaceLabel` supplies the origin-system text when present. Outside a return-aware set, keep the header `ReturnLink`. Test: `PlatformPage.return-row.test.tsx`.
- `archetypes/AnalysisLayout.tsx` — 분석 화면의 KPI 띠·차트 2열·전체 폭 분해 표, 단위별 접기와 접힌 항목 칩 복원·메뉴별 기억·포커스 이동을 소유한다(06 §12.6, ADR-0022). 선택적 `density`는 regular(기본값) 또는 compact(1–4열)를 고르며, 차트의 `AnalysisSection.span: 'full'`은 활성 열 전체를 차지한다. 크기와 상속은 06 §12.6을 따른다.
- `archetypes/DrillLayout.tsx` — `DrillPath`·`DrillLayout`·`ReturnLink`(06 §12.7·§13·§22, ADR-0025; 내부 훅 `useReturnNavigation`이 `ReturnLink`와 `PlatformPage`의 복귀 줄이 나누는 이동·포커스·되돌린 Context 알림이고 `index.ts`로 내지 않는다). 경로 바는 `useDrill()`을 읽고, 형식 오류와 결과에 없는 값은 본문 자리에 상태를 그린다. 복귀 버튼은 `returnOrigin()`의 메뉴 이름과 단계 값을 쓴다. 선택 `summary`는 경로 바 옆 한 줄(`<nav>` 밖, 0단계 숨김, 문자열이면 말줄임+`title`, ADR-0078). 선택 `fill`(+`QueryView fill`)은 부모 높이를 채우는 flex 열이고 없으면 출력이 같다(06 §12.7).
- `archetypes/ManagementLayout.tsx` — 관리 화면의 filter/table/drawer 슬롯. 자기 폭에 따른 접을 수 있는 sticky 필터 레일과 좁은 폭 팝오버, 공통 접힘 기억·포커스 이동을 소유한다(06 §12.6, ADR-0022). `pendingFilterCount`가 있으면 접힌·좁은 `필터 · N` 버튼에 `미적용 n` 글 표식과 설명(접근 가능한 이름은 그대로)을, 레일 머리에 미적용 변경 수를 보인다(ADR-0037).
- `filters/PageFilterBar.tsx` — consumer가 정의한 검색·텍스트·Select·custom 필드와 actions를 표시한다. field value·URL key·변경·reset/apply 의미는 consumer가 소유하며, 현재 알 수 없는 Select 값은 표시 옵션으로 유지한다(#54, 06 §13·§15). 입력·Select는 40px 기본 높이를 쓰며 덮어쓰지 않는다. 관리 화면은 `onApply`로 막대를 `<form>`으로 만든다 — submit이 유일한 적용 경로이고, 막대는 한글 조합 중(`isComposing`·keyCode 229·compositionend 직후) Enter의 암묵 submit만 막는다. 적용으로 포커스된 `적용` 버튼이 꺼지면 같은 컨테이너의 첫 필드로 포커스를 옮긴다.
- `PlatformPage` 칸 모드(`screenMode === 'pane'`, ADR-0049) — 머리(50px)와 `slots.contextBar`를 그리지 않고 자동 도착 포커스(`page`)를 하지 않는다(보드가 칸 머리·Context 바를 소유). 명시적 드릴·반환 포커스는 칸 안에서 현재 단계, 없으면 칸 루트로 간다(`DrillLayout`의 드롭다운 닫힘 포커스도 그 칸 안에서만 찾는다 — 4단계에서 가운데 메뉴로 단계를 고르면 트리거가 사라지므로 조회 범위는 사라지지 않는 경로 바 `<nav>`에서 잡는다, #497 D1). Scope 게이트와 그 복구 동작, `contextExtension`, `OutcomeScope`·`OutcomeBanners`·본문(`data-platform-page-content`)은 그대로이고 거부·검증 중에는 보호된 본문을 마운트하지 않는다. `DetailDrawer`는 칸 안이면(`paneLabel`) 제목 위에 `칸 N · 메뉴` 캡션을 보이고 그 칸의 화면(pathname)이나 분석 Context가 열린 뒤 바뀌면 `onClose`를 한 번 부른다(`DetailDrawer.pane.test.tsx`). 연 요소가 사라지면 `data-pane-id` 칸 루트(#497이 `tabIndex=-1`로 제공)로, 칸이 아니면 main으로 포커스를 돌린다. 검증 `PlatformPage.pane.test.tsx`·`PlatformPage.pane-drill.test.tsx`.

Esc는 열린 메뉴·Popover가 먼저 받고, 남은 Esc가 가장 안쪽 최대화만 끝낸다. 엔진 안내 방송(영어)은 끈다. 선택 prop `currentPanelId`는 호스트의 현재 칸으로, 좁은 폭 표시가 그 칸을 보인다(없으면 첫 그룹 활성 탭·사용자 선택). 좁은 폭 탭은 `panels` 순서다. `tabA11y(panelId)`는 탭 요소에 `aria-description`·`aria-keyshortcuts`를 단다. Tab/Shift+Tab은 활성 탭 → 헤더 슬롯의 버튼 → 그 칸 안(첫 포커스 요소, 없으면 칸 내용의 첫 `tabindex=-1` 하위 요소, 그것도 없으면 `data-dock-panel` 자체) → 다음 그룹의 활성 탭 순서로 `DockLayout`이 옮긴다(엔진 DOM 순서 유지, 그룹은 `dockGroupsInReadingOrder`: 위쪽 좌표 다음 왼쪽 좌표). 칸 안 첫 컨트롤 판정은 Radix 라디오 그룹처럼 `tabindex=0` 감싸개가 내부 항목에 포커스를 넘기는 경우도 첫 정지점으로 본다. 읽기 순서의 마지막 그룹 뒤 Tab과 첫 그룹 탭 앞 Shift+Tab은 DOM 순서에 맡기지 않고 레이아웃 밖의 다음·이전 포커스 요소로 직접 나간다(`leave`). 탭의 Shift+F10·ContextMenu·오른쪽 클릭으로 연 메뉴를 선택 없이 닫으면 포커스는 트리거가 아니라 그 탭으로 돌아온다. 레이아웃 루트는 `overflow-hidden`이라 보이지 않는 패널의 오버레이가 옛 자리에 남아도 담은 컨테이너를 넓히지 않는다. `tabA11y`가 단 `aria-description`·`aria-keyshortcuts`는 엔진이 탭 요소를 다시 만든 다음(reconcile)과 엔진이 탭을 옮긴 다음(`onDidMovePanel`)에도 다시 단다. 최대화한 채 크기가 바뀌면 엔진이 숨긴 그룹의 px 크기를 옛 값으로 돌려주므로(비율이 틀어짐) `DockEngine`이 복원 때 저장된 비율을 다시 적용한다. 엔진이 다시 짜면서 포커스가 있던 탭이 사라지면 같은 칸의 탭에 포커스를 돌려준다. 검증은 `dock/` 테스트(jsdom은 엔진 기하가 없어 구조만 단언하고 크기는 E2E에서 본다).

## 규칙

**표 소유 내보내기·복사(#173·#174, [ADR-0008](../../../docs/adr/0008-table-owned-export-fixed-toolbar.md), 06 §15).** 메뉴는 `exportRows(request, signal)`(선택 ids 또는 필터 전체 + 표의 활성 `sorting`)·`exportNote`·`exportFilterSummary`·`exportContext`만 주고, outcome 처리·CSV/XLSX 직렬화·파일·토스트·[복사]는 `PlatformDataTable`이 소유한다. 직렬화기는 내부 모듈 `src/table/tableExport.ts`(`index.ts` 비공개). 화면에 보이는 값만 나가며 라벨·시간 열은 `PlatformColumn.exportValue`로 같은 텍스트를 준다. 게이트는 manifest `features.export`. XLSX(`write-excel-file/browser`)는 클릭 때 동적 `import()`로만 불러 별도 청크에 둔다. 툴바 순서·거절 문구·시트 구성·클립보드 경로의 세부는 `table/__tests__/PlatformDataTable.test.tsx`·`table/__tests__/PlatformDataTable.copy.test.tsx`·`table/__tests__/tableExport.test.ts`가 고정하고, 테스트가 고정하지 않는 접근성·클립보드 규칙은 06 §15 "표 내보내기·복사 구현 계약"에 있다 — 바꾸면 테스트·06 §15·ADR-0008부터 고친다.

**메뉴 선언 Workbook 내보내기(#860, 06 §15).** `table/workbook.ts`(공개 `WorkbookSheet`·`checkWorkbook`·`toWorkbookXlsx`·`WORKBOOK_LIMITS`·`WorkbookError`)는 시트 이름 규칙·상한·셀 변환을, `table/useWorkbookExport.ts`(공개 `WorkbookRefusal` — `build`의 거절된 서버 조회를 표와 같은 원인 토스트로)는 `features.export` 게이트·중복 실행 방지·취소·다운로드·토스트·결과 값을 소유한다. 셀 규칙(`xlsxCell` — 유한하지 않은 숫자·`''`·`null`은 빈 셀, 글자는 `xlsxText`로 자름, #891)과 행 상한은 표 내보내기와 공유하고, 파일 다운로드·이름 stamp는 `table/download.ts`를 표와 함께 쓴다. 표의 2시트 내보내기는 바꾸지 않는다.

- import 가능: `@ap/contracts`, `@ap/kernel`, `@ap/ui`와 표·차트 라이브러리. `@ap/shell`, 앱, mock, 메뉴 화면 import 금지.
- 컴포넌트는 도메인 의미(설비, 지표 이름)를 모른다. 컬럼·셀·탭 내용은 props로 주입받는다.
- 06 §19 상태, §18 Data Trust, 접근성(키보드·포커스 복귀·레이블) 의무를 컴포넌트가 소유한다. 페이지가 따로 구현하게 두지 않는다.
- 차트 클릭으로 전역 Context를 조용히 바꾸지 않는다. 명시적 콜백(`onPointClick`, "분석 구간 적용")만 제공한다.
- 도메인을 모르는 범용 조각은 소비자 수와 관계없이 SDK(여기)에 둔다. 메뉴 안에서 생긴 패턴은 실제 메뉴 2~3곳 반복이 확인된 뒤 올린다(06 §24, 루트 `AGENTS.md`의 "SDK는 범용 조각을 준다"). 스타일은 `@ap/ui` 토큰 유틸리티만.
- `DetailDrawer`는 셸 상세 슬롯에 portal로 내용을 넘긴다(ADR-0013, 06 §13). AppShell 또는 같은 `DetailPanelSlotProvider` 아래에서만 쓴다. URL 도착으로 `focus=`와 함께 열린 패널은 포커스를 가져가지 않고, 같은 화면에서 연 패널만 닫기 버튼으로 포커스한다(ADR-0032). 포커스를 가져가지 않은 패널은 언마운트 때 포커스가 패널 안에 있을 때만 복귀한다. 탭 전환으로 포커스된 컨트롤이 사라지면 선택된 탭 트리거(없으면 패널)로 옮긴다(06 §26, #353).

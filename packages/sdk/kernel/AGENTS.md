# @ap/kernel

Platform Kernel runtime (contract/kernel.md §4). It knows neither the menu list nor the server implementation; the app injects both.

## Rules

- Import only `@ap/contracts`, React, icon libraries and the query engine `@tanstack/react-query` (exact pin `5.62.7`, same version as `@ap/feature-bridge` — bump together, ADR-0086). Lint `denyQueryEngine` blocks the engine for menus, menu mocks, components, shell and apps (feature-bridge allowed); its types never reach the public `.d.ts`. Never import `ui`/`components`/`shell`/apps/mocks.
- Reach the server and session only through `adapter`. A session is a synchronous snapshot plus `subscribe`; on a change notice raise the revision to hide earlier results. `adapter.test.tsx` pins this invalidation contract: change the test first.
- Global Context keys and URL rules are the contract/kernel.md §6 contract. Raise a change as a platform decision; never change it for a menu's need.
- When changing Registry validation, add a failing case to `registry.test.ts`. Tests use fixture Registries only and never import real menus (a test needing real menus is an app integration test).
- Test fixtures (`testAdapter`·`testSession`·`testSpace`·`noContext`·`memoryStorage`) live once in `src/testing.ts`, exported as `@ap/kernel/testing` (ADR-0040). Import them from test files only; when adding a port method, fix the defaults here in the same PR. `testing.ts` is not exported from `index.ts`.
- Add a slot to `PlatformSlots` only when contract/kernel.md §8 Shell Slot grounds it. `analysisActions` are items the app attaches to the `⋯` of screens chosen by `pageTypes` (default `['analysis']`); only the type is Kernel, the item shape is `HeaderOverflowItem`, `subject` comes from `MenuMeta.subjectPageKeys`. `boardEntry` is the `분석 보드에 열기…` item in the `⋯` of board-capable menus (type only in Kernel; implemented by shell `OpenInBoardAction`, docs/contract/16 §6).
- Public entry points: `index.ts` (menu surface), `host.ts` (`@ap/kernel/host`, ADR-0076), `testing.ts`.

## Layout

`src/` root holds only the entry files `index.ts`·`host.ts`·`testing.ts` plus `i18n.tsx`·`stable.ts`·`test-setup.ts`; everything else lives in folders (ADR-0090): `registry/`, `context/`, `links/`, `scope/`, `audit/`, `query/`, `platform/`, `saved-view/`, `error/`. Tests sit in each folder's `__tests__/`. File names below are given without the folder.

## Registry (`registry.ts`, `module.ts`, `module-host.ts`)

- `createRegistry({ spaces, groups, menus, permissions?, platformHomeMenuId?, reservedRoots?, carrySets? })`. Contract: platformHome designation and validation, canonical paths, aliases and redirects, and the `replace` option are in [contract/kernel.md §6.4](../../../docs/contract/kernel.md#64-url-계약-decided-필드명enum-문자열은-candidate); `registry.canonical.test.ts` and `platform.alias-redirect.test.tsx` verify them.
  - `reservedRoots` are roots the app serves outside the Registry; a space id cannot take one. Kernel's own roots are only `board`·`api`·`auth`.
  - `permissions` is the app-declared `MenuPermission[]` (omitted → Kernel permissions only, ADR-0072); the app's list is closed. The returned `registry.permissions` is the Kernel permissions followed by the app's in declaration order.
  - The returned Registry provides `matchRoute`·`safeReturnTo`·`canonicalHref`·`pathFor(menu, params)`·`carrySetOf(menu)`.
- `createRegistry` rejects with `RegistryError`:
  - paths `/board` and `/board/…` (reserved `BOARD_PATH`, docs/contract/16 §7); duplicate ids/groups; missing parent or a parent path with params; undeclared group; not exactly one primary per group; `pageKeys` colliding with global keys; `contextResetKeys` ⊄ `pageKeys`; canonical-path collisions.
  - `drill` with zero levels (no upper bound), duplicate keys, or keys in `pageKeys`·`contextResetKeys`·`returnTo`; `drill.resetKeys` that are undeclared `pageKeys`, level keys, `returnTo` or duplicated (they need not be `contextResetKeys`) — §6.4.
  - spaces without `space`·`homeMenuId`·non-empty `description`, or with an empty `subtitle`; `scopePresentation` other than `default`/`hidden`; a `hidden` space holding a `requiresScope: true` menu, module menus included (§9.1, ADR-0108); `feedbackTracking` other than `true` (self-registration rule in [§9.1](../../../docs/contract/kernel.md#91-업무-시스템-decided-2026-09-26), ADR-0110).
  - Apply mode inconsistencies: `query.mode: 'apply'` with `context.time: 'apply'`, the apply capability in `required.context`, and declared `required.page` keys with non-empty ko/en labels (ADR-0061).
  - malformed ids (empty, whitespace, `? # & /`, `:` in a non-module group id); a menu in an unprefixed or another module's group; for non-module entries, a group/space/permission outside the declarations or a bad `moduleScreen`; declared permissions overlapping Kernel permissions or not shaped `<ns>:<action>`; a module using a Kernel/app permission namespace.
  - `navTree` combined with navHidden/navViews, duplicate `navTree` declarations in a group, empty ko/en labels; a `navTree` on a module entry.
- `MenuEntry` = `PlatformMenuEntry` (`MenuMeta & { icon, component? }`) | `ModuleMenuEntry` (`module`, `<module>:`-prefixed `permission`·`group`, `moduleScreen`); `GroupDef` = `PlatformGroupDef` | `ModuleGroupDef` (`module`, prefixed `id`). `GroupDef` carries `id`·`label`·`icon`·`space` (`space: null` = global utility) and optional `hideLabelWhenSingle`.
- Dynamic sidebar (`PlatformMenuEntry.navTree`, contract/kernel.md §5): owns the stable render-prop `Source`, label and optional mode/icons/current-node resolver. It is absent from JSON `MenuMeta`. The shell gates Source mounting before menu code runs.
- Carry sets: `createRegistry({ carrySets })` validates set IDs/keys, member declarations and navView exclusions; `carrySetOf(menu)` is independent of spaces. Internal space entry/resume resolution never borrows current set state. Favorites clear destination set keys explicitly; recents keep stored clean URLs. A carry set listing `returnTo` retains it across member links regardless of space.
- Menu permissions ([contract/kernel.md §5](../../../docs/contract/kernel.md)): `MenuMeta.additionalPermissions` is ANDed with the primary `permission`. Every access check uses `menuPermissions(menu).every(can)` from `@ap/contracts`; never add primary-only readers. `createRegistry` rejects empty lists, a repeated primary, duplicate/unknown/malformed grants, and additional lists on module menus (`registry.test.ts`, `platform.additional-permissions.test.tsx`).
- `mountModule(manifest, screens, { prefix, groupSpace, config, icons, features? })` (ADR-0053; default host features `query`·`detailSlot`·`write`) returns `{ menus, groups }` for `createRegistry`. Menu id is `<module.id>:<screen.id>` (also for `parent`). It rejects with `RegistryError`: unknown `contract`, a `requires` feature the host lacks, missing `config` keys, unprefixed permission/group, undeclared group, bad `prefix` or screen path (dot segments including encoded, backslash, `?`, `#`, `//`, control characters), a platform-namespace module id, screen↔component mismatch, duplicate screen id, `parent` outside the module. Entries carry `moduleFeatures` (`requires` ∪ `optional`, limited to what the host provides) and `moduleConfig`.
- `useModuleHost(entry, params, ports)` (ADR-0053, no UI) builds one screen instance's `ModuleHost` from `useHostPlatform()`; the shell-only `status`·`focusTarget`·`detail` arrive through `ports`.
  - The host is a snapshot, a new object whenever URL/session/language changes; screens depend on the values they read, not host identity.
  - `setPage` throws `RangeError` before navigating for an undeclared page key; `page(key)` gives `null`.
  - `href`/`navigate` resolve only registered menus via `resolveLink`; `{screen}` is valid only for `<module>:<screen>` whose entry's `module` is this module (nested modules sharing a prefix and platform menu ids are rejected). Unknown → `null`/`false`. Never build URLs from module strings. `navigate` requests arrival focus `page` when the pathname changes.
  - `context()` maps `apply`/`reference` keys to GlobalContext fields (time→from/to, lot→lotIds, recipe→recipeIds, metric→metricId+metricVersion), returns `unsupported` key names separately, and carries `scopeId` only on `requiresScope` screens.
  - `act` exists only if the module declares `write` and the host provides it. It uses the same `actionRequest`/`launchWrite`, one slot per (instance, `spec.id`); a released instance sends nothing and throws `AbortError`; pending waits for re-setup like `query` but does not apply the applied-Context rule (writes do not project analysis Context).
  - `query` exists only on screens declaring the `query` feature and uses the same request path as `menu-query` (non-hook `menuRequest` in `query.ts`). Each call captures revision, user and `projectContext` at start; release or a change of those (applied-Context changes included, reference-only changes excluded) rejects with `AbortError` even if the adapter ignores cancellation or never settles, and validity is rechecked before delivering success.
  - Unmount aborts the `signal` already handed out in layout cleanup, rejects pending calls and clears subscriptions. Until the owner's setup returns (StrictMode replays descendants' layout setup before the owner's) the host is pending: a new `query` waits without adapter work and starts at setup. If no setup follows after the commit's synchronous work (microtask), release is final and pending calls reject with `AbortError`. A pending host's `signal` is already aborted, and passing it to a pending `query` does not count as caller abort.
  - Tests: `module-host.test.tsx`.

## Platform provider (`platform/`)

`platform.tsx` is a thin barrel that re-exports public names explicitly; the code lives in sibling files (import paths from `index.ts`·`host.ts`·`testing.ts` and other folders stay stable). `PaneDraftContext` is the one context created outside `contexts.ts` (in `PaneProviders.tsx`). Behavior is pinned by `adapter.test.tsx` and `platform.*.test.tsx`: change the test first.

- **Provider surface.** `PlatformProvider adapter registry slots` with slots `contextBar`·`topBarTools`·`features`, optional `notifications` (`NotificationsSlot`), optional `vocCompose` (`VocComposeSlot`), optional `homeTodo` (`HomeTodoSlot`: the only slot menus read via `usePlatform().homeTodo`; the shell does not read it), optional `accessRequest` (`AccessRequestSlot`: `Pending` render prop + controlled `Dialog` for the blocked-place request entry, ADR-0154 decision 6; the shell and `@ap/components` draw the places), §8. `PlatformProvider.savedViews` is an optional `SavedViewStore` (absent → no saved-view UI, §21). `usePlatform()`·`usePlatformOptional()` return null outside a Provider.
- **Context writes.**
  - `setGlobal`/`resetContext`: when the value really changes, clear the current menu's `contextResetKeys` in the same navigation (§6.4). `dropResetKeys` (`paneContext.ts`, internal) is the only rule clearing `contextResetKeys` from page pairs on a Context write.
  - `pageParam`/`setPage`: a patch that changes a drill level key also clears the current menu's `drill.resetKeys` in the same write (panes the same per pane). A reset key value given directly in the patch wins. `setGlobal` and Back/Forward do not apply it.
- **Links and spaces.** `linkTo`/`resolveLink` only build hrefs (§22); `returnTo: true` never mints an internal origin. `canOpen` = menu permission ∧ space entry, separate from URL building. `spaceEntry`: last screen → openable home → first sidebar menu. `spaceResume`/`switchSpace`: [contract/kernel.md §9.1](../../../docs/contract/kernel.md#91-업무-시스템-decided-2026-09-26), verified by `platform.space-resume.test.tsx`.
- **Return.** `returnTarget`/`returnOrigin` expose, for an accepted openable `returnTo`: menu name, continued drill values, reverted global Context entries (`revertedContext`, Scope included), `accepted` (true only when adopted, false for fallback) and `spaceLabel` (origin menu's space name, else null). When absent or rejected, fall back in order: openable parent → openable `registry.platformHome` → openable `sidebarSpace.homeMenuId` → `/` (exception guard).
- **Misc state.** Scope state (`scope`·`retryScope`; the Provider masks frames of a changed session), favorites/recents, `reportError`. `reportError` sends identifying fields only to the adapter; never `Error.message`, URL or Context values.
- **Usage.** Utilization goes to `adapter.recordUsage` (entry/dwell). A main-screen entry carries `via` and `fromMenuId`:
  - `via` of `navigate`/`PlatformLink` is `MainUsageVia` (pane values excluded; dropped at runtime too). The last `navigate`/`PlatformLink` mark wins; with no mark the tab's first entry is `direct`, later ones `link`, popstate `history`.
  - `fromMenuId` is the previous main screen's menu id (null if not a menu).
  - Consume at the real entry time (inside `setTimeout 0`) and reset when the user changes. Test: `platform.usage.test.tsx`.
  - Board pane entries use the per-pane ref trace of `useScreenState`: `via` (`paneOpen` for the pane's first admitted screen, then `paneReplace`) and `fromMenuId` (the pane's previous menu id; null on open and after a non-admitted screen). Reads with `countUsage={false}` leave the trace untouched (`platform.pane.test.tsx`).
- **Render isolation** (ADR-0049, ADR-0076 addendum). `PlatformProvider` holds app-wide state (session, permissions, favorites, `slots`) in one `useMemo`d value. Frequently changing shell state (recent visits, toasts, palette, switcher) sits in separate per-concern contexts (`useRecentVisits()`·`useToastList()`·`useOverlayState()`, `HostPlatform.readRecent()`) so menus, tables and charts are not woken. `useScreenState`'s `screen`·`queryPolicy` and members keep the same reference when content is equal; `MainScreenProvider` is `memo`. Test: `platform.render-count.test.tsx`.
- **Screens.** `useScreenState` builds the URL-bound **main screen** (route, Context, page, Scope, writes, links, return, `reportError`, utilization dwell). `PaneScreenProvider paneId screen={{ menuId, params, query }} onChange onLeave` (`PaneScreen`) builds **one pane's screen** by the same rules and binds descendants' `useHostPlatform()` to the pane; its address is `pathFor(menu, params) + query` and the pane's `url`/`pathname` are that virtual address.
  - `useHostPlatform()` merges app-wide fields, main-screen-bound shell fields (`visibleMenus`·`sidebarSpace`·`spaceResume`·`spaceEntry`·`switchSpace`) and the nearest screen state, plus `screenMode`·`paneId`. Shell outside panes (rail, sidebar, switcher, palette, feature links) always reads the main screen.
  - Pane writes (`setGlobal`·`setPage`·`resetContext`·drill·default period/metric-version materialize) go only through `onChange(next, 'push'|'replace')` and ignore permissions and `features.board`.
  - `navigate`/`PlatformLink`/return: another `features.board` menu that is `canOpen` → `onChange(…, 'push')` (same pane address keeps the `replace` option); otherwise `onLeave(href)`; external, absolute or same address → false.
  - Materialize merges period and metric version into one `replace` and never repeats the same input/output proposal (`onChange` may not apply immediately).
  - Only the main screen handles popstate, recents, `space-last`, `lastScope` and `#platform-main` scroll. A pane validates its own Scope and counts utilization as `source: 'board'` + `stayId` (admission key includes `paneId`).
  - A pane write's menu, params and current address come from the rendered screen (descendant layout-effect writes target the new screen). Pane consumers do not re-render on main-screen Scope/toast/palette changes (pane-only Context; the main bundle is memoized) and re-render once, following `mainBound`, when the main address changes.
  - Precondition (caller, board): a registered `menuId` with all path params, validation of saved screens, and the "cannot open" state for missing/disabled menus — shell `board/boardMenus.ts` `admitPaneScreen` guards this.
  - A second Provider reading the same pane (board Context bar) uses `countUsage={false}` so utilization is not double-counted. Tests: `platform.pane.test.tsx`.
- **Platform screen** (docs/contract/16 §7). When the main path is `/board` (trailing slash allowed), `useHostPlatform().platformScreen` is `'board'` (null elsewhere and inside panes), `route` and `contractError` are null and main Context is empty (the Context codec does not run). This screen is not cancelled as an unregistered path (the arrival-focus request stays for the board to consume) and does not feed recents, space-last or menu utilization. It is read-only; `hasDotSegment`·`isBoardPath`·`BOARD_PATH` are public for the shell. Tests: `platform.board.test.tsx`, `registry.test.ts`.
- **Detail expansion URL boundary** (ADR-0126). `links/detail-expansion.ts` owns stripping and writing the internal reserved key. `useScreenState` exposes `detailExpanded`/`setDetailExpanded` on HostPlatform only; keep `expand` off MenuPlatform and page/query/share data.
  - `expand=1` is removed before query parsing, draft identity and saved-view comparison; `setPage` and Registry declarations reject it. Old preference addresses are stripped on read.
  - Same-screen writes and materialization retain it; host toggles always replace, without changing guard semantics.
  - Cross-menu navigation, return origins, links/carry sets, favorites, recents and space-last/resume do not carry it.
  - Board and pane host setters are no-ops: presentation lives in memory in the slot owner.
  - Test: `platform.detail-expansion.test.tsx`.

## Navigation and URL helpers

- `return-to.ts`: internal `stripReturnToFromUrl` removes `returnTo` pairs from a URL string; the pair-list rule (`RETURN_TO_KEY`·`withoutReturnTo`·`carriesReturnTo`) belongs to `@ap/contracts`. `returnTo` is navigation info, not screen state, so space-last (`writeSpaceLast`) and recents (`recordVisit`) strip it before storing and query history strips it before normalizing. Test: `platform.return-to.test.tsx`.
- `hiddenState.ts` (internal, not exported): `readHiddenState`·`withHiddenState`·`splitHidden`·`sameHidden`. Page keys a menu declares in `hiddenPageKeys` stay out of the main screen address and live in `history.state.apHidden = { v: 1, pairs }` (other state fields untouched).
  - `MainScreenProvider.commit` strips hidden pairs from every write/navigation address (a pair change makes a new entry even with the same address); first load and popstate move leftover hidden keys from the address into state by `replace` on the same entry.
  - `useScreenState` reads visible address + hidden pairs as one query, so `page`·`pageParam(s)`·`contextResetKeys`·drill reset apply unchanged.
  - `repeatedPageKeys` allow duplicates via `parseQuery(…, { repeated })`; `pageParams` and array values of `setPage` read and write them.
  - Panes have no hiding: everything stays in the pane query. Test: `platform.url-keys.test.tsx`.
- `returnHidden.ts` (internal): stores a leaving screen's hidden pairs in `sessionStorage` (`ap.kernel.returnHidden`, version 2, limits 16 entries / 32 pairs / 32 KB; keyed by the visible origin address; bound to user id, deployment and menu id) via `rememberReturnHidden`, and restores them when the return link is followed (`readReturnHidden` → `commit`'s `restoreHidden`; `validateHidden` filters by the destination menu's hidden keys and single-value rule). Storage errors mean "no hidden pairs"; a return whose write failed is not restored (fail closed). Test: `platform.hidden-keys.test.tsx`.
- `drill.ts` — `useDrill()` reads the current menu's `drill.levels` page values as `depth`·`trail`·`invalid`. `enter`/`goTo` clear later-level keys with one `setPage` (push); `drill.resetKeys` are cleared by `setPage` (focus-request decisions use the same predicate in `drillReset.ts`; §6.4, ADR-0025). Drill moves are not counted in utilization.
- `drillReset.ts` (internal): `drillLevelChanged` (does the patch change a level key; `''`/absent = `null`) and `dropDrillResetKeys` (adds `drill.resetKeys` as `null` to the patch when it does; values the patch gives directly win). Used by `setPage` and `drill.ts`. Test: `drillReset.test.ts`.
- `pageNavigation.ts` — after-navigation focus requests held by the Provider (`PageFocus`: `drill`·`return`·`page`, §26).
  - Only explicit navigation makes requests: `PlatformLink` and palette when the pathname changes, Back/Forward popstate between menus when the pathname changes (`page`), and `switchSpace`. `PlatformPage` consumes a request only when generation and pathname match.
  - `PageNavigation` offers `requestReturn`·`consume`·`subscribe`·`claimsDetailFocus`. `claimsDetailFocus` is false for URL arrival (`page`·`return`, first-load `focus=`) and true when `focus` appears on the same screen or for `drill` (ADR-0032).
  - The palette connects only through the injected `isBlocked()` and release notice `notify()`, and a blocked `page` request is preserved.
- `paletteFocus.ts` — owns palette open/close, generation, Dialog instance ownership, render state and cleanup on Provider session replacement. Opening cancels the previous navigation request; the shell gets session-bound `claim(owner)`·`release(owner)`·`isCurrent()` handles. Only the current owner releases the block, in the deferred release after Dialog close autofocus or FocusScope cleanup. Pinned by `paletteFocus.test.ts` (transitions), `packages/sdk/shell/src/routing/__tests__/CommandPalette.test.tsx`, `packages/sdk/components/src/archetypes/__tests__/DrillLayout.test.tsx` and E2E `메뉴 이동 포커스 (06 §26)` (focus results).
- `navigationGuard.ts` — Kernel-internal store of the unsaved-navigation guard (ADR-0115, §6.4): `createNavigationGuard()` plus `history.state.apIdx` helpers.
  - One registration = one dirty hook; any registration holds navigation; the innermost (latest) `message` shows. On confirm, run `onDiscard` of the blocking registrations newest first once, then `proceed` once. One pending request: it is dropped without confirmation when the blocking registrations vanish or the session generation changes. One `beforeunload` listener while dirty; accepted Back/Forward is signalled by `onTraversal`.
  - Public names: root `useUnsavedGuard(dirty, { message?, leaves?, onDiscard? })`·`UnsavedGuardOptions` (`hooks.tsx`); host `useLeaveRequest()`·`LeaveRequest`.
  - It blocks in exactly two places: `MainScreenProvider.commit` (push that is not a redirect, materialize or `bypassGuard`; returns `false` when blocked) and the stable popstate listener (corrects with `history.go(-delta)` from the `apIdx` difference; on confirm `go(delta)`; if it cannot be undone, pass through + `reportError`).
  - `useSavedViews` judges selection release by `onTraversal`, not raw popstate. Panes (`PaneScreenProvider`) have no commit seam and are not guarded. Tests: `navigationGuard.test.ts`, `platform.nav-guard.test.tsx`.

## Query lifecycle (`query/`)

- `query-engine.ts` — an internal `QueryClient` per Provider (defaults `staleTime 0`, `gcTime` 5 min, `retry false`, `structuralSharing false`), generation cleanup `removeOtherGenerations`, write invalidation `invalidateEndpoints`, and Provider lifetime `startQueryEngine` (`client.mount()`/`unmount()` plus one cache subscription that cancels a query that is fetching, offline-paused included, with no open observer) (ADR-0086).
  - `PlatformProvider` keeps one client for its whole life. The session generation `gen = adapterEpoch:revision:userId` (`adapterEpoch` rises when the adapter prop changes) is the second element of every key; on change, queries of other generations are removed in the same commit.
  - Only the internal hook `useQueryEngine()` reads it; it is not on `HostPlatform`/`MenuPlatform`. Test: `query-engine.test.tsx`.
- `query.ts` — `useQueryLifecycle` on the engine (ADR-0086; lifecycle contract owner: §19). Key `[kind, gen, …identity, idle]`. An open instance shows the key's result (`refreshing` while fetching); a closed instance shows only results it accepted. When closed, or when every open observer leaves, the `startQueryEngine` subscription runs `cancelQueries` (no per-hook effect). `refetch`/`refreshEpoch` use `refetch({ cancelRefetch: false })` so they never open a closed gate.
  - `usePlatformQuery`: key `['platform', gen, useId(), …]` (caller supplies `run`, so no sharing); `identity: 'session'` excludes global Context.
  - `useEntityQuery`: §22 destination `adapter.getEntity`, shared key `['entity', gen, ref, pageInputs, false]`.
  - `useMenuQuery`: returns `MenuQueryState<P,T>` = `QueryState<T> & { resultParams?: P }`, shared key `['menu', gen, spec.id, projected, params, idle]`. The fourth argument `{ keepPrevious }` (`MenuQueryOptions`, ADR-0114) is opt-in: when only params change it keeps the last accepted `ok`/`empty` result as `refreshing`, with `completedAt` that result's time. Only with `keepPrevious` on does it also return `resultParams` (params of the visible result) and `showingPrevious` (kept result's params ≠ current params); otherwise both are `undefined`. A change of Context, Scope, session, endpoint or gate hides it. Test: `menu-query.test.tsx`.
  - `useMenuFetch`: menu `EndpointSpec` → `adapter.menuQuery`, including Scope/period gates and the assessments kind check; a call before `ready` is a `not_ready` error.
  - `useEndpointRefreshEpoch(endpointIds)`: the sum of `refreshEpochs.get(id)` over the listed ids, via `useSyncExternalStore` on `refreshEpochs.subscribe`. `PlatformDataTable` folds it into its request identity for `refreshOn` (ADR-0137); `useMenuQuery` is refreshed through the engine sink and does not use it.
  - `useAdapterRequest`: shell fetch, key `['request', gen, useId(), key]`; the caller puts every dependency in `key`.
  - `useEntityAudit(ref, enabled?)`: §13 destination audit `adapter.entityAudit` (ADR-0085). `query` is the first page (session identity, for `QueryView`); spread `timeline = { events, more: AuditMore }` into `AuditTimeline`. Appended pages are bound to a read generation that rises at every fetch start, so a ref/Scope/revision/user change or a re-fetch of the same target discards them and aborts an in-flight `load`.
  - Cancellation is judged only by Kernel's own `signal.aborted`; an adapter-timeout `AbortError` is an error. The decision rules are owned by §19 and [checklist §3](../../../docs/integration/real-server-checklist.md), pinned by `menu-query.test.tsx`.
- `cursor-pages.ts` (internal) — `useCursorPages(first, run, { id, order })`: domain-free lifecycle that reads the first page elsewhere (`usePlatformQuery`) and appends cursor pages (dedupe by id, retry with the same cursor, abort on identity change, `load` blocked on `forbidden`, `error` when `nextCursor` equals the sent or an already seen cursor). Unlike `selection-port-cache.ts` it serves envelope ports and has no shared cache. An exception thrown because its own `AbortSignal` fired is discarded; any other `AbortError` (adapter timeout) becomes `error` (same rule as `query.ts`). Test: `entity-audit.test.tsx`.
- `query-draft.ts` — `useQueryDraft()`: live/apply draft, missing-required, atomic apply (§11, ADR-0061). Board body and editor Providers share per-pane stores through the common `PaneQueryDraftProvider screens`. Analysis requests gate on idle and report the accepted response time as `QueryState.completedAt`. Test: `query-draft.test.tsx`.
- `condition-preset.ts` — Condition presets (ADR-0083, §6.4).
  - `activeConditionPreset(menu, page, condition?)`: the preset of the page value if any; else the first declared preset containing every non-empty Condition axis; else the declared default (test `condition-preset.test.ts`).
  - `narrowedGlobal(menu, page, global)` keeps only the active preset's axes of the global Context; `menuRequest`·`useMenuQuery`·`useMenuFetch` and the module host `query` validity check (`projectMenuContext`) pass it to `projectContext`. A pane decides by its own menu and applied page (`platform.page`).
  - Do not narrow `host.context()`, `withPaneContext`, the URL or the global Condition.
  - Public `useQueryContext(): GlobalContext` calls `narrowedGlobal(route?.menu, page, global)` with the applied screen page/global (same arguments as `projectMenuContext`, not the draft: an Apply menu's `setDraftPage` does not change the value, applying does; a pane uses its own values; a menu with no preset returns the same object as `global`). Table query identity and export headers use it.
  - Shell read-only `useConditionPreset()` → `{ key, presets, activeId (draft), appliedId, outsideAxes } | null`; switch with `useQueryDraft().setDraftPage({ [key]: id })`. `PlatformProvider` throws at render if a preset axis id is not in `equipmentAxes`.
- `query-history.ts` — `useQueryHistory` and the logical draft-owned history state. From the first render after a session/revision/Scope change it hides earlier rows and provides values only after the existing Scope / room grant / resolveSelection validation. Restore replaces the whole draft atomically; an occurrence is recorded only at Apply address confirmation (§11). The returned object is `useMemo`d; methods close over the current render input and reject stale calls through `current()`; masked rows keep the same reference while enabled, rows and permissions are equal. Tests: `query-history.test.tsx`, `platform.pane.test.tsx`.
- `action.ts` — screen side of the write port (ADR-0054). Non-hook core `actionRequest(spec, input, expectedVersion, inputs)`:
  - A version-rule violation throws `RangeError` synchronously before sending. An unmet Scope gate returns a `not_ready` error with no adapter call and no `retry`.
  - Each call builds the request once with a `crypto.randomUUID()` key and a `structuredClone`d input; every `retry` resends that object.
  - It never passes a release signal to the adapter (a sent write cannot be undone); a throw becomes `unknown` (`message: String(error)`). Only `error` and `unknown` get `retry`.
  - On `ok`, `conflict` or `unknown`, raise the refresh epochs of `spec.invalidates` whether or not anyone awaits the response.
  - `launchWrite(flight, send)` is the owner's (hook or host instance) flow control: single-flight per slot (`run`, `retry` and host `act` share one promise); `valid()` just before delivery (release or generation change → `AbortError`; a sent write still completes); `retry` is recursively wrapped in the same control (a `retry` held after release or generation change is not sent and gives `AbortError`).
  - `useMenuAction(spec)` → `{ ready, pending, run(input, { expectedVersion }) }`: single-flight per hook instance (a `run` while unresolved returns the earlier promise and ignores the new input); unmount or `revision`/user change throws `AbortError` immediately; `pending` includes retry sends.
  - Tests: `action.test.tsx` (two panes included); host side `module-host.test.tsx`.
- `refresh-epochs.ts` — app-wide refresh-epoch store (one per `PlatformProvider`, exposed as `useHostPlatform().refreshEpochs`, not per pane): `bump(ids)`·`get(id)`·`total()`·`subscribe` (public types unchanged).
  - The internal sink of `createRefreshEpochs(sink?)` is attached when the store is created (with the client, in the Provider), so a bump never precedes the engine.
  - `invalidateEndpoints` in `query-engine.ts` runs `cancelQueries` on every `menu` query of the bumped endpoints, then `invalidateQueries({ cancelRefetch: false })` (a group retry started after the cancel is not split and cut again; an in-flight first read is replaced; open queries keep the previous result and re-read as `refreshing`; closed ones are marked stale; ADR-0086).
  - The host folds `total()` into `changeKey` so `host.subscribe` listeners fire after a write. A table refreshes through `refreshOn` (`useEndpointRefreshEpoch(ids)` in `query/query.ts`, the sum of the listed endpoints' epochs, read with `useSyncExternalStore`); `useMenuFetch` alone still does not refresh (ADR-0137).

# @ap/kernel

Platform Kernel 런타임(06 §4). 메뉴 목록도, 서버 구현도 모른다. 둘 다 앱이 주입한다.

## 파일

폴더 배치(ADR-0090, #713c; 아래 파일 이름은 폴더 없이 적는다): `src/` 루트에는 진입 파일 `index.ts`·`host.ts`·`testing.ts`와 `i18n.tsx`·`stable.ts`·`test-setup.ts`만 둔다. 나머지는 `registry/`(`registry`·`module`·`module-host`·`metric-init`), `context/`(`paneContext`·`location`·`pageNavigation`·`paletteFocus`·`drill`·`drillReset`·`equipmentAxes`), `links/`(`return-to`), `scope/`(`selection-ports`·`selection-port-cache`), `audit/`(`cursor-pages`), `query/`(`query`·`query-engine`·`query-history`·`query-draft`·`draft-state`·`condition-preset`·`refresh-epochs`·`action`), `platform/`(`platform.tsx` 배럴과 갈래 파일), `error/`(오류 문구 테스트)에 있고, 테스트는 각 폴더의 `__tests__/`(루트 `src/__tests__/`는 `testing.test.ts`)에 둔다. 이동 스크립트 `.agents/conductor/moves/713c.sh`.

- `registry.ts` — `createRegistry({ spaces, groups, menus, permissions? })`(`permissions`는 앱이 선언한 메뉴 권한 `MenuPermission[]`, 생략하면 Kernel 권한만, ADR-0072): §5 검증(`/board`·`/board/…` 경로 금지 — 분석 보드가 쓰는 예약 경로 `BOARD_PATH`, docs/16 §7, id·그룹 중복, parent 존재·파라미터 없는 경로, 선언 그룹, 그룹별 primary 1개, `pageKeys`×전역 키, `contextResetKeys`⊆`pageKeys`, `drill` 1단계 이상(상한 없음)·키 중복·`pageKeys`·`contextResetKeys`·`returnTo` 금지, `drill.resetKeys`는 선언된 `pageKeys`·단계 키 아님·`returnTo` 아님·중복 없음(`contextResetKeys`일 필요 없음) — 06 §6.4, 경로 정규형 충돌, 공간 `space`·`homeMenuId`·비어 있지 않은 `description`, 있으면 비어 있지 않은 `subtitle` — 06 §9.1)과 정적 세그먼트 우선 매칭. `GroupDef`는 `id`·`label`·`icon`·`space`(`space: null`이면 전역 유틸리티)와 선택적 사이드바 표시 선언 `hideLabelWhenSingle`을 가진다. 반환 Registry가 `matchRoute`·`safeReturnTo`를 제공하고 `pathFor(menu, params)`가 경로를 만든다. `MenuEntry`는 `PlatformMenuEntry`(`MenuMeta & { icon, component? }`)와 모듈 변형 `ModuleMenuEntry`(`module`·`<module>:` 접두사 `permission`·`group`·`moduleScreen`)의 합이고, `GroupDef`도 `PlatformGroupDef`·`ModuleGroupDef`(`module`, 접두사 `id`)다. 접두사가 없거나 다른 모듈의 그룹에 놓인 메뉴, `module` 없는 항목의 선언 밖 그룹·공간·권한(앱이 선언한 목록이 닫힌 목록이다)·모양이 틀린 id(비어 있음·공백·`? # & /`, module 없는 그룹 id의 `:`)·`moduleScreen`, 선언된 권한이 Kernel 권한과 겹치거나 `<ns>:<action>` 모양이 아닌 경우, Kernel·앱 선언 권한의 네임스페이스를 쓰는 모듈은 `RegistryError`. 반환 Registry의 `permissions`는 Kernel 권한 다음에 앱 선언 순서의 전체 목록이다.
  Apply 모드 검증은 `query.mode: 'apply'`와 `context.time: 'apply'`, `required.context`의 apply capability, `required.page`의 선언된 키와 비어 있지 않은 ko/en 라벨을 확인한다(ADR-0061).
- `module.ts` — `mountModule(manifest, screens, { prefix, groupSpace, config, icons, features? })`(기본 호스트 기능 `query`·`detailSlot`·`write`)(ADR-0053): 모르는 `contract`, 호스트에 없는 `requires` 기능, 빠진 `config` 키, 접두사 없는 권한·그룹, 선언 안 된 그룹, 잘못된 `prefix`·화면 경로(인코딩 포함 점 세그먼트·역슬래시·`?`·`#`·`//`·제어 문자), 플랫폼 네임스페이스 모듈 id, 화면↔컴포넌트 불일치, 중복 화면 id, 모듈 밖 `parent`를 `RegistryError`로 거부하고 `createRegistry`에 넘길 `{ menus, groups }`를 돌려준다. 메뉴 id는 `<module.id>:<screen.id>`(`parent` 포함). 메뉴 항목에는 호스트 포트가 쓸 선언 기능(`moduleFeatures` = `requires` ∪ `optional` 중 호스트가 주는 것)과 `moduleConfig`가 실린다.
- `module-host.ts` — `useModuleHost(entry, params, ports)`(ADR-0053, UI 없음): 모듈 화면 한 인스턴스의 `ModuleHost`를 `useHostPlatform()`에서 만든다. 셸만 줄 수 있는 `status`·`focusTarget`·`detail`은 `ports`로 받는다. 호스트는 URL·세션·언어가 바뀔 때마다 새 객체인 스냅샷이다(화면은 호스트 정체성이 아니라 읽은 값에 의존). `setPage`는 화면이 선언하지 않은 page key면 이동 전에 `RangeError`를 던지고 `page(key)`는 `null`을 준다. `href`/`navigate`는 등록된 메뉴만 `resolveLink`로 풀고(`{screen}`은 같은 모듈의 `<module>:<screen>`이고 그 항목의 `module`이 이 모듈일 때만 — 접두사만 같은 중첩 모듈·플랫폼 메뉴 id는 거부; `navigate`는 pathname이 바뀌면 도착 포커스 `page`를 요청한다) 모르면 `null`/`false`다 — 모듈 문자열로 URL을 만들지 않는다. `context()`는 `apply`·`reference` 키를 GlobalContext 필드로 옮기고(time→from/to, lot→lotIds, recipe→recipeIds, metric→metricId+metricVersion) `unsupported` 키 이름을 따로 돌려주며 `scopeId`는 `requiresScope` 화면에서만 싣는다. `act`는 `write` 기능을 선언하고 호스트가 줄 때만 있다 — 같은 `actionRequest`/`launchWrite`를 쓰고 슬롯은 (인스턴스, `spec.id`)당 하나이며, 해제된 인스턴스는 보내지 않고 `AbortError`, 보류 상태는 `query`처럼 re-setup까지 미루되 적용 Context 규칙은 쓰지 않는다(쓰기는 분석 Context를 투영하지 않는다). `query`는 `query` 기능을 선언한 화면에만 있고 `menu-query`와 같은 요청 경로(`query.ts`의 비훅 `menuRequest`)를 쓴다 — 호출마다 시작 시점의 revision·user·`projectContext`를 잡아 두고, 해제나 그 값의 변화(적용 Context 변화 포함, 참조 전용 변화는 제외)가 있으면 어댑터가 취소를 무시하거나 끝나지 않아도 `AbortError`로 거부하며 성공 전달 전에 유효성을 다시 본다. 해제(언마운트)는 layout cleanup에서 이미 건넨 `signal`을 abort하고 대기 중 호출을 거부하며 구독을 비운다. 그 뒤 소유자의 setup이 다시 오기 전까지(StrictMode 재실행은 자손의 layout setup이 소유자보다 먼저다)는 보류 상태라 새 `query`는 어댑터 작업 없이 기다렸다가 setup에서 시작하고, 같은 커밋의 동기 작업 뒤(microtask)에도 setup이 없으면 해제가 확정되어 보류 호출은 `AbortError`로 거부된다(보류 중 호스트의 `signal`은 이미 abort 상태이고, 보류 중 `query`에 그 `signal`을 넘겨도 호출자 abort로 보지 않는다). 검증 `module-host.test.tsx`.
- `platform/` 파일 나눔(ADR-0090, #713d; 동작 불변) — `platform.tsx`는 공개 이름만 명시해 다시 내보내는 얇은 배럴이고(`index.ts`·`host.ts`·`testing.ts`·다른 폴더의 import 경로는 그대로), 코드는 `types.ts`(공개 타입·`RETURN_CONTEXT_LABELS`·`UNDO_WINDOW_MS`)·`preferences.ts`(저장 설정·공간 마지막 화면 유틸)·`contexts.ts`(화면·앱이 함께 쓰는 내부 컨텍스트 객체와 타입 — 칸 전용 `PaneDraftContext`만 예외로 `PaneProviders.tsx`에서 `createContext`)·`useScreenState.ts`·`PlatformProvider.tsx`·`MainScreenProvider.tsx`·`PaneProviders.tsx`(`PaneScreenProvider`·`PaneQueryDraftProvider`)·`hooks.tsx`(소비 훅·`PlatformLink`·내부 `useQueryEngine`·`useSelectionPortCache`)에 있다. 아래 `platform.tsx` 설명은 이 파일들 전체를 가리킨다.
- `platform.tsx` — `PlatformProvider adapter registry slots`(슬롯 `contextBar`·`topBarTools`·`feedbackOps`·선택 `notifications`(`NotificationsSlot`, #652)·선택 `vocCompose`(`VocComposeSlot`, #655)·선택 `homeTodo`(`HomeTodoSlot` — 메뉴가 `usePlatform().homeTodo`로 읽는 유일한 슬롯이고 셸은 읽지 않는다, #657), 06 §8)와 `usePlatform()`·`usePlatformOptional()`(Provider 밖에서는 null): 전역 Context(`setGlobal`·`resetContext` — 실제로 바뀌면 현재 메뉴의 `contextResetKeys`를 같은 내비게이션에서 지운다, 06 §6.4)·`pageParam`/`setPage`(단계 키 값을 바꾸는 패치는 현재 메뉴의 `drill.resetKeys`도 같은 쓰기에서 지운다 — 칸도 칸 단위로 같다, 패치가 직접 준 reset 키 값이 이긴다, `setGlobal`·뒤로/앞으로는 적용하지 않는다)·`linkTo`/`resolveLink`(06 §22; 공간 `carriedPageKeys`에 `returnTo`가 있으면 그 공간 안 같은 공간 링크는 `returnTo: true`여도 현재 값을 이어받기만 하고 만들지 않으며 키를 두 번 싣지 않는다, #760)·`canOpen`(URL 생성과 분리된 메뉴 권한 ∧ 공간 진입 판정)·`spaceEntry`(마지막 화면 → 열 수 있는 홈 → 첫 사이드바 메뉴)·`spaceResume`/`switchSpace`([06 §9.1](../../docs/contract/kernel.md#91-워크스페이스-decided-2026-09-26), 검증 `src/platform.space-resume.test.tsx`)·`returnTarget`/`returnOrigin`(열 수 있는 채택된 `returnTo`의 메뉴 이름·연속 드릴 값·되돌린 전역 Context 항목(`revertedContext`, Scope 포함)·`accepted`(채택된 경우만 true, fallback은 false)·`spaceLabel`(채택된 출발 메뉴의 공간 이름, 없으면 null), 없거나 거부되면 열 수 있는 parent → 열 수 있는 `/` 메뉴 → 열 수 있는 `sidebarSpace.homeMenuId` → 예외 방지 `/` fallback)·Scope 상태(`scope`·`retryScope`, 세션이 바뀐 프레임은 Provider가 가린다)·즐겨찾기/최근·`reportError`. `reportError`는 식별 필드만 어댑터로 보낸다 — `Error.message`·URL·Context 값은 금지. 활용률은 `adapter.recordUsage`(entry/dwell). 본 화면 entry에는 이동 경로 `via`(마지막 `navigate`/`PlatformLink`의 표시가 이기고, 표시가 없으면 탭 첫 entry는 `direct`·그 뒤는 `link`, popstate는 `history`)와 `fromMenuId`(바로 앞 본 화면의 메뉴 id, 메뉴가 아니면 null)가 실린다 — 실제 entry 시점(setTimeout 0 안)에 소비하고 사용자가 바뀌면 초기화한다(#605, 검증 `platform.usage.test.tsx`). 동작은 `adapter.test.tsx`·`platform.*.test.tsx`가 고정하므로 바꾸면 테스트부터 고친다.
- `platform.tsx`의 화면 층(ADR-0049, #496) — `PlatformProvider`는 앱 전체 상태(세션·권한·즐겨찾기·`slots`)를 `useMemo`한 한 값으로 들고, 자주 바뀌는 셸 상태(최근 방문·토스트·팔레트·전환기)는 관심사별 컨텍스트 셋(`useRecentVisits()`·`useToastList()`·`useOverlayState()`, `HostPlatform.readRecent()`)에 따로 둬서 메뉴·표·차트를 깨우지 않는다(ADR-0076 보충, #824, 검증 `platform.render-count.test.tsx`; `useScreenState`의 `screen`·`queryPolicy`와 멤버는 내용이 같으면 같은 참조, `MainScreenProvider`는 `memo`). 또 URL에 묶인 **본 화면**을 `useScreenState`로 만든다. 화면 상태는 route·Context·page·Scope·쓰기·링크·반환·`reportError`·활용률 체류다. `PaneScreenProvider paneId screen={{ menuId, params, query }} onChange onLeave`(`PaneScreen`)가 같은 규칙으로 **칸 하나의 화면**을 만들어 자손의 `useHostPlatform()`을 칸에 묶는다(주소 = `pathFor(menu, params) + query`, 칸의 `url`·`pathname`은 이 가상 주소). `useHostPlatform()`은 앱 전체 필드 + 본 화면에 묶인 셸 필드(`visibleMenus`·`sidebarSpace`·`spaceResume`·`spaceEntry`·`switchSpace`) + 가장 가까운 화면 상태를 합치고 `screenMode`·`paneId`를 더한다 — 칸 밖의 셸(레일·사이드바·전환기·팔레트·FeedbackOps 링크)은 늘 본 화면을 읽는다. 칸의 쓰기(`setGlobal`·`setPage`·`resetContext`·드릴·기본 기간/지표 버전 materialize)는 `onChange(next, 'push'|'replace')`로만 가고 권한·`features.board`를 보지 않는다. `navigate`/`PlatformLink`/반환은 다른 `features.board` 메뉴이고 `canOpen`이면 `onChange(…, 'push')`(같은 칸 주소면 `replace` 옵션 유지), 그 밖이면 `onLeave(href)`, 외부·절대·같은 주소는 false. `linkTo`/`resolveLink`는 href만 만든다. materialize는 기간과 지표 버전을 한 번의 `replace`로 합치고 같은 입력·출력 제안은 되풀이하지 않는다(`onChange`는 즉시 반영하지 않을 수 있는 제어 콜백). popstate·최근·`space-last`·`lastScope`·`#platform-main` 스크롤은 본 화면만 한다. 칸은 자기 Scope를 따로 검증하고 칸 활용률은 `source: 'board'`+`stayId`로 센다(admission 키에 `paneId`). 칸 쓰기의 메뉴·params·현재 주소는 렌더된 화면에서 오고(자손 layout effect의 쓰기도 새 화면을 향한다), 칸 소비자는 본 화면의 Scope·토스트·팔레트 같은 변화에 다시 그려지지 않고(칸 전용 Context, 본 화면 묶음은 메모), 메인 주소가 바뀌면 `mainBound`를 따라 한 번만 다시 그려진다(ADR-0076 보충 #824, 백로그). 전제(호출자 #497): 등록된 `menuId`와 모든 경로 param, 저장된 화면의 검증·없는/꺼진 메뉴의 '열 수 없음' 상태(셸 `board/boardMenus.ts`의 `admitPaneScreen`이 지킨다). 같은 칸을 읽는 두 번째 Provider(보드 Context 바)는 `countUsage={false}`로 활용률을 중복해서 세지 않는다. 검증 `platform.pane.test.tsx`.
- 플랫폼 화면(docs/16 §7, #497a) — 본 화면의 경로가 `/board`(끝 슬래시 허용)이면 `useHostPlatform().platformScreen`이 `'board'`(그 밖·칸 안은 null)이고 `route`·`contractError`는 null, 본 화면 Context는 비어 있다(Context 코덱을 돌리지 않는다). 이 화면은 미등록 경로의 취소를 받지 않고(도착 포커스 요청이 남아 보드가 소비한다) 최근 방문·공간 마지막 화면·메뉴 활용률을 쓰지 않는다. 읽기 전용 상태이며 `hasDotSegment`·`isBoardPath`·`BOARD_PATH`는 셸이 쓰도록 공개한다. 검증 `platform.board.test.tsx`·`registry.test.ts`.
- `return-to.ts` — 내부 도우미 `stripReturnToFromUrl`(URL 문자열에서 `returnTo` 쌍을 뗀다). 쌍 목록 규칙(`RETURN_TO_KEY`·`withoutReturnTo`·`carriesReturnTo`)은 `@ap/contracts`(#851). `returnTo`는 화면 상태가 아니라 이동 정보라서 공간 마지막 화면(`writeSpaceLast`)과 최근 방문(`recordVisit`)이 저장 전에, 질의 이력(`query-history.ts`)이 정규화 전에 쓴다(#760). 검증 `platform.return-to.test.tsx`.
- `drill.ts` — `useDrill()`: 현재 메뉴 `drill.levels`의 page 값을 `depth`·`trail`·`invalid`로 읽고, `enter`/`goTo`는 `setPage` 한 번(push)으로 그 단계 뒤 키를 지우고, `drill.resetKeys`는 `setPage`가 지운다(포커스 요청 판정은 `drillReset.ts`의 같은 술어, 06 §6.4, ADR-0025). 단계 이동은 활용률 계측에 넣지 않는다.
- `drillReset.ts` — 내부 순수 도우미(공개 export 아님): `drillLevelChanged`(패치가 단계 키 값을 바꾸는가, `''`/없음 = `null`)와 `dropDrillResetKeys`(바꾸면 `drill.resetKeys`를 패치에 `null`로 더함, 패치가 직접 준 값이 이김). `platform.tsx`의 `setPage`와 `drill.ts`가 쓰며 검증 `drillReset.test.ts`.
- `pageNavigation.ts` — Provider가 가진 이동 뒤 포커스 요청(`PageFocus`: `drill`·`return`·`page`, 06 §26). 명시적 이동만 요청을 만들고(`PlatformLink`·팔레트는 pathname이 바뀔 때, 메뉴 사이 Back/Forward popstate도 pathname이 바뀔 때 `page`, `switchSpace`), 세대·pathname이 맞을 때만 `PlatformPage`가 소비한다. 페이지 소비용 `PageNavigation`은 `requestReturn`·`consume`·`subscribe`·`claimsDetailFocus`를 제공한다. `claimsDetailFocus`는 URL 도착(`page`·`return`, 첫 로드의 `focus=`)이면 false이고, 같은 화면에서 `focus`가 생기거나 `drill`이면 true다(ADR-0032). 팔레트는 주입된 `isBlocked()`와 해제 알림 `notify()` 경계로만 연결하며 차단 중 `page` 요청을 보존한다.
- `paletteFocus.ts` — 팔레트 열기·닫기, 세대·Dialog 인스턴스 소유·렌더 여부·Provider 세션 교체 정리를 소유한다. 열기는 이전 이동 요청을 취소하고, 셸에는 세션에 묶인 `claim(owner)`·`release(owner)`·`isCurrent()` 핸들을 준다. Dialog close autofocus 또는 FocusScope cleanup 뒤 지연 해제에서 현재 소유자만 차단을 푼다. 상태 전이는 `paletteFocus.test.ts`, 포커스 결과는 `packages/shell/src/CommandPalette.test.tsx`·`packages/components/src/archetypes/__tests__/DrillLayout.test.tsx`·E2E `메뉴 이동 포커스 (06 §26)`이 고정한다.
- `query-engine.ts` — Provider당 내부 `QueryClient`(기본값 `staleTime 0`·`gcTime 5분`·`retry false`·`structuralSharing false`)와 세대 정리 `removeOtherGenerations`, 쓰기 무효화 `invalidateEndpoints`, Provider 수명 `startQueryEngine`(`client.mount()`/`unmount()`와 "조회 중(오프라인 대기 포함)인데 열린 관찰자가 없으면 취소" 캐시 구독 하나)(ADR-0086). `PlatformProvider`가 클라이언트 하나를 수명 내내 들고, 세션 세대 `gen = adapterEpoch:revision:userId`(어댑터 prop이 바뀌면 `adapterEpoch`이 오른다)를 모든 키의 둘째 요소로 쓰며, 바뀌면 같은 커밋에서 다른 세대 쿼리를 지운다. 내부 훅 `useQueryEngine()`만 읽고 `HostPlatform`·`MenuPlatform`에는 없다. 검증 `query-engine.test.tsx`.
- `query.ts` — 엔진 위의 `useQueryLifecycle`(ADR-0086; 수명주기 계약 원본은 06 §19): 키 `[kind, gen, …신원, idle]`, 열린 인스턴스는 키의 결과(조회 중이면 `refreshing`), 닫힌 인스턴스는 자기가 수락한 결과만, 닫히거나 열린 관찰자가 모두 떠나면 `startQueryEngine`의 구독이 `cancelQueries`(훅별 effect 없음), `refetch`/`refreshEpoch`은 `refetch({ cancelRefetch: false })`라 닫힌 게이트를 열지 않는다. `usePlatformQuery`(키 `['platform', gen, useId(), …]` — 호출자가 `run`을 주므로 공유 없음, `identity: 'session'`이면 전역 Context 제외), `useEntityQuery`(§22 목적지 `adapter.getEntity`, 공유 키 `['entity', gen, ref, pageInputs, false]`), `useMenuQuery`(공유 키 `['menu', gen, spec.id, projected, params, idle]`)/`useMenuFetch`(메뉴 `EndpointSpec` → `adapter.menuQuery`; Scope·기간 게이트와 assessments kind 검사 포함, `ready` 전 호출은 `not_ready` error), `useAdapterRequest`(셸 조회, 키 `['request', gen, useId(), key]` — 의존 값은 호출자가 `key`에 전부 넣는다), `useEntityAudit(ref, enabled?)`(§13 목적지 감사 `adapter.entityAudit`, ADR-0085: `query`는 첫 쪽(session 정체성, `QueryView`용), `timeline = { events, more: AuditMore }`는 `AuditTimeline`에 펼쳐 넣는다 — 붙인 쪽은 조회가 시작될 때마다 오르는 읽기 세대에 묶여 ref·Scope·revision·user 변경이나 같은 대상 재조회로 버려지고 진행 중 `load`는 abort된다). 취소는 Kernel 자신의 `signal.aborted`로만 판정하고 어댑터 타임아웃 `AbortError`는 오류다. 판정 규칙의 원본은 06 §19·[체크리스트 §3](../../docs/integration/real-server-checklist.md)이고 `menu-query.test.tsx`가 고정한다.
- `cursor-pages.ts` — 내부(공개 export 아님) `useCursorPages(first, run, { id, order })`: 첫 쪽을 다른 곳(`usePlatformQuery`)에서 읽고 이어지는 커서 쪽을 붙이는 도메인 무관 수명주기(id 중복 제거, 같은 커서 재시도, 정체성이 바뀌면 abort, `forbidden`이면 `load` 막힘, `nextCursor`가 보낸 커서나 이미 본 커서와 같으면 `error`). `selection-port-cache.ts`와 달리 envelope 포트용이고 공유 캐시가 없다. 자기 `AbortSignal`이 끊겨 던진 예외는 버리고 그 외 `AbortError`(어댑터 타임아웃)는 `error`로 만든다(`query.ts`와 같은 규칙). 검증 `entity-audit.test.tsx`.
- `query-draft.ts`의 `useQueryDraft()` — live/apply 초안·필수 누락·원자적 적용 API(06 §11, ADR-0061). 보드 본문·편집기 Provider는 공통 `PaneQueryDraftProvider screens`에서 칸별 저장소를 공유한다. 분석 요청은 idle을 게이트하고 `QueryState.completedAt`으로 수락한 응답 시각을 준다. 검증 `query-draft.test.tsx`.
- `condition-preset.ts` — Condition 프리셋(ADR-0083, 06 §6.4): `activeConditionPreset(menu, page, condition?)`은 page 값이 있으면 그 프리셋, 없으면 Condition의 비어 있지 않은 축을 모두 포함하는 첫 선언 프리셋, 그것도 없으면 선언된 기본값이다(ADR-0083 보충, 검증 `condition-preset.test.ts`). `narrowedGlobal(menu, page, global)`이 그 활성 프리셋의 축만 남긴 전역 Context를 만들고, `menuRequest`·`useMenuQuery`·`useMenuFetch`·모듈 호스트 `query`의 유효성 검사(`projectMenuContext`)가 그것을 `projectContext`에 건넨다. 칸은 자기 메뉴·적용 page(`platform.page`)로 정한다. `host.context()`·`withPaneContext`·URL·전역 Condition은 좁히지 않는다. 공개 `useQueryContext(): GlobalContext`는 `narrowedGlobal(route?.menu, page, global)`을 적용된 화면 page·global로 부른다(`projectMenuContext`와 같은 인자, 초안 아님 — Apply 메뉴의 `setDraftPage`는 값을 바꾸지 않고 적용이 바꾼다; 칸은 그 칸의 값; 프리셋이 없는 메뉴는 `global`과 같은 객체). 표 조회 신원과 내보내기 머리말이 쓴다(#819). 셸용 읽기 전용 `useConditionPreset()` → `{ key, presets, activeId(초안), appliedId, outsideAxes } | null` (전환은 `useQueryDraft().setDraftPage({ [key]: id })`). `PlatformProvider`는 프리셋 축 id가 `equipmentAxes`에 없으면 렌더에서 던진다.
- `query-history.ts` — `useQueryHistory`와 논리적 초안 소유 이력 상태. 세션/revision/Scope 변경 첫 렌더부터 이전 행을 숨기고 기존 Scope·room grant·resolveSelection 검증 후에만 값을 제공한다. 복원은 원자적 초안 전체 교체이며 Apply 주소 확인에서만 occurrence를 기록한다(06 §11). 반환 객체는 `useMemo`이고 메서드는 현재 렌더 입력을 닫아 `current()`로 낡은 호출을 거부하며, 가린 행은 enabled·rows·권한이 같으면 같은 참조다(#824). 검증 `query-history.test.tsx`·`platform.pane.test.tsx`.
- `action.ts` — 쓰기 포트의 화면 쪽(ADR-0054, #502). 비훅 코어 `actionRequest(spec, input, expectedVersion, inputs)`: 버전 규칙 위반은 보내기 전 `RangeError`(동기), Scope 게이트 미충족이면 어댑터 호출 없이 `not_ready` error(`retry` 없음), 호출마다 `crypto.randomUUID()` 키와 `structuredClone`한 입력으로 요청을 한 번 만들고 모든 `retry`가 그 객체를 다시 보낸다. 어댑터에 해제 신호를 넘기지 않으며(보낸 쓰기는 되돌릴 수 없다) 던지면 `unknown`(`message: String(error)`)이다. `error`·`unknown`에만 `retry`가 붙는다. `ok`·`conflict`·`unknown`이면 응답을 기다리는 쪽이 있든 없든 `spec.invalidates`의 새로고침 번호를 올린다. `launchWrite(flight, send)`가 소유자(훅 인스턴스·호스트 인스턴스)의 흐름 제어다: 슬롯당 single-flight(`run`·`retry`·호스트 `act`가 같은 promise), 전달 직전 `valid()`(해제·세대 변화면 `AbortError`, 보낸 쓰기는 끝까지 간다), `retry`를 재귀로 같은 제어에 감싼다(해제·세대 변경 뒤 붙들린 `retry`는 보내지 않고 `AbortError`). `useMenuAction(spec)` → `{ ready, pending, run(input, { expectedVersion }) }`: 훅 인스턴스당 single-flight(미해결 중 `run`은 앞 promise를 돌려주고 새 입력은 무시), 언마운트·`revision`/사용자 변화면 즉시 `AbortError`, `pending`은 재시도 전송 포함. 검증 `action.test.tsx`(칸 둘 포함), 호스트 쪽은 `module-host.test.tsx`.
- `refresh-epochs.ts` — 앱 전체 새로고침 번호 저장소(`PlatformProvider`가 하나 들고 `useHostPlatform().refreshEpochs`로 준다, 칸마다 따로 아님). `bump(ids)`·`get(id)`·`total()`·`subscribe`(공개 타입 불변). `createRefreshEpochs(sink?)`의 내부 sink가 저장소 생성 때 걸려 있어(Provider가 클라이언트와 함께 만든다) bump가 엔진보다 먼저 일어나지 않고, `query-engine.ts`의 `invalidateEndpoints`가 올라간 엔드포인트의 모든 `menu` 쿼리를 `cancelQueries`한 뒤 `invalidateQueries({ cancelRefetch: false })`한다(취소 뒤 시작된 그룹 재시도는 나누고 다시 끊지 않는다; 진행 중 첫 읽기도 대체되고, 열린 것은 이전 결과를 두고 `refreshing`으로 다시 읽고, 닫힌 것은 낡은 것으로 표시, ADR-0086). 호스트는 `total()`을 `changeKey`에 접어 넣어 쓰기 뒤 `host.subscribe` 리스너가 불린다. `useMenuFetch`·표는 새로고침하지 않는다([백로그](../../.planning/backlog.md)).
- `host.ts` — 호스트 전용 진입점 `@ap/kernel/host`(ADR-0076): 전체 값 `useHostPlatform()`·`useHostPlatformOptional()`(`HostPlatform`)과 셸·공통 컴포넌트·앱만 쓰는 `PaneScreenProvider`·`PaneScreen`·`PaneQueryDraftProvider`·`useToastList`·`useOverlayState`(+ `OverlayState`)·`useModuleHost`·`ModuleShellPorts`·`useAdapterRequest`·`useQueryHistory`·`withPaneContext`·`paneHref`·`BOARD_PATH`·`hasDotSegment`. root `usePlatform()`은 같은 런타임 값을 메뉴 표면 `MenuPlatform`(`platform.tsx`의 `Pick`)으로 좁혀 돌려주고, 메뉴가 `HostPlatform` 필드를 필요로 하면 그 필드를 `MenuPlatform`으로 올린다(host import 허용이 아니라). `adapter`는 메뉴 표면에 남는다(콘솔·감사 포트, my-activity 세션 세대). Kernel 안의 훅(`query.ts`·`module-host.ts` 등)은 `useHostPlatform()`을 읽는다. `index.ts`에서 내보내지 않으며 lint가 메뉴·메뉴 mock·호스트 모듈의 import를 막는다. 검증 `platform.host-types.test.ts`.
- `testing.ts` — 테스트 전용 공개 진입점 `@ap/kernel/testing`(어댑터·세션·공간 fixture와 토스트 읽기 `ToastProbe`·`useToastsForTest()`, 끝난 조회를 화면에 올리는 대기 `settleQueries()`(ADR-0086, #907), ADR-0040). `index.ts`에서 내보내지 않는다.
- `i18n.tsx` — `I18nProvider`, `useI18n()`(`tx`, `lang`), `contractErrorSentence()`(계약 오류 문장), `invalidValueSentence()`(잘못된 URL 값 경고 문장 한 곳 — `value`·`filter`·`plain`·`drillGap`), `topicParticle()`(한국어 조사 은/는, #410부터 공개). `metric-init.ts` — 지표 쌍 초기화 분류.

## 규칙

- import 가능: `@ap/contracts`와 React·아이콘 라이브러리, 조회 엔진 `@tanstack/react-query`(정확 고정 `5.62.7`, `@ap/fo-bridge`와 같은 버전 — 함께 올린다. ADR-0086, 메뉴·메뉴 mock·components·shell·앱의 import는 lint `denyQueryEngine`이 막는다(fo-bridge 허용). 그 타입은 공개 `.d.ts`에 나가지 않는다). `ui`/`components`/`shell`/앱/mock import 금지.

- 새 슬롯은 06 §8 Shell Slot에 근거가 있을 때만 `PlatformSlots`에 추가한다. `boardEntry`는 보드 지원 메뉴 머리 `⋯`의 `분석 보드에 열기…` 항목(타입만 Kernel, 구현은 셸 `OpenInBoardAction`, 16 §6).
- `paneContext.ts` — 내부 도우미 `dropResetKeys`(공개 export 아님, Context 쓰기 때 `contextResetKeys`를 page 쌍에서 지우는 유일한 규칙, `setGlobal`이 사용)와 `withPaneContext(menu, query, global)`(칸 주소의 Context만 바꾸고 page 키는 reset 키만 지운다 — 보드의 일괄 적용·복사·바꾸기, 주소가 틀리면 `ContractError`). `PaneScreenProvider`의 선택 prop `paneLabel`은 `useHostPlatform().paneLabel`(본 화면은 null, 읽기 전용)로 나가 `DetailDrawer`가 `칸 N · 메뉴`를 보인다.

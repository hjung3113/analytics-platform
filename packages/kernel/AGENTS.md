# @ap/kernel

Platform Kernel 런타임(06 §4). 메뉴 목록도, 서버 구현도 모른다. 둘 다 앱이 주입한다.

## 파일

- `registry.ts` — `createRegistry({ spaces, groups, menus })`: §5 검증(id·그룹 중복, parent 존재·파라미터 없는 경로, 선언 그룹, 그룹별 primary 1개, `pageKeys`×전역 키, `contextResetKeys`⊆`pageKeys`, `drill` 1–4단계·키 중복·`pageKeys`·`contextResetKeys`·`returnTo` 금지 — 06 §6.4, 경로 정규형 충돌, 공간 `space`·`homeMenuId`·비어 있지 않은 `description`, 있으면 비어 있지 않은 `subtitle` — 06 §9.1)과 정적 세그먼트 우선 매칭. `GroupDef`는 `id`·`label`·`icon`·`space`(`space: null`이면 전역 유틸리티)와 선택적 사이드바 표시 선언 `hideLabelWhenSingle`을 가진다. 반환 Registry가 `matchRoute`·`safeReturnTo`를 제공하고 `pathFor(menu, params)`가 경로를 만든다. `MenuEntry`는 `PlatformMenuEntry`(`MenuMeta & { icon, component? }`)와 모듈 변형 `ModuleMenuEntry`(`module`·`<module>:` 접두사 `permission`·`group`·`moduleScreen`)의 합이고, `GroupDef`도 `PlatformGroupDef`·`ModuleGroupDef`(`module`, 접두사 `id`)다. 접두사가 없거나 다른 모듈의 그룹에 놓인 메뉴, `module` 없는 항목의 닫힌 어휘(`PERMISSIONS`·`GROUP_IDS`) 이탈·`moduleScreen`, 플랫폼 권한 네임스페이스를 쓰는 모듈은 `RegistryError`.
- `module.ts` — `mountModule(manifest, screens, { prefix, groupSpace, config, icons, features? })`(ADR-0053): 모르는 `contract`, 호스트에 없는 `requires` 기능, 빠진 `config` 키, 접두사 없는 권한·그룹, 선언 안 된 그룹, 잘못된 `prefix`·화면 경로(인코딩 포함 점 세그먼트·역슬래시·`?`·`#`·`//`·제어 문자), 플랫폼 네임스페이스 모듈 id, 화면↔컴포넌트 불일치, 중복 화면 id, 모듈 밖 `parent`를 `RegistryError`로 거부하고 `createRegistry`에 넘길 `{ menus, groups }`를 돌려준다. 메뉴 id는 `<module.id>:<screen.id>`(`parent` 포함). 메뉴 항목에는 호스트 포트가 쓸 선언 기능(`moduleFeatures` = `requires` ∪ `optional` 중 호스트가 주는 것)과 `moduleConfig`가 실린다.
- `module-host.ts` — `useModuleHost(entry, params, ports)`(ADR-0053, UI 없음): 모듈 화면 한 인스턴스의 `ModuleHost`를 `usePlatform()`에서 만든다. 셸만 줄 수 있는 `status`·`focusTarget`·`detail`은 `ports`로 받는다. 호스트는 URL·세션·언어가 바뀔 때마다 새 객체인 스냅샷이다(화면은 호스트 정체성이 아니라 읽은 값에 의존). `setPage`는 화면이 선언하지 않은 page key면 이동 전에 `RangeError`를 던지고 `page(key)`는 `null`을 준다. `href`/`navigate`는 등록된 메뉴만 `resolveLink`로 풀고(`{screen}`은 같은 모듈의 `<module>:<screen>`) 모르면 `null`/`false`다 — 모듈 문자열로 URL을 만들지 않는다. `context()`는 `apply`·`reference` 키를 GlobalContext 필드로 옮기고(time→from/to, lot→lotIds, recipe→recipeIds, metric→metricId+metricVersion) `unsupported` 키 이름을 따로 돌려주며 `scopeId`는 `requiresScope` 화면에서만 싣는다. `query`는 `query` 기능을 선언한 화면에만 있고 `menu-query`와 같은 요청 경로(`query.ts`의 비훅 `menuRequest`)를 쓴다 — 호출마다 시작 시점의 revision·user·`projectContext`를 잡아 두고, 해제나 그 값의 변화(적용 Context 변화 포함, 참조 전용 변화는 제외)가 있으면 어댑터가 취소를 무시하거나 끝나지 않아도 `AbortError`로 거부하며 성공 전달 전에 유효성을 다시 본다. 해제(언마운트)는 `signal`을 abort하고 대기 중 호출을 거부하며 구독을 비운다. 검증 `module-host.test.tsx`.
- `platform.tsx` — `PlatformProvider adapter registry slots`(슬롯 `contextBar`·`topBarTools`·`feedbackOps`, 06 §8)와 `usePlatform()`·`usePlatformOptional()`(Provider 밖에서는 null): 전역 Context(`setGlobal`·`resetContext` — 실제로 바뀌면 현재 메뉴의 `contextResetKeys`를 같은 내비게이션에서 지운다, 06 §6.4)·`pageParam`/`setPage`·`linkTo`/`resolveLink`(06 §22)·`canOpen`(URL 생성과 분리된 메뉴 권한 ∧ 공간 진입 판정)·`spaceEntry`(마지막 화면 → 열 수 있는 홈 → 첫 사이드바 메뉴)·`spaceResume`/`switchSpace`([06 §9.1](../../docs/06_platform_ui_contract.md#91-워크스페이스-decided-2026-09-26), 검증 `src/platform.space-resume.test.tsx`)·`returnTarget`/`returnOrigin`(열 수 있는 채택된 `returnTo`의 메뉴 이름·연속 드릴 값·되돌린 전역 Context 항목(`revertedContext`, Scope 포함), 없거나 거부되면 열 수 있는 parent → 열 수 있는 `/` 메뉴 → 열 수 있는 `sidebarSpace.homeMenuId` → 예외 방지 `/` fallback)·Scope 상태(`scope`·`retryScope`, 세션이 바뀐 프레임은 Provider가 가린다)·즐겨찾기/최근·`reportError`. `reportError`는 식별 필드만 어댑터로 보낸다 — `Error.message`·URL·Context 값은 금지. 활용률은 `adapter.recordUsage`(entry/dwell). 동작은 `adapter.test.tsx`·`platform.*.test.tsx`가 고정하므로 바꾸면 테스트부터 고친다.
- `drill.ts` — `useDrill()`: 현재 메뉴 `drill.levels`의 page 값을 `depth`·`trail`·`invalid`로 읽고, `enter`/`goTo`는 `setPage` 한 번(push)으로 그 단계 뒤 키를 지운다(06 §6.4, ADR-0025). 단계 이동은 활용률 계측에 넣지 않는다.
- `pageNavigation.ts` — Provider가 가진 이동 뒤 포커스 요청(`PageFocus`: `drill`·`return`·`page`, 06 §26). 명시적 이동만 요청을 만들고(`PlatformLink`·팔레트는 pathname이 바뀔 때, 메뉴 사이 Back/Forward popstate도 pathname이 바뀔 때 `page`, `switchSpace`), 세대·pathname이 맞을 때만 `PlatformPage`가 소비한다. 페이지 소비용 `PageNavigation`은 `requestReturn`·`consume`·`subscribe`·`claimsDetailFocus`를 제공한다. `claimsDetailFocus`는 URL 도착(`page`·`return`, 첫 로드의 `focus=`)이면 false이고, 같은 화면에서 `focus`가 생기거나 `drill`이면 true다(ADR-0032). 팔레트는 주입된 `isBlocked()`와 해제 알림 `notify()` 경계로만 연결하며 차단 중 `page` 요청을 보존한다.
- `paletteFocus.ts` — 팔레트 열기·닫기, 세대·Dialog 인스턴스 소유·렌더 여부·Provider 세션 교체 정리를 소유한다. 열기는 이전 이동 요청을 취소하고, 셸에는 세션에 묶인 `claim(owner)`·`release(owner)`·`isCurrent()` 핸들을 준다. Dialog close autofocus 또는 FocusScope cleanup 뒤 지연 해제에서 현재 소유자만 차단을 푼다. 상태 전이는 `paletteFocus.test.ts`, 포커스 결과는 `packages/shell/src/CommandPalette.test.tsx`·`packages/components/src/DrillLayout.test.tsx`·E2E `메뉴 이동 포커스 (06 §26)`이 고정한다.
- `query.ts` — `usePlatformQuery`(식별자 `[revision, user.id, global, pageInputs]`, `identity: 'session'`이면 전역 Context 제외), `useEntityQuery`(§22 목적지 `adapter.getEntity`), `useMenuQuery`/`useMenuFetch`(메뉴 `EndpointSpec` → `adapter.menuQuery`; Scope·기간 게이트와 assessments kind 검사 포함, `ready` 전 호출은 `not_ready` error), `useAdapterRequest`(셸 조회, 식별자 `[revision, user.id, key]` — 의존 값은 호출자가 `key`에 전부 넣는다). 취소는 Kernel 자신의 `signal.aborted`로만 판정하고 어댑터 타임아웃 `AbortError`는 오류다. 판정 규칙의 원본은 06 §19·[체크리스트 §3](../../docs/integration/real-server-checklist.md)이고 `menu-query.test.tsx`가 고정한다.
- `testing.ts` — 테스트 전용 공개 진입점 `@ap/kernel/testing`(어댑터·세션·공간 fixture, ADR-0040). `index.ts`에서 내보내지 않는다.
- `i18n.tsx` — `I18nProvider`, `useI18n()`(`tx`, `lang`), `contractErrorSentence()`(계약 오류 문장), `invalidValueSentence()`(잘못된 URL 값 경고 문장 한 곳 — `value`·`filter`·`plain`·`drillGap`), `topicParticle()`(한국어 조사 은/는, #410부터 공개). `metric-init.ts` — 지표 쌍 초기화 분류.

## 규칙

- import 가능: `@ap/contracts`와 React·아이콘 라이브러리. `ui`/`components`/`shell`/앱/mock import 금지.
- 서버·세션 접근은 `adapter`로만. 세션은 동기 snapshot + `subscribe`; 변경 알림을 받으면 revision을 올려 이전 결과를 숨긴다. 이 무효화 계약은 `adapter.test.tsx`가 고정하므로 바꾸면 테스트부터 고친다.
- Registry 검증 규칙을 바꾸면 `registry.test.ts`에 실패 사례를 추가한다. 테스트는 fixture Registry만 쓰고 실제 메뉴를 import하지 않는다(실제 메뉴가 필요한 테스트는 앱 통합 테스트).
- 전역 Context 키·URL 규칙은 06 §6 계약이다. 메뉴 요구 때문에 바꾸지 말고 플랫폼 결정으로 올린다.
- 테스트의 어댑터·세션·공간 fixture(`testAdapter`·`testSession`·`testSpace`·`noContext`)는 `src/testing.ts` 한 벌이고 `@ap/kernel/testing`으로 공개한다(ADR-0040). 테스트 파일에서만 import하며, 포트 메서드를 더하면 여기 기본값을 같은 PR에서 고친다.
- 새 슬롯은 06 §8 Shell Slot에 근거가 있을 때만 `PlatformSlots`에 추가한다.

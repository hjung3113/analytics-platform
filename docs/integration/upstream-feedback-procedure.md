# 업데이트와 문제 환류 절차 — 사내에서 찾은 것을 공개 저장소로 되돌리는 길

상태: **Candidate** — 절차 초안. 수용 기준은 [#1706](https://github.com/hjung3113/analytics-platform/issues/1706)의 v0.36.0 몫 댓글이 소유한다. 공개 이슈 양식은 [`.github/ISSUE_TEMPLATE/platform-feedback.yml`](../../.github/ISSUE_TEMPLATE/platform-feedback.yml)이다. 사내 적용 가이드 §5의 교체는 조립 시험이 통과한 뒤 릴리스 문서 PR에서 한다([ADR-0141](../adr/0141-in-house-assembly-in-separate-repository.md)).

## 1. 버전 교체 순서

사내 조립에서 플랫폼 버전을 바꿀 때는 이 순서를 지킨다.

1. 고정 버전을 바꾼다(반입 묶음 한 벌, [승인 릴리스 반입 묶음](approved-release-bundle.md)). 묶음은 시작 키트 자체이므로 목표 버전 키트를 새 폴더에 풀고 조립 몫만 옮긴다([시작 키트 «버전 교체와 되돌리기»](../guides/standalone-start-kit.md#버전-교체와-되돌리기)).
2. 설치 검사를 통과시킨다.
3. 시작 키트의 `check`를 돌린다.
4. 사내 메뉴를 다시 검증한다. 메뉴 폴더의 적합성 사례를 실어댑터 하네스로 돌린다([실서버 연결 체크리스트 §4](real-server-checklist.md#4-적합성-묶음으로-확인하기)).
5. 실패하면 직전 묶음(N-1)으로 되돌린다([ADR-0143](../adr/0143-release-units-and-compatibility-train.md)). 되돌리기도 1과 같은 순서에 N-1 키트를 넣는다([시작 키트 «버전 교체와 되돌리기»](../guides/standalone-start-kit.md#버전-교체와-되돌리기)).

## 2. 문제의 분류

| 분류 | 정의 | 어디로 |
| --- | --- | --- |
| 업무 의미 | 사내 메뉴·어댑터·설정의 문제 | 사내에서 고친다. 공개 저장소로 보내지 않는다 |
| 공통 빈 곳 | 공개 계약이 더 있어야 풀리는 문제 | 공개 이슈. [ADR-0141](../adr/0141-in-house-assembly-in-separate-repository.md)이 #428을 닫을 때 적은 다시 여는 조건 «정적 조립으로 풀 수 없는 확장 지점»을 인용해야 한다. 기각된 허용 목록·기여 지점·`defineSystem`·manifest 필드를 되살리는 요청은 받지 않는다([ADR-0142](../adr/0142-out-of-repo-menu-package-and-host-module-split.md)) |
| 플랫폼 결함 | 공개 코드의 오작동 | 공개 이슈. 합성 재현 + 공통 수정 + 회귀 시험을 함께 낸다 |

## 3. 나가도 되는 것과 안 되는 것

| 나가는 것 | 나가지 않는 것 |
| --- | --- |
| 계약 항목 id | 값, 로그, 화면, 스키마 |
| 상태(어떤 계약 항목이 어떻게 어긋났는가) | 사내 `.npmrc`, 사내 lockfile |
| 일반화한 설명 | 사내 식별자·컬럼명·주소 |
| 합성 재현 | 실제 데이터로 만든 재현 |

비식별화는 반출 허가가 아니다. 사람이 검수하고 승인한 요약만 나간다.

## 4. 급한 수정의 임시 override

공개 릴리스를 기다릴 수 없는 수정은 사내 조립에서 임시 override로 둘 수 있다. override에는 기한과 제거 조건(어느 공개 릴리스가 이를 대신하는가)을 적고, 목록으로 관리한다. 제거 조건 없는 override는 두지 않는다.

## 5. 공개 이슈 양식

양식 하나가 분류, 계약 항목, 플랫폼 버전, 합성 재현을 묻고 «사람이 검수·승인한 요약만»이라는 경고를 싣는다. 사내에서 자동으로 보내는 경로는 만들지 않는다.

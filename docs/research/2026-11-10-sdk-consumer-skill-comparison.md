# SDK 소비자 스킬 사용 전후 비교

근거 기록이며 권위 원본이 아니다. 설계는 [SDK 소비자 스킬 설계](../design/devkit-sdk-consumer-skill.md), 결정은 [ADR-0131](../adr/0131-sdk-consumer-skill-and-intent-table.md)이 소유한다. 실행일: 2026-11-10.

## 결론

- 이 세 작업에서는 스킬의 효과를 확인하지 못했다. 스킬이 없어도 잘못된 SDK import와 직접 만든 중복 구현이 0건이어서 줄어들 여지가 없었다.
- 폴더 안내문 포인터가 없으면 에이전트는 스킬을 읽지 않았다(3건 중 0건). 포인터가 있으면 3건 모두 작업 초반에 읽었다.
- 비용 차이는 작업마다 방향이 달라 경향을 말할 수 없다. 각 칸이 1회 실행이므로 통계가 아니다.
- 작업 2의 포인터 조건은 GLM 주간 한도(재설정 2026-11-11 15:10 KST)로 변경 기록과 보고서 단계 전에 멈췄다. 멈춘 시점의 코드를 그대로 쟀다.

## 방법

같은 지시문을 세 조건에 그대로 주었고, 지시문에는 스킬을 적지 않았다. 모델은 모두 `glm-5.3-flash`, effort `max`다.

측정 항목:

- 잘못된 이름: 추가한 코드의 `@ap/*` import 중 각 worktree의 `tooling/sdk/api/*.api.txt`에 export가 없는 것. `@ap/menu-*`와 `@ap/mock-server`는 SDK가 아니므로 뺐다.
- 직접 구현: 추가한 코드의 `<table`, `echarts` 직접 import, `fetch(`, 손으로 만든 `href`, `<dialog`, `window.confirm(`, 지역 Stat/Kpi/Summary 카드 정의.
- 스킬 읽기: omp 세션 기록의 도구 호출 인자에 `ap-sdk-consumer`나 `skill://`이 있는 읽기.
- 활성 시간: 세션 메시지 간격 중 15분 이상인 대기를 뺀 합. 한도로 멈춘 시간을 빼기 위한 것이다.

## 한계

- 이 저장소에는 비슷한 메뉴가 이미 많아, 스킬이 없어도 이웃 코드를 따라 맞는 조각을 찾는다. 세 작업이 이 스킬이 도울 만큼 어렵지 않았을 수 있다. 저장소 밖 소비자나 낯선 조각을 다루는 작업은 재지 않았다.
- 조각의 사용이 알맞은지는 보지 않았다. 있는지 없는지와 lint, typecheck, 테스트만 쟀고, 브라우저로 화면을 확인하지 않았다.
- 토큰은 비교에서 뺐다. 포인터 조건은 한도로 세션이 끊겨 캐시를 잃었고, 컨텍스트 압축이 값을 바꾼다.
- 한 번에 여러 실행이 함께 돌았으므로 시간은 부하의 영향을 받는다.
- 비교용 worktree는 기록 후 지웠다. 위 수치가 남는 기록이다.

## 다시 여는 조건

비교 당시의 조건은 "3건 비교에서 잘못된 import나 중복 구현이 줄지 않거나 의도어 표만으로 부족한 경우"였다. 글자대로는 "줄지 않음"에 해당하지만 기준선이 이미 0건이어서 줄어들 수 없었고, 생성형 Catalog가 고칠 오류도 관찰되지 않았다.

리드는 2026-11-10 Catalog, `inspect`, `check`를 계속 닫아 두기로 하고 조건을 바꿨다. 현재 조건은 [ADR-0131](../adr/0131-sdk-consumer-skill-and-intent-table.md)이 소유한다.

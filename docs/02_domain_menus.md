# 02. 도메인 메뉴 그룹 및 플랫폼 코어 공통 기능 (기획/PM 담당자용)

이 문서는 capability catalog다. 아래 Phase 번호는 [05의 과거 Deferred 가설](05_roadmap_and_open_questions.md#deferred--과거-phase-roadmap-가설-non-authoritative)을 가리키며 구현 순서나 착수 승인이 아니다. 기능 간 의존은 유지하되 실제 구현 순서는 별도 작업 계획에서 정한다.

## 플랫폼 코어 공통 기능

개별 메뉴가 아니라 플랫폼 자체가 제공해야 여러 메뉴가 재사용하는 기능들.

- **메뉴 레지스트리**: 메뉴를 선언적으로 등록해 신규 메뉴 추가 시 셸 코드 수정 없이 확장 — 배포 없이 설치하는 외부 플러그인은 별개 요구로, 초기에는 코드 내 선언만으로 충분
- **전역 필터 컨텍스트**: 기간/설비/Lot 등 공통 필터를 메뉴 간 유지되는 상태로 관리
- **필터 포워딩(딥링크) 프로토콜**: URL query param 계약을 전역 필터 컨텍스트와 동일한 상태로 설계 — 다른 기능보다 먼저(Phase 1) 계약을 고정해야 이후 메뉴가 늘어도 재작업이 없다. 상세는 `06_platform_ui_contract.md` §6
- **공통 위젯/대시보드 프레임워크**: 차트/표/도식 배치 레이아웃 엔진 — 실제 분석 화면 2~3개에서 반복되는 책임을 먼저 확인한 뒤 추출(후순위, Phase 4)
- **지표 정의 관리**: 계산식뿐 아니라 grain/분자·분모/기간/버전·발행이력/커버리지까지 데이터로 관리해 여러 분석 메뉴가 같은 정의를 참조
- **데이터 최신성/커버리지 표시 + 재집계(지연 완료) 정책**: 열린 occurrence는 결과 테이블에 없고, 늦게 완료되면 과거 구간 집계가 다시 바뀔 수 있다 — "확정/미확정" 개념과 캐시 무효화 모델이 필요(재계산 트리거는 지연 완료뿐 아니라 마스터 소급 정정·설비 재분류·지표 정의 변경도 포함, 상세는 [01 재계산 트리거](01_architecture_and_data_contract.md#mart-재계산-트리거-2차-리뷰-보강)와 [R/H 정책](01_architecture_and_data_contract.md#late-arrival-policy))
- **권한/역할 관리**: 메뉴 단위 + [06 §6.2의 Site→Line Scope](06_platform_ui_contract.md#62-scope와-권한-decided--open) 접근 제어(StGroup은 Scope 계층이 아닌 교차 분류), 캐시·내보내기·저장된 뷰·공유 링크에도 동일하게 적용
- **변경 감사(Audit Trail)**: 마스터/기준정보/지표 정의 변경의 who/when/before-after 기록 — 유효기간 이력과는 별개 기능(언제 바뀌었는지 계산 vs 누가 바꿨는지 기록)
- **저장된 조회조건/즐겨찾기, 최근 조회 이력**

## 도메인 capability catalog

| 메뉴 그룹 | 대표 기능 | 비고 |
| --- | --- | --- |
| 설비관리 | 설비 마스터(유효구간 이력) 조회·속성 관리, 사용중지/복원 | `docs/23` §1.2 `equipment_master` 설계 채택 — 조인 키는 `equipment_id` 하나뿐. 단순 CRUD·물리 삭제 대신 유효기간 종료로 이력 보존. 설비는 파서 로그에 실재하는 `equipment_id`에서 발견(import)하고, 플랫폼은 room/maker/model/설비그룹 같은 business 속성만 부여. 같은 필드를 외부 마스터 import와 플랫폼 수동 수정이 동시에 건드리지 않도록 필드별 원천 소유자를 Phase 0에서 구분(`01_architecture_and_data_contract.md`) |
| 기준정보관리 | 공정/레시피/자재 등 마스터 데이터 CRUD | 외부 시스템(MES 등)이 관리하는 항목과 플랫폼이 직접 관리하는 항목을 구분 |
| 생산성 분석 | 물리 점유율/비Process 체류, Wafer Journey 이송 분포, 사이클타임 P50/P95, Job 기준 처리량 | 파서 데이터만으로 낼 수 있는 범위로 한정(`docs/23` 제안 1/2/4). 가동률(SEMI E10)·수율은 설비 상태 이력·외부 라벨 데이터가 전제라 이번 범위에서 제외하거나 "제한된 정의"임을 화면에 명시 |
| 지표관리 | 지표 정의(grain/분자·분모/기간/버전) 등록·발행·이력 관리 | 계산식 저장소가 아니라 grain/분모/커버리지 카탈로그로 설계 — 다른 분석 메뉴가 참조. 예: 설비별 가동률·P95를 평균해 전체값으로 만들지 않고 분자·분모를 각각 합산하는 규칙을 스키마에 강제 |
| 공지 | 공지 등록/수정, 게시기간·대상 메뉴·권한 스코프 설정 | 새 플랫폼 축이 아니라 기준정보관리와 동일한 패턴(등록/수정 + 변경 감사 재사용) — 별도 알림 엔진 없이 로그인 배너/목록 노출로 충분. "대상 메뉴·권한 스코프" 타게팅은 메뉴 레지스트리 + 권한/스코프 모델에 의존하므로 Phase 1 코어 셸 이후에만 가능. Phase 1~2 배치 |
| VOC | 접수/상태 관리(접수→처리중→완료), 담당자 배정 | 접수/담당자/상태전이/댓글은 **VOC 자체 도메인 모델**로 관리(변경 감사 재사용은 who/when 기록에만 해당) — 인증·권한·변경 감사 공통 기능은 재사용. 담당자 배정에는 플랫폼 메타 DB의 사용자/조직 모델이 필요(Phase 1 전제). VOC 열람 권한이 원본 설비·Lot 분석 권한을 자동으로 부여하지 않도록 별도 권한 규칙 필요. 최소 구현은 Phase 2, 장애·버그 신고로 확장되어 운영 알림(적재 중단 등)과 연결이 필요해지면 그때는 Phase 3 이후로 |

### 정보구조 그룹과의 관계

이 표는 6개 도메인 capability를 분류한다. navigation IA의 단일 기준은 `06_platform_ui_contract.md` §9다. 공지와 VOC는 별개 도메인이지만 하나의 내비게이션 그룹을 공유하며, 운영 개요·관리·감사는 플랫폼 기능 그룹이다. 도메인 표와 navigation IA를 동일한 목록으로 맞추지 않는다.

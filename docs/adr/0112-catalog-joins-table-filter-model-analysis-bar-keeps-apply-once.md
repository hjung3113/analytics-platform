# 지표 카탈로그는 표 필터 모델로 합치고, 분석 조건 줄은 적용 한 번을 지키며 칩 줄만 맞춘다

상태: **Decided (2026-11-05)**. ADR-0105를 보충한다(0016·0037·0105는 그대로).
- 결정자: 사용자 — 2026-11-05, [#1218](https://github.com/hjung3113/analytics-platform/issues/1218) 이슈 댓글. 실제 앱 위 시안([아티팩트](https://claude.ai/artifact/DfN3eqFjmevnfEwRaWx5ev))을 보고 추천안 그대로(카탈로그 B, 분석 B, 버킷 표기 통일)를 골랐다.

## 배경

ADR-0105는 관리 화면 표 필터를 모델 하나로 합쳤다. `PageFilterBar`의 소비처는 지표 카탈로그(행 모드)와 사이클타임 분석(`mode="draft"`) 둘만 남았고, 두 곳이 같은 모델에 어디까지 맞아야 하는지가 열려 있었다.

- 카탈로그의 검색·상태·도메인은 표 행을 줄이는 조건이고 서버가 거른다. ADR-0105가 푸는 문제와 같다.
- 분석 조건 줄의 필드는 집계 단위, 백분위, 정렬이다. 행을 줄이는 조건이 아니라 조회 방식을 고르는 값이어서 「포함·이상」 같은 연산자가 맞지 않는다. 한 번 적용하면 추세·요약·분포·느린 실행을 함께 다시 조회하므로 조건마다 즉시 적용하면 조회가 늘고 중간 상태의 차트가 서로 다른 조건을 보인다(시안 C에서 설정 세 번에 요청 4건).
- 분석 화면의 「버킷」·「분포 구간」 칩은 조건 줄과 다른 모양으로 따로 있었고, 같은 버킷 값이 칩·요약·내보내기에서 세 가지 모양이었다.

## 결정

1. **카탈로그는 표 필터 모델로 완전히 합친다.** `q`는 빠른 검색(`TableQuickSearch`)으로 남고, 상태·도메인은 필터 선언 + 칩 줄 + 편집기 하나가 된다. 조건 하나씩 적용이 지금의 즉시 반영과 같아 동작은 그대로다. 바뀌는 것은 모양과 URL 키(`status`·`domain` → 숨은 반복 키 `filter`)다. `PageFilterBar`의 행 모드는 소비처가 없어져 정리한다.
2. **분석 조건 줄은 모델을 합치지 않는다.** 초안 + 적용 한 번을 유지한다. 합치는 것은 겉모양이다. 적용된 조건(집계·느린 실행 기준·정렬)과 차트 클릭 좁히기(버킷·분포 구간)를 표 필터와 같은 칩 어휘로 한 줄에 보인다. 칩은 적용된 상태에서 파생하고 초안은 바꾸지 않는다. 지울 수 있는 칩은 좁히기 둘뿐이다. `PageFilterBar`의 추가형 opt-in(`appliedChips`)이며 prop이 없으면 DOM이 바뀌지 않는다.
3. **버킷·분포 구간 값 표기는 한 가지다.** 칩·조건 요약·내보내기 「조회 정보」가 같은 문자열을 쓴다(날짜 형식은 wall-clock, 초와 `T` 없음). 긴 값은 칩에서 줄이고 전체 글은 `title`과 접근 이름에 둔다.

## 대안과 버리는 이유

- 카탈로그 C(검색 우선, 칩 모양 드롭다운): 가볍지만 연산자(제외·비어 있음)를 못 쓰고 다른 표와 모양이 달라진다.
- 분석 C(전면 즉시 적용): 한 번의 변경마다 조회가 나가고 차트·KPI가 서로 다른 조건을 보이는 중간 상태가 생긴다. 기준은 「그 변경이 다시 계산하는 대상의 비용」이다 — 화면에 있는 목록을 좁히면 즉시, 차트·KPI를 다시 조회하면 적용 한 번.

## 결과

- 계약: Components §15에 소비처 변경, `PageFilterBar` 칩 요약 opt-in 한 문단. Kernel·와이어·URL 규칙은 그대로다. 카탈로그의 옛 `?status=`·`?domain=` 주소는 더 이상 page key가 아니다(호환 약속 없음).
- 공개 API 추가(`appliedChips`)와 `PageFilterBar` 일부 prop 제거(`onApply`, 비접이식 형태)는 SDK 스냅샷과 릴리스 행에 적는다.

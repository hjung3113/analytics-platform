# 시퀀스 보기는 도메인을 모르는 SDK 범용 조각(`OrderedIntervalTrack`)으로 처음부터 제공한다

상태: **Decided (2026-11-07, 소유자 답 반영).** 결정자: 소유자(2026-11-07). 초안: 설계 레인, 근거 [#1344](https://github.com/hjung3113/analytics-platform/issues/1344), 설계 [`log-explorer` §6.6](../design/features/log-explorer/README.md#66-시퀀스-sdk-조각-orderedintervaltrack-이름-후보).

## 배경

로그 탐색의 시퀀스 보기는 줄(lane)별 구간(시작/끝 쌍)과 상태 전이를 **로그 순서**로 그린다. 이 모양은 Job/Wafer/로그를 모르는 범용 조각이다(다른 메뉴의 단계·상태 타임라인도 같다). 루트 AGENTS 승격 기준: 도메인을 모르는 범용 조각은 소비자 수와 관계없이 SDK에 둔다([ADR-0052](0052-rich-content-stays-in-the-sdk.md)). 초안은 «기존 차트 계약으로 가능한지 먼저 확인 후»를 추천했다.

## 결정

1. **`@ap/components`가 `OrderedIntervalTrack`(이름 후보)을 처음부터 제공한다**(소유자 2026-11-07; 초안 추천과 다름). 메뉴는 줄·상태 이름·색 토큰 매핑·항목을 선언하고 조각은 그 선언대로 그린다. 짝 맞추기·전이 판정은 하지 않는다.
2. **순서 축이 기본이다.** 위치는 소비자가 준 서수이고 조각은 시간으로 재정렬하지 않는다(로그 순서 보존). 시간 축은 소비자가 명시했을 때만 쓴다.
3. 끝이 없는 구간은 `open`으로 닫힌 구간과 다르게 그려 불완전을 확정 오류로 보이지 않게 한다.
4. 대용량은 가시 창 가상화 + 소비자 `onRangeRequest(..., signal)` 지연 로딩·취소로 처리한다. 한 번에 받는 항목 수 상한은 성능 이유로 계약에 둔다. 깊이·줄 수 같은 도메인 정책 상한은 두지 않는다.
5. 키보드 이동·텍스트 대안·색 외 구분을 접근성 이유로 계약에 둔다. Zoom/Brush는 chart.md §16 공통 Interaction을 따른다.
6. 기본 동작 불변인 선택 조각이다.

## 대안과 버리는 이유

- **메뉴 로컬 컴포넌트로 시작해 소비자 2–3곳 뒤 승격:** 범용 조각을 «아직 필요한 메뉴가 없다»로 미루는 것이라 승격 기준과 어긋난다. 기각.
- **기존 차트 계약(ECharts 프레임)에 시리즈로 얹기:** 서수 축·열린 구간·창 지연 로딩이 차트 계약의 시간 축 전제와 맞지 않으면 우회가 늘어난다. 구현 노드 첫 단계에서 차트 프레임·Interaction을 재사용하는 범위를 확인하되 조각 자체는 SDK 소유로 정한다.
- **소비자(로그 탐색)에 특화한 시퀀스 뷰:** 도메인(Job/Wafer)을 조각에 넣게 된다. 기각.

## 결과

- 공개 추가: `@ap/components`의 조각·타입, `sdk:api` 스냅샷·버전·next-release 행 갱신. 계약 원본은 `docs/contract/components.md`(§13)·`chart.md`(§16).
- 시각이 바뀌는 새 부품이라 구현 전 `?variant=` 2–3안을 아티팩트로 컨펌한다. 합성 소비자(수천 항목)로 계약을 검증한다.
- 시험: 느린 응답·취소·빠른 창 이동에서 오래된 응답이 덮지 않음, 열린 구간 표시, 서수 순서 보존(시간 역전 입력), 키보드·스크린리더, 기존 메뉴 무변화.

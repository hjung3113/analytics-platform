# StGroup은 URL 소유 딥링크 키가 아니라 선택 시점에 equipmentIds로 물질화한다

StGroup(분임조) 소속은 가변적이고, v1의 분석/조회는 "현재 소속 기준"만 쓴다([CONTEXT.md](../../CONTEXT.md)). 06 §6.1은 딥링크 왕복이 조회조건을 재현해야 한다는 원칙을 세워뒀는데, `stGroupId`를 URL 소유 키로 승격하면 저장한 링크를 나중에 다시 열 때 그사이 소속이 바뀐 설비만큼 조회 대상 설비 집합이 **조용히** 달라진다 — 지연완료·마스터 정정과는 다른 새로운 종류의 비재현성이라, 기존 계약에 예외를 추가하지 않고는 둘 수 없었다(2026-09-22 grilling). 대신 **StGroup 프리셋을 선택하는 순간 그 시점의 멤버 EquipmentID 목록을 `equipmentIds`로 물질화**해 URL에 기록하는 쪽을 채택했다.

## Considered Options

- **(채택) equipmentIds로 물질화**: StGroup은 UI 선택 보조일 뿐, URL은 항상 물질화된 `equipmentIds`만 소유. 재현성 원칙에 예외를 만들지 않는다.
- **stGroupId를 URL 키로 승격, 항상 현재 소속으로 재평가**: 조회는 최신 소속을 반영하지만 URL이 "언제 봐도 같은 결과"를 보장하지 못한다. Data Trust에 "현재 소속 기준" 표시로 완화 가능했으나, 06의 재현성 원칙에 새 예외 클래스를 만들어야 했다.
- **둘 다 지원**: 초기 복잡도 대비 실제 수요 근거가 없어 기각.

## Consequences

- StGroup 소속이 바뀐 뒤 예전 프리셋을 다시 눌러도 다른 설비 목록이 나올 수 있다는 걸 사용자는 "다시 선택하는 순간"에만 알 수 있다 — 저장된 링크 자체는 항상 저장 당시 그대로 재현된다.
- StGroup 소속 변경 이력을 소급 추적하는 수요가 실제로 확인되면(예: "그때 StGroup X였던 설비들"을 과거 시점 기준으로 다시 조회), 이 결정을 재검토해야 한다 — 현재는 그 수요가 확인되지 않았다.

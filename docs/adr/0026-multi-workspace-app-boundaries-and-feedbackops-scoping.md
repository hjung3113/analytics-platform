# 독립 업무 워크스페이스를 공통 셸에서 전환하고 FeedbackOps는 시스템별로 노출한다

상태: **Decided (2026-10-08)**.
- 결정자: 사용자 — 독립적으로 메뉴가 많은 각 시스템에 워크스페이스를 부여하고, 각 시스템별 VOC·Task를 다루는 v2 인터랙티브 시안을 확인한 뒤 "이거 좋은데? ... 이거대로 설계" 방향을 승인.

## 맥락

기존 [06 §9.1](../06_platform_ui_contract.md#91-워크스페이스-decided-2026-09-26)은 `분석 / 운영 콘솔 / 피드백` 3개 공간을 제시한다. 신규 요구에는 생산성 분석, 지표관리, 표준 로그 개발, 개선 실행처럼 **각각 하위 메뉴가 많은 독립 업무 시스템**이 포함된다. 모두 한 Sidebar에 묶으면 메뉴가 과밀해지고, 별도 웹 제품으로 흩어지면 사용자가 일관된 디자인·탐색·연결을 잃는다. 기존 독립 서비스의 백엔드/DB를 통합할 목적은 없다.

FeedbackOps는 VOC·Finding·Task Request·Task·Survey의 도메인 권한과 상태 규칙을 소유하고, 플랫폼은 이를 여러 업무 시스템에서 같은 사용 경험으로 접근할 필요가 있다. 도메인 API 유지 결정([ADR-0018](0018-feedbackops-stage2-screens-into-platform-menus.md))은 변경하지 않는다.

상세 IA, 화면 계약, 세부 Open 항목은 [15번 설계](../15_multi_workspace_ui.md)가 소유한다. 승인된 [HTML 프로토타입](../prototypes/multi-workspace-v2/index.html)은 디자인 참조이며 기존 셸 치수와 상단 바 동작을 자동 재정의하지 않는다.

## 결정

- 최상위는 **플랫폼 공통 홈(시스템 선택기) + 공통 Rail**이다. Rail에서 업무 워크스페이스를 전환하며 각 워크스페이스는 **독립 Sidebar/그룹/메뉴/작업 화면**을 가진다.
- 핵심 업무 워크스페이스는 **생산성 분석, 지표관리, 표준 로그 개발, 개선 실행** 네 개를 기준으로 설계하고, 개발·운영 콘솔은 별도 권한이 필요한 지원 워크스페이스로 둔다.
- **FeedbackOps는 각 시스템의 공통 협업 진입점**이다. 시스템별 VOC·Task·설문을 그 시스템으로 범위를 좁혀 보여주고, 접근 권한이 있는 담당자에게는 **전체 협업 허브**를 제공한다.
- 시스템별 업무 객체와 FeedbackOps Task는 합치지 않고 명시적인 관련 링크만 둔다. 시스템 전환과 교차 이동은 출발 위치, 대상 식별자, 지원·권한 검증된 Context를 명시한다.
- 서로 다른 백엔드·DB를 강제 합치지 않는다. 플랫폼 Registry·디자인 시스템·권한 판정 계약 및 ADR-0018의 도메인 소유권을 유지한다.
- 기존 분석 플랫폼의 설비관리/기준정보/공지 등은 **이관 계획이 확정될 때까지 유지**한다. 제품 소유권/메뉴 귀속은 세부 Open 항목이다.

## Considered Options

- **(A) 하나의 거대한 분석 워크스페이스 + 모든 업무 메뉴 나열:** 초기 조립은 단순하지만 메뉴 증가에 취약하고 제품 경계가 드러나지 않는다.
- **(B, 채택) 공통 셸 + 독립 업무 워크스페이스 + 시스템별 협업:** 내비게이션 계층과 제품 책임을 나누면서 시각적 일관성을 유지한다.
- **(C) 시스템마다 별개 프론트엔드/셸·로그인, 디자인만 공유:** 독립 배포는 쉬우나 시스템 이동 때 UX·Context·검색이 단절되고 중복 개발 비용이 크다.
- **FeedbackOps 별도 인스턴스를 시스템마다 복제:** VOC/Task 업무 표면을 통일하기 어렵고 전역 담당자 관점이 분산되므로 선택하지 않는다. 하나의 원천 서비스 + 권한 있는 범위별 화면을 채택한다.

## 결과

- [06 §9·9.1](../06_platform_ui_contract.md#9-information-architecture)의 IA 소유 계약을 새 목표에 맞게 갱신한다. 3개 공간 구조는 *현행 코드/전환기 구성*으로 남긴다.
- [15번 설계](../15_multi_workspace_ui.md)와 프로토타입, [구현 지도 #249](https://github.com/hjung3113/analytics-platform/issues/249)를 후속 입력으로 사용한다.
- 실제 앱의 Rail 52px/Sidebar 240·56px/페이지 머리 50px/도킹 상세 패널(ADR-0011·0013)은 이번 결정으로 변경되지 않는다.
- FeedbackOps의 Managed System 매핑, SSO·권한, 전체 허브 진입 방식과 레거시 메뉴 귀속 등은 **Open**이다. 사용자에게 확인받지 않은 선택을 구현에서 암묵적으로 고정하지 않는다.

# 공간은 업무 시스템 단위로 나누고, FeedbackOps는 별도 공간 대신 각 시스템 안의 협업 진입과 권한자용 전체 허브로 붙인다

상태: **Decided (2026-10-08)** — UX 구성 원칙. FeedbackOps 진입의 형태는 [ADR-0027](0027-feedbackops-stays-standalone-entry-links.md)(2026-10-09)이 정했다: 협업 진입은 FeedbackOps를 새 탭으로 여는 링크이고, 전체 허브는 FeedbackOps 자체 화면이다. 기존 메뉴의 귀속, 허브의 등록 형태, 시스템별 복원 저장은 Candidate, 인증·Managed System 매핑은 Open이다.
- 결정자: 사용자 — 클릭형 HTML 시안 [멀티 워크스페이스 v2](../prototypes/multi-workspace-v2/index.html)를 승인하고 구현 추적 이슈 [#249](https://github.com/hjung3113/analytics-platform/issues/249)를 올렸다.

06 §9.1(2026-09-26)은 그룹 위에 분석 / 운영 콘솔 / 피드백 세 공간을 두었다. 그 뒤 이 플랫폼 위에 올라갈 업무 시스템이 넷(생산성 분석, 지표관리, 표준 로그 개발, 개선 실행)이고, 시스템마다 고유 메뉴·업무 객체가 많다는 것이 분명해졌다. 분석 공간 하나에 모두 담으면 사이드바가 평면으로 커지고, FeedbackOps를 별도 공간으로 두면 사용자가 지금 쓰는 시스템의 VOC·Task·설문을 찾으려고 공간을 바꿔야 한다. 화면 설계의 상세는 [15](../15_multi_workspace_ui.md), 계약 원본은 [06 §9.1](../06_platform_ui_contract.md#91-워크스페이스-decided-2026-09-26)이다.

## 결정

- **공간 = 업무 시스템.** 핵심 업무 공간은 생산성 분석 · 지표관리 · 표준 로그 개발 · 개선 실행 넷이고, 지원 공간으로 개발·운영 콘솔을 둔다. 공간은 서로 독립된 메뉴 집합이며 모든 사용자가 모든 공간에 들어간다고 가정하지 않는다.
- **플랫폼 홈은 시스템 런처다.** 모든 메뉴를 한 사이드바에 합치지 않는다. 레일은 공간 전환, 사이드바는 현재 공간의 그룹·메뉴만 보인다.
- **FeedbackOps는 공간이 아니라 공통 협업 서비스다.** 각 공간 사이드바에 그 시스템의 VOC·Task·설문 진입을 두고, 진입하면 현재 시스템으로 범위를 좁혀 조회·등록한다. 권한이 있는 담당자에게만 전 시스템 **전체 협업 허브**를 연다. 허브는 새 저장소나 권한 우회 경로가 아니다.
- **ADR-0018의 화면 이전은 ADR-0027이 대체했다.** FeedbackOps 화면은 옮기지 않고, 시스템별 협업 진입과 전체 허브는 FeedbackOps로 가는 링크다.
- **시스템별 업무 객체를 FeedbackOps Task로 합치지 않는다.** 로그 결함·검증 Round, 개선 과제·실적, 지표 정의·버전은 각 시스템이 소유하고 필요한 관계만 링크한다.
- 셸 치수(레일 52px, 사이드바 240/56px, 페이지 머리 50px, 오른쪽 상세 440px, ADR-0011·0013)와 디자인 토큰은 바꾸지 않는다. 시안의 56px 레일·252px 사이드바·상단 바는 표현 차이다.

## Considered Options

- **(채택) 업무 시스템 공간 + 시스템별 협업 진입 + 전체 허브**: 메뉴가 많아도 1층 탐색(레일·런처)과 2층 탐색(현재 시스템 사이드바)이 분리된다. 사용자는 지금 쓰는 시스템 안에서 협업 기능을 찾는다. 대신 공간마다 협업 진입이 반복되고, 현재 시스템 → FeedbackOps Managed System 매핑이 필요하다.
- **기존 3공간(분석 / 운영 콘솔 / 피드백)**: 공간이 적어 전환기가 단순하다. 업무 시스템이 늘면 분석 공간의 사이드바가 평면으로 커지고, 협업 기능이 업무 맥락과 떨어진다.

## 결과

- 06 §9.1의 공간 표와 07 셸 와이어프레임을 이 구성으로 고친다. 기존 운영 개요·설비관리·기준정보관리·공지의 최종 귀속은 Candidate이고, 전환기에는 기존 라우트·메뉴를 유지한다.
- FeedbackOps 2단계(#213)의 남은 결정 중 "피드백 공간 메뉴 구성"은 "시스템별 협업 진입의 메뉴 구성과 전체 허브의 형태(독립 공간인지 전역 경로인지)"로 바뀐다. Scope↔Managed System 매핑(#81)·세션 공유(#150)는 그대로 선행 조건이다.
- 구현 순서는 셸·Registry 확장(포털, 시스템별 사이드바, 협업 진입 자리)이 FeedbackOps 화면 이전보다 먼저다(#249). 셸 코드는 실제 앱 위 `?variant=` 시안으로 다시 컨펌받는다.

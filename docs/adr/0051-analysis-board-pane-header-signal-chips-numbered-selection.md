# 분석 보드 칸 머리는 다른 키만 칩으로, 선택된 칸은 번호와 왼쪽 막대로 표시한다

상태: **Decided (2026-10-19, 결정자: 코디네이터 — 사용자가 시안 확인을 Opus UX 리뷰에 맡기고 그 판정으로 정하라고 함. 되돌릴 수 있음)** — 구현은 [#421](https://github.com/hjung3113/analytics-platform/issues/421). 화면 사양은 [16 §4](../16_analysis_board.md#4-화면-구조-decided).

[16](../16_analysis_board.md)의 1차 동작은 정해졌지만 칸 머리 모양은 정하지 않았다. 사례 조사([분석 보드 화면 패턴](../research/2026-10-19-analysis-board-patterns.md)) 뒤 세 안을 아티팩트 시안으로 만들고(사용자 요청으로 실제 앱 `?variant=` 대신), UX 리뷰가 1440×900 2×2, 1280×800 + 상세 440px, 좁은 화면에서 비교했다.

## 결정

- **칸 머리는 한 줄이다(A 신호형).** 업무 시스템 칩, 메뉴 이름, 같은 시트의 다른 칸과 **다른 키만** `키 값` 칩으로 보이고, 같은 키는 `같음 N` 팝오버에 모은다. 칸 동작은 `⋯` 메뉴에 둔다.
- **선택된 칸 표시는 번호와 왼쪽 막대다(C 제목형에서 가져옴).** 모든 칸(빈 칸 포함)에 번호 배지가 늘 보이고, Context 바·상세 머리·토스트도 같은 `칸 N`을 쓴다. 선택된 칸은 번호 배지가 강조색이 되고, 칸 전체 높이의 왼쪽 2px 막대와 머리 선택 표면을 가진다. 색만으로 선택을 나타내지 않는다(DESIGN.md).
- 버린 것: 모든 조건 칩(B), 다른 값을 제목 글자로 쓰기(C), 머리 채움만으로 선택 표시(A), 숫자 키 `1`–`4`(C).

## Considered Options

- **B 전부 펼침:** 머리가 두 줄 65px이고 좁은 칸에서 99–121px(1280에서 칸 높이의 21–39%)까지 커진다. 실제 조건 키가 9개라 더 나빠진다. 테두리 선택은 포커스 링과 구별되지 않는다.
- **C 제목형:** 키 이름이 빠져 `· 전체`가 어느 키인지 모르고, 다른 키가 셋 이상이면 비교 값이 잘린다.
- **A 그대로:** 머리 밀도와 차이 읽기(PHOTO vs ETCH를 2초 안에)는 가장 좋지만, 선택 표시가 1.2:1 색 차이뿐이고 칸 번호가 없어 Context 바가 어느 칸을 편집하는지 이어 주지 못한다.

## 결과

- 16 §4의 칸 머리·선택 문장을 이 결정으로 바꾸고, 리뷰가 찾은 공통 결함(키보드로 칸 선택, 머리 동작 시 먼저 선택, 넘침 규칙, 포커스 복귀, `UndoToast` 재사용, 시트 조건 복사의 뜻)을 16에 구현 요구로 적는다.
- 06 §7에 보드의 Scope 선택기 한 줄을 더한다(보드에는 시스템 사이드바가 없다).
- 시안은 버리는 코드다. 아티팩트 링크와 리뷰 요약은 #421 코멘트에 남긴다.

## 추가 (2026-10-21, 결정자: 사용자 — #536)

- 차이 `키 값` 칩에 공간을 먼저 준다. 차이 칩이 모두 들어가면 기존 `같음 N` 버튼을 유지하고 넘침은 만들지 않는다.
- 차이 칩이 모두 들어가지 않을 때는 `같음 N`을 넘침 버튼에 합친다. `+N`의 N은 숨은 차이 조건과 같은 조건의 합이며 접근 이름은 `칸 {n}의 조건 {N}개 더 보기`다.
- 넘침 배치를 쓰고 차이 칩이 하나 이상 있으면 메뉴 이름 최소 폭을 기본 96px에서 64px로 줄여 차이 칩에 공간을 먼저 주고 이름은 말줄임한다. 넘침이 없거나 다른 조건이 없으면 96px를 유지한다(결정자: 콘덕터, 사용자 결정 BX-3 A 적용). 치수 규칙은 [16 §4](../16_analysis_board.md#4-화면-구조-decided)를 따른다.
- 넘침 Popover는 그 칸의 전체 조건, 기존 `다름` 표식, `Context 바에서 편집`을 보여 준다. 칸 머리는 한 줄로 유지한다.

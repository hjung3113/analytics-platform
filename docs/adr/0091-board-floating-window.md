# 분석 보드는 일반 화면 위에 뜨는 자유 창으로도 볼 수 있다

- Status: Decided (2026-10-27)
- Decider: 사용자(#893 코멘트, 2026-10-27, 시안 A 선택), 되돌릴 수 있다.
- Scope: [#893](https://github.com/hjung3113/analytics-platform/issues/893) 노드 893d. 관련: [ADR-0087](0087-board-minimize-restore-history.md)(최소화·복원·history), [ADR-0088](0088-surface-pause-detail-slot.md)(표면 중지), [docs/design/analysis-board.md §4](../design/analysis-board.md).

## 맥락

보드를 최소화하면 일반 화면과 보드를 동시에 볼 수 없다. 일반 화면을 보면서 보드를 참고하는 표시가 필요하다. 보드는 한 React 인스턴스로 남아야 하고(ADR-0087), 시작 청크 계약(`check:lazy-chunks`)과 모달·토스트 레이어를 깨면 안 된다.

## 대안

- **A. 자유 창(선택)**: 일반 화면 위에 뜨는 비모달 창. 끌기·핸들·키·메뉴로 위치·크기를 바꾼다.
- B. 모서리 고정: 네 모서리 중 하나에 고정 크기. 기각 — 사용자가 위치와 크기를 정할 수 없고 가리는 내용을 비킬 수 없다.
- C. 측면 패널: main 옆에 폭을 나눠 가진다. 기각 — 일반 화면 폭이 줄어 반응형 계약(Context 바 넘침, 상세 슬롯)을 흔들고, 좁은 폭에서는 쓸 수 없다.

## 결정

A. 세 안에 공통인 규칙: 배경 차단막·포커스 가두기 없음, 끌기 없는 이동·크기 경로(방향키·메뉴), 화면 밖 clamp, 폭 900 미만이면 창 대신 최대화 표시, 토스트·모달에 가려도 접근 가능(레일 버튼). 최소화는 893c 칩 그대로다.

- 저장소(`board/boardPresentation.ts`)에 `floating`·`lastMode`·`geometry`를 더한다. 표시 모드는 여전히 파생이다(`/board`면 최대화, `live && floating`이면 창, 아니면 최소화).
- 창은 주소를 소유하지 않는다. 최대화↔창은 replace, 창 최소화·복원은 주소를 바꾸지 않는다.
- 보드는 `FloatingWindow`(`@ap/components`)의 자식으로 모든 표시에서 같은 자리에 두어 재마운트하지 않는다. 창 코드는 lazy 보드 청크(`board/BoardHost.tsx`)에 둔다.
- `geometry`는 실행 세션 범위다(새로고침 뒤엔 사라진다).

## 결과와 한계

- 창이 열린 채 일반 메뉴를 옮겨도 창은 남는다(자동 최소화는 최대화 중에만).
- 창은 토스트 띠(스택 `bottom` 오프셋 + 한 줄)만큼 영역에서 뺀다. 그 띠는 창이 없을 때도 쓰지 못한다.
- 창 안 보드 제목은 `h2`이고 페이지 제목 표지(`data-page-heading`)를 갖지 않는다. 도착 포커스는 뒤 화면 몫이다.

## 되돌리기

`창으로 보기` 버튼과 `BoardHost`의 창 모드를 빼면 ADR-0087의 두 표시(최대화·최소화)로 돌아간다. `geometry`는 저장되지 않는다.

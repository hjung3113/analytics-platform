## 맥락

ADR-0066은 모든 사용자가 쓰는 FeedbackOps 기능(VOC 등록·내 VOC·설문 응답·알림·권한 요청·내 활동)을 공간 밖 플랫폼 전역 기능으로 두기로 했다. ADR-0028은 전역 유틸리티(홈·공지·내 VOC)를 사이드바 없이 두었고, ADR-0042는 레일 맨 위 전환기를 업무 시스템 전환에만 썼다. 전역 기능이 여섯으로 늘자 질문이 둘 생겼다. 전역 화면에서 이 기능들 사이를 어떻게 오가는지, 업무 시스템 안에서 어떻게 닿는지다.

시안 1차(A/B/C)와 2차(P1 전역 사이드바·P2 홈 허브·P3 레일 아이콘)를 실제 앱 위에서 비교했다. 사용자는 P1을 고르고, 어느 시스템 안에서든 플랫폼 메뉴에 닿을 수 있게 고쳤다. 화면 사양은 [15 §3.1–3.2](../15_multi_workspace_ui.md#31-셸-배치-decided-2026-10-09), 셸 계약은 [06 §8·§9.1·§10·§13](../06_platform_ui_contract.md#8-shell-slots), 기능 배치는 [합류 설계](../integration/feedbackops-merge-design.md) §3.1이 소유한다.

## 결정

1. **전역 화면에는 플랫폼 사이드바를 둔다.** 홈을 포함한 전역 화면에 `홈` / `내 활동`(`알림` · `내 VOC` · `설문` · `권한 요청`) / `공지` 사이드바를 붙인다. 접을 수 있다. 이 화면들은 그대로 `space: null`이다. 공간이 아니고 공간 수에 들지 않는다. 각 항목은 자기 메뉴 권한으로 판정한다.
2. **업무 시스템 안에서는 전환기 팝오버로 플랫폼 메뉴에 닿는다.** 레일 맨 위 전환기 버튼의 이름을 `시스템 및 플랫폼 메뉴`로 바꾼다. 팝오버 위쪽에 `플랫폼 메뉴` 구역(글자 링크와 배지)을 따로 두고, 그 아래에 업무 시스템 카드를 둔다. 현재 시스템 표식은 유지한다. 플랫폼 메뉴는 시스템 카드가 아니다. Ctrl+K 메뉴 검색에서도 같은 목적지에 닿는다.
3. **전환기에 `플랫폼` 시스템을 따로 두지 않는다.** ADR-0028이 모든 사용자용 공통 공간을 기각한 이유(공간 0개 상태가 깨진다)가 그대로 유효하다.
4. **레일에 `VOC 등록`과 `알림`을 더한다.** `알림`은 종 모양이고 읽지 않은 수 배지를 단다. 누르면 팝오버가 열리고 `모두 보기`로 알림 페이지에 간다. `언어`와 `FeedbackOps 전체` 링크는 사용자 메뉴로 옮긴다. `FeedbackOps 전체`는 [#595](https://github.com/hjung3113/analytics-platform/issues/595)가 담당자에게 셸 안 진입을 줄 때까지만 둔다. 사이드바 FeedbackOps 블록에서는 `VOC 등록` 항목을 뺀다.
5. **VOC 등록은 오른쪽 도킹 드로어다.**
   - 본문을 밀어낸다. 본문을 덮는 overlay가 아니다.
   - 열 때 지금 화면의 Context를 고정해 지울 수 있는 칩으로 보인다: 시스템·메뉴, URL page key, 집계 단위, 시각까지 쓴 기간, Global Context(Condition·Selection 포함), 열려 있는 상세 엔티티, 보이는 Correlation ID. 지운 칩은 첨부하지 않는다.
   - Managed System과 Analytics Area는 [ADR-0068](0068-permission-scope-and-business-system-link.md)의 연결에서 채운다. 연결이 없으면 사용자가 명시적으로 고른다. 화면 이름으로 추정하지 않는다.
   - Amended (#761 761p1b): FeedbackOps 화면에서 열면 그 화면의 `managedSystem` 값이 UUID 하나이고 사용자 목록에 있을 때 양식의 Managed System을 미리 고른다. 아니면 위처럼 명시적으로 고른다. 화면 이름으로 추정하지 않는 점은 그대로다.
   - 오른쪽 패널은 한 번에 하나다. 상세와 드로어를 바꿔 열어도 초안과 상세 선택은 남는다.
   - 내용이 있는 초안을 닫으면 드로어 안에서 확인을 묻는다(`작성 중인 내용을 버릴까요?`).
   - Esc는 포커스가 드로어 안에 있을 때만 받는다. 닫으면 포커스가 트리거로 돌아간다. 모달이 열리면 맨 위 포커스는 모달이 갖는다.
6. **설문은 전체 페이지다.** 알림·홈·플랫폼 메뉴에서 들어간다. 레일 자리는 없다. 미리 선택된 답이 없다. 제출하면 완료 안내와 출발 화면 복귀 링크(Kernel `ReturnLink`)를 보인다(출발 화면이 있을 때). 설문 응답은 VOC를 만들지 않는다(합류 설계 §2 원칙 3).
7. **알림의 읽음 상태는 설문 완료와 별개다.** 알림을 읽어도 설문이 끝나지 않고, 설문을 내도 알림이 저절로 읽히지 않는다.
8. **홈 순서는 시스템 카드 → `내 할 일` → `즐겨찾기` · `최근 방문` · `공지`다.**
   - `내 할 일`에는 `응답할 설문`(마감 순), `내 VOC`(지난 방문 이후 바뀐 것), `권한 요청`(대기·결정됨)이 들어간다. 비어 있는 묶음은 숨긴다. 차트는 없다.
   - 공간이 0개인 홈에는 `권한 요청` 버튼을 둔다. ADR-0028이 열어 둔 "공간 0개 사용자의 권한 요청 안내 목적지"를 이것으로 닫는다.
   - `내 활동`은 사이드바 묶음 이름과 홈의 이 구역이다. 별도 페이지가 아니다.

여기서 정하지 않는 것: FeedbackOps 화면을 Kernel 라우팅에 올리는 기술 방식(합류 설계 §7 O5)과 FeedbackOps API 경로(O13, ADR-0069 결정 3이 #594로 미룸)는 #594 구현에서 연다.

## Considered Options

- **(A/B/C, 1차)**: 같은 질문의 첫 시안이다. 2차의 세 방향으로 좁혔다.
- **(P2) 홈 허브**: 전역 기능을 홈에서만 열면 기능 사이를 오갈 때마다 홈을 거쳐야 한다.
- **(P3) 레일 아이콘**: 전역 기능마다 레일 아이콘을 주면 레일이 13칸 가까이 되고, 업무 사이드바와 목적지가 겹친다.
- **(P1 그대로)**: 전역 화면에서는 좋지만, 업무 시스템 안에서는 사용자 메뉴로만 닿고 공지가 빠진다.
- **(`플랫폼` 시스템 추가)**: 모든 사용자에게 공간 하나를 만들어 공간 0개 상태를 깨뜨린다(ADR-0028이 기각).
- **(수정 P1, 채택)**: 전역 화면에는 늘 보이는 글자 메뉴가 있고, 어느 시스템에서든 기존 버튼으로 두 번 누르면 같은 목적지에 간다. 대신 사용자가 시스템 버튼 안에 개인 메뉴가 있다고 예상하지 못할 수 있다. 그래서 버튼 이름 변경과 팝오버의 두 구역 분리를 필수로 둔다.

# 감사 화면의 시각 범위는 한쪽만 열 수 있고 입력은 보는 사람 시간대다

상태: **Decided (2026-10-15)**.
- 결정자: 사용자 — 2026-10-15, [#305](https://github.com/hjung3113/analytics-platform/issues/305) 추천안을 채택했다.

감사 화면 page key `fromAt`/`toAt`는 전역 분석 기간 `from`/`to`와 다르다. 전역 기간은 [06 §6.3](../06_platform_ui_contract.md#ctx-time)·[§6.4](../06_platform_ui_contract.md#64-url-계약-decided-필드명enum-문자열은-candidate)대로 한쪽만 있으면 형식 오류다. 이 결정은 그 규칙을 바꾸지 않고 감사 조회 창만 연다. 시각의 화면 표시는 같은 §6.3대로 보는 사람 시간대이고, URL과 포트에 실리는 값은 zone이 붙은 시점이다.

공통 시점 입력은 아직 만들지 않는다. 승격 기준은 [06 §14](../06_platform_ui_contract.md#14-platform-component-promotion-rule)와 [한 화면만의 일반화 금지](../06_platform_ui_contract.md#premature-platformization)다.

## 결정

- `fromAt`만 있으면 그 시점 이후(포함)이고, `toAt`만 있으면 그 시점 이전(미포함)이다. 둘 다 있으면 반열린 `[fromAt, toAt)`이며 `fromAt >= toAt`는 오류다.
- 이 화면의 두 칸은 보는 사람 시간대의 초 단위 날짜·시각이다. 표의 `시각` 열과 같은 시간대다. 적용할 때 zone이 붙은 시점으로 바꾸고, 딥링크의 시점은 같은 시간대의 칸 값으로 되돌린다.
- URL에서 복원한 칸을 편집하지 않았으면 적용 때 원래 시점 문자열을 그대로 다시 쓴다. 편집한 칸만 다시 변환한다. 초 단위 칸이 편집하지 않은 경계의 소수 초를 반올림하거나 자르지 않는다.
- 그 시간대에 없는 현지 시각과, 둘 이상의 시점에 대응하는 현지 시각은 칸 오류다. 하나를 고르거나 선택 UI를 만들지 않는다.
- 잘못된 초안은 그 칸 아래에 이유와 `aria-invalid`를 두고 URL을 바꾸지 않는다. `fromAt >= toAt`는 두 번째 칸에 보인다. 이미 잘못된 딥링크는 표 자리 경고에 어느 키가 왜 잘못인지 한 줄로 말한다.
- 변환과 칸은 감사 메뉴 폴더 안에 둔다.

## Considered Options

- **양쪽 필수 유지**: 전역 `from`/`to`와 같은 쌍 규칙이다. 감사 조회는 상한만 또는 하한만으로도 성립하므로 기각한다.
- **UTC 입력 유지**: 표의 `시각` 열은 보는 사람 시간대다. 그 시각을 칸에 옮기면 다른 시점으로 해석되어 해당 행이 빠질 수 있으므로 기각한다.
- **공통 시점 입력으로 지금 승격**: 소비자가 이 화면 하나이므로 기각한다.
- **한쪽 열린 범위와 보는 사람 시간대 입력(채택)**: 감사 page key만 열고, 전역 기간 규칙과 wire 형식은 유지한다.

## 결과

- 파서, mock 서버, `AuditTrailQuery` 주석이 같은 열린 범위를 따른다. 전역 `from`/`to`가 적힌 06 §6.3·§6.4는 그대로다.
- 구현은 감사 메뉴의 화면과 변환 모듈이다. 다른 메뉴의 시점 입력은 이 결정을 공통 부품으로 삼지 않는다.

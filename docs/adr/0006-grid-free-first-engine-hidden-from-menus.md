# 그리드·차트 도구는 무료로 시작하고, 표 엔진은 메뉴에 드러내지 않는다

상태: **Decided (2026-10-02)**. 방침과 범위는 사용자 결정, 엔진 은닉은 그 방침을 싸게 지키기 위한 플랫폼 결정(#160에서 구현). 후보별 판정·근거·출처는 [04 그리드·차트·데이터 도구 검토](../04_frontend_ui_ux.md#그리드차트데이터-도구-검토-2026-10-02)가 소유한다.

분석 화면 사용자는 "엑셀 수준의 그리드 편의성"을 원한다. 그런데 그 핵심 기능(셀 범위 선택·여러 셀 복붙·채우기·사용자 피벗·XLSX)은 대표 후보인 AG Grid에서 유료(Enterprise)이고, 필요한 범위가 아직 실제 사내 메뉴로 확인되지 않았다. 지금 `PlatformDataTable`(TanStack Table + Virtual, MIT)은 06 §15 기본 기능을 이미 갖췄다. 문제는 메뉴가 표 엔진 타입(`ColumnDef`·`SortingState`)을 직접 써서, 나중에 엔진을 바꾸면 모든 메뉴를 고쳐야 했다는 점이다.

## Considered Options

- **(채택) 무료로 시작 + 엔진 은닉 + 필요성 확인 시 유료 전환**: TanStack을 유지하고, 메뉴는 플랫폼 소유 열 타입(`PlatformColumn`)만 쓴다(엔진 import는 lint 금지). 유료 전환은 그 기능이 업무 필수로 확인될 때 `@ap/components` 안에서만 일어난다. 비용은 엔진 래핑 한 층.
- **지금 AG Grid Community로 교체**: 무료지만 §15 기능은 이미 있어 얻는 것이 적고, 화면 모양이 바뀌어 디자인(M2) 컨펌이 필요하다. 원하는 기능은 결국 Enterprise라 교체 이유가 되지 않는다.
- **지금 AG Grid Enterprise 구매**: 필요성이 확인되지 않은 비용이고, 망분리 라이선스 검증·테마·접근성을 평가하지 않은 채 묶인다.
- **무료 캔버스 그리드(Glide 등)로 엑셀식 기능 확보**: 무료지만 캔버스 렌더링이라 06 §26 접근성, CSS 디자인 토큰, 한글 입력 편집을 따로 검증해야 하고 저장·집계를 직접 만들어야 한다.

## Consequences

- 메뉴 열 정의는 `PlatformColumn<T>`(id·header·value·cell·size·align·sortable·hideable), 정렬 상태는 contracts `PageSort[]`. TanStack 변환은 `@ap/components` 내부 모듈에만 있고 공개 진입점에 엔진 타입이 없다(#160, 테스트로 고정).
- 2026-10-02 범위(#159, 사용자): **행 복사와 전체 결과 XLSX를 무료 경로로 먼저 적용**한다. 자유 피벗(Perspective POC #163)과 셀 범위 복붙·채우기(AG Grid Enterprise 평가 #164)는 이슈로 남겨 보류한다. 붙여넣기 대량 편집은 그리드와 별개로 쓰기 계약(메뉴 선언 쓰기 엔드포인트·서버 검증·권한·감사)이 먼저라 이번 범위가 아니다. 셀 수식은 공식 지표가 서버 계산이라 채택하지 않는다.
- 유료 전환은 [04 유료 전환 계획](../04_frontend_ui_ux.md#그리드차트데이터-도구-검토-2026-10-02)의 트리거(업무 필수 확인, 사내 메뉴 2–3곳 근거) → 평가판 POC(#164) → `PlatformDataTable` 내부 교체 순서다. 읽기 기능은 메뉴 코드 변경 없이 바뀐다.
- 차트는 ECharts(Apache-2.0)를 유지한다. Plotly·uPlot 같은 두 번째 엔진은 통계 trace·고빈도 파형 요구가 생길 때까지 들이지 않는다.
- 그리드의 SUM·AVERAGE는 공식 지표의 집계 방식을 정하지 않는다. 공식 지표는 서버 계산이다.

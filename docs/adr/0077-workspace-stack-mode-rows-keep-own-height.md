# ADR-0077 — 작업 영역 "아래로 쌓기" 모드 (C안)

- Status: Decided (2026-10-23)
- Decider: 사용자(2026-10-23) — Opus xhigh UX 리뷰 뒤 "C를 기본 베이스로 — 패널 크기가 계속 바뀌면 불편" 이라며 실제 앱 시안 A/B/C 중 C를 컨펌했다.
- Scope: [#686](https://github.com/hjung3113/analytics-platform/issues/686) 2단계(선택 모드로 병합). 관련: [ADR-0067](0067-dockview-layout-engine-board-v2.md)(작업 영역), [ADR-0075](0075-page-head-one-line-fold-thin-outcome-strip.md)(fill 페이지 머리). **ADR-0067 결정 4(스키마 필드), 8(separator 방향키 5%), 21(작업 영역은 남은 높이를 채운다)을 아래 범위에서 고친다.**

## 맥락

`PanelWorkspace`는 남은 높이를 패널이 나눠 갖는다. 패널이 많은 분석 화면에서는 패널 하나가 커지면 다른 패널이 줄어 크기가 계속 바뀌고, 패널마다 쓸 만한 높이를 얻지 못한다. 사용자는 패널 크기가 흔들리지 않기를 원한다.

## 결정

시안(실제 앱 캡처, C 절): <https://claude.ai/artifact/5J22WQ6ge7XwEAf2dKqHuE>

- 작업 영역에 두 번째 높이 방식 **`아래로 쌓기`**(`stack`)를 더한다. 첫 방식 **`화면 맞춤`**(`fit`, 오늘의 방식)이 이 단계의 기본이고, 사용자가 도구줄·호스트 `⋯` 메뉴의 라디오 묶음 `높이 방식`에서 고른다. 기본값을 쌓기로 바꾸는 일과 상호작용 필수 항목(포커스 스크롤, 끌기 자동 스크롤, 최대화 한계 등)은 [#701](https://github.com/hjung3113/analytics-platform/issues/701)이다.
- **줄 모델:** 쌓기에서 최상위 레이아웃은 줄의 열이고, 각 줄은 사용자가 정한 px 높이를 갖는다. 줄 px가 유일한 원본이고 최상위 비율은 그 투영이다. 줄 하나를 바꿔도 다른 줄은 px를 지키고, 작업 영역이 그만큼 늘거나 줄며 페이지가 스크롤된다.
- **새 줄:** 패널은 마지막 줄 아래 띠나 그룹 메뉴로 새 줄(고정 시작 높이)이 될 수 있다. 편집이 만든 줄은 살아남은 줄의 px를 가져가지 않는다.
- **연결:** 쌓기 작업 영역은 가장 가까운 `PlatformPage`를 흐름 크기로 바꾸며, 연결은 내부 등록 컨텍스트로 하고 공개 prop은 없다. 저장은 키·`v:1`을 그대로 두고 선택 필드를 더한다. 좁은 폭에서는 쌓기를 끄되 저장값은 지우지 않는다.
- **보충 (2026-10-24, #690):** `PanelWorkspace`의 선택 prop `initialMode`가 만지지 않은 작업 영역의 높이 방식을 정한다. 기본값 전환(#701)이 아니라 메뉴가 선언하는 시작값이고, 저장된 선호(`화면 맞춤` 포함)가 항상 이기며 `기본 배치`는 사용자의 방식을 바꾸지 않는다. 규칙은 06 §12.8.
- 세부 규칙(최소·최대, 경계 키, 띠의 거절, 간격, 복원, 페이지 흐름 경계, 저장 정규화)은 [06 §12.8](../06_platform_ui_contract.md) "높이 방식"이 소유한다.
- 공개 API 변화는 `WorkspaceCommand.group`과 `radioGroupsOf`(`@ap/components/dock`, 라디오를 묶음별로 그리는 호스트용)뿐이다. 줄 모델은 `workspace/workspaceRows.ts`(작업 영역 소유)에, 엔진 쪽 줄 능력은 공개 `DockLayoutProps` 밖의 내부 `DockLayoutBase`에 있다.

## Considered Options

- **A 늘리기 손잡이:** 높이를 늘리는 손잡이를 두는 안. 사용자가 시안을 비교해 C를 골랐다.
- **B 높이 프리셋:** 높이를 몇 단계 프리셋으로 고르는 안. 사용자가 시안을 비교해 C를 골랐다.
- **C (채택) 줄이 자기 높이를 갖고 쌓기:** 줄 px를 사용자가 정하고 페이지가 스크롤된다. 한 줄을 키워도 다른 줄이 흔들리지 않는다.

## 결과

- 계약은 06 §12.8(모드·줄 모델·경계·띠·저장·페이지 흐름), docs/16 §4(최상위 줄 경계 키 예외)다. ADR-0067에는 이 ADR을 가리키는 한 줄을 더했다.
- 이 단계에서 쌓기의 최대화는 오늘처럼 작동한다(쌓기 전체를 채움). 보이는 영역 한계로 맞추는 일은 #701이다(`.planning/backlog.md`).
- 세부 동작(줄 사이 간격을 상자에 넣는 방식, 최대 높이에서 빼는 고정 영역, 띠가 드래그를 소비하는 범위, dock 패널의 흐름 경계, 엔진 끌기의 새 줄 판정)은 06 §12.8에 있다. 공개 `onLayoutChange`는 그대로이고 엔진의 놓기는 내부 줄 통로로 전달된다.

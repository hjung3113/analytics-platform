# 표 내보내기·복사는 표 부품이 소유하고, 툴바는 고정 배치로 둔다

상태: **Decided (2026-10-02)**.
- 사용자 결정: 툴바 모양 — 프로토타입 #172의 D안(4안 비교 후 "d로가자").
- 플랫폼 결정: 내보내기를 표 부품이 소유하는 계약, 직렬화 규칙, 형식 경로(지금 패턴 + 클라이언트 직렬화), XLSX 라이브러리 — #173. 메뉴 3곳 반복(06 §24)과 [ADR-0006](0006-grid-free-first-engine-hidden-from-menus.md)의 "행 복사·XLSX를 무료 경로로 먼저" 결정의 구현.

계약의 세부(`exportRows`·`exportNote`, 직렬화 규칙, 결과 처리)는 [06 §15](../06_platform_ui_contract.md#15-platform-data-table-contract)와 `PlatformDataTable` 테스트(`PlatformDataTable.test.tsx`·`PlatformDataTable.copy.test.tsx`·`tableExport.test.ts`)가 소유하고, 서버 행 상한은 [실서버 연결 체크리스트](../integration/real-server-checklist.md) §3-9가 소유한다. 이 ADR은 결정과 이유만 둔다.

#173 전까지 표 내보내기는 메뉴 3곳(지표 카탈로그·설비 마스터·사이클타임)이 CSV를 각자 손으로 만들었다. BOM·줄바꿈·따옴표 규칙이 서로 달라(사이클타임은 BOM이 없어 엑셀에서 한글이 깨질 수 있었다) 같은 표가 메뉴마다 다른 파일을 냈고, 응답 상태 처리와 선택 행 거르기도 메뉴마다 따로 했다.

## Considered Options

누가 파일을 만드는가:

- **(채택) 표 부품이 만든다**: 메뉴는 "서버에서 내보낼 행을 읽는 법"(`exportRows(scope, signal)`)만 준다. 열 정의(`PlatformColumn`)로 직렬화하므로 화면과 파일의 열이 같고, 결과 처리·선택 대조·크기 상한·취소를 한 곳에서 지킨다.
- **메뉴가 계속 만든다**: 메뉴마다 규칙이 갈라진다(이미 3곳에서 갈라졌다). 새 메뉴마다 같은 코드를 다시 쓴다.

어디서 직렬화하는가:

- **(채택) 지금 패턴 — 내보내기 엔드포인트가 행 배열을 돌려주고 클라이언트가 직렬화**: `PlatformAdapter`를 바꾸지 않는다. 크기는 서버 행 상한(`limits.maxRows`, #175)이 막는다.
- **서버가 파일을 만든다(openpyxl·XlsxWriter)**: 대용량에 유리하지만 파일 다운로드 경로가 `PlatformAdapter` 밖이라 전송 형식(#149)과 Kernel 포트 결정이 먼저다. 그때 다시 본다.

XLSX 라이브러리:

- **(채택) `write-excel-file`**(MIT, 의존 `fflate` 하나): 쓰기 전용으로 작다. 브라우저 진입점(`write-excel-file/browser`)을 내보내기를 누를 때만 동적 import해 별도 청크(약 72kB)로 받는다. 문자열 셀은 수식으로 해석되지 않는다(수식은 셀 타입을 명시할 때만).
- **SheetJS(npm `xlsx`)**: npm 배포가 멈춘 옛 버전이라(배포처가 CDN으로 이동) 사내 미러·보안 갱신이 어렵다.
- **exceljs**: Node 지향 의존이 많고 무겁다.

툴바 모양(#172, 사용자):

- **(채택) D — 고정 툴바, 메뉴에서 대상 선택**: [컬럼] [복사] [내보내기 ▾]가 선택 여부와 관계없이 같은 자리에 있다. 내보내기 메뉴 안에서 "선택 N행"과 "필터 결과 전체 N행"을 고르므로 선택을 풀지 않고도 전체를 받는다. 모든 메뉴의 표에 똑같이 붙는 부품이라 자리가 고정인 것이 가장 중요하다.
- **A — 내보내기 메뉴 하나**: 공간은 가장 적게 쓰지만 자주 쓰는 복사가 메뉴 안에 숨는다.
- **B — 선택 동작 바**: 행을 고르면 버튼이 선택 바로 옮겨 가고 페이지 필터까지 밀린다.
- **C — 따로 놓인 버튼 + 대상 안내 줄**: 자리는 고정이지만 안내 줄이 선택 바와 겹치고, 선택 중에는 전체를 받을 수 없다.

## Consequences

- 메뉴는 파일을 만들지 않는다. 내보내기 전용 엔드포인트(행 배열, `limits.maxRows` 선언)를 두고 `exportRows`로 넘긴다. 화면의 렌더 게이트 조회와 내보내기 조회는 분리한다.
- Excel 파일에는 두 번째 시트 "조회 정보"(대상, 내보내기 조회가 실제로 적용한 Scope·기간·전역 Context, 메뉴가 준 페이지 필터 요약, 데이터 신뢰 정보 — 시트 이름과 항목은 화면 언어)를 함께 쓴다 — 파일이 앱 밖으로 나가도 어떤 조건의 결과인지, 잠정·커버리지 같은 맥락이 남는다. CSV는 형식을 깨지 않도록 본문에 넣지 않고, 잠정이면 파일 이름과 완료 안내에 표시한다.
- 파일의 행 순서는 화면의 정렬을 따른다 — 표가 현재 정렬을 내보내기 요청에 실어 보내고, 서버가 페이지 조회와 같은 규칙으로 정렬한다.
- 내보내기 파일은 화면에 보이는 값을 쓴다 — 코드를 라벨로 보여 주는 열이나 시각을 서식으로 보여 주는 열은 `exportValue`로 같은 값을 준다. 설비 wall-clock은 문자열 그대로(06 §6.3).
- 복사(#174)는 같은 직렬화와 같은 게이트(`features.export`)를 쓴다 — 복사도 내보내기다.
- 서버 파일 생성이 필요해지면 #149·Kernel 포트 결정으로 다시 올린다.

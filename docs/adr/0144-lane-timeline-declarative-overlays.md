# ADR-0144 — LaneTimeline 표시는 선언형 `overlays` prop으로 받고, 명령형 그리기 콜백은 두지 않는다

- 상태: Decided (2026-11-11, lane 1746c, 소유자가 되돌릴 수 있음). 이슈 [#1746](https://github.com/hjung3113/analytics-platform/issues/1746). 첫 소비자는 #1744(메뉴 쪽 오버레이).
- 결정자: lane (계획 D1·D4 범위 안의 판단). 소유자가 바꾸라고 하면 되돌린다. 추가 prop이라 되돌려도 기존 소비자는 영향이 없다.
- 근거 규칙: [ADR-0052](0052-rich-content-stays-in-the-sdk.md)(도메인 없는 범용 부품은 SDK에 둔다), [ADR-0064](0064-topn-bar-and-lane-timeline.md)(LaneTimeline 계약).

## 배경

메뉴는 시간선 위에 로그·동작 같은 시각, 점검 구간, 특정 구간 집합을 표시해야 한다. SDK는 그 의미를 몰라야 하고, 선택이 바뀔 때마다 렌더러를 다시 만들지 않는 구조(1746c)에서 이 표시를 어떻게 받을지 정해야 했다.

## 결정

`overlays?: TimelineOverlay[]`를 선택 prop으로 둔다. 종류는 `instant`(시각), `range`(구간), `segments`(구간 집합) 셋이고, 모두 위치·색 토큰·모양만 가진다. 쌓는 순서는 데이터 층 < 오버레이(배열 순서) < 선택 윤곽이다. 오버레이 변경은 오버레이 canvas만 다시 그린다. 잘못된 항목은 제외하고 진단을 남기며, `label`이 있는 표시는 화면 읽기용 요약에 나온다. `LaneTimelineHandle`은 그대로다.

## 대안과 이유

| 안 | 결과 |
| --- | --- |
| 선언형 `overlays` 배열 (채택) | SDK가 그리기 순서·클리핑·좌표를 소유해 선택 윤곽이 항상 위에 있고, 이미지 복사와 화면 읽기 요약에 자동으로 들어간다. 값으로 비교할 수 있어 층 하나만 다시 그린다. 메뉴는 의미를 데이터로 옮기기만 한다 |
| 명령형 `drawOverlay(ctx, helpers)` 콜백 | 표현력은 크지만 메뉴가 canvas 상태·클리핑·DPR을 직접 다뤄 순서 보장이 깨지고, 콜백 참조가 매 렌더 바뀌어 다시 그릴지 알 수 없다. 이미지 복사·보조기기 대응이 메뉴마다 달라진다 |
| 메뉴가 DOM 요소를 위에 얹기 | 줌·스크롤과 좌표를 메뉴가 따로 맞춰야 하고 렌더러 밖에서 어긋난다 |
| 오버레이를 `TimelineSegment`로 흉내 | 레인·depth·선택·요약에 섞여 의미가 새고 모델 인덱스를 불필요하게 키운다 |

## 구현하지 않음 (다시 여는 조건)

- 호버 강조: 소유자 목표에 없고 기본 모양을 바꾼다. 요구가 생기면 `overlays`와 별도 선택 prop으로 연다.
- 명령형 콜백: 선언형으로 표현할 수 없는 표시가 둘 이상의 메뉴에서 확인될 때 다시 연다.

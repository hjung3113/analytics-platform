# 등록된 패널을 다른 메뉴에 빌려준다

상태: **Decided (2026-11-18, 사용자 결정 #2490)**.

메뉴의 일부에서 다른 메뉴에 이미 있는 분석을 보여 주려면 조회 대상과 조건을 정확히 연결해야 한다. 받는 메뉴는 화면의 선택이 무엇을 뜻하는지 알고, 원본 메뉴는 어떤 입력과 권한으로 자기 데이터를 조회하는지 안다.

## 결정

- 받는 메뉴가 선택 필드 `MenuMeta.lentPanels`에 `{ source, context?, page? }`를 둔다. `source`는 `<menuId>/<panelId>`다. 두 맵의 키는 원본 조회 입력이며, 값은 `{ kind: 'context' | 'page' | 'value', key }`다. Context는 적용 값, page는 받는 메뉴의 선언된 키, value는 렌더 시 넘기는 값이다. 이름 있는 맵에 두면 원본이 입력을 추가할 때 빠진 연결을 조립 시점에 찾을 수 있다.
- 원본과 받는 메뉴를 Menu Registry에서 함께 검증한다. 권한은 받는 메뉴, 원본 메뉴, 원본 패널 엔드포인트에서 요구하는 권한 전부다. 필수 입력 확인과 권한 판정은 순수 verdict로도 제공한다. 렌더링 경계에서 공간 권한과 검증된 Scope를 확인한 뒤 원본을 마운트하므로, 허용되지 않은 패널은 조회를 시작할 수 없다.
- 각 원본 엔드포인트가 받는 메뉴에서 요구하는 Scope와 현재 적용 중인 전역 제약을 전달해야 다른 데이터 범위가 열리지 않는다. 현재 적용 중인 값에는 명시 공집합도 포함된다. Selection으로만 명시적 부분집합을 넘길 수 있다. 받는 메뉴가 적용한 값을 보존하기 위해 출력 연결을 거부하고 원본에는 연결된 값만 읽는 화면 경계를 제공한다. 원본의 URL·Context·초안 쓰기는 효력이 없고 헤더 동작은 받는 메뉴의 화면 경계에서 실행된다.
- 앱은 [ADR-0128](0128-app-joins-menus-for-embedded-bodies.md)의 조립 방식으로 제한된 서브패스에서 원본 구현을 등록한다. 원본은 선택 함수 `accepts`로 실제로 읽을 수 있는 입력 조합을 선언한다. 받는 메뉴의 사유와 마운트 여부가 어긋나지 않도록 `useLentPanel`과 `LentPanel`이 같은 판정을 쓴다.
- 원본의 조회는 연결된 값과 등록한 엔드포인트로 한정한다. 이미 닫혔거나 다른 입력·세션으로 바뀐 연결에서 예전 데이터가 섞이는 것을 막기 위해 수동 호출도 시작 시 연결의 유효성을 확인하고 진행 중인 요청은 연결이 끝날 때 취소한다. 서버는 자기 선언으로 요청을 검증한다.

## 검토한 대안

- 받는 메뉴에서 원본 메뉴를 직접 import하면 앱의 메뉴 조립과 접근 판정을 건너뛴다. 같은 패널을 여러 메뉴가 쓸 때 의존 관계도 함께 늘어난다.
- 받는 메뉴가 조회와 차트 구현을 따로 가지면 원본의 권한, 조회 입력, 판정선 규칙을 함께 유지해야 한다. 등록된 원본과 그 엔드포인트를 재사용하면 한 곳에서 관리할 수 있다.

조회 계약과 등록 오류는 [Kernel의 패널 선언](../contract/kernel.md#패널-빌려주기-s2-2490)을 따른다. 원본 화면으로 이동할 때는 [메뉴 간 Context 링크](../contract/cross-menu-links.md#22-cross-menu-context-link)를 사용한다.

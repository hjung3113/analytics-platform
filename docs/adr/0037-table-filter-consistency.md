# 관리 표는 내용만큼 커지고 동작 열은 오른쪽에 고정하며, 필터는 초안을 적용으로 한 번에 반영한다

상태: **Decided (2026-10-16)**.
- 결정자: 사용자 — 2026-10-16, [#306](https://github.com/hjung3113/analytics-platform/issues/306). 추천안 1–5를 방향으로 정했다. 디자인 시스템 리서치를 거쳐 실제 앱 위 `?variant=` 3안 시안을 만들었다(브랜치 `hjung3113/proto-306-table-filter`, 설비 마스터·변경 감사·내 VOC). 사용자는 "A 기본 + 표 높이만 C"를 골랐다. 그 조합을 UX 리뷰 한 번(gpt-6-astra high, "confirm with changes")에 맡겼고, 사용자가 리뷰의 두 스펙 변경을 넣어 확정했다.

전체 점검(2026-10-13)에서 표와 필터가 화면마다 달랐다. 표 높이는 430px로 고정돼 1행에도 430px였다. 상세를 여는 유일한 동작 열이 가로 스크롤 밖에 있었다. 내보내기가 꺼진 표에도 선택 체크박스가 있었다. 같은 필터 패널 안에서 Select는 바로, 텍스트는 `적용`으로 반영됐다. `PageFilterBar`는 FeedbackOps 입력 높이 `h-10`을 `h-8`로 덮었다. 리서치(MUI Data Grid·Ant Design·SAP Fiori·IBM Carbon·Primer·Shopify)에서 다섯 갈래 모두 이 방향이 관례와 맞았다.

## 결정

- **표 높이**: 내용이 짧으면 내용만큼 줄어들고, 길면 쓸 수 있는 높이까지만 커져 안쪽에서 스크롤한다. 행 영역 높이는 `min(N, max(240px, R))`이다. N은 실제 표 내용 높이(머리 + 그려진 행 + 스크롤바)이고, R은 툴바·상태 줄·쪽 넘김·형제 내용을 뺀 남은 높이다. 240px은 쓸 수 있는 높이가 그보다 작을 때 확보하는 최소 스크롤 예산이며, 빈 공간을 강제하지 않는다. 쪽 넘김은 잘리지 않는다. 고정 `height`는 쓰지 않는다. 불러오기·빈 결과·오류 상태는 자기 높이를 갖고, 다시 불러오는 동안 현재 높이를 유지해 접혔다 펴지지 않는다.
- **상세 열기**: 관리 표의 동작 열(`보기`·`상세`)은 오른쪽에 고정하고, 뒤가 비치지 않는 배경과 경계선을 둔다. 마지막 데이터 열과 그 포커스 대상까지 스크롤로 닿아야 한다. 관리 표에서 행 클릭으로 상세를 열지 않으며, 행마다 Tab 정지점을 더하지 않는다. 드릴 표의 들어가기(chevron)는 그대로다.
- **선택 열**: 선택을 쓰는 기능(내보내기·복사)이 켜진 표에만 체크박스 열이 있다.
- **필터 적용**: 관리 화면 필터는 텍스트와 Select 모두 초안이고 `적용`으로 한 번에 반영한다. 텍스트에서 Enter도 적용이다(한글 조합 중 Enter는 적용하지 않는다). `적용`은 바뀐 것이 없으면 꺼져 있고, 적용된 값과 다른 필드 수를 `적용 (n)`으로 보인다. 필터를 접어도 미적용 변경이 있음을 글로 알린다(예: "적용된 필터 2개, 미적용 변경 1개"). 숫자 `+1`만으로 알리지 않는다. 적용 전에는 URL·결과·건수가 바뀌지 않는다. `페이지 필터 초기화`는 적용된 필터가 있을 때만 보이고, 적용 값과 초안을 함께 지운다.
- **필터 높이**: FeedbackOps 기본 입력 높이(40px)를 쓴다. 호출하는 곳에서 높이를 덮어쓰지 않는다. 더 촘촘한 크기가 필요하면 FeedbackOps에 이름 붙은 크기로 제안한다.
- **행 높이**: 승인된 32px 밀도(ADR-0023)를 기본·최소로 되돌린다. 셀 위아래 여백과 동작 버튼 크기를 함께 맞춘다. 줄바꿈되는 값(감사 시각 등)은 더 높아질 수 있다.

## Considered Options

- **(B) 행 수만큼 커지고 페이지가 스크롤 + 행 클릭으로 상세**: Fiori 방식. 시안에서 표가 25행 전부를 그려 1000px을 넘었다. 행마다 Tab 정지점이 생겨 첫 행까지 50번 넘게 눌러야 했다. 행 클릭은 들어가기가 하나뿐인 드릴 표에만 맞는다. 바뀐 필터 개수 표시만 가져왔다.
- **(C) 즉시 적용 + 32px 밀도**: MUI·Shopify 방식. 감사 시각처럼 입력 중인 텍스트가 0.3초 뒤 형식 오류를 먼저 보였고, 서버 조회가 무거운 관리 표에는 맞지 않는다. 32px 입력은 다른 화면의 40px 입력과 짝이 맞지 않는다. 내용만큼 줄어드는 표 높이만 가져왔다.
- **(A, 채택) 오른쪽 고정 동작 + 초안·적용 + 40px**: 위 결정. 시안에서 감사 표의 `상세`가 1440 첫 화면과 가로 스크롤 중에도 보였고, 키보드로 18번 만에 닿았다. 남은 높이를 늘 채우는 A의 표 높이는 행 2개인 VOC에 572px 빈 영역을 만들어 C의 규칙으로 바꿨다.

## 결과

- 구현은 #306이다. 표 높이·선택 열·동작 열 고정은 `PlatformDataTable`, 필터 초안·적용 표시는 `PageFilterBar`·`ManagementLayout`과 각 화면이 맡는다. 필터 값·URL 키·적용 의미는 여전히 화면이 소유한다(ADR-0016, ADR-0029).
- 고정 동작 열은 ADR-0024의 사용자 왼쪽 고정·보이기·저장된 설정과 겹치지 않게 맞춘다.
- 구현의 합격 기준: 1280 + 상세 패널에서 본문 전체가 가로로 스크롤되지 않고, 가로 스크롤은 표 안에서만 일어난다. 툴바는 줄을 바꿔 들어간다. 건수는 끊기지 않고, 신뢰 정보는 이름 붙은 컨트롤로 끝까지 볼 수 있다. 구현 PR의 UX 리뷰는 내 VOC와 1280 + 상세 패널 화면을 본다.
- #380(표 `sort`/`page` 경고 블록 공통화)은 같은 표 부품을 만지므로 순서를 맞춘다.

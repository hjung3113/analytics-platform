# 지표 이력은 공용 감사 저장소에서 읽는다 — 메뉴 mock이 감사 시드를 내고 앱 조립이 넣는다

상태: **Decided (2026-10-19).** #90.
- 결정자: 사용자 — 2026-10-19, 세 안(A 카탈로그를 mock 서버로, B 얇은 이력 수용, C 조립 시 메뉴 시드 주입) 중 에이전트 권고 C를 골랐다("c").

#50 뒤로 설비 상세 Audit 탭과 전역 `/admin/audit`은 같은 mock 감사 저장소(`auditTrail`·`entityAudit`)를 읽는다. 지표 상세 '변경 이력'만 메뉴 엔드포인트 `metrics.history`가 카탈로그를 그 자리에서 접어 만들었다. 그래서 같은 지표의 이력이 두 화면에서 달랐고(전역 쪽은 손으로 쓴 3건), 사유·값이 보는 사람의 언어로 바뀌었고, 시각에 임시 zone `+09:00`이 붙어 있었다. `@ap/mock-server`는 메뉴를 import할 수 없어(패키지 경계 §3) 카탈로그를 직접 읽지 못한다.

## 결정

- **메뉴 mock이 감사 시드를 낸다.** `@ap/menu-metrics/mock`이 카탈로그에서 지표 감사 이벤트(`metricsAuditEvents`)를 만든다. 사유·값은 기록된 문자열 하나(한국어 원문)이고, 시각은 카탈로그의 서울 벽시계를 실제 instant(UTC `Z`)로 바꾼 값이다.
- **앱 mock 조립이 넣는다.** `apps/platform-web/src/dev/mock-assembly.tsx`가 `MOCK_AUDIT_EVENTS`를 `createMockAdapter({ …, auditEvents })`로 넘긴다. mock 서버는 받은 시드를 자기 설비 이벤트와 한 저장소로 합쳐 `auditTrail`·`entityAudit` 둘 다에 쓰고, 등록 때 모양(대상 유형, instant, id 중복, 지표의 `scopeId: null`)을 검사한다. 서버 적합성 테스트도 같은 목록을 읽는다.
- **지표 상세는 `entityAudit({ type: 'metric', id, scopeId: null })`를 읽는다**(설비 상세와 같은 포트 경로). 메뉴 엔드포인트 `metrics.history`와 손으로 쓴 지표 3건은 지운다.

## 고르지 않은 안

- **A — 카탈로그를 mock 서버로:** 실서버 모양과 가장 가깝지만 지표 카탈로그·버전 해석·정의 조회까지 옮겨야 하고, 메뉴가 소유한 mock 핸들러(#129) 구조를 되돌린다.
- **B — 얇은 이력:** 가장 작지만 지표 상세 이력 탭이 버전별 등록·게시·폐기 대신 몇 건만 보이게 된다.

## 결과

- 같은 지표의 이력이 전역 감사와 상세 탭에서 같다. 영어 화면에서도 사유·값은 기록된 한국어 그대로다(감사 기록은 번역하지 않는다).
- mock 서버 포트가 메뉴 어휘를 얻지 않는다. 시드는 `AuditEvent` 계약 모양 그대로이고, 실서버에서는 서버 저장소가 이 자리를 대신한다(조립 계층만 다르다).
- 다른 메뉴가 감사 대상을 갖게 되면 같은 방식으로 시드를 낸다. 대상 유형 목록(`AUDIT_TYPES`)은 mock 서버가 계속 소유한다.

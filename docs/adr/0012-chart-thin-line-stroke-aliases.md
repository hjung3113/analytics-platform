# 차트의 얇은 선·외곽선은 전용 진한 stroke 별칭을 쓰고, 채움·범주 색은 유지한다

상태: **Decided (2026-10-04)**.
- 결정자: 사용자. 에이전트가 제시한 세 안 중 추천안 B를 골랐다("B. 선 전용 진한 색 추가").

세부(별칭 이름·값, 적용 범위, 검증)는 [DESIGN.md](../../DESIGN.md) "Chart stroke contrast"와 구현 이슈 [#203](https://github.com/hjung3113/analytics-platform/issues/203)이 소유한다. 이 ADR은 결정과 이유만 둔다.

#193 UI/UX 리뷰(UIUX-193-04)가 문제를 찾았다. FeedbackOps 토큰 위에서 카드 표면이 `#fbfdff`가 됐고, 그 위의 얇은 선 마크가 의미 있는 비텍스트 기준(3:1)에 못 미친다. `chart-blue` `#3b9cff`는 2.79:1, `chart-teal` `#00a3b5`는 2.98:1이다(`chart-purple` 막대는 3.25:1). 실선/점선 구분과 같은 데이터 표가 시리즈 구분과 대체 경로는 주지만, 선 자체가 잘 보이게 하지는 않는다. 차트·범주 색은 플랫폼 확장 층에 있고, 플랫폼이 소유한다(ADR-0010·ADR-0011).

## 결정

- **얇은 선·외곽선 마크에만 쓰는 진한 stroke 별칭을 플랫폼 확장 층에 추가한다.** 모든 차트 표면(card·canvas·sunken)에서 3:1 이상이어야 하고, 지금 색과 같은 계열로 알아볼 수 있어야 한다.
- **막대·영역 채움 색과 범주 식별색(`chart-*`, `cat-*`)은 그대로 둔다.**
- 별칭 값은 보이는 변화라서, 실제 차트 화면 위 `?variant=` 프로토타입으로 사용자 컨펌을 받은 뒤 구현한다(#203).

## Considered Options

- **(A) 현재 팔레트 유지**: 변경 비용이 없다. 대신 선 대비 부족이 그대로 남는다.
- **(B, 채택) 선 전용 진한 별칭 추가**: 범주 식별과 채움은 그대로 두고, 대비가 필요한 얇은 선만 고친다. 바뀌는 범위가 가장 작다. 별칭이 늘고, 범례와 선 색을 맞추는 규칙이 하나 생긴다.
- **(C) 차트 팔레트 자체 변경**: 일관성은 가장 좋다. 대신 범주 색·채움·범례 소비처가 모두 바뀌고, 다시 프로토타입 확인을 받아야 한다.

## 결과

- DESIGN.md의 Open Decision은 Decided(B)로 닫는다. 05에는 Decided 행을 둔다.
- 구현(#203) 전까지 코드의 차트 선은 기존 색이다. 이 ADR은 런타임 변경이 아니다.

# 분석 보드는 최소화된 채 마운트를 유지하고 열기·최소화·복원은 history replace로 전이한다

- Status: Decided (2026-10-27)
- Decider: 코디네이터(사용자 결정: 복원 진입점은 왼쪽 아래 칩 + 레일 버튼 상태 표시, 2026-10-26), 되돌릴 수 있다.
- Scope: [#893](https://github.com/hjung3113/analytics-platform/issues/893) 노드 893c. 관련: [docs/16 §4·§7](../16_analysis_board.md), [ADR-0049](0049-board-pane-kernel-context.md).

## 맥락

보드는 사용자가 일하는 중간 상태(선택 칸, 미적용 입력, 차트 확대, 스크롤)를 갖는다. 홈이나 다른 메뉴를 한 번 보고 돌아오면 이 상태가 사라지고, 돌아가는 길은 메뉴·시트를 다시 고르는 것뿐이었다. 레일 열기는 `push`라 보드를 오갈 때마다 history 항목이 쌓였고 Back이 보드와 직전 화면 사이를 맴돌았다.

## 대안

- **a. 지금처럼 `/board`를 떠나면 언마운트.** 단순하지만 상태가 사라진다.
- **b. 최소화를 `history.back()`에 맡기기.** 직접 입력으로 들어온 `/board`에서는 갈 곳이 없고 항목 수가 흔들린다.
- **c. 별도 `mode` 저장 + URL.** 두 정본이 어긋날 수 있다(Back/Forward가 URL만 바꾼다).
- **선택. d. URL이 최대화의 정본이고, 열려 있다는 사실(`live`)만 저장한다.** 보드는 한 React 인스턴스로 남고 컨테이너만 가린다.

## 결정

**d.** 표시 상태 저장소 `boardPresentation`(사용자별 모듈 저장소, 보드 엔진을 import하지 않는다)은 `live`, 돌아갈 일반 경로 `returnHref`, 칩에 쓸 마지막 시트(id·이름), 숨기기 직전 포커스를 쥔다. `maximized = live && /board`, `minimized = live && 그 밖`은 파생이다.

| 전이 | 동작 | history |
| --- | --- | --- |
| 레일: 닫힘 → 열기 | `/board?sheet=<마지막 시트>` | replace |
| 일반 메뉴·홈·팔레트·링크로 이동(보드 최대화 중) | 이동한 경로가 곧 최소화. 추가 조작 없음 | 사용자의 이동 그대로(push) |
| 보드 머리 `최소화` | 마지막 일반 경로(열 수 없으면 홈)로 이동, 포커스는 칩 | replace |
| 칩·레일: 복원 | `/board?sheet=<마지막 시트>`, 도착 포커스 요청 없음 | replace |
| `분석 보드에 열기…` 확인 | `/board?sheet=<대상>` | replace |
| 보드 머리 `보드 닫기` | `live` 종료, 최대화 중이면 마지막 일반 경로(없으면 홈)로 이동. 저장된 시트는 남는다 | replace |
| 직접 입력·Back/Forward로 `/board` 도착 | 열림(`live`) | 브라우저 그대로 |
| 최소화 중 Back/Forward가 일반 경로 사이 이동 | 최소화 유지 | 브라우저 그대로 |

반복 왕복(열기 → 최소화 → 복원 …)은 현재 항목만 바뀌고 `A, A` 중복이 생기지 않는다. 일반 경로로 이동할 때마다 `returnHref`가 그 경로로 갱신된다(열 수 있는 `registry.safeReturnTo` 통과 경로만).

호스트는 `RouteOutlet`이다: 일반 화면과 보드를 형제로 두고, 보드는 처음 열릴 때 lazy로 마운트한 뒤 최소화 중 `hidden`+`inert`+`aria-hidden` 컨테이너로만 가린다(키·부모·Provider 불변). 다른 앱은 `RouteOutlet`만 쓰면 되고 `Outlet` 주입 경로(`BoardScreen`에 `ScreenOutlet`)는 그대로다. 한 번도 열지 않은 사용자는 보드 청크를 받지 않는다.

숨은 보드는 `visible=false`다: 도착 포커스를 가져가지 않고, 주소를 쓰지 않고(일반 경로를 `/board`로 되돌리지 않는다), 0으로 측정되는 컨테이너 크기를 좁은 폭으로 받아들이지 않는다(마지막 유효 폭 유지, 복원 직후 재측정). 복원 포커스는 숨기기 직전 보드 안 마지막 요소(없으면 제목), 스크롤은 건드리지 않는다.

## 결과와 한계

- 계측: `via`는 `navigate` 호출마다 기록되고 `enter`/`recordVisit`은 일반 경로 도착마다 남는다. 보드 왕복도 일반 화면 쪽은 매번 한 방문이다(`/board`는 방문·계측 대상이 아니다, docs/16 §7).
- 일반 화면은 최대화 ↔ 최소화마다 다시 마운트한다(`ScreenOutlet`을 `/board`에서 내린다). 일반 화면 상태까지 살리는 것은 이 결정의 범위 밖이다(알려진 한계).
- 최소화 중 보드의 상세·overlay·토스트 처리와 세션·권한 경계는 893c2가 이어받는다. `visible=false`가 그 노드의 훅이다.
- 최소화 알림은 명시적 최소화·복원·닫기에만 낭독한다. 메뉴 이동으로 인한 자동 최소화는 목적지의 도착 포커스가 낭독을 맡는다.

## 되돌리기

`RouteOutlet`을 `/board`일 때만 보드를 그리도록 되돌리고 레일의 `navigate`에서 `replace`를 빼면 이전 동작이다. 저장소와 칩은 다른 곳에서 참조하지 않는다.

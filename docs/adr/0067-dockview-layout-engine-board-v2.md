# 보드와 분석 작업 영역은 같은 무료 Dockview 엔진을 쓰고, 보드 저장 모델을 V2로 옮긴다

상태: **Decided (2026-10-22, 사용자 — #575 P0 추천안 채택 "니추천대로", 설계는 Opus xhigh 리뷰 1회 반영)**. 엔진 선택(무료 `dockview-react`)은 #575 2026-10-21 결정이다. 구현 순서·API 세부는 코디네이터 판단이고 되돌릴 수 있다.

## 맥락

- MARS 이관 화면은 조건·대상·범례·차트·표·상세가 한 화면에 있어 면적이 모자라고, 분석 보드는 1×1–2×2 고정 격자와 자체 경계선([ADR-0060](0060-analysis-board-pane-sizing-collapse-maximize.md))만 있다. 사용자는 두 곳 모두 탭 합치기·방향 도킹·최대화를 원했다(#575).
- P0 시안(`?variant=`, 버릴 브랜치 `feat/575-dockview-proto`)에서 탭 이동·합치기·전환 6개 조작의 재조회 0회, 중첩 → 바깥 끌기 거부, 콘솔 오류 0을 확인했다. 시안 결함(차트 패널 눌림, 조회 바 아래에서 시작, 숨은 탭 재측정 누락, 칸 번호 없음, 머리 중복, 초기화 3중)은 아래 수용 기준으로 옮겼다(콘덕터 보관 `575-JUDGE-REPORT`).
- 사용자 결정(2026-10-21): 메뉴는 `balanced` 기본 + `focus` 프리셋(`compare` 제외), 보드는 `board-dock-tabs`(`board-grid`는 V1 대체 경로, `board-dock-split` 제외), 메뉴는 opt-in, 보드 칸 X = 기존 `비우기` + 실행 취소.

## 결정

### 엔진과 패키지
1. 엔진은 `dockview-react`(MIT) **정확한 버전 고정**, `dockview-enterprise` 0개. 고정 판은 배포 후 14일이 지난 판을 기본으로 하고, 수용 기준에 걸린 결함 수정이 그 뒤 판에만 있으면 이유를 이 ADR 결과 절에 적고 예외로 쓴다(P0는 8.6.1 — StrictMode 재생성·`always` 마운트 크기·중첩 숨김 상태 수정).
2. 엔진은 `@ap/components` 안의 **lazy 청크**로만 불러온다. 메인 청크에 `dockview`가 없어야 한다(빌드 검사). `dockview-*`는 `@ap/components` 밖에서 import하지 않는다(경계 lint).
3. `@ap/components/dock`은 **호스트 전용 진입점**이다: 제어형 `DockLayout`, 레이아웃 스키마와 정규화기, `WorkspaceCommandsHost`. 메뉴·모듈 패키지는 import하지 않는다(lint 게이트). 공개 API에는 Dockview 타입과 엔진 JSON이 없다.

### 레이아웃 스키마와 동작
4. 스키마 v1은 재귀 트리 `branch{dir, children, sizes(비율)}` | `group{panels, active}` + (작업 영역 전용) `hidden`·`preset`. 최대화는 저장하지 않는다. 엔진 JSON·패널 params는 저장하지 않는다.
5. 정규화: 모르는 id·중복 id는 버리고, 빠진 id는 기본 그룹에 붙인다. 비율이 틀리면 기본값. 좁은 폭에서의 표시 clamp는 저장값에 쓰지 않는다.
6. 패널은 모두 `renderer:'always'`(상태 유지, 재조회 0). 보이지 않는 패널에는 `inert`와 `TransientOverlayScope`를 단다. 중첩 레이아웃은 다시 보일 때 다시 잰다(P0 UX-3은 원인 진단 뒤 확정).
7. **엔진 닫기를 막는다**(탭 Delete/Backspace, `close()` 경로 포함). 제거·숨김·이동·합치기·최대화는 플랫폼 명령이고, 칸 `⋯` 메뉴의 배치 묶음(탭에서 Shift+F10·오른쪽 클릭, 2c에서 그룹 `⋯`를 흡수)이 끌기와 같은 키보드 경로다.
8. 경계선마다 플랫폼 `role="separator"`를 둔다 — [docs/16 §4](../16_analysis_board.md)의 방향키 5%·Home/End 계약을 지킨다(무료 엔진에는 키보드 크기 조절이 없다). Esc는 가장 안쪽 최대화만 풀고, 열린 메뉴·Popover·상세 슬롯을 먼저 닫는다.
9. 바깥과 안쪽 인스턴스 사이 드롭은 거부한다(엔진 기본 + `onWillDrop`).

### 분석 보드 (셸)
10. 보드 V2: `sheet.panes: {id, screen, previous}[]`(배열 순서 = 화면의 칸 번호), `selectedPaneId`, `layout` 트리(모든 칸이 정확히 한 번, 숨김 없음). 칸은 시트당 4개, 시트는 20장 그대로.
11. **선택은 보드가 소유**하고 사용자 활성화만 반영한다. 엔진 활성 이벤트(이동·복원·추가)는 선택을 바꾸지 않는다. 선택 칸은 늘 그 그룹의 활성 탭이다. 처음 열면 첫 칸.
12. 칸 X(내용 있음) = `비우기` + 실행 취소(사용자 결정). 빈 칸은 `⋯ 칸 닫기` + 실행 취소(번호를 당긴다). `칸 추가`는 4칸에서 끈다. `복제`는 빈 칸이 없으면 새 칸을 만든다.
13. 시트 간 조건 복사·일괄 적용은 **칸 번호** 기준이고 배경 탭 칸을 포함한다.
14. 이행: V1→V2는 순수 함수다. row-major 칸 → 번호, 비율 → 트리, V1 접힘 칸 → 같은 열 형제 그룹의 비활성 탭. V1 원문은 백업 키에 한 번 옮기고 V1 키는 더 쓰지 않는다. 더 새 버전은 읽기 전용, 손상 값은 원문을 백업한 뒤 새 보드로 시작하고 알린다.
15. 저장소의 원본은 V2 하나이고 `분석 보드에 열기`도 저장소를 거친다. `board.layoutEngine='grid'`는 V2를 오늘의 격자로 그리는 대체 렌더러다(새 `PaneSplitter` 래퍼를 만들지 않는다).
16. dock 모드 보드 머리에는 `1×1…2×2`·`크기 초기화`가 없고 `기본 배치`가 하나다. 칸 머리는 [ADR-0051](0051-analysis-board-pane-header-signal-chips-numbered-selection.md)의 번호·차이 칩·`같음 N`·`⋯`를 그대로 갖고, 선택 강조는 DESIGN.md의 선택 표식을 쓴다. **결과(2c, Opus 판정 2026-10-22 §4)**: 칸 머리는 그룹마다 40px 띠 한 줄이다 — 탭 목록(`칸 N` 배지·말줄임 이름·X) 뒤 오른쪽 끝에 활성 칸의 시스템 칩·차이 칩·`같음 N`·`이전 화면`·보이는 최대화 토글·`⋯` 하나(`칸 N 동작`: 내용 묶음 + 배치 묶음)를 둔다. 그룹 `⋯`와 칸 안 머리 행은 없다. 선택은 배지 채움(Context 바와 같은 부품)·띠 선택 표면·왼쪽 막대로 나타내고 점은 없다. 좁은 띠의 줄이기 순서는 docs/16 §4다.
17. 좁은 폭(692px 미만)에서는 한 탭 그룹으로 **표시만** 바꾼다.

### 메뉴 작업 영역 (opt-in)
18. 메뉴 façade(이름은 06 §12.2 "Analysis Workspace" 아키타입과 겹치지 않게 `PanelWorkspace` 계열로 정한다): `panels{id, title:Text, render, primary?, minWidth?, minHeight?}`, `presets`, `initialPreset`, `compactPreset`, `persistKey`. 툴바는 `프리셋 · 숨긴 패널 n · 기본 배치`. 보드 칸 안에서는 툴바 대신 명령을 칸 `⋯`에 등록한다.
19. 프리셋 전환과 기본 배치는 있는 패널을 재배치만 한다(리마운트 0회). 숨긴 패널의 하위 트리는 언마운트될 수 있으므로 남아야 할 상태는 façade 위(메뉴·Kernel)에 둔다.
20. 로컬 선호는 `@ap/components`가 소유한다(`AnalysisLayout` 접기 기억과 같은 방식). 키 `platform:workspace:v1:<userId>:<menuId>:<persistKey>`, 변경은 debounce, 복원은 조회를 일으키지 않는다. compact 상태는 저장하지 않는다. 서버 저장·공유는 #294 결정 뒤.
21. 높이: `PlatformPage layout="fill"`과 차트 `size: 'fill'`(최소 320px)을 opt-in으로 둔다. 작업 영역은 접힌 조회 바 아래 남은 높이를 채우고 primary 패널이 남는 공간을 받는다. dock 안 카드 제목은 시각적으로만 숨긴다.
22. 공개 API는 두 번째 실제 소비자(#586 HW Time)가 쓰기 전까지 Candidate로 둔다(06 §24).

## 구현 순서

1. **보드 저장소·모델 V2**(셸만, 보이는 변화 없음): V2 모델, 이행 함수·백업, 손상·새 버전 처리, grid 투영, `분석 보드에 열기` 저장소 경유.
2. **`DockLayout`(`@ap/components/dock`)과 보드 dock 렌더러**: lazy 엔진, 테마, separator, 가시성·inert, 엔진 닫기 차단, 선택 소유, 칸 추가·닫기, 좁은 폭(2a·2b, 플래그 기본값 `grid`). 실제 앱 UX 리뷰 → 사용자가 컨펌을 Opus 판정에 위임(2026-10-22): 칸 머리 C(한 줄 띠, 2c) 뒤 **기본값을 `dock`으로 바꿨다**(`BOARD_LAYOUT_ENGINE_DEFAULT`). `grid`는 대체 렌더러로 한 릴리스 둔다(4).
3. **메뉴 façade**: 프리셋·숨김·기본 배치·로컬 선호, 명령 호스트·compact, fill, 첫 소비자(코드 opt-in 견본), 보드 칸 안 중첩 E2E.
4. 한 릴리스 뒤 grid 경로·V1 읽기·백업 키 제거(백로그, 다시 열 조건 포함).

이슈 본문의 "메뉴 façade 먼저"와 순서가 다르다: 보드가 불변식이 가장 어렵고 실제 플랫폼 소유 소비자이며, 견본 하나에 맞춘 공개 API를 먼저 내보내지 않기 위해서다(코디네이터, 되돌릴 수 있다).

## 수용 기준(요약 — 테스트 층은 #575 설계 리뷰 Q3)

- 재조회 0회: 이동·합치기·탭 전환·최대화/해제·기본 배치·프리셋 전환(어댑터 `menuQuery` 호출 수, 보드는 칸마다) + E2E 네트워크 수.
- 1440×900: primary 패널 ≥ 작업 영역 55%·≥ 320px, ECharts canvas ≥ 300px, 페이지 세로 스크롤 없음(E2E). jsdom에서는 Dockview 기하가 0이라 unit은 구조만, 크기는 E2E에서만 단언한다.
- 이행: V1 모든 모양 × 접힘 × 비율 × previous × 1·20시트가 유효한 V2가 되고 칸·previous·번호 보존, V1 키 값 불변, 손상 값 백업.
- 칸 번호·선택: 이동 뒤 번호 불변, Context 바 = 선택 칸, 선택 칸은 늘 활성 탭. 칸 X/Delete = 비우기 + 되돌리기.
- 권한 회수: 배경 탭 칸 DOM에 이전 데이터가 즉시 없다.
- separator 키보드, Esc 순서, 중첩 끌기 거부(두 레이아웃 직렬화 동일), 칸 탭을 시트 탭에 끌어도 시트 순서 불변.
- 메인 청크에 `dockview` 없음, `sdk:api`·`sdk:pack`·`consumer-check`.

## 결과

- 보드는 격자 대신 같은 엔진의 탭·도킹을 얻고, 칸 번호가 위치와 분리되어 조건 복사·Context 의미가 이동에 흔들리지 않는다.
- V1 저장값은 백업과 grid 대체 렌더러로 되돌릴 수 있다. 정리 전까지 렌더러가 둘이다.
- 무료 엔진에 없는 키보드 크기 조절·키보드 도킹은 플랫폼 코드(separator, `⋯` 명령)로 갖는다.
- Dockview 고정 판: 8.6.1로 확정한다(2026-10-22, 구현 2단계 2a). 배포 14일 기준의 최신판은 8.4.1이지만 그 판에는 수용 기준에 걸린 결함이 남아 있다 — StrictMode·Activity에서 인스턴스가 다시 만들어짐(#1670, 8.5.0 수정), `clear()` 뒤 비율 소실(#1694, 8.6.0), `renderer:'always'` 패널의 첫 마운트 크기(#1689, 8.6.1), 중첩 숨김 상태(#1697·#1698, 8.6.1). 결정 1의 예외를 적용한다. 판을 올릴 때는 이 결함들의 회귀를 `DockLayout` 테스트와 E2E로 다시 확인한다.

## 고려한 대안

- **보드는 `PaneSplitter` 유지, 메뉴만 Dockview:** 두 레이아웃 엔진을 따로 유지하게 된다. 사용자가 철회했다(#575 2026-10-21).
- **`board-dock-split`(탭 없는 자유 분할):** 격자보다 얻는 것이 없다(P0 판정).
- **`panesById` + `displayOrder` 두 구조:** 같은 정보를 두 번 들고 동기화 불변식이 생긴다. 순서 배열 하나로 둔다.
- **Kernel 공개 포트 `usePanelPreference`:** 소비자가 하나뿐이고 components가 이미 저장을 소유한다(ADR-0029 접기 기억).
- **엔진 활성 패널 = 선택 칸:** 이동·복원 이벤트가 선택을 바꿔 Context 바가 다른 칸을 편집한다.
- **Dockview Enterprise:** 초기 범위 밖. 수요가 확인되면 다시 판단한다.

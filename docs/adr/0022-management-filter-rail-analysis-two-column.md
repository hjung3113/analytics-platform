# 관리 화면은 접을 수 있는 왼쪽 필터 레일, 분석 화면은 KPI 띠 + 차트 2열

상태: **Decided (2026-10-05)**.
- 결정자: 사용자 — 실제 앱 위 `?variant=` 프로토타입(#156, 브랜치 `hjung3113/proto-156-layout-slots`)에서 관리 A(현재)/B(표 안 필터)/C(왼쪽 필터 레일) 중 C를 골랐고 접기는 필수라고 했다("결국 메인화면이 주니까"). 분석 A(세로 쌓기)/B(KPI 띠 + 차트 2열)/C(KPI 레일) 중 B를 골랐으며 섹션별 접기도 요구했다.

플랫폼은 사내에서 새로 만드는 관리·분석 메뉴에 공통 레이아웃 슬롯을 제공한다. 세부 동작은 [06 §12.6](../06_platform_ui_contract.md#126-pagetype의-현재-계약과-레이아웃-슬롯-104-156), 시각 규칙은 [DESIGN.md](../../DESIGN.md#shell-visual-rules)가 소유한다.

## 결정

- 관리 화면은 접을 수 있는 왼쪽 필터 레일을 채택한다. 필드가 많아도 표가 위에서 바로 시작하고, 스크롤해도 필터를 볼 수 있다. 표가 주인공이므로 레일을 접어 전체 폭을 쓸 수 있어야 한다.
- 분석 화면은 KPI 띠 + 차트 2열과 섹션별 접기를 채택한다. KPI와 두 차트를 첫 화면에서 함께 보고, 표는 전체 폭으로 읽는다. 분석 구현은 #156 다음 작업이다.
- 분석 공통 레이아웃은 §24의 반복 기준(소비자 2–3곳)보다 먼저 올린다. 사내에서 분석 메뉴를 새로 만들 플랫폼이라는 목적에 따른 사용자 결정이다.

## Considered Options

- **관리 (A) 현재 필터 행**: 필드가 많으면 표 시작 위치가 밀리고 스크롤 중 필터 접근이 어렵다.
- **관리 (B) 표 안 필터**: 표 카드에 필터와 결과가 모이지만 많은 필드가 표의 공간을 차지한다.
- **관리 (C, 채택) 왼쪽 필터 레일 + 접기**: 필터와 표를 나란히 읽고 필요할 때 표에 전체 폭을 돌려준다.
- **분석 (A) 세로 쌓기**: KPI와 두 차트를 한 화면에서 함께 비교하기 어렵다.
- **분석 (B, 채택) KPI 띠 + 차트 2열**: 주요 지표와 차트를 함께 보고 상세 표에는 전체 폭을 준다.
- **분석 (C) KPI 레일**: KPI가 차트의 가로 공간을 계속 차지한다.

## 결과

- 관리 공통 컴포넌트 `ManagementLayout`을 설비 마스터·변경 감사·권한/역할에서 소비한다. 자기 폭에 대응하며 상세는 셸 슬롯을 유지한다.
- 필터 값·URL page key·초안 적용·초기화 의미는 소비자가 소유한다. 레일 접힘 기억과 좁은 폭 팝오버는 공통 레이아웃이 소유한다.
- Analysis 구현은 #156의 다음 작업이 이어받는다. 프로토타입 코드와 variant 분기는 본 코드에 넣지 않는다.
- 06 §12.6과 DESIGN.md가 레이아웃 계약과 시각 규칙을 소유한다.

# 분석 보드는 화면 안 그리드와 열별 크기 조절·칸 접기·최대화를 쓴다

상태: **Decided (2026-10-21, 결정자: 사용자)** — [#536](https://github.com/hjung3113/analytics-platform/issues/536). 세부 동작·저장 계약은 [16 §4](../16_analysis_board.md#4-화면-구조-decided)·[§7](../16_analysis_board.md#7-저장url조회-decided-1차)이 소유한다. 사용자 컨펌: [실제 앱 시안 D](https://claude.ai/artifact/9TU7C6Y7AyR2H3NigroPz7).

## 문제

내용이 긴 메뉴를 칸에 넣으면 그리드 행이 콘텐츠만큼 자라 2×2 아래 칸이 화면에서 멀어진다. 네 화면을 동시에 비교할 수 있어야 하며, 분석 중인 칸에 더 많은 공간도 줄 수 있어야 한다.

## 결정

**D를 채택한다.** 그리드는 사용 가능한 화면 높이에 맞추고 칸 본문은 독립 스크롤한다. 열 너비와 열별 상하 높이를 조절하고, 칸 접기·최대화/복원을 제공한다. 비율과 접힘은 브라우저의 시트·레이아웃별로 저장하며 최대화는 임시 상태다. 기존 한 줄 칸 머리(ADR-0051), 340px 쌓기 경계, Context/page·상세 소유 관계를 보존한다.

## Considered Options

- **A — 화면 안 고정 동일 배분**: 네 칸 비교가 가능하고 가장 단순하지만 중요한 칸에 공간을 더 줄 수 없다. 표 내부 스크롤과 칸 스크롤의 중첩도 남는다.
- **B — 화면 안 행·열 조절**: 비교하면서 공간을 배분할 수 있어 UX 검토의 기본 권장안이었다. 공통 행 경계만으로는 열마다 다른 높이를 원하는 요구를 충족하지 못한다. 시안의 새로고침 초기화는 최종 저장 계약으로 해결한다.
- **C — 콘텐츠 기반 높이와 최대화**: 최대화는 집중에 유용하지만 기본 높이 때문에 아래 칸을 다시 찾아야 해 동시 비교 목적에 부족하다. 최대화만 D에 포함한다.
- **D — 화면 안 크기 조절·열별 행 분할·칸 접기·최대화 (채택)**: B의 비교 공간과 C의 집중 동작을 합치고 열마다 독립적으로 공간을 배분한다. UX 제안의 칸 접기를 실제 앱 시안으로 구체화한 안을 사용자가 선택했다. 이전 A/B/C 캡처는 D의 런타임 검증 근거로 쓰지 않는다.

## 결과

- 크기·접힘은 기존 v1 보드에 선택 필드로 저장하고 잘못된 항목은 레이아웃 단위로 격리한다. 반응형 clamp를 저장 비율에 쓰지 않는다.
- 세로 쌓기에서는 펼친 칸 전체 최소 400px(본문 약 358px), 접힌 칸 42px을 두고 보드 본문을 스크롤한다. 쌓기 밖의 본문 최소 120px은 유지한다(콘덕터 결정, 되돌릴 수 있음: 좁은 칸에서도 첫 데이터와 조작 영역을 함께 읽기 위한 최소 공간).
- 동일한 React ancestry로 화면 인스턴스를 유지하고, 숨길 칸의 transient portal 및 지연 포커스를 취소한다. 공유 상세는 닫지 않는다.
- **Not built**: 떠다니거나 겹치는 창, 자유 모서리 resize, 별도 OS 창. 고정 비교 공간을 넘어 z-index·창별 포커스·저장 모델을 늘리므로 이번 범위에서 제외했다. 고정 그리드 제약이 반복 보고되면 재검토한다([백로그](../../.planning/backlog.md)).

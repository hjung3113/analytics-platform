# 메뉴 뷰에 표 열 묶음을 저장한다

상태: **Decided (2026-11-18)**
- 결정자: 사용자(#2492, 2026-11-17). 선택 필드·슬롯 등록·상한은 구현 계획과 검토 P1–P12에 따른다.
- 관련: [ADR-0092](0092-saved-view-units-tiers-and-groups.md), [ADR-0099](0099-server-saved-view-persistence.md), [ADR-0167](0167-editable-column-groups.md). 계약: [kernel §21](../contract/kernel.md#21-saved-view-contract), [components 열 묶음](../contract/components.md#사용자가-편집하는-열-묶음).

## 결정

메뉴 뷰에 `tables?: Record<string, TableViewState>`를 추가한다. 키는 표의 `preferenceKey`, 값은 `{ groups?: StoredColumnGroups }`다. 형식 버전은 `schemaVersion: 1`을 유지하고 기존 jsonb 내용에 선택 필드로 저장한다. DB 이주는 없다. 조건 세트에는 넣지 않는다.

Kernel의 화면별 등록소가 메인 화면의 편집 가능한 표만 수집한다. 같은 키의 등록은 목록이며 저장은 마지막 등록값, 적용은 모든 등록에 전달한다. 보드 칸은 참여하지 않는다. 호스트 전용 `useSavedViewTableState`가 등록을 담당하고 메뉴가 범용 JSON 슬롯을 등록하지 않는다.

항목 없음은 그 표를 건드리지 않고 비교하지 않는다는 뜻이다. `{}`는 선언 묶음으로 돌아간다는 뜻이다. 새 저장·덮어쓰기는 마운트된 표를 모두 기록하고 마운트되지 않은 표의 기존 항목은 보존한다. 성공한 뷰 적용만 표 설정에 쓰며 같은 적용 토큰에서 키마다 호환 등록이 수락한 적용을 한 번만 전달한다. 수락 전 대기·재시도, 유효 묶음 투영과 수정 표시의 상세 의미는 kernel §21이 소유한다.

타입과 상한은 contracts가 소유한다. 엄격한 스키마와 HTTP 가드가 같은 경계를 검증한다. 표 최대 20개, 키 1–200자, basis 최대 16,384자, 묶음 최대 200개, 고유 id 1–200자, 묶음별 구성원 최대 500개(각 1–200자), 이름 trim 후 1–60자(`u:` id는 필수), 폭은 유한수 60 이상이다. 항목·groups·묶음 객체의 미지 키를 거부하고 표 키에는 일시 상태 이름 금지 규칙을 적용하지 않는다. 승인 변경 요약은 내용 없이 «열 묶음» 한 줄이다.

## 검토한 대안

- page 키: URL 길이와 라벨 노출 때문에 거절.
- `layout`·`chartOptions`: 검증되지 않는 JSON 슬롯에 새 의미를 섞으므로 거절.
- 화면 전용 overlay: 공통 표·저장 선택기·수정 비교가 갈라지므로 거절.
- schemaVersion 증가: 기존 필수 모양을 바꾸지 않는 선택 필드라 거절.
- contract/server와 UI를 별도 PR로 분리: 같은 배포 단위이고 중간 상태의 이득이 없어 거절. 한 PR로 제공한다.

## 결과

옛 뷰는 표 설정을 유지한다. 편집을 끈 표의 기본 동작과 components의 기존 공개 재수출은 유지한다. 숨은 열만 가진 묶음 라벨은 뷰 ACL 안에 남고 읽는 사람의 개인 열 설정에는 복사되지 않는다.

옛 `@ap/http-adapter`의 엄격한 응답 가드와 옛 서버의 update 재검증은 `tables`를 포함한 뷰를 거부한다. 어댑터와 서버를 함께 업그레이드해야 한다. 이 변경 이전으로 되돌리면 새 뷰를 옛 클라이언트에서 읽지 못한다. `savedScopeId`(#2175)와 같은 배포 특성이다.

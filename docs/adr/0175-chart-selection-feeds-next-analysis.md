# 차트 선택은 다음 분석의 입력이 되고, 값 묶음·범위만 URL과 메뉴 간 링크에 싣는다

상태: **Decided (2026-11-23, 소유자 결정)**. 계약 문구는 구현 이슈에서 [§16 차트](../contract/chart.md), [06 URL 소유 상태](../contract/kernel.md), [§22 메뉴 간 연결](../contract/cross-menu-links.md)에 넣는다.

소유자는 «차트에서 데이터를 선택하면 그 선택 결과가 다음 분석의 입력으로 연결되는 구조»를 분석 UX의 가장 중요한 요구로 꼽았다(2026-11-23). 지금은 차트 선택(점 선택, `{from,to}` 범위)이 차트 안에만 있고 URL에 실리지 않는다. 선택을 밖으로 내보내는 길은 «분석 구간으로 적용»(전역 기간으로 쓰기)과 메뉴가 손으로 쓰는 페이지 키뿐이다. `PanelDeclaration.outputs`도 지금은 표시용 메타데이터다. 근거와 화면 설계는 [디자인 시스템 리뷰 2026-11-23](../reviews/2026-11-23-design-system-visual-review.md) §J2·J3·M3에 있다.

## 결정

- 패널이 `outputs`에 선언한 키로 차트 선택을 내놓으면, 그 선택은 페이지 키가 되어 URL에 실린다. 실리는 것은 **값 묶음**(예: 설비 두 대)과 **범위**(예: 14:00–16:00)다. 공유 링크를 받은 사람도 같은 선택을 보고, 뒤로 가기로 선택을 한 단계씩 되돌린다.
- **행 묶음**(산점도·표에서 고른 행 키 목록)은 URL에 싣지 않는다. URL 길이와 보안 경계 때문이다. 화면 안에서만 유지하고, 넘기려면 범위나 값 묶음으로 바꾸게 안내한다.
- 메뉴 간 링크(`resolveLink`)는 목적지가 그 선택 키를 받는다고 선언할 때만 선택을 싣는다. 목적지 ID와 분석 Context의 분리는 그대로다.
- 선택은 페이지 안의 연결 패널에만 바로 걸린다. 전역 기간과 설비 선택은 지금처럼 명시 동작(«분석 구간으로 적용»과 그 일반화)으로만 바뀐다.
- `outputs`를 선언하지 않은 패널과 메뉴의 동작은 바뀌지 않는다.

## Considered Options

- **(가) 선택을 싣지 않는다:** URL과 계약은 그대로지만, 공유 링크와 뒤로 가기로 선택이 되살아나지 않는다. 받은 사람에게는 «다음 분석의 입력»이 성립하지 않아 선택하지 않았다.
- **(채택) (나) 값 묶음과 범위만 페이지 키로 싣는다:** 장치는 지금의 페이지 키이고, 새로 생기는 것은 메뉴가 선언한 키 이름뿐이다. 행 묶음을 빼서 URL 길이와 경계 위험을 막는다.
- **(다) 저장된 보기에만 싣는다:** 링크 한 번으로 상태가 넘어가지 않고, 저장 단계가 하나 더 생겨 선택하지 않았다.

## 결과

- 구현은 #2732(선택을 `outputs` 통로로), #2733(선택 칩), #2734(다음 분석 동작), #2735(메뉴 간 링크와 넘겨받은 맥락)에서 한다.
- 차트 선택의 이름은 «분석 선택»이다([ADR-0176](0176-user-analysis-menu-one-definition-two-homes.md), [GLOSSARY.md](../../GLOSSARY.md)). 기존 «Selection»은 설비 선택(ADR-0059)이다.
- 선택 키는 패널 인스턴스 id 기준이고, 메뉴 간 링크는 차원·모양·값을 싣는다(ADR-0176).

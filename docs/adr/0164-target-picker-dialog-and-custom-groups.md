# 조회 대상 고르기는 한 대화창에서 축을 나란히 좁히고, 커스텀 그룹은 코어 서버에 저장해 조회 직전에 펼친다

상태: **Decided (2026-11-16)**
- 결정자: 개념·배치·이름은 소유자(#2390 본문과 댓글, 2026-11-16). 포트·저장·펼치기 방식은 레인 결정(소유자 위임 범위, 되돌릴 수 있음).
- Scope: 셸 조회 막대의 대상 편집, `@ap/components` `FacetedSetDialog`, 어댑터 포트(설비 기본 정보 전량, 커스텀 그룹), 코어 서버 저장소. 계약 원천은 [kernel.md §6.1·§6.4](../contract/kernel.md#61-식별자와-url-소유-상태-decided)와 [§21.2](../contract/kernel.md#212-소유공유-decided)이다. 관련: [ADR-0059](0059-app-injected-equipment-axes-and-condition.md), [ADR-0099](0099-server-saved-view-persistence.md).

## 맥락

조회 막대는 같은 대상 집합을 세 단추(공정, 설비 그룹 조건, 설비 선택)로 따로 고른다. 축은 하나만 고를 수 있고, 값을 보기 전에 축을 정해야 하며, 결과 대수가 끝까지 보이지 않는다. 마지막 설비 선택은 규칙을 고정 목록으로 바꾸는데 화면이 이를 알리지 않는다. 소유자는 개념(축을 나란히, 서로 좁히기와 값별 대수, 체크 안 하면 규칙·체크하면 고정, 검색 하나, 팀과 공유하는 저장 묶음)과 배치(가운데 대화창)를 정했다. 시안 비교는 #2390 댓글에 있다.

`searchEquipment`는 1–200개씩 쪽을 나눠 주므로 3만 대에서 값별 대수를 브라우저가 계산할 수 없다. 저장된 뷰의 공유 대상 묶음은 이미 코어 서버에 있다(ADR-0099). 분석 데이터와 설비 포트는 사내 서버 몫이고 코어 서버에는 핸들러가 없다.

## 결정

1. **한 단추, 한 대화창.** 조회 막대의 공정·설비 그룹 조건·설비 선택은 대상 단추 하나로 합친다. 단추는 가운데 모달 대화창을 연다. 대화창 위에는 검색 하나와 모든 축의 머리를 나란히 두고, 값 목록은 쓰는 축만 펼친다. 결과 표는 남은 높이를 모두 쓰고 보이는 행만 그린다. 대화창 안에서는 고르는 즉시 대수와 결과가 바뀌고 분석은 적용할 때 한 번 다시 조회한다. 닫힌 단추는 방식·대수·그룹 이름을 글자로 보이고 열지 않고 지울 수 있다.
2. **대수는 자기 축을 뺀 교차 수다.** 값의 대수는 다른 축의 선택을 모두 적용한 결과에서 그 값을 가진 수다. 축 사이는 AND, 한 축 안은 OR다(ADR-0059 결정 2와 같다). 0인 값도 보이고, 이미 고른 값은 자동으로 지우지 않는다.
3. **규칙과 고정.** 결과 행을 하나도 체크하지 않으면 Condition(규칙)이고 다시 열면 지금 소속으로 다시 센다. 하나라도 체크하면 Selection(고정)이다. 화면은 `조건 · 지금 N대` / `고정 N대`로 적고 적용 단추도 `조건 적용 · N대` / `고정 N대 적용`으로 방식을 말한다. 고정 상태에서 축을 바꿔도 체크한 ID는 남기고 조건 밖 ID는 따로 보인다(ADR-0059 결정 6과 같다).
4. **공정·Line·PRC 그룹은 화면에서 다른 축과 같은 급이다.** 대화창은 `roomNames`·`lineNames`·`prcGroups`를 주입 축과 나란히 보이지만 URL 키와 Context 필드는 바꾸지 않는다. 기존 링크와 저장된 뷰를 깨지 않기 위해서다. ADR-0059의 «재검토 대기»(전역 고정 키 이원 구조)는 화면 쪽만 풀렸고 키 이전은 미구현이다(아래).
5. **설비 기본 정보 전량 포트.** 새 포트 `listEquipmentFacts({ scopeId }, signal)`는 Scope와 room grant 안의 설비 전부를 `searchEquipment`와 같은 `EquipmentSummary` 행(EquipmentID, room, 축별 값 맵 — Line·PRC 소속도 서버 소유 맵 키)과 데이터 버전으로 준다. 권한 밖 설비는 행 자체가 없다. 지금 소속만 담는다. 브라우저는 이를 한 번 받아 색인하고 대수·결과·검색을 계산한다. 서버 쪽 쪽 나누기 포트(`listAxisOptions`·`searchEquipment`·`resolveSelection`)는 그대로 두며 최종 판정은 여전히 서버다.
6. **커스텀 그룹은 Condition의 플랫폼 축이다.** 저장한 묶음은 플랫폼이 붙이는 예약 축 `customGroup`의 값(그룹 id)이 되어 다른 축과 같은 맵에 들어간다(`equipmentGroup={"customGroup":["g1"],"model":["X"]}`). URL 형식은 그대로다. 앱 축 id `customGroup`은 예약한다. 그룹 하나는 규칙(축 맵, `customGroup` 축은 담지 않는다 — 중첩 금지) 또는 고정 ID 목록이다. 이름·만든 사람·Scope·버전을 갖는다.
7. **저장과 공유는 코어 서버.** 커스텀 그룹은 저장된 뷰 저장소(ADR-0099)의 세 번째 종류 `custom-group`으로 코어 서버 `platform` 스키마에 저장한다. 공개 범위는 `나만`과 공유 그룹뿐이고 공식 등록·승인은 없으며, 뷰로 복원되지 않는다. 만든 사람만 고치고 지운다. 공유 대상은 `나만` 또는 저장된 뷰의 **공유 그룹**(ADR-0099)이며, 서버가 읽을 때마다 객체 ACL만 판정한다. 공유는 메뉴·Scope·room 권한을 주지 않는다. 그룹을 읽을 수 없으면 id와 이유만 보인다.
8. **조회 직전에 펼친다.** 사내 서버는 커스텀 그룹을 모른다. Kernel은 조회 요청을 만들 때 Condition에서 `customGroup`을 떼고, 고른 그룹들의 구성원 합집합(규칙 그룹은 설비 기본 정보로 지금 소속을 계산, 고정 그룹은 ID 목록)을 Selection과 교집합해 보낸다. Selection이 없으면 그 합집합이 Selection이 된다. 서버의 Scope → room grant → Condition → Selection 판정 순서는 그대로이므로 그룹이 Condition을 우회하지 못한다. 읽을 수 없는 그룹이 있으면 조회하지 않고 이유를 보인다(빈 결과로 바꾸지 않는다).
9. **이름.** 조회 대상 묶음은 «커스텀 그룹», 저장된 뷰를 공유받는 사람 묶음은 «공유 그룹»이다. ADR-0092·0099 본문의 «커스텀 그룹»은 지금의 «공유 그룹»을 뜻한다(2026-11-16 개명, GLOSSARY).

## Considered Options

- **배치:** 막대 아래 비모달 판, 오른쪽 옆 시트, 가운데 대화창을 같은 시나리오로 비교했다(#2390). 옆 시트는 축이 세로로 쌓여 «나란히»를 지키지 못하고, 비모달 판은 폭 1,100px로 분석을 대부분 덮어 비모달의 이득이 작다. 대화창(채택)은 초점·Esc·취소의 뜻이 분명하다.
- **대수 계산:** 서버에 축마다 대수를 묻는 포트를 더할 수 있으나 고를 때마다 7개 축 왕복이 생긴다. 전량 한 번(채택)은 3만 대 규모에서 소유자가 정했다.
- **커스텀 그룹 저장소:** 코어 서버에 별도 모듈을 둘 수 있으나 저장된 뷰가 이미 가진 객체 ACL·공유 그룹·버전·HTTP 명령·mock 저장소를 다시 만들게 된다. 저장된 뷰의 새 종류(채택)는 그 기계를 그대로 쓰고 종류별 제한(공개 범위, 승인 없음)만 더한다.
- **커스텀 그룹 평가:** 사내 서버가 그룹을 읽어 평가하면 규칙 그룹의 과거 소속까지 서버가 맡을 수 있지만 사내 서버에 새 저장소 의존이 생긴다. 조회 직전 펼치기(채택)는 사내 서버를 바꾸지 않는 대신 커스텀 그룹을 지금 소속으로만 평가한다.
- **Line·PRC 키 이전:** 같은 맵 축으로 옮기면 계약이 한 가지가 되지만 기존 링크·저장된 뷰 이행이 필요하고 사용자가 보는 차이는 없다. 화면에서만 같은 급으로 둔다(채택).

## 구현하지 않는 것 (미구현)

- `lineNames`·`prcGroups`를 Condition 축으로 옮기는 키 이전. 다시 여는 조건: 업무 시스템과 무관한 전역 키만 남기는 ADR-0059 재검토(#557 이후)를 소유자에게 올릴 때.
- 커스텀 그룹과 `membershipBasis=asOf`. 펼치기가 지금 소속만 계산하므로 커스텀 그룹이 있으면 그 시점 소속을 고를 수 없다(조용히 바꾸지 않고 막는다). 다시 여는 조건: 설비 기본 정보에 소속 이력이 들어오거나 사내 서버가 그룹을 평가하게 될 때.
- 대화창 안 값별 대수의 그 시점 소속. `asOf`를 고르면 대수는 지금 소속 기준임을 표시하고 최종 결과는 서버가 판정한다. 다시 여는 조건: 위와 같다.
- 조직 팀 단위 공유. ADR-0099와 같은 이유(믿을 만한 멤버십 원천 없음)다.

# ADR-0136 — 기능 검증은 기대 동작표로 판정하고 플랫폼 제공 기능을 Home에서 눌러서 확인한다

- 상태: Decided (2026-11-10, 소유자 결정, 되돌릴 수 있음). 이슈 [#1660](https://github.com/hjung3113/analytics-platform/issues/1660).
- 결정자: 소유자 — 초안의 추천안에 "추천대로"(2026-11-10), 점검 대상과 방법을 추가 지시.
- 바꾸는 결정: 메뉴 활용률 열람 권한([05](../overview/roadmap-and-open-questions.md), [§9.1](../contract/kernel.md)의 "개발자·운영자 기본 + 개별 부여").

## 배경

mock E2E는 통과했지만 무엇이 맞는 동작인지 적은 기준이 없어 전수 점검의 통과와 결함을 가를 수 없었다. 안내서는 업무 흐름 쪽만 다루고, 계약은 흩어져 있으며, 일부 동작은 근거가 없거나 원본끼리 달랐다. 실서버 자동 묶음은 CI에서 돌지 않아 낡은 테스트가 남아 있었다.

## 결정

1. 기대 동작은 [`docs/product/expected-behavior/`](../product/expected-behavior/README.md)의 공통 문서와 표에 둔다. 표에는 눌러서 확인할 수 있는 문장과 원본 링크만 적고 규칙은 복사하지 않는다. 근거가 없으면 지어내지 않고 기준 없음으로 적는다.
2. 점검 대상은 플랫폼이 제공하는 것이다. 메뉴는 견본이다. 공통 부품은 메뉴가 노출한 곳에서 기능을 하나씩 확인하고, 메뉴가 어떤 데이터를 보여야 맞는지와 메뉴 고유 업무 기능은 보지 않는다.
3. 점검은 Home에서 시작해 사람처럼 눌러서 한다. 주소 입력은 딥링크와 새로고침 자체를 확인할 때만 쓴다.
4. 결과는 통과, 결함, 확인 불가, 기준 없음·기준 충돌로 나누고 심각도는 blocker, major, minor다. 낡은 테스트의 실패는 테스트 수리로 따로 센다.
5. 검증은 mock E2E, 실서버 자동, 화면 점검, 블라인드로 나눈다. 블라인드는 `review-check-terra` 역할 effort `medium`으로 업무 흐름 한 공간에서 시범하고 `xhigh`와 비교한 뒤 넓힐지 정한다.
6. 메뉴 활용률 열람은 지금 동작대로 `console:access`(Admin)만 한다.
7. 실서버 자동 묶음은 슬라이스 마감에 돌린다.

이유: 기준을 한곳에 모으되 원본을 복사하지 않아야 문서가 어긋나지 않고, 근거 없는 동작이 드러난다. 플랫폼 위 메뉴는 사내에서 다시 만들므로 메뉴의 값을 검증해도 남는 것이 없다. 화면을 눌러서 확인해야 사용자가 겪는 경로의 결함이 보인다.

## 대안

- **안내서에 모두 추가:** 안내서는 하려는 일 순서이고 업무 흐름 쪽만 다룬다. 점검표를 넣으면 안내서 구실을 못 한다.
- **메뉴마다 명세 문서 신설:** 계약과 ADR을 옮겨 적게 되어 원본이 둘이 된다.
- **E2E 코드를 명세로:** 소유자가 읽을 수 없고 실서버에서 못 도는 메뉴가 비게 된다.
- **활용률 열람을 문서대로 넓히기:** 볼 수 있는 사람이 달라지고 개별 부여 쓰기 수단도 새로 만들어야 한다.

## 추천이 바뀌는 조건

- 사내 메뉴가 들어와 메뉴별 값 검증이 플랫폼 책임이 될 때.
- 블라인드 시범에서 표 점검이 놓친 결함이 나오지 않거나, 반대로 표 점검보다 많이 찾을 때.
- 역할 소속 원천([#98](https://github.com/hjung3113/analytics-platform/issues/98))이 정해져 활용률 열람 부여가 필요해질 때.

# 업무 시스템은 레일 맨 위 전환기 하나로 바꾸고, 레일은 현재 시스템의 섹션으로 쓴다

상태: **Proposed (2026-10-18)** — 방향 검토, 구현 안 함. 채택되면 [ADR-0028](0028-workspace-shell-launcher-pinned-feedbackops-global-utilities.md)의 "공간 전환은 레일 하나"·"레일 맨 위 로고 = 홈 링크"·FeedbackOps "새 탭"·"레일 하단 FeedbackOps 전체"를 대체한다. 카드 런처 홈, 사이드바 바닥 고정 FeedbackOps 블록, 전역 유틸리티, 마지막 화면 복원은 그대로 둔다. FeedbackOps를 셸 안에서 여는 부분은 [ADR-0038](0038-host-module-contract-and-feedbackops-mounting.md)(Proposed) 채택이 전제다.
- 결정자: 사용자 (미정) — 방향은 사용자 제안(2026-10-18): "FeedbackOps는 두 단을 쓰잖아? 다른 시스템도 그럴 수 있고 … 아이콘 모양 눌러서 시스템 변경하는 방안은 어때?", "피드백옵스 연계는 A로 하더라도 결국 시스템마다 분리도 필요하지 않나?"

ADR-0028은 레일을 공간(업무 시스템) 전환에, 사이드바를 현재 공간의 그룹·메뉴에 썼다. 그런데 FeedbackOps 앱은 이미 자기 레일(홈·VOC·Findings·Tasks·연동·Surveys·관리자)과 사이드바 두 단을 쓰고, 앞으로 들어올 시스템(표준 로그 개발 등)도 메뉴가 많아 두 단이 필요할 수 있다. 플랫폼 레일이 시스템 전환을 차지하면, FeedbackOps 화면을 셸 안에 올릴 때(ADR-0038) 그 레일을 사이드바로 접거나 세 번째 단을 만들어야 한다. 셸 탑재 방식 A–D를 클릭형 시안으로 비교했고(#249 코멘트), UX 리뷰(로컬 `.review/mw-shell/MW-UX-REPORT.md`)는 D의 시스템별 레일 + A의 FeedbackOps 이동·복귀를 권했다. 화면 사양은 [15 §3.2](../15_multi_workspace_ui.md#32-시스템별-레일-candidate-adr-0042)가 소유한다.

## 결정 (제안)

- **시스템 전환은 레일 맨 위 전환기 하나.** 누르면 권한 있는 업무 시스템 목록(현재 표식, `이어서: <메뉴명>`)과 `플랫폼 홈` 링크가 뜬다. 버튼은 현재 시스템을 드러낸다(시스템 아이콘 + 작은 펼침 표시, 접근 이름 `업무 시스템 전환 · 현재: <시스템>`).
- **레일 가운데는 현재 시스템의 섹션.** 플랫폼 레지스트리의 그룹이 섹션이 된다(생산성 분석: 분석·설비관리·기준정보관리). 모듈 시스템은 자기 섹션을 그대로 낸다(FeedbackOps: 홈·VOC·Findings·Tasks·Surveys·관리자). 사이드바는 고른 섹션의 메뉴다. 섹션이 하나인 시스템도 레일을 채우려고 섹션을 쪼개지 않는다.
- **레일 아래는 플랫폼 공통 도구로 고정**: 메뉴 검색(모든 시스템, 결과에 `시스템 › 섹션 › 메뉴`), 분석 보드 진입([16](../16_analysis_board.md), 미구현 자리), 도움말, 언어, 사용자. 시스템을 바꿔도 위치가 변하지 않는다.
- **FeedbackOps는 업무 시스템 하나.** 전환기에서 들어가면 자기 레일·사이드바로 열린다. 업무 시스템 사이드바 바닥 블록 `FeedbackOps · <시스템>`은 FeedbackOps로 이동하며 업무 시스템(Managed System)을 미리 채우고, 본문 맨 위에 `← <출발 메뉴>로 돌아가기` 줄을 둔다. 전체 허브는 FeedbackOps 안에서 담당자에게만 보인다.
- **홈은 유지한다.** 홈 카드와 전환기 목록은 같은 권한 필터·이름·순서를 쓰고, FeedbackOps도 포함한다. 준비 중 시스템은 전환기에서 비활성 행으로만 보이고 빈 화면으로 이동시키지 않는다.

## Considered Options

- **(현행) ADR-0028 유지 — 레일 = 공간 전환**: 시스템 이동이 한 번이고 이미 구현돼 있다. 대신 두 단 메뉴를 가진 시스템(FeedbackOps)을 올리면 그 레일을 사이드바로 평탄화하거나 세 번째 단이 생긴다. 시스템이 늘수록 레일이 길어진다.
- **(A) 레일에 협업 공간 하나 추가**: FeedbackOps 연결(이동 + 미리 채움 + 복귀)은 명확하지만, FeedbackOps 메뉴가 협업 사이드바 한 단으로 평탄화된다. 연결 방식만 채택.
- **(B) 공간마다 협업 그룹**: 같은 FeedbackOps 화면이 공간 수만큼 등록되고, 담당자가 여러 시스템을 한곳에서 볼 수 없다.
- **(C) 오른쪽 패널에서 빠른 등록**: 분석을 끊지 않지만 상세 슬롯과 자리가 겹치고 FeedbackOps 전체 탐색 구조가 없다. 나중에 빠른 등록만 따로 더할 수 있다.
- **(D, 제안) 전환기 + 시스템별 레일, 연결은 A 방식**: 시스템마다 자기 두 단 구조를 유지하고 레일이 시스템 수와 무관하다. 대신 시스템 사이 이동이 두 번 누르기가 되고, 레일 아이콘의 의미가 시스템마다 바뀌므로 현재 시스템 표식이 필수다. ADR-0028이 기각한 "로고 팝오버 런처"와 겉모양은 비슷하지만, 그때의 문제(레일 공간 버튼·팝오버·사이드바 머리 전환기의 중복, 메뉴 끝에 묻힌 진입)는 이 안에 없다 — 전환 경로가 전환기 하나이고 바닥 블록은 고정이다.

## 결과

- 채택하면 ADR-0028을 부분 대체로 바꾸고, 06 §9.1의 레일·로고 문장과 15 §3.1을 15 §3.2로 옮긴다. Registry의 그룹이 섹션 역할을 하므로 모양 변경은 작다. 모듈 시스템의 섹션 선언 모양은 ADR-0038의 호스트 계약에서 정한다.
- 보이는 모양이 바뀌므로 실제 앱 위 `?variant=` 시안 컨펌이 먼저다(루트 AGENTS). 다음 시안이 다룰 보완은 15 §3.2.
- Context 바는 "현재 칸의 Context 편집기"로 적는다. 본 화면은 칸이 하나인 경우이고, 분석 보드(#421)가 생겨도 의미가 바뀌지 않는다.
- 추적: #249(지도), #421(분석 보드 자리).

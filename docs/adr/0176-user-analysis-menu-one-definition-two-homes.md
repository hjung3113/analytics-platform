# 사용자 분석 메뉴는 정의 형식 하나를 두 곳에 담고, 숫자 등급을 화면이 말한다

상태: **Decided (2026-11-23, 소유자 결정 — 후속 리뷰 권고 채택)**. 계약 문구는 구현 이슈에서 [06 §21 저장된 뷰](../contract/kernel.md#21-saved-view-contract), [§16 차트](../contract/chart.md), [§22 메뉴 간 연결](../contract/cross-menu-links.md)에 넣는다. ADR-0171의 출력 연결 금지를 부분 개정한다.

소유자는 «노코드쪽과 분석화면을 재사용하는것(다른사람과 공유가능한 메뉴로 만드는것)»을 플랫폼 1차 최종 목적에 가장 가까운 부분으로 꼽았다(2026-11-23). 근거와 흐름은 [노코드 사용자 분석 메뉴 리뷰](../reviews/2026-11-23-nocode-user-menu-review.md)에 있고, 에픽은 [#1761](https://github.com/hjung3113/analytics-platform/issues/1761)이다.

현재 상태는 이렇다.
- 저장된 뷰는 서버 저장, 객체 ACL, 공식 승인을 이미 갖췄다(ADR-0092, ADR-0099).
- `MenuView.panels`는 형식 없는 `unknown`이다.
- 메뉴는 정적 Registry에 등록해야만 생긴다.
- `ChartSpec`은 데이터와 콜백을 품고 있어 저장할 수 없다.

## 결정

- **정의 형식 하나.** 사용자 분석 메뉴의 내용은 `패널 인스턴스 목록 + 연결 + 배치`다.
  - 패널 인스턴스의 `source`는 둘 중 하나다. `declared`는 코드가 만든 패널이고 빌린 패널도 여기에 든다. `chart`는 설정으로 만든 패널이다.
  - 연결(`inputs[].from`, 받는 방식, 따라가기·붙잡기)은 직렬화되는 데이터다.
  - 배치는 지금의 도킹 트리다.
  - 원천은 `@ap/contracts`의 Zod 스키마 하나다. JSON Schema와 서버 검증 모델은 거기서 만든다. 서버는 저장할 때와 열 때 같은 스키마로 검증한다.
- **담는 곳 둘.**
  - 코드 메뉴에서 출발한 것은 `MenuView.panels`에 담는다.
  - 분석 데이터셋에서 출발한 것은 새 저장 종류 `analysis-menu`에 담고, 등록된 Host 메뉴 하나가 그린다.
  - 둘 다 같은 저장소, ACL, 공유, 승인 흐름을 쓴다.
  - 사용자마다 Registry 항목을 동적으로 만들지 않는다.
- **내 메뉴는 저장 객체의 내비 자리다.**
  - 사용자에게 보이는 말은 «내 메뉴»와 «공식» 둘이다.
  - 공식 승인이 코드 메뉴를 자동으로 만들지 않는다. 승인된 정의는 개발 요청의 명세가 된다.
- **순서.**
  - 기존 화면 → 내 메뉴 → 그룹 공유 → 공식 흐름을 먼저 낸다(로드맵 0~2단계).
  - 분석 데이터셋 계층(#1704)은 2단계가 끝난 뒤에 연다(소유자 2026-11-25, #2906 — 처음 결정 «나란히 진행»을 고침). 내 메뉴 사용에서 드러난 지표가 발행 우선순위가 된다.
  - 데이터셋에서 새로 만드는 흐름은 그 뒤에 온다.
- **숫자 등급.**
  - 공식 지표만 지표 버전을 단다.
  - 데이터셋 측정과 사용자 계산은 제목 줄에 `탐색` 표시를 단다. 이미지 복사와 내보내기에도 찍힌다.
  - 사용자가 붙인 제목이 공식 지표 이름과 같으면 서버가 저장을 거절한다.
  - 계산 필드는 처음에는 없다. 다음 단계에서 집계 사이 비율과 사칙연산을 연다. 행 단위 식은 닫힌 함수 목록의 식 트리로만 연다.
- **버전.**
  - 저장할 때 데이터셋과 지표 버전을 고정한다.
  - 뜻이 같은 변경은 다음에 열 때 자동으로 따라간다.
  - 뜻이 바뀌는 변경은 화면에 알리고, 바뀐 점을 미리 보여 준 뒤 사용자가 올린다. 공식 메뉴는 승인자가 올린다.
  - 다른 버전으로 말없이 바꾸지 않는다.
- **조인.** 사용자가 조인 키를 정하지 않는다. 발행자가 선언하고 서버가 승인한 관계만 쓴다.
- **공식 승인자.**
  - 공식 승인은 시스템(공간)별 승인자가 한다.
  - 데이터셋 측정을 쓴 패널이 있으면 그 데이터 책임자의 동의를 더한다.
  - 객체 권한과 데이터 권한은 지금처럼 따로다.
- **차트 설정과 그리기 입력.**
  - 저장되는 `ChartConfig`(종류·매핑·옵션)와 그리는 입력 `ChartSpec`을 가른다.
  - 순수 함수 `resolve(config, rows, fieldMeta) → ChartSpec`이 둘을 잇는다.
  - 저장물에는 hex·px·글꼴 값, 데이터, 함수가 없다.
  - 선·막대가 첫 `ChartConfig` 종류다(#2745 범위 변경).
- **선택 키와 전달.**
  - URL 선택 키는 패널 인스턴스 id 기준이다(`<인스턴스>.<출력 키>`). 코드 메뉴는 인스턴스 id가 선언 id와 같아 바뀌지 않는다.
  - 출력은 `dimension`과 `shape`(`set`/`range`)를 갖는다.
  - 메뉴 간 링크는 `{dimension, shape, 값}`을 싣는다. 목적지는 «이 차원을 이 페이지 키로 받는다»고 선언한다.
- **빌린 패널의 출력(ADR-0171 부분 개정).** 빌린 패널은 받는 화면이 소유한 분석 선택 키에만 출력할 수 있다. 원본의 URL·전역 Context·초안 쓰기 금지는 그대로다.
- **주소.**
  - `analysis-menu`는 Host 메뉴 경로 아래 서버가 낸 불투명 정의 id 하나로 연다.
  - 정의 id는 목적지 ID이고, 분석 Context와 따로 실린다.
  - 저장하지 않은 편집과 정의 본문은 주소에 싣지 않는다.

## Considered Options

- **사용자마다 Registry 항목을 동적으로 넣는다:** 정적 선언, 권한 목록, 경로 검증이 조립 시점 계약이라 받지 않았다.
- **전부 `MenuView`로 한다:** 데이터셋에서 출발하면 `menuId`와 `menuSchemaVersion`이 뜻을 잃어 받지 않았다.
- **전부 새 저장 종류로 한다:** 메뉴 뷰의 저장, 마이그레이션, 승인을 버려야 해서 받지 않았다.
- **(채택) 형식 하나, 담는 곳 둘.**
- **선·막대를 지금 `ChartSpec` 모양으로 넣는다:** 저장할 수 없는 모양이 굳어 노코드 단계에서 다시 뜯어야 해서 받지 않았다.

## 결과

- 용어 «분석 선택»과 «분석 데이터셋»을 [GLOSSARY.md](../../GLOSSARY.md)에 올렸다.
- 진행 중인 이슈의 계약 선택은 #2732–#2735, #2737, #2744, #2745에 적었다.
- 1·2단계 구현은 #1761 아래 이슈에서 한다.
  - 1단계: 패널 구성 저장(#2760), 선택기 2단계(#2761), 패널 설정 서랍(#2762), 빌린 패널 출력(#2763).
  - 2단계: 내 메뉴 내비 자리(#2764), 공식 승인 화면(#2765).
- 패널 설정 서랍과 내 메뉴 내비 자리는 새 SDK 시각 조각이자 셸 영역이라 변형과 소유자 선택을 먼저 거친다.
- 3단계 데이터셋 계층은 #1704, 4단계 이후는 #1761에 남는다.
- 제품 방향, 하지 않는 것, 단계 순서는 [사용자 분석 메뉴 — 제품 방향](../design/user-analysis-menu-direction.md)에 있다.

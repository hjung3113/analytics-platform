# 멀티 워크스페이스 셸은 카드 런처 홈 · 사이드바 바닥 고정 FeedbackOps 진입으로 하고, 홈·공지·내 VOC는 공간 밖 전역 유틸리티로 둔다

상태: **Decided (2026-10-09)**. 레일 52px, 사이드바 240/56px, 페이지 머리 50px, 오른쪽 상세 440px(ADR-0011·0013)은 바꾸지 않는다.
- 결정자: 사용자 — 실제 앱 위 `?variant=A|B|C` 시안(버리는 브랜치 `hjung3113/proto-250-workspaces`, #250)을 본 뒤 조합 판정을 UX 리뷰어(GPT-6-Astra high, 페르소나 7명의 작업 흐름 기준)에게 위임했고, 그 판정을 채택했다. 홈·공지·내 VOC를 전역 유틸리티로 두는 계약 변경은 사용자가 직접 골랐다.

ADR-0026은 공간을 업무 시스템 단위로 나누고 레일은 공간 전환, 사이드바는 현재 공간 메뉴만 보이기로 했고, ADR-0027은 FeedbackOps를 공간별 진입 링크로 정했다. 남은 질문은 플랫폼 홈의 모양, FeedbackOps 진입이 사이드바 어디에 놓이는지, 기존 메뉴(운영 개요·설비관리·기준정보관리·공지·내 VOC)의 귀속이었다. 시안에서 드러난 제약도 있었다: 모든 메뉴가 그룹을 거쳐 어느 공간에 속해야 해서, 지표관리만 쓰는 현업 문의자는 생산성 분석 공간에 있는 내 VOC·공지를 열 수 없었다.

## 결정

- **플랫폼 홈 = 카드 런처.** `/`는 사이드바 없이 업무 시스템 카드(이름·한 줄 목적·검증된 마지막 화면이 있으면 `이어서: <메뉴명>`) → 최근 방문·즐겨찾기 → 공지 순서다. 레일 맨 위 로고는 실제 홈 링크다. 시스템 건강 상태·메뉴 수 같은 숫자는 두지 않는다.
- **FeedbackOps 진입은 사이드바 바닥 고정.** 매핑된 공간에서만 메뉴 스크롤 밖 바닥에 `FeedbackOps · <시스템>` 블록(VOC 등록 → VOC → Task → 설문, 새 탭)을 둔다. 접힘 56px에서도 아이콘 넷이 같은 순서로 남는다. 메뉴가 많은 시스템에서도 위치가 바뀌지 않는다.
- **"FeedbackOps 전체" 링크는 레일 하단 도구 영역 맨 위.** 공간 버튼과 섞지 않는다. 사이드바에 중복 링크를 두지 않는다.
- **공간 전환은 레일 하나.** 사이드바 머리의 공간 전환기와 사이드바 `업무`/`협업` 탭은 두지 않는다. 같은 공간으로 돌아오면 그 공간의 마지막 화면으로 간다 — 사용자+공간별로 탭 세션 범위에 저장하고, 가기 전에 경로·메뉴 권한·공간 진입을 다시 확인한다(실패하면 공간 첫 화면).
- **홈·공지·내 VOC는 전역 유틸리티.** 어떤 공간에도 속하지 않고 자기 메뉴 권한(`platform:view`·`notice:view`·`voc:view`)으로만 판정하며, 공간 수에 들지 않는다. 이 화면들은 업무 공간 사이드바를 붙이지 않고 레일의 공간 표식도 끈다. 계약은 [06 §9.1](../06_platform_ui_contract.md#91-워크스페이스-decided-2026-09-26)이 소유한다.
- **기존 메뉴 귀속.** 운영 개요(플랫폼 현황)는 홈 런처에 합친다. 설비관리·기준정보관리는 생산성 분석 공간에 분석 그룹 다음으로 둔다. 관리·감사는 운영 콘솔 그대로다. 경로와 메뉴 권한은 바꾸지 않는다.

## Considered Options

- **(채택) A 카드 런처 + 바닥 고정 진입 + C의 레일 하단 전체 링크 + 전역 유틸리티**: 처음 쓰는 엔지니어에게 시작점이 분명하고, 메뉴 수와 무관하게 VOC 등록이 1클릭이다. 대신 바닥 블록이 1280×800에서 메뉴 목록 높이를 약 190px 줄이고, Registry에 공간 밖 메뉴라는 새 모양이 생긴다.
- **B 레일 로고 팝오버 런처 + 메뉴 목록 끝 진입 + 사이드바 머리 전환기**: 페이지 이동 없이 전환하지만, 메뉴가 많은 시스템에서 진입이 스크롤 끝에 묻히고 공간 전환 길이 레일·팝오버·머리 셋으로 겹친다. 설비·기준정보를 운영 콘솔에 두면 운영 권한 없는 분석 엔지니어가 설비 마스터를 잃는다.
- **C 최근 작업 홈 + 업무/협업 탭 + 공통 기준정보 공간**: 숙련자에게 최근 작업이 빠르지만 기록 없는 사용자에게 효용이 없고, 링크 몇 줄에 탭 하나를 쓴다. 로그인 사용자 전원에게 열린 공통 공간은 권한 없는 사용자에게도 공간 1개를 만들어 "공간 0개" 상태를 깨뜨린다.
- **홈·공지·내 VOC를 공간 안에 둠(계약 유지)**: Registry 변경이 없지만, 그 공간 진입권 없는 사용자는 자기 VOC와 공지를 볼 수 없다.

## 결과

- 06 §9.1에 전역 유틸리티 메뉴 규칙을 더하고 기존 메뉴 귀속·마지막 화면 복원을 Decided로 바꾼다. Registry 표현(공간 없는 그룹의 필드 모양)은 구현 이슈에서 정한다.
- 셸 배치의 상세(레일·사이드바 순서, 홈 구성, 0개/1개 상태, 접힘, 접근성)는 [15 §3.1](../15_multi_workspace_ui.md#31-셸-배치-decided-2026-10-09)이 소유한다.
- 구현은 #250. FeedbackOps 블록의 실제 링크는 매핑(#81)과 링크 계약(#251)이 생기기 전까지 그리지 않는다. 표준 로그 개발·개선 실행 공간은 메뉴가 생길 때 등록한다(#252).
- "FeedbackOps 전체" 링크를 보일 권한, 공간 0개 사용자의 권한 요청 안내 목적지는 아직 정하지 않았다(#251, #250).

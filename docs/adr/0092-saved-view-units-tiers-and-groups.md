# 저장된 뷰는 조건 세트와 메뉴 뷰 두 단위이고, 소유는 개인 → 그룹 → 공식이며, 선택기는 조회 도구행에 둔다

- Status: Decided (2026-10-27)
- Decider: 저장 단위·소유 단계·그룹 일반화·커스텀 그룹 첫 구현·사람 지정은 사용자(#294 코멘트, 2026-10-27). 시안 선택은 사용자가 Astra 리뷰어에게 위임했고(#294 코멘트) 코디네이터(사용자 위임)가 기록한다. 되돌릴 수 있다.
- Scope: [#294](https://github.com/hjung3113/analytics-platform/issues/294) 결정, 구현은 [#1011](https://github.com/hjung3113/analytics-platform/issues/1011)(mock 범위). 관련: [ADR-0083](0083-condition-presets.md)(조건 프리셋 — 저장된 뷰가 아니다), [ADR-0059](0059-app-injected-equipment-axes-and-condition.md)(주입 축·Condition), [ADR-0061](0061-query-draft-applied-address-and-required-gate.md)(초안/적용 주소). 계약 본문은 `docs/contract/kernel.md` §21.

## 맥락

사용자는 "개인·팀 뷰"를 원하고, 중요한 질문은 무엇을 한 단위로 저장하느냐다. 서버 저장·ACL·감사는 사내 백엔드(#155) 합의 전이라 이 결정은 UI·계약 모양을 정하고 구현은 로컬 mock으로 검증한다.

## 대안

저장 단위: A 조건 세트 / B 메뉴 뷰 / C 보드 시트 / D 패널 하나.
시안(실제 앱 `?variant=`, 캡처 31장): A 뷰 탭 줄 / B 조회 막대 드롭다운 + 저장 버튼 / C 뷰 라이브러리 패널.

## 결정

1. **저장 단위는 A 조건 세트 + B 메뉴 뷰.** 조건 세트는 지원 Context(설비 선택·조건축·기간 규칙)를 메뉴 사이에 재사용한다. 메뉴 뷰는 한 메뉴의 적용 조건 + 필터·표 상태·차트 옵션·배치 + 패널별 좁히기 설정이다. 보드 시트(C)는 "B 여러 개의 배치"라 새 형식이 없다. 패널(D)은 #911(메뉴가 Context를 소유)과 어긋나 따로 저장하지 않고 B 안의 패널별 설정이다. 일시 hover·단순 줌·열린 대화상자는 저장하지 않는다.
2. **소유 단계는 개인 → 그룹 → 공식.** 그룹은 조직 팀(Engineer 조직단위 `team`, 인사/SSO 원천, 멤버 편집 불가; 설비 작업 대체 묶음 `stgroup`과 다르다)과 커스텀 그룹(사용자가 만들고 멤버를 관리)을 같은 계약으로 다룬다. 공유 대상은 `나만 / 사람 지정 / 그룹 / 공식 신청`이다. 사람 지정 목록은 커스텀 그룹으로 저장할 수 있다. **커스텀 그룹은 첫 구현 범위다.**
3. **공유는 권한을 주지 않는다.** 열람·복원 때마다 서버가 Scope·room·메뉴 권한을 다시 판정한다. 권한 밖 뷰는 허용된 정보만 이유와 함께 `열 수 없음`으로 보인다. 멤버 이탈·회수는 그 공유 경로를 즉시 끊는다(다른 유효 경로가 있으면 그 경로는 남는다).
4. **UI는 시안 B 기본 + 요청형 관리 표면.** 조회 도구행 안의 현재 뷰 선택기(이름 검색·그룹 필터·현재 항목 체크·`내 기본` 표시·수정됨·저장 메뉴)가 일상 경로이고, 소유자·저장 내용·승인 큐·낡음/권한 설명은 선택기의 `뷰 관리`가 여는 요청형 표면에서 본다(C의 정보 구조, 상시 도킹 패널 아님). 시안 A(탭 줄)는 뷰가 늘면 더보기 의존이고 등급·그룹을 담기 좁아 채택하지 않는다. 시안 C의 상시 패널은 본문 폭을 점유해 채택하지 않는다.
5. **Astra 지적 M1–M10·m1–m2는 구현 전 반영한다**: 되돌리기 의미 분리와 변경 전 저장 경로(M1), 기본 뷰·주소 우선순위(M2), 낡음·권한 부족의 갱신 경로(M3), 패널 좁히기는 Selection 교집합과 분리(M4), 객체별 권한과 승인 상태의 분리(M5), 그룹 저장은 공유 확정이 아님(M6), 새 그룹·선택 요약 표시와 검색(M7), QueryHistory와 승인 업무 분리(M8), 키보드·포커스(M9), 조회 도구행 통합·밀도(M10), 문구·기간 요약·부품 일관성(m1·m2). 세부는 계약 §21.

## 결과와 한계

- 선택기·저장 대화상자·공유 대상 선택기·그룹 편집기·뷰 관리 표면은 도메인을 모르는 SDK 조각이다. 메뉴는 지원 선언과 직렬화를 준다.
- 저장소는 `SavedViewStore` 포트(앱이 주입, QueryHistory와 같은 방식)다. 이번 단계의 구현은 브라우저 로컬 mock이며 서버 포트·ACL·감사는 #155에서 정한다. 공식 회수 뒤 공개 대상과 관리자 부재 시 소유권은 그때 정한다(시안의 임의 재게시는 폐기).
- 패널 설정의 실제 저장·복원은 #911이 계약을 낼 때까지 페이로드 슬롯과 읽기 전용 요약만 둔다.

## 되돌리기

저장소 포트는 선택 주입이라 주입하지 않으면 기능과 UI가 없다(메뉴 `features.savedView`가 켜진 화면만 선택기를 단다). 선택기 위치(도구행)는 ADR 갱신으로 바꿀 수 있다.

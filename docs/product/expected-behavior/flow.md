# 업무 흐름 기대 동작표

[기대 동작표](README.md)의 형식을 따른다. 공통 기대와 같은 내용은 적지 않는다. 표와 상세 패널의 기능별 기대는 [공통 부품](shared-components.md)을 따른다.

업무 흐름은 플랫폼 기능이므로 동작 자체가 대상이다. 실서버에서 시드 계정으로 확인한다. Mock Developer One은 `tableau`, Mock Developer Two는 `power-bi` 범위만 갖고 User는 권한이 없다([안내서](../../user-guide/features/manual.md) §12). 가는 길은 Home의 `업무 흐름` 카드에서 시작한다.

| 틀린 복귀 주소 | 외부 주소를 `returnTo`에 넣어 주소 입력 | 외부로 나가지 않고 복귀 줄이 나오지 않는다 | §22 복귀 줄 | 화면 점검(실서버) |
| 대시보드 범위 | 대시보드, `새로고침` | 처리할 큐와 현황이 범위에 맞게 나오고 다른 범위의 건이 섞이지 않는다 | [08 대시보드](../features/08-dashboard-system.md) FR-DASH-001 | 화면 점검(실서버) |
| 저장된 관점과 숫자 | VOC 처리 › 분류, 사이드바 `높음`·`미배정`·`연결 없음` | 관점을 고르면 그 큐가 열리고 사이드바 숫자가 남은 건수다. 처리하면 숫자가 줄어든다 | 안내서 §3 | 화면 점검(실서버) |

## VOC 처리

| 플랫폼 기능 | 견본과 가는 길 | 맞는 모습 | 근거 | 확인 |

| 상세의 읽기 전용 | VOC 처리함, 행 선택, `분류에서 변경` | 상세 패널에서는 분류를 못 바꾸고, 버튼이 그 VOC가 선택된 분류 화면으로 간다 | 안내서 §3 | 화면 점검(실서버) |
| 입력창 분리 | VOC 상세 | 리포터 답장, 내부 코멘트, 공개 업데이트가 서로 다른 입력창이다 | 안내서 §3, §4 | 화면 점검(실서버) |
| 내부 코멘트 가림 | Admin이 쓴 뒤 그 VOC의 리포터 계정 | 리포터 화면에 내부 코멘트가 없다 | 안내서 §3 | 화면 점검(실서버) |
| 상태 변경의 공개 | 리포터 상태 변경 | 공개 업데이트를 쓰거나 건너뛰는 사유를 적어야 저장된다. 건너뛰면 사유가 감사에 남는다 | 안내서 §4 | 화면 점검(실서버) |
| 범위 밖 판단 금지 | Developer One, 다른 시스템의 VOC | 분류 수단이 없다 | 안내서 §9 | 화면 점검(실서버) |
| 반복 VOC | 반복 VOC, 생성 | `draft`로 시작해 구성원을 넣고 빼고 `confirmed`로 확정한다. 묶음에서 공개 업데이트와 Task Request를 낼 수 있다 | 안내서 §5 | 화면 점검(실서버) |

## Finding과 Task

| 플랫폼 기능 | 견본과 가는 길 | 맞는 모습 | 근거 | 확인 |
| --- | --- | --- | --- | --- |
| Finding 만들기 권한 | Developer Two(`finding.manage` 없음) | 만들기와 수정 수단이 없고 읽기는 된다 | 안내서 §6, §12 | 화면 점검(실서버) |
| Finding 근거와 연결 | Finding 상세 | 근거를 추가하거나 기존 근거를 연결한다. 연결된 VOC와 Task로 이동하고 복귀한다 | 안내서 §6, §22 | 화면 점검(실서버) |
| 근거 찾기 | Finding › 근거 | 읽기 전용이다. 인용문과 부모 Finding 이름으로 찾고, `Finding 보기` 뒤 뒤로 가면 조건과 선택이 복원된다 | 안내서 §6 | 화면 점검(실서버) |
| 근거 가림 | 원본 권한이나 승인이 사라진 근거 | 내용이 가려진다 | 안내서 §6 | 화면 점검(실서버) |
| Task Request 결정 | Task 요청 | 승인, 반려, 근거 보강 요청을 고른다. 승인하면 Task로 전환하거나 기존 Task에 연결한다 | 안내서 §7 | 화면 점검(실서버) |
| 본인 승인 | Developer One의 자기 요청 | 정책이 허용할 때만 되고 감사에 별도 라벨이 붙는다 | 안내서 §7 | 화면 점검(실서버) |
| Task 보드 | Task 보드 | 카드를 끌어 상태를 옮기고 저장이 성공한 뒤에만 자리가 바뀐다 | 안내서 §7, README 공통 기대 | 화면 점검(실서버) |
| 상태 비전파 | Task를 `released`로 이동한 뒤 연결된 VOC | 리포터 상태가 그대로다 | 안내서 §0, §7 | 화면 점검(실서버) |
| Task의 맥락 이동 | Task 상세의 맥락 | 출발 Finding으로 가고 돌아올 수 있다 | 안내서 §7 | 화면 점검(실서버) |
| 마일스톤 권한 | Developer Two | 만들기 수단이 없다. Admin과 `finding.manage`가 있는 Developer One은 만들 수 있다 | 안내서 §7 | 화면 점검(실서버) |

## 설문

| --- | --- | --- | --- | --- |
| 초안 만들기 | 설문 운영 › 설문 관리, 설문 생성 | 시작 방법이 처음에 `빈 설문`이다. `초안 만들기`가 성공하면 그 설문의 builder로 가고 응답 수집은 시작되지 않는다 | 안내서 §8 | 화면 점검(실서버) |
| 생성 실패 | 같은 창, 입력 유지 | 실패해도 입력이 남고, 취소하면 입력과 문항 선택이 초기화된다 | 안내서 §8 | 화면 점검(실서버) |
| 문항 고정 | `open` 설문의 builder | 문항 추가, 삭제, 순서 변경이 되지 않는다 | 안내서 §8, §11 | 화면 점검(실서버) |

| 개인 응답 권한 | Admin(명시 권한 없음), 설문 결과 | 개별 응답 원문과 내려받기가 막힌다 | 안내서 §8, §12 | 화면 점검(실서버) |
| 후속 조치 | 저조 평점이 있는 닫힌 Outcome 설문, `후속 조치 검토` | 응답별 화면이 열리고 `후속 조치 없음…`에 사유가 필요하며 `다시 열기…`로 바꾼다 | 안내서 §8 | 화면 점검(실서버) |

## 연동과 설정

| 플랫폼 기능 | 견본과 가는 길 | 맞는 모습 | 근거 | 확인 |
| --- | --- | --- | --- | --- |
| 연동 복구 항목 | 연동 › 연동 대시보드 | 대시보드와 연동이 같은 복구 항목을 보여도 수명 상태는 하나다. `내 화면에서 이번 항목 숨기기`는 표시만 바꾸며 다른 화면의 집계는 바뀌지 않는다 | 08 대시보드 Purpose | 화면 점검(실서버) |
| 연결의 권한 | 연동 › 연결 관계 | 숨김 행은 상태, 시스템, 만든 사람과 시각만 보이고 양쪽 대상 ID와 요약이 없다. `internal_only` 연결은 리포터에게 보이지 않는다 | [11 연결](../features/11-entity-linking.md) FR-LINK-002 | 화면 점검(실서버) |
| 커버리지 표시 | 연동 › 커버리지 | 부분 연동을 전체처럼 보이지 않게 커버리지를 함께 표시한다. 0건을 수집 중단으로 말하지 않는다 | 08 대시보드 Coverage Metrics, FR-DASH-003 | 화면 점검(실서버) |
| 시스템 관리 | 설정 › 시스템 | 등록, 보관, 기본 담당자·검토자 지정이 된다 | 안내서 §10 | 화면 점검(실서버) |
| 기본 담당자 적용 | 기본 담당자를 둔 시스템에 VOC 등록 | 담당자가 자동으로 들어가고 분류 대기는 그대로 남는다 | 안내서 §10 | 화면 점검(실서버) |
| 시스템 보관 | 보관한 시스템으로 VOC 등록 | 새 VOC를 등록할 수 없고 기존 데이터는 남는다 | 안내서 §10 | 화면 점검(실서버) |
| 분석 영역 | 설정 › 분석 영역 | 시스템 아래 분석 영역을 만들고 관리한다 | 안내서 §10 | 화면 점검(실서버) |
| 흐름 정책 | 설정 › 흐름 정책 | `권한 요청 직접 승인`을 바꾸면 권한 요청의 본인 승인에 반영된다. Task 요청의 자가승인은 이 설정과 무관하다 | 안내서 §9, §10 | 화면 점검(실서버) |

# 기대 동작표

상태: Decided (2026-11-10, 소유자, [ADR-0136](../../adr/0136-verification-expected-behavior-and-criteria.md)).

## 점검 대상

플랫폼이 제공하는 것을 본다. 메뉴는 그것을 확인하는 견본이다.

| 영역 | 원본 |

| 전역 Context | [kernel.md](../../contract/kernel.md) §6·§11 |
| 딥링크와 주소 복원 | [kernel.md](../../contract/kernel.md) §6.4 |

| 공통 부품 | [components.md](../../contract/components.md) §13·§15·§18·§19·§20 |
| 차트 계약 | [chart.md](../../contract/chart.md) §16 |

- 공통 부품은 메뉴가 노출한 곳에서 기능을 하나씩 확인한다.
- 메뉴가 어떤 데이터를 보여야 맞는지는 보지 않는다. 예를 들어 HW Time에 어떤 값이 나와야 하는지는 대상이 아니다.
- 메뉴 고유의 업무 기능도 대상이 아니다. 업무 흐름의 VOC·Task처럼 플랫폼이 제공하는 기능은 대상이다.

## 점검 방법

- Home에서 시작한다.
- 사람처럼 화면을 누르며 이동한다. 레일, 사이드바, 전환기, 화면 안 링크를 쓴다.
- 주소 입력, API 호출, 스크립트는 이 점검을 대신하지 않는다.
- 주소 입력은 딥링크나 새로고침 자체를 확인할 때만 쓴다.
- 데스크톱 1440×900만 본다.
- 역할은 Admin, Developer, User 세 가지로 나눠 본다.

## 공통 기대

메뉴 줄에는 여기와 다른 점만 적는다.

| 영역 | 기대 | 원본 |
| --- | --- | --- |
| 내비게이션 | 볼 수 있는 공간과 메뉴만 전환기·사이드바·팔레트·홈 카드에 나온다 | §9.1, §10, §17 |
| 내비게이션 | 공간을 다시 들어가면 그 공간의 마지막 화면으로 돌아간다 | §9.1 |
| 권한 | 메뉴를 열 권한이 없으면 주소를 그대로 둔 채 권한 없음 화면을 보인다. 빈 결과로 보이지 않는다 | §9.1, §17 |
| 권한 | 권한 밖 값은 필터 선택지, 결과, 내보내기, 연결에도 나오지 않는다 | §17 |
| 주소 | 주소가 가진 상태(탭, 필터, 정렬, 쪽, 상세 선택)는 새로고침과 뒤로·앞으로에서 복원된다 | §6.4 |
| 주소 | 줌, 브러시, 시리즈 표시는 복원 대상이 아니다 | §6.4 |
| 상태 | 로딩, 조회 전, 결과 없음, 오류, 권한 제한을 서로 다른 모습으로 보인다 | §19 |
| 상태 | 0건을 수집 중단이나 지연으로 말하지 않는다 | §19 |
| 쓰기 | 저장 후 화면이 서버 값으로 바뀌고, 감사 대상이면 변경 감사에 행위자와 대상이 남는다 | §4, §9.1 |
| Context | Scope와 기간을 바꾸면 그에 맞게 다시 조회하고, 이전 결과를 새 조건의 결과처럼 보이지 않는다 | §6, §11, §19 |
| 연결 | 메뉴 간 링크는 목적지가 지원하는 Context만 넘기고 권한 없는 목적지로 열어 주지 않는다 | §22 |
| 레이아웃 | 메뉴는 선언한 Page Archetype의 슬롯 순서를 따른다 | §12 |

## 판단 기준

| 결과 | 뜻 |
| --- | --- |
| 통과 | 표의 문장대로 실제로 동작한다 |
| 결함 | 표의 문장과 다르게 동작하고 재현된다 |
| 확인 불가 | 사유를 적는다: 사내 입력 필요([#150](https://github.com/hjung3113/analytics-platform/issues/150), [#151](https://github.com/hjung3113/analytics-platform/issues/151), [#155](https://github.com/hjung3113/analytics-platform/issues/155)), 실서버 미제공, 시드 없음 |
| 기준 없음 | 어떤 원본에도 근거가 없다. 결함으로 세지 않고 소유자에게 묻는다 |
| 기준 충돌 | 원본끼리 다르다. 결함으로 세지 않고 소유자에게 묻는다 |

| 심각도 | 기준 | 처리 |
| --- | --- | --- |
| blocker | 권한 우회, 데이터 누출·손실, 잘못 저장, 쓰기인데 감사 기록 없음, 주 업무가 막히고 우회로 없음 | 이슈를 열고 이번 릴리스에서 고친다 |
| major | 기대와 다르지만 우회로가 있거나 일부 경로만 해당한다. 주소 복원 실패, 오류를 빈 상태로 표시 | 이슈를 열고 이번 릴리스에서 고친다 |
| minor | 업무 영향이 없다. 문구, 보조 기기용 표시 | 결과 파일이나 [backlog](../../../.planning/backlog.md)에 남긴다 |

테스트가 낡아서 실패한 것은 제품 결함이 아니라 테스트 수리로 따로 센다.

## 검증 분담

| 층 | 맡는 것 | 작업자 | 시점 |
| --- | --- | --- | --- |
| mock E2E | 플랫폼 계약 회귀 | CI | PR, 릴리스 |
| 실서버 자동 | 메뉴×역할 진입, 저장, 권한 | 스크립트 | 슬라이스 마감 |
| 화면 점검 | 이 표의 문장을 Home에서 시작해 눌러서 확인 | `research` 역할 | 전수 점검 |
| 블라인드 | 안내서만 보고 쓸 수 있는가, 표가 놓친 것 | `review-check-terra` 역할, effort `medium`에서 시작해 `xhigh`와 비교 | 업무 흐름 한 공간 시범 뒤 결정 |

- 실서버 자동은 화면 점검을 대신하지 않는다. 사람이 누르는 점검에서 반복만 덜어 낸다.
- MARS, BRAVO, CLAS는 실서버에 분석 권한과 Site 범위가 없어 [실서버 체크리스트](../../integration/real-server-checklist.md) §8의 사용 불가 항목이다. 이 공간에서만 노출되는 공통 부품과 차트는 mock 조립에서 눌러서 확인하고, 실서버 칸은 확인 불가로 둔다.
- 블라인드 테스터에게는 실행 중인 앱, 역할 전환 방법, 메뉴 목록, [GLOSSARY](../../../GLOSSARY.md), 안내서만 준다. 이 표, 코드, 이슈, PR, 기존 테스트 결과는 주지 않는다.
- 블라인드에서 보고된 결함은 재현한 뒤에만 이슈로 올린다.

## 표 형식

공간별 표와 공통 부품 표는 같은 칸을 쓴다. 한 줄은 플랫폼 기능 하나다.

| 칸 | 적는 것 |
| --- | --- |
| 플랫폼 기능 | 확인할 기능 한 가지 |
| 견본과 가는 길 | 어느 메뉴에서, Home부터 어떻게 눌러서 가는가 |
| 맞는 모습 | 눌러서 확인할 수 있는 문장 |
| 근거 | 원본 문서와 절. 없으면 기준 없음 |
| 확인 | mock E2E, 실서버 자동, 화면 점검(실서버), 화면 점검(mock), 소유자 판단 중 하나 |

# Log Test Datasets

Index and global rules: [03-api-contracts.md](../03-api-contracts.md). This file is the normative contract for the test datasets of the log domain (#1477 node D-a): two reads and six writes of menu `log-datasets`; node b (#1478) adds two baseline reads and three baseline writes (section Baselines). Design and decisions: `docs/design/features/log-test-datasets/README.md` §2, §3.1, §3.2, §3.7, §5, §6, §8 and [ADR-0120](../../../adr/0120-regression-runs-reuse-validation-queue-dataset-identity-separate-from-round.md). Node c (#1479) adds regression suites and suite runs (section Suites and runs). Node d (#1480) adds the comparison, coverage, result review labels and the rerun diff (section Comparison). Not here yet: screens (node e). Dataset ≠ data-collection Source, Baseline ≠ metric Baseline (`GLOSSARY.md`).

## Transport and permission

- Owning menu id `log-datasets` (`LOG_DATASETS_MENU_ID`). Reads: `permission: 'platform:view'`, `requiresScope: false`, `context: {}`, `mergeTimeDomain: false`; the workspace is the session actor's and no param names it.
- A bad param is an `error` outcome (HTTP 200, `data: null`, `message`), never an empty page. The outcome set has no `not_found`: an unknown, other-workspace or invisible id answers `ok` with `data: null` (the list answers an empty page).
- **Visibility.** `share_scope = 'workspace'` is visible to every member of the workspace; `private` to its owner only (not to an Admin either). A write on a dataset the actor cannot see is `not_found` (versioned actions) or `invalid` `datasetId:not_found` (`revisionCreate`) — the same answer as another workspace's id. Only the owner changes `shareScope` (`invalid` `shareScope:owner_only`).
- Writes: `POST /api/v1/menu-action`, `requiresScope: false`, menu permission `dataset:manage`, capability `dataset.manage` (workspace-scoped, non-sensitive, **session-only**: design §9 defers token calls, so a personal or service token is refused for writes and, by the endpoints' `authorize`, for both reads too; it cannot be listed as a token scope; `adminModuleBypass: 'always'`, refused for a User recipient like `lifecycle.*`). Developers receive it by grant.
- **Availability probes** ask the Source owner's ACL first: `LogDatasetsDeps.sourceOwnerAccess` is the log-explorer `SourceOwnerAccess` seam (`denyAllSourceOwners` by default; `buildServer({ logDatasets: { sourceRead, sourceOwnerAccess } })`). A denied owner means no Source call and every file `permission_denied` (revision availability `unavailable`). The per-call (2 s) and total (10 s) deadlines are enforced by timers of the check itself, so an adapter that ignores the abort signal or never settles leaves its file `error` (availability `unverified`).
- Refusals use the dispatch envelope: HTTP 200 `{ outcome: 'invalid', fieldErrors: [{ path, code }] }`; `conflict` is only an `expectedVersion` mismatch; creates replay by `idempotencyKey`. Codes: `required`, `too_long`, `malformed`, `too_many`, `duplicate`, `not_found`, `illegal_transition`, `owner_only`, `unexpected_field`.

## Reads

| Endpoint | Params | Answer |
| --- | --- | --- |
| `logDataset.datasets` | `q?`, `page?`, `pageSize?`, `sorting?`, `filters?` (ADR-0105) | `{ rows, total }`; row = `id, name, purpose, owner{id,displayName}, shareScope, modelIds, scenarioTags, status, synthetic, revisionCount, latestRevisionSeq, version, createdAt, updatedAt`. **No stale field** (a list-wide «기준 낡음 요약» needs one Source check per dataset; not implemented, see Baselines). |
| `logDataset.datasetDetail` | `datasetId` | the head plus `revisions` (newest first) or `null` |

- Filters of `datasets`: `status` (`in`/`notIn`; `active`, `archived`), `tag` (set cell; `in` = any held, `notIn` = tagged and none of them, `isEmpty` = untagged, `isNotEmpty`), `model` (set cell over `modelIds`; same ops). Sort ids: `updatedAt` (default, desc), `name`, `status`, `createdAt`, `revisionCount`; ties by `id`. `q` matches name and purpose (case-insensitive contains).
- `datasetDetail.revisions[]`: `id, seq, sourceOwner, fileCount, digest, inputMeta, note, createdBy, createdAt, availability, availabilityChecked, baselines`. Only the **latest** revision lists `files[]` (`fileRef, order, sha256, state`, user order) and is checked against the Source **at read time**; older revisions are `availability: 'unverified'` with `availabilityChecked: false` (they are not re-checked: one Source call per file).

### Availability

A display computed at read time, never stored. Per-file states from the Source check: `match`, `hash_mismatch`, `hash_unknown` (file exists, hash not readable), `absent`, `permission_denied`, `unsupported`, `error` (call failed, aborted or out of budget). Revision availability, first match wins:

| Availability | When |
| --- | --- |
| `unavailable` | any file `absent` or `permission_denied` |
| `hash_mismatch` | else any file `hash_mismatch` |
| `available` | else every file `match` |
| `unverified` | everything else, including **no port**, `unsupported`, `error`, `hash_unknown`, or no check made |

`available` is claimed only when every file was found **and** its hash matched; an unsettled check is never shown as confirmed.

The check uses the injected `SourceReadPort` (log-explorer, ADR-0119); production injects none yet, so every availability is `unverified` there. The v0 port has no file-hash read: existence is asked with `getWindow` (line 1) and answers `hash_unknown`; a port that also offers the optional `describeFile({ sourceOwner, fileRef })` (`ok{sha256}` / `source_absent` / `permission_denied` / `unsupported`) can reach `match` / `hash_mismatch`. Start values: one call ≤ 2 s, whole check ≤ 10 s, 8 files in flight; a file not reached in time is `error`. The module never imports the synthetic adapter or `testing/`.

## Writes

| Action | `input` | Concurrency | Answer data |
| --- | --- | --- | --- |
| `logDataset.datasetCreate` | `name`, `purpose?`, `shareScope?` (default `private`), `modelIds?`, `scenarioTags?`, `synthetic?` | none | `datasetId, version` |
| `logDataset.datasetUpdate` | `id`, any of `name, purpose, shareScope, modelIds, scenarioTags` | version | `version` |
| `logDataset.datasetArchive` | `id` | version | `version` |
| `logDataset.revisionCreate` | `datasetId`, `sampleSet`, `inputMeta?`, `note?` | none | `revisionId, seq, digest, availability, availabilityChecked, fileCount, counts` |
| `logDataset.candidateCreate` | `origin`, `roundId?`, `evidenceRefs?`, `name`, `purpose?`, `modelIds?`, `scenarioTags?`, `sampleSet`, `inputMeta?`, `note?` | none | `candidateId, version` |
| `logDataset.candidateDecide` | `id`, `decision` (`approve`/`reject`), `reason?` (required for reject) | version | approve: `datasetId, revisionId, version`; reject: `version` |

- Limits: `name` 1–200, `purpose`/`note`/`reason` ≤ 2000 characters, `modelIds` ≤ 50 distinct uuids (log-knowledge stable ids; **no existence check, no FK** — an unknown id only never matches), `scenarioTags` distinct members of the closed set `normal, exception, boundary, regression, file_boundary, carryover, partial_support` (DB check too), `inputMeta` strict `{ encoding?, format? }` (confirmed values only; an unknown key is refused so a guess cannot be stored).
- `sampleSet` is the log-lifecycle shape and digest (`parseSampleSet`, `sampleManifestDigest`, re-exported, not copied): `{ sourceOwner, files: [{ fileRef, order, sha256 }] }`, ≤ 1000 files, order 1..n once. The digest is order-sensitive. The same digest twice in one dataset is `invalid` `sampleSet:duplicate`; another dataset may hold it.
- **Revisions are immutable.** `seq` is `max + 1` under the dataset row lock (`FOR UPDATE`), gapless per dataset. There is no edit or delete action; a DB trigger refuses UPDATE and DELETE for every role, and `platform_app` holds no such grant. A different file list is a new revision. An archived dataset takes no revision (`datasetId:illegal_transition`).
- **`revisionCreate` file check.** Each `fileRef` is checked through the port **before** the dataset row is locked (a slow adapter never holds the lock). The revision is created whatever the check answers; the answer is returned (`availability`, per-state `counts`) and audited but not stored. No port → `availability: 'unverified'`, `availabilityChecked: false`.
- `datasetUpdate`: a save that changes nothing answers `ok` with the current version and writes no audit row. Archived is final (`id:illegal_transition`).
- **Candidates** hold data references only (`origin` `manual`/`round_evidence`; `roundId` + `evidenceRefs` for the latter, `EvidenceRef` of log-explorer: `fileRef, line, fileSha256, note?`, no line body). No field takes code or a shell command; an unknown key is `unexpected_field`; there is no `llm` origin and no field naming another proposer: the proposer is the session actor. `candidateDecide` is final (`id:illegal_transition` when decided).
- **Approve** inserts the `dataset` (owner = proposer, `share_scope = 'workspace'`, so the reviewer sees what they decided), its first revision (`created_by` = reviewer) and the decision in **one transaction**; a failure at any step rolls all three back. **Reject** requires a reason and creates nothing.

## Baselines (#1478 D-b)

An expected baseline is the human-approved expectation per rule of ONE dataset revision (design §3.3; not the metric Baseline of the glossary). `draft` is editable; `approved` and `superseded` never change content. A baseline never changes from run results.

| Endpoint / action | Params / input | Answer |
| --- | --- | --- |
| `logDataset.baselines` | `datasetRevisionId` | `{ datasetRevisionId, datasetId, revisionSeq, rows }` or `null`; row = `id, datasetRevisionId, seq, status, profilePin, expectationCount, scopeCount, hasParserGolden, author{id,displayName}, approvedBy, approvedAt, supersededAt, version, createdAt, updatedAt, stale` (`stale` only on the approved row, else `null`) |
| `logDataset.baselineDetail` | `baselineId` | the row plus `datasetId, revisionSeq, expectedScope, expectations, parserGoldenRef, events[]` (`kind, before, after, reason, actor, selfApproved, at`) or `null` |
| `logDataset.baselineDraftCreate` | `datasetRevisionId`, `fromAttemptId?` | `baselineId, seq, version`; concurrency none |
| `logDataset.baselineUpdateDraft` | `id`, any of `profilePin, expectedScope, expectations, parserGoldenRef` (`null` clears) | `version`; concurrency version |
| `logDataset.baselineApprove` | `id`, `reason` (required, ≤ 2000) | `version, supersededBaselineId, selfApproved`; concurrency version |

- **Rights.** Draft actions: `dataset.manage` (menu permission `dataset:manage`). `baselineApprove`: `dataset.baseline.approve` (menu permission `dataset:baseline-approve`), workspace-scoped, **sensitive, session-only, no Admin role bypass**, refused for a User recipient. An Admin without the grant is `forbidden`. **Self-approval is not blocked**: the event (`self_approved`) and the audit row (`selfApproved`) record it. Reads need `platform:view` and are session-only like the dataset reads.
- **Visibility** is the dataset's: a baseline of a `private` dataset is invisible to everyone but its owner on every read and write (same absence as a missing or other-workspace id: `data: null` / `not_found` / `invalid` `datasetRevisionId:not_found`). An archived dataset's baselines are frozen (`illegal_transition`).
- **Content.** `expectedScope`: distinct `ruleId`s (≤ 1000). `expectations`: distinct `ruleId`, `expected` ∈ `PASS, FAIL, WARN, NOT_APPLICABLE, EXPECTED_UNSUPPORTED` (anything else `malformed`), optional `exception { reason, scope }` (≤ 500 each) and `evidence [{ fileRef, line }]` (≤ 20; the `fileRef` must belong to the baseline's revision, else `expectations.i.evidence.j.fileRef:not_found`); ≤ 1000 entries. `profilePin` (strict; known values only, absent = unknown): `specPin { modelId, softwareId|null, revisionId, changeSetDigest }`, `ruleSetRevision`, `parserVersion`, `engineProfileRef`. `parserGoldenRef { location, digest }` is a location and digest only, never content. A save that changes nothing answers `ok` with the current version and writes no event or audit row. `ruleId` is not checked against the rule catalog (backlog).
- **Approve and supersede are one transaction** under the dataset row lock: the revision's previous `approved` baseline becomes `superseded` first, then the draft becomes `approved` (the partial unique index is the wall). Two approvals of one revision are therefore strictly ordered and never leave two approved; the same draft approved twice is one `ok`, one `conflict`. An empty baseline (no expectation) is `invalid` `id:empty`; a baseline that is not a draft is `id:illegal_transition`. Lock order everywhere: dataset, then baselines.
- **`fromAttemptId`** (copy an attempt's results into a draft) is refused with `invalid` `fromAttemptId:unsupported`: not implemented, because no log-lifecycle read port for attempt results exists yet (reopen when it does).
- **기준 낡음** (design §3.4) is computed at read time for the **approved** baseline only, never stored and never changing the approval: `stale: { state: 'fresh'|'stale'|'unknown', reasons[], unknown[] }`. `reasons` ⊆ `file_hash_changed, file_unavailable, spec_pin_changed` are asserted only from a comparison that ran: the revision's files through the Source (Source-owner ACL first: a denied owner makes no Source call; the per-call and total deadlines of `source-check.ts`; no port = unchecked), and `profilePin.specPin` against `knowledgeLookup.getEffectiveSpecPin`. What could not be judged is listed in `unknown` (`files`, `spec_pin`, `rule_set`, `parser`, `engine_profile`) and gives `state: 'unknown'` when no reason is asserted — never `stale`. A pinned `ruleSetRevision`, `parserVersion` or `engineProfileRef` is always `unknown` while no engine capability read exists (not implemented; reopen when the engine port is fixed, design §9). `datasetDetail.revisions[].baselines` = `{ draftCount, supersededCount, approved: { id, seq, stale } | null }`; `stale` is filled for the latest revision only (from the file check the read already makes), older revisions have `stale: null`.
- Codes added: `empty`, `unsupported`.

## Suites and runs (#1479 D-c)

Reads (right `platform:view`, session only, workspace = the session's; an unknown or other-workspace suite answers `data: null`): `logDataset.suites` (`q`, `page`, `pageSize`, `sorting` `updatedAt|name|createdAt`; rows `id, name, itemCount, engineProfileRef, lastRunAt, createdBy, version`), `logDataset.suiteDetail { suiteId }` (the suite and its items; per item `resolvesTo` = the revision and baseline it would pin now, or the problem), `logDataset.suiteRuns { suiteId, page, pageSize ≤ 50 }` (runs newest first; per run the DERIVED `state` `queued|running|succeeded|failed|cancelled`, `counts` by request state, and the pinned items with their request state, attempt count, latest verdict name and the 기준 낡음 badge recorded at request time). An item whose dataset the actor cannot see (a `private` dataset of another owner) is `{ ordinal, restricted: true }` with no id, name or digest. Reads return ids, ordinals, seqs, digests and state names, never log text.

| Action | `input` | Right | Concurrency |
| --- | --- | --- | --- |
| `logDataset.suiteCreate` | `name`, `items` (1–20 of `{ datasetId, datasetRevisionId?, baselineId? }`), `engineProfileRef?` (≤ 200), `requiredPin?` (the baseline `profilePin` shape) | `dataset.manage` | none |
| `logDataset.suiteUpdate` | `id`, any of the above (`engineProfileRef: null` clears) | `dataset.manage` | version |
| `logDataset.suiteRun` | `suiteId`, `idempotencyKey` (1–200) | `dataset.suite.run` (menu permission `dataset:suite-run`) | none |

`dataset.suite.run`: Workspace scope, **not sensitive**, **session-only**, Admin passes the module bypass, a Developer by grant, a User never (the CURRENT role is checked on every run, so a grantee demoted to User is refused; `dataset.baseline.approve` precedent). Why non-sensitive: a run spends worker capacity but exposes nothing the actor cannot already read (same shape as `lifecycle.round.manage`); the per-user cap bounds the capacity. Its permission rows are in the audit projection allow-list (migration 0114 copies the 0110 body and appends it); no dataset or suite subject is projected.

`suiteRun`: (1) replay: the same `(suite, actor, idempotencyKey)` answers the same run with `replayed: true` and writes and audits nothing more; (2) cap: a user with 3 runs still active (any item request `queued` or `claimed`, counted through the lifecycle port under an advisory lock per user) is refused with `['suiteId'] suite.run_limit`; (3) every item is resolved to an APPROVED baseline and its revision (named baseline must be approved, else `baseline_not_approved`; a named revision uses its approved baseline; an omitted revision = the latest revision that has an approved baseline; none = `no_approved_baseline`; an archived dataset = `archived`; a dataset the actor cannot see = `not_found`, all at `['items','<i>','datasetId']`) and ANY failing item refuses the whole run; (4) revision, baseline, `sample_manifest_digest`, a digest of the baseline content and the 기준 낡음 badge are PINNED in `suite_run_item` (a stale baseline does not block, the badge is recorded; the Source is asked once per distinct revision behind the Source-owner ACL with the per-call/total deadlines, a denied owner or an unsettled check is `unknown`); the suite's `engineProfileRef` and `requiredPin` are snapshotted in `suite_run`; (5) one execution request per item is registered through the lifecycle port (`lifecycleSuiteRequests`, priority 0, not immediate), never by a write to a lifecycle table. `requiredPin` is stored and snapshotted; judging a baseline's pin against it belongs to the comparison (node d). Nothing changes a baseline from results.

Field errors added: `['items','<i>','datasetId'|'datasetRevisionId'|'baselineId'] not_found`, `['items'] required|too_many|duplicate`, `['suiteId'] not_found|suite.run_limit`, `['items','<i>','datasetId'] no_approved_baseline|baseline_not_approved|archived`.

## Comparison, coverage, review labels, rerun diff (#1480 D-d)

Design `docs/design/features/log-test-datasets/README.md` §3.6 / §6 / §8. Everything below is COMPUTED at read time from the run item's pinned baseline and the rule results of the item request's **latest `succeeded` attempt**; no result is copied or stored, and nothing here changes a baseline, a result or a classification. The lifecycle data is read only through the log-lifecycle barrel port `lifecycleSuiteResults` ([api/log-lifecycle.md](log-lifecycle.md#suite-result-read-port-1480)), on the caller's transaction. Responses carry rule ids, classification and result names, counts and ids only — never log text, an expected/observed text, an excerpt or an evidence location (a review label's `reason` is the reviewer's own text and is returned).

**Reads** (right `platform:view`, session only: a token is refused `forbidden`; workspace = the session's). An unknown, other-workspace or invisible run answers `ok` with `data: null` — the same answer. Visibility is the dataset's: an item whose dataset the actor cannot see is `{ ordinal, restricted: true }` (no id, name, digest, rules or labels); a run with NO visible item is the absence answer.

- `logDataset.comparison { suiteRunId, ordinal?, q?, page, pageSize ≤ 200, sorting, filters }` → `{ run { id, suiteId, createdAt, state, counts }, items[], rules { total, rows[] }, labels { total } }`. `items[]` (always every item): `ordinal, datasetId, datasetName, datasetRevisionId, revisionSeq, baselineId, baselineSeq, baselineStale, requestId, requestState, observed { attemptId, attemptNo, ruleSetRevision } | null, counts { unchanged, regressed, fixed, new, not_comparable, missing }, coverage | null, labelCount`. An item whose request has no succeeded attempt (queued, running, failed, cancelled, expired) has `observed: null`, empty `counts`, `coverage: null` and no rule rows: it is NOT classified (no «all missing»). `rules.rows[]`: `ordinal, ruleId, classification, expected | null, observed | null, required | null, label { label, reason, actorId, at } | null` (the LATEST label of that rule in this run and revision). `ordinal` restricts only the rule list. Filters (ADR-0105, one condition per field): `classification`, `observed` and `expected` (their values or `none`), `label` (a label name or `none`), `required` (`true|false`); `q` = rule id substring; `sorting` `severity` (default: regressed, not_comparable, missing, new, fixed, unchanged) | `ruleId`, ties by rule id then item.
- `logDataset.rerunDiff { fromRunId, toRunId, kinds?, page, pageSize ≤ 200 }` → `{ from, to, revisions[], diffs { total, rows[] } }`. Both runs must be runs of the SAME suite and hold the same revision at every (visible) item ordinal; items are matched by ordinal, so a suite that repeats a resolved revision keeps every item (each diff row carries its `ordinal`); otherwise `outcome: 'error'` with `data.fieldErrors = [{ path: ['toRunId'], code: 'revision_mismatch' }]` (the same run twice: `same_run`). Items are matched by `datasetRevisionId`. Per revision: `status` `compared|incomplete` (`incomplete` = a side has no succeeded attempt: nothing is compared, never reported as «no change»), both sides' observed attempt and counts, and `diffCounts { same, improved, worsened, changed, appeared, disappeared }` (complete, whatever `kinds` filters the list). `diffs.rows[]`: `datasetRevisionId, ruleId, kind, from | null, to | null` (each `{ classification, observed }`); `kinds` default = every kind except `same`. `kind`: a rule only in `to` = `appeared`, only in `from` = `disappeared`; equal classification and observed result = `same`; else by classification rank (fixed = unchanged < new < regressed < not_comparable = missing): higher = `worsened`, lower = `improved`, equal rank = `changed`. A rule that stopped being checked is therefore never an improvement.

**Classification** (rule level; `expected` from the baseline's `expectations`, `observed` from the attempt's `rule_result`; a rule is classified when it has an expectation or a result):

| expected \ observed | PASS | FAIL | WARN | NOT_CHECKED | SKIPPED | NOT_APPLICABLE | ERROR | no result |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| PASS | unchanged | regressed | regressed | not_comparable | not_comparable | not_comparable | regressed | missing |
| FAIL | fixed | unchanged | fixed | not_comparable | not_comparable | not_comparable | not_comparable | missing |
| WARN | fixed | regressed | unchanged | not_comparable | not_comparable | not_comparable | not_comparable | missing |
| NOT_APPLICABLE | new | new | new | unchanged | unchanged | unchanged | new | missing |
| EXPECTED_UNSUPPORTED | new | new | new | unchanged | unchanged | new | not_comparable | missing |
| (no expectation) | new | new | new | new | new | new | new | not classified |

The design table fixes: PASS→FAIL/WARN/ERROR regressed, FAIL→PASS fixed, EXPECTED_UNSUPPORTED↔NOT_CHECKED/SKIPPED unchanged, an observation without an expectation (including an unexpected FAIL) new, an expected check that was not made not_comparable, an expected rule absent from the result missing. The cells the design leaves open are decided here: ERROR against an expected PASS is `regressed` (named in the design's regressed row) and `not_comparable` against any other expected check; a better/worse EVALUATED result (PASS < WARN < FAIL) is `fixed`/`regressed` for an expected FAIL or WARN; a NOT_APPLICABLE expectation expects no check; an EXPECTED_UNSUPPORTED rule the engine now reports is `new`; an expectation with no result at all is `missing` even for EXPECTED_UNSUPPORTED/NOT_APPLICABLE (never silently equal). **`not_comparable` never counts as PASS** (it is neither `unchanged` nor `fixed`; tests pin all cells). A rule that occurs twice in one result keeps its least favourable result (FAIL > ERROR > WARN > NOT_CHECKED > SKIPPED > NOT_APPLICABLE > PASS); the DB's unique key makes this a pure-function guard only.

**Coverage** (per item, from `expected_scope` against the same results): a scope rule is *executed* when its result is PASS, FAIL, WARN or NOT_APPLICABLE; NOT_CHECKED, SKIPPED, ERROR and no result are *not executed* (`reason` `not_checked|skipped|error|missing`). `{ scopeCount, executedCount, notExecutedCount, ratio | null (empty scope: no ratio is invented), executed[], notExecuted[] { ruleId, reason, required }, requiredGapCount, outsideScope[] }`. `required` is the result's flag, `null` for a rule with no result (unknown). `notExecuted` is ordered required gaps first, then unknown, then non-required, each by rule id; `outsideScope` = rules that ran although the scope did not name them. Duplicate scope ids count once.

**Review labels** — action `logDataset.reviewLabelAdd { suiteRunId, ruleId (≤ 200), datasetRevisionId, label, reason (1–2000) }`, `label` ∈ `false_positive|false_negative|accepted_change|needs_review`. Right `dataset.manage` (no new capability; Workspace scope, session-only; Admin passes the bypass, a Developer by grant; a User is refused on the CURRENT role even with a live grant). Concurrency none. Rules: the run item is the one of that run holding that revision, in the actor's workspace, and its dataset must be visible (else `['suiteRunId'] not_found`; the run visible but the revision not in it: `['datasetRevisionId'] not_found`); the rule must exist in that item — named by its pinned baseline's `expected_scope`/`expectations` or reported by its latest succeeded attempt (else `['ruleId'] not_found`; ids are exact). A label is APPENDED to `log_datasets.suite_review_label` (UPDATE/DELETE refused by trigger for every role); a later label for the same rule is a new row and the latest one is shown, `labels.total` / `labelCount` count them all. A label does not change a baseline, a result or a classification (a baseline changes only by a new draft and approval). Answer `{ labelId, at }`. Field errors: `required|too_long|malformed` on the five keys, `not_found` as above.

## Audit

One `core.audit_log` row per write, in the same transaction, body-free (`packages/feature-shared/src/audit/log-datasets.ts`, strict schemas). Subject types `dataset`, `dataset_revision`, `dataset_candidate`, `dataset_baseline`. They are **not** in the `core.platform_audit_events` projection (migration 0110 adds only the capability `dataset.manage` to its permission-row allow-list): the platform audit trail (`POST /api/v1/platform/audit-trail/search`) never returns them, so a private dataset's existence does not reach `console:access` Admins. Not implemented: a dataset audit view needs a caller-aware projection (reopen when one is requested).

Never in an audit row: a `fileRef`, a hash list, sample content, the text of a note, purpose or reason (length only), an expectation, an exception reason or an evidence location. `baseline_event.before/after` hold status, seq, counts and a content digest only (the approval `reason` text is in the event row's `reason` column, which is readable through `baselineDetail`).

## Storage

Schema `log_datasets` ([04](../04-database-and-migrations.md#log-test-datasets-1477-d-a)): `dataset`, `dataset_revision`, `dataset_candidate`, `expected_baseline`, `baseline_event`, `regression_suite` (version-checked, column-limited UPDATE), `suite_run` and `suite_run_item` (immutable: trigger, every role; no stored state), `suite_review_label` (append-only: SELECT/INSERT for `platform_app`, UPDATE/DELETE refused by trigger for every role); every table has `workspace_id` and composite same-workspace FKs (`ON DELETE RESTRICT`). `platform_app`: SELECT and INSERT on the three tables, column-limited UPDATE on `dataset` and `dataset_candidate`, no DELETE anywhere, no UPDATE on `dataset_revision`. `expected_baseline`: SELECT, INSERT and a column-limited UPDATE, guard trigger for the state machine and immutability; `baseline_event`: SELECT, INSERT only, UPDATE/DELETE refused by trigger for every role.

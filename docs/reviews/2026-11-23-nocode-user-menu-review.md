# 2026-11-23 — 노코드 사용자 분석 메뉴 리뷰

## 이 문서의 지위

점검 증거 기록이다. 권위 문서가 아니다. 소유자가 이 영역을 플랫폼 1차 최종 목적에 가장 가깝다고 했다(«노코드쪽과 분석화면을 재사용하는것(다른사람과 공유가능한 메뉴로 만드는것) … 플랫폼의 1차 최종 목적과 가장 유사한 부분», 2026-11-23). 같은 날 [디자인 시스템 시각 리뷰](2026-11-23-design-system-visual-review.md)는 이 영역을 패널 추가 단계까지만 다뤘다. 그래서 Fable에게 후속 리뷰를 따로 맡겼다. 에픽은 [#1761](https://github.com/hjung3113/analytics-platform/issues/1761)(보류)이다. 끝의 «소유자에게 갈 결정»은 소유자가 권고대로 정했다(«ㅇㅋ 추천대로», 2026-11-23, [ADR-0176](../adr/0176-user-analysis-menu-one-definition-two-homes.md)). 진행 중인 이슈(#2732–#2735, #2737, #2744, #2745)에 미치는 계약 제안은 각 이슈에 «제안:» 댓글로 달았다.

## 리뷰 본문


기준: 워크트리 `uxaudit-full`, 브랜치 `docs/design-system-review-2026-11-23` (07d917ce3). 코드, ADR, 이슈를 읽어 대조했다. 앱을 띄우거나 테스트를 돌리지는 않았다. 아래 타입 이름과 JSON 모양은 전부 제안이다.

### 요약

- 1차 목표로 가는 길은 둘이고 순서가 있다. 먼저 "기존 분석 화면을 고쳐서 내 메뉴로 저장하고 공유"(흐름 a)를 낸다. 서버 저장, 객체 ACL, 공식 승인이 이미 있어서 가깝다. "데이터셋에서 새로 만들기"(흐름 b)는 데이터셋·지표 계층(#1704)이 없어서 멀다.
- 두 흐름은 저장 형식 하나를 쓴다. `패널 인스턴스 목록 + 연결 + 배치`다. 흐름 a는 그것을 `MenuView.panels`에 담고, 흐름 b는 같은 것을 새 저장 종류에 담아 Host 메뉴 하나가 그린다.
- 지금 가장 위험한 것은 #2745다. 현재 `ChartSpec`은 데이터와 콜백을 품고 있어 저장할 수 없다. 선·막대를 지금 모양 그대로 유니온에 넣으면 노코드 경로에서 한 번 더 뜯어야 한다. 저장 가능한 `ChartConfig`와 그리는 입력 `ChartSpec`을 지금 가른다.
- 두 번째는 선택 키의 이름이다. #2732가 URL 키를 패널 선언 id로 지으면 같은 패널을 두 번 넣는 사용자 메뉴에서 깨진다. 키는 인스턴스 기준으로, 메뉴 간 전달은 차원 기준으로 정한다.
- 사용자 집계 값은 화면에서 항상 "탐색"으로 표시되고 지표 버전을 달 수 없다. 공식 지표와 같은 이름을 쓸 수 없다. 이 규칙은 서버가 판정한다.

#### 눈에 띈 충돌

- **"Dataset"이라는 말이 이미 쓰인다.** `GLOSSARY.md:170`의 Dataset은 검증용 테스트 데이터셋이고, 권한 `dataset:manage`도 그 뜻이다(`apps/platform-web/src/menus.ts:50`). 분석에 발행하는 데이터셋에는 다른 이름이 필요하다. 제안은 "분석 데이터셋"(코드 `AnalysisDataset`)이고, 소유자가 정해 용어집에 올린다.
- **리뷰 H3의 "격자 6/12칸"은 지금 코드와 다르다.** 실제 배치는 도킹 트리다. 새 격자 엔진을 만들지 않고 도킹 트리를 쓴다. 지침의 "끌어 놓는 대시보드"는 이미 있는 것으로 본다.

### 2. 목표 흐름

두 흐름 모두 편집 전용 화면을 따로 두지 않는다. 분석하던 그 화면에서 고친다. Hex의 "노트북 → 앱" 두 모드를 가져오지 않는 이유는, 이 플랫폼의 분석이 이미 한 화면의 연결 패널이기 때문이다. Hex에서 가져오는 것은 세 가지다: 선택이 아래 칸의 입력이 되는 것, 발행된 화면에서 "탐색" 사본을 여는 것, 종류별 no-code 칸.

#### 흐름 a. 기존 분석 화면 → 내 메뉴 → 그룹 공유 → 공식

예: 사이클타임 상세에서 PHOTO 공정 야간 구간을 보는 화면을 만든다.

| 단계 | 사용자가 보는 것 | 하는 조각 |
| --- | --- | --- |
| 1. 조건을 맞춘다 | 접힌 조회 줄의 조건 칩. 지금과 같다 | QueryBar, Apply(ADR-0170) |
| 2. 패널을 더한다 | 조회 줄의 "+ 패널" → 720×440 팝오버. 위는 "이 메뉴의 패널", 아래는 "종류로 만들기"(범주가 옆으로 나란한 열). 종류를 고르면 오른쪽에 지표 칩과 나누기 칩 | SDK `PanelAddMenu` 확장(#2744), 패널 인스턴스 계약 |
| 3. 패널을 고친다 | 패널 ⋯ → "패널 설정" 서랍(오른쪽, 한 장). 구역 넷이 세로로: 데이터 / 매핑 / 모양 / 연결. 탭 없음 | SDK 패널 설정 서랍(새 조각), `ChartConfig` |
| 4. 선택 사슬을 만든다 | 추세에서 구간을 끌면 조회 줄에 선택 칩이 생기고 연결 패널이 갱신된다. 동작 막대의 "새 패널"로 그 선택을 입력으로 받는 패널을 더한다. 패널 머리에 `입력: 추세 구간 · 따라가기` | SDK 선택 모델, 칩, 동작 막대(#2732~#2734) |
| 5. 배치한다 | 패널 머리를 끌어 옮기고 나눈다. 지금과 같다 | `PanelWorkspace` |
| 6. 저장한다 | 뷰 선택기의 저장 메뉴 → "새 뷰로 저장". 이름 칸 아래 체크 하나: "내 메뉴에 올리기" | kernel 저장된 뷰, `MenuView.panels` 형식화 |
| 7. 내 메뉴에서 연다 | 사이드바 현재 시스템 메뉴 묶음 아래 "내 메뉴" 구역. 한 줄 = 이름 + 원본 메뉴 이름(옅은 글자). 누르면 원본 메뉴가 그 뷰로 열린다 | shell 내비 자리(새 영역, 시안 필요), kernel 뷰 목록 |
| 8. 그룹에 공유한다 | 뷰 관리 표면에서 "공유 대상: 나만 / 사람 지정 / 그룹". 받은 사람의 "내 메뉴" 구역에 "공유받음" 표시와 함께 뜬다. 받은 사람은 고칠 수 없고 "복제해서 탐색"이 있다 | kernel `setVisibility`(`saved-view.ts:104`), 서버 ACL |
| 9. 공식을 신청한다 | "공식 신청" → 승인자에게 바뀌는 점이 줄로 보인다(`changes`). 대기 중에는 일반 열람자에게 마지막 승인본이 보인다 | kernel `requestOfficial / decide`(`saved-view.ts:106-107`), 서버 |
| 10. 공식이 된다 | 그 시스템의 메뉴 묶음에 "공식 뷰"로 올라가고 이름 옆에 승인 표시. 코드 메뉴로 만드는 것은 별도 개발 요청이다 | shell 내비, 운영 콘솔 승인 큐 |

권한이 없는 사람이 링크를 열면 이름도 내용도 없는 "열 수 없음"과 사유만 본다(`saved-view.ts:71`). 패널 하나만 권한 밖이면 그 패널 자리에 사유가 뜨고 나머지는 그려진다.

#### 흐름 b. 발행된 데이터셋 → 새 분석 메뉴

| 단계 | 사용자가 보는 것 | 하는 조각 |
| --- | --- | --- |
| 1. 데이터셋을 고른다 | 데이터 카탈로그(Catalog 유형). 한 줄 = 이름, 데이터 단위(예: Job 1건), 갱신 시각, 버전, 데이터 책임자. 권한 있는 것만 보인다. 서랍에 필드 목록과 "이 데이터로 분석 만들기" | 서버 카탈로그 API(#1704, #1711), SDK Catalog 유형 |
| 2. 빈 화면이 열린다 | Host 메뉴 화면. 조회 줄에 데이터셋 칩(`Job 실행 v3`)과 기간. 본문 가운데 "+ 패널" 하나 | kernel Host 메뉴(등록된 메뉴 1개), 정의 저장 종류 |
| 3. 패널을 만든다 | 같은 팝오버. "이 메뉴의 패널" 구역이 "이 데이터셋의 지표"로 바뀐다(공식 지표, 한 번 누르면 들어감). "종류로 만들기"는 같다 | SDK `PanelAddMenu` (흐름 a와 같은 조각) |
| 4. 필드를 매핑한다 | 패널 설정 서랍. **데이터**: 지표 또는 필드 + 집계, 나누기, 거르기. **매핑**: X / Y / 계열 / 색 칸에 필드 칩을 끌어 놓거나 목록에서 고른다. 필드 칩은 역할(차원 / 측정 / 시각)과 타입 아이콘을 가진다. 맞지 않는 조합은 흐려지고 이유가 툴팁에 나온다 | SDK 서랍, 서버가 준 필드 메타와 허용 집계 |
| 5. 미리 본다 | 서랍을 고치면 패널이 바로 다시 그려진다. 사용자 집계면 제목 옆에 `탐색` 표시 | 서버 `dataset.query`(닫힌 질의), SDK `resolve(config, rows)` |
| 6. 거르기를 잇는다 | 서랍의 **연결** 구역: 이 패널이 내놓는 선택, 받는 선택(거르기 / 강조만 / 무시). 같은 데이터셋의 같은 필드는 기본으로 이어져 있다 | SDK 선택 모델 |
| 7. 저장, 공유, 공식 | 흐름 a의 6~10과 같다. 주소만 다르다 | kernel, 서버 |

조인 키는 사용자가 정하지 않는다. 데이터 책임자가 데이터셋을 발행할 때 관계를 선언하고 서버가 승인한 관계만 쓸 수 있다. 사용자에게는 "함께 쓸 수 있는 데이터셋" 목록으로만 보인다. 이것이 지침의 "조인 키 설정"을 이 플랫폼에 맞춘 해석이다.

### 3. 핵심 설계 결정

#### D1. 사용자 메뉴, 저장된 뷰, 정적 메뉴의 관계

| 안 | 내용 | 판단 |
| --- | --- | --- |
| A | 사용자마다 Registry에 `MenuEntry`를 동적으로 넣는다 | 반려. 정적 선언, 권한 목록, 경로 검증이 전부 조립 시점 계약이다 |
| B | 전부 `MenuView`로 한다. 새 화면도 "빈 스튜디오 메뉴의 뷰" | 반쪽. 흐름 a에는 맞다. 흐름 b에서는 `menuId`와 `menuSchemaVersion`이 뜻을 잃는다 |
| C | 전부 새 저장 종류로 한다 | 반려. 이미 있는 메뉴 뷰의 저장, 마이그레이션, 승인을 버린다 |
| **D (권고)** | **내용 형식은 하나, 담는 곳은 둘.** 기존 메뉴에서 출발한 것은 `MenuView`(뿌리 = 코드 메뉴). 데이터셋에서 출발한 것은 새 종류 `analysis-menu`(뿌리 = 데이터셋 참조)이고 Host 메뉴 하나가 그린다. 둘 다 같은 저장소, 같은 ACL, 같은 승인 흐름을 쓴다 | |

- "내 메뉴"는 저장 형식이 아니라 **내비에 자리를 가진 저장 객체**다. 뷰에 `nav: true` 같은 표시 하나를 더하는 것이고, 개인 기본 뷰처럼 사용자 설정으로 둔다.
- 정적 메뉴로의 승격은 자동이 아니다. 공식 승인된 정의는 개발자가 코드 메뉴를 만들 때의 명세가 된다.
- 필요한 개정: ADR-0092 §1("패널은 따로 저장하지 않는다")은 유지된다. 패널은 여전히 뷰 안에 있다. 바뀌는 것은 `panels`가 형식을 갖는 것과 저장 종류 하나가 느는 것이다.

#### D2. 정의 스키마

새 스키마를 처음부터 만들지 않는다. 층을 넷으로 가르고 층마다 기존 조각을 쓴다.

| 층 | 저장하는 것 | 기존 조각 | 저장하지 않는 것 |
| --- | --- | --- | --- |
| 데이터 | 데이터셋 참조와 버전, 지표 참조 또는 필드 + 집계, 나누기, 거르기 | `PanelDeclaration`의 입력·`grain`, `MeasureMeta` | 행, SQL, 연결 정보 |
| 설정 | 종류, X / Y / 계열 / 색 매핑, 쌓기·정렬·Top N 같은 옵션 | `ChartSpec`에서 데이터와 함수를 뺀 부분 | hex 색, px, 글꼴 |
| 그리기 | 없음. 토큰과 테마가 정한다 | ECharts 테마, 토큰 | |
| 상호작용 | 내놓는 선택, 받는 선택과 방식, 따라가기 / 붙잡기 | `outputs`, `PanelBinding` | hover, 줌, 스크롤 |
| 배치 | 도킹 트리 | `PanelWorkspaceLayout` | 엔진 원본 JSON |

```jsonc
{
  "schemaVersion": 1,
  "root": { "kind": "dataset", "ref": "job-runs", "version": 3 },   // 흐름 a에서는 { "kind": "menu", "menuId": "cycle-time" }
  "panels": [
    { "id": "p1",
      "source": { "kind": "declared", "panel": "cycle-time/trend" } },
    { "id": "p2",
      "source": { "kind": "chart",
        "data":   { "measure": { "metric": "cycle_time_p95", "version": 4 }, "by": ["equipment"] },
        "config": { "kind": "bar", "x": "equipment", "y": "measure", "stack": "none", "topN": 20 } },
      "inputs": [ { "from": "p1.range", "mode": "filter", "follow": true } ],
      "outputs": [ { "key": "set", "dimension": "equipment", "shape": "set" } ] }
  ],
  "layout": { "type": "branch", "dir": "row", "sizes": [1, 1],
              "children": [ { "type": "group", "panels": ["p1"] }, { "type": "group", "panels": ["p2"] } ] }
}
```

- 원천은 `@ap/contracts`의 Zod 스키마 하나이고, JSON Schema와 서버 검증 모델을 거기서 만든다(#531의 방향). 클라이언트와 서버가 같은 스키마로 판정한다.
- 패널 `id`는 정의 안에서만 유일한 짧은 값이고 다시 쓰지 않는다. URL 키와 연결이 이 값을 쓴다.
- `source`는 둘이다. `declared`는 코드가 만든 패널(빌려주기 포함), `chart`는 설정으로 만든 패널. 이 구분이 H절의 1단계와 2~3단계다.

#### D3. 데이터셋·지표 계층과 관리

숫자를 세 등급으로 가르고, 화면이 등급을 항상 말하게 한다.

| 등급 | 무엇 | 화면 표시 | 공식 메뉴에 쓸 수 있나 |
| --- | --- | --- | --- |
| 공식 지표 | 지표 카탈로그에 버전과 모집단이 정의된 값. 서버가 계산한다 | 제목 옆 지표 버전, 원천 줄. 지금과 같다 | 예 |
| 데이터셋 측정 | 발행자가 허용 집계를 선언한 필드(예: 실행 수 = 개수, 처리 시간 = 합·P50·P95) | 제목 옆 `탐색` 표시, 원천 줄에 `데이터셋 v3 · 사용자 집계` | 승인자가 확인한 뒤 |
| 사용자 계산 | 계산 필드 | `탐색` 표시 + 식을 툴팁에 | 아니오. 지표로 등록한 뒤에만 |

- 사용자 집계는 `metricVersion`을 가질 수 없다. 스키마에서 `metric` 참조일 때만 버전 칸이 있다.
- 사용자가 붙인 패널 제목이 공식 지표 이름과 같으면 저장을 거절한다. 서버가 판정한다.
- 공식 지표를 다른 기준으로 다시 집계하는 것은 `MeasureMeta.reaggregation`이 허락하는 방식으로만 한다. `none`이면 나누기 기준을 서버가 지원하는 것만 고를 수 있다.
- 서로 다른 데이터셋의 필드를 이름이 같다고 잇지 않는다. 승인된 관계만 쓴다.

#### D4. 계산 필드와 더할 수 없는 지표

| 단계 | 허용 | 이유 |
| --- | --- | --- |
| 처음 | 계산 필드 없음. 허용 집계 목록에서 고르기만 | 지표 등급 표시와 서버 판정이 먼저 자리 잡아야 한다 |
| 다음 | 집계된 측정 사이의 사칙연산과 비율. 비율은 분자·분모 측정을 따로 고르는 형식만(`ratioOfSums`) | 비율의 평균을 형식에서 막는다 |
| 나중 | 행 단위 식(조건, 시간 차, 구간 나누기). 닫힌 함수 목록의 식 트리로 저장하고 서버가 타입과 비용을 판정 | 임의 SQL·JS 없이 표현력을 준다 |

- 식은 문자열이 아니라 트리(JSON)로 저장한다. 편집기는 칩과 목록으로 조립하는 방식이고, 글자 입력은 그 트리로 변환되는 것만 받는다.
- 분위수는 서버만 계산한다. 브라우저는 P95를 평균하거나 합치지 않는다(`measure.ts:7`).
- 쌓기와 100%는 `sum`인 측정에만 허용한다(#2737과 같은 규칙).

#### D5. 권한과 공유

- 가시성과 승인은 지금 계약 그대로 쓴다. 새 역할을 만들지 않는다.
- 객체 권한과 데이터 권한은 따로다. 공유받아도 매 조회에서 Scope, 필드, 행 권한을 서버가 다시 판정한다(ADR-0099).
- 공식 승인 권한은 지금 `console:access`다. 메뉴 단위 정의에는 넓다. 선택지: (가) 그대로, (나) 시스템(공간)별 승인자, (다) 데이터 책임자 동의 추가. 권고는 (나) + 데이터셋 측정을 쓴 패널이 있으면 (다). 소유자가 정할 일이다.
- 승인 화면이 보여 줄 것: 쓰인 데이터셋과 지표의 버전, `탐색` 등급 패널 목록, 이전 승인본과의 차이 줄, 승인자 Scope에서 그린 실제 화면.
- 공유 대상이 그 데이터를 볼 수 없을 때는 공유할 때 "받는 사람 3명 중 1명은 패널 2개를 볼 수 없음"이라고 알린다. 막지는 않는다.

#### D6. 데이터셋·지표 버전이 바뀔 때

| 안 | 판단 |
| --- | --- |
| 항상 최신을 따라간다 | 반려. 숫자의 뜻이 말없이 바뀐다 |
| 항상 고정하고 사용자가 손으로 올린다 | 안전하지만 낡은 메뉴가 쌓인다 |
| **고정이 기본, 바뀌면 알리고 미리 보기로 올린다 (권고)** | |

- 저장할 때 데이터셋과 지표 버전을 고정한다.
- 발행자가 새 버전을 낼 때 변경을 둘로 분류한다: 뜻이 같은 변경(필드 추가, 설명 수정)과 뜻이 바뀌는 변경(모집단, 식, 단위, 필드 삭제).
- 뜻이 같은 변경은 다음에 열 때 자동으로 올라가고 원천 줄에 새 버전이 보인다.
- 뜻이 바뀌는 변경은 열 때 조회 줄에 `지표 v4 → v5 · 바뀐 점 2`가 뜨고, 누르면 차이 줄과 "올리기 / 그대로 두기"가 나온다. 메뉴 뷰의 마이그레이션 미리보기(`saved-view.ts:117-118`)와 같은 장치다.
- 공식 메뉴는 승인자가 올린다. 그전까지 옛 버전으로 그려지고 표시가 붙는다.
- 옛 버전을 서버가 더는 계산할 수 없으면 그 패널은 "이 버전은 더 제공되지 않음"과 올리기 단추를 보인다. 다른 버전으로 말없이 바꾸지 않는다.
- 발행자 화면에는 "이 버전을 쓰는 메뉴 n개"가 보여야 한다.

#### D7. URL과 딥링크

- 흐름 a: 원본 메뉴의 경로 + 뷰 id. 지금 저장된 뷰의 주소 규칙을 그대로 쓴다(그 규칙의 현재 키 이름은 이번에 확인하지 않았다).
- 흐름 b: Host 메뉴 경로 아래 정의 id 하나. 예 `/<system>/analysis/<definitionId>`. id는 서버가 낸 불투명 값이고 이름이 바뀌어도 그대로다. 정의 id는 목적지 ID이고 분석 Context와 따로 실린다.
- 판(revision)은 주소에 없으면 "내가 볼 수 있는 최신". 승인본을 가리키려면 명시 키 하나.
- 선택 키는 `<패널 인스턴스 id>.<출력 키>` 꼴이다. 패널 선언 id로 짓지 않는다.
- 저장하지 않은 편집은 주소에 싣지 않는다. 주소에 싣는 것은 조건, 선택, 고정 같은 페이지 키까지다. 정의 본문을 주소에 넣으면 길이와 보안 경계가 무너진다.
- 삭제되거나 회수된 정의의 링크는 "열 수 없음"과 사유로 끝난다. 다른 메뉴로 보내지 않는다.

#### D8. 선택 → 다음 분석이 사용자 메뉴 안에서 어떻게 이어지나

- 연결은 정의의 데이터다(`inputs[].from`). 코드가 훅으로 잇지 않는다. 그래서 사용자 메뉴와 코드 메뉴가 같은 장치를 쓴다.
- 기본 연결: 같은 데이터셋의 같은 필드를 내놓고 받는 패널은 "거르기"로 이어진다. 사용자는 서랍의 연결 구역에서 "강조만 / 무시"로 바꾼다.
- 다른 데이터셋 사이는 승인된 관계가 있을 때만 이어진다. 없으면 연결 칸이 흐리고 이유가 나온다.
- 순환은 저장할 때 거절한다. 패널 A의 선택이 B를 거르고 B의 선택이 A를 거르는 것은 "강조만"일 때만 허용한다.
- 따라가기와 붙잡기는 입력마다 저장한다. 붙잡은 값은 정의에 값으로 들어간다(값 묶음과 범위만, 행 묶음은 안 됨).
- **빌린 패널의 출력.** 지금은 금지다(`lent-panels.ts:270`). 이유는 받는 메뉴가 적용한 값을 보존하기 위해서다. 사용자 메뉴에서 코드 패널(`declared`)의 선택이 다른 패널로 흘러야 하므로, "출력은 받는 화면이 소유한 선택 키에만 쓴다"는 형태로 ADR-0171을 넓혀야 한다. 전역 Context 쓰기 금지는 그대로다.

| #2745 선·막대 `ChartSpec` | 선·막대를 지금 `ChartSpec` 모양(데이터 + 콜백 포함)으로 넣지 않는다. ① 직렬화되는 `ChartConfig`(종류 + 매핑 + 옵션, 데이터·함수 없음)를 정한다. ② 순수 함수 `resolve(config, rows, fieldMeta) → ChartSpec`을 둔다. ③ `valueFormat` 같은 함수는 형식 서술자로, 콜백은 컴포넌트 props로 옮긴다. ④ 선·막대가 첫 `ChartConfig` 종류가 되고, 기존 7종은 `ChartSpec`을 그대로 받는 경로를 유지한다 | 지침의 "Data / Configuration / Rendering / Interaction 분리"가 걸린 곳이 여기다. `AnalysisChart.tsx:36`, `:51-55`가 보여 주듯 지금 유니온은 저장할 수 없다 |

| 토큰(#2722~#2725) | ① 저장되는 설정에 hex, px, 글꼴 크기를 넣지 않는다. 색은 "어느 필드로 색을 나눈다"와 팔레트 토큰 순번까지. ② 대상 → 색 표는 패널이 아니라 데이터셋(또는 메뉴) 선언에 둔다. ③ 차트 높이는 이름 붙은 단계(촘촘 / 기본 / 큼). ④ 선택 옅은 바탕 토큰과 `탐색` 표시 색을 이번 토큰 묶음에 넣는다. ⑤ 범주색 개수를 고정하고, 넘으면 Top N + 기타로 가는 규칙을 SDK가 갖는다 | 토큰 값이 바뀌어도 저장된 메뉴가 따라오게 하려면 저장물에 값이 없어야 한다 |

### 5. 단계 로드맵

"처음 내보낼 수 있는 셀프서비스 메뉴"는 2단계 끝이다. 데이터셋에서 새로 만드는 것은 4단계 끝이다. 3단계는 0~2단계와 나란히 갈 수 있다.

| 단계 | 범위 | 종류 | 끝났다는 시험 | 의존 |
| --- | --- | --- | --- | --- |
| 0. 기반 계약 | 분석 선택(#2732~#2735), `ChartConfig` + 선·막대(#2745), 선택기 1단계(#2744), 쌓기 옵션(#2737), 용어 둘(분석 선택, 분석 데이터셋) | SDK, kernel | 사이클타임 상세에서 구간 선택 → 연결 패널 갱신 → 주소 복사 → 다른 세션에서 같은 선택. 차트 카탈로그에서 JSON 설정 하나로 선 차트가 그려진다 | 토큰 변형 선택(색 표시) |
| 1. 패널 구성 저장 | `MenuView.panels`를 패널 인스턴스 목록으로 형식화. 연결과 따라가기/붙잡기 저장. 선택기 2단계(종류 × 지표 × 나누기). 패널 설정 서랍. 빌린 패널 출력 허용(ADR-0171 개정) | SDK, kernel, 서버(검증) | 사용자 A가 패널 2개를 더하고 사슬을 만들어 저장 → 새로고침 뒤 같다. 없어진 패널 id가 든 뷰는 그 자리에 사유를 보이고 나머지는 그려진다. 옛 `panels` 값은 읽을 때 깨지지 않는다 | 0단계. kernel §21.1 개정. 서랍은 새 SDK 시각 조각이라 시안 필요 |
| 2. 내 메뉴와 공유 | 내비의 "내 메뉴" 구역, 공유받은 메뉴, "복제해서 탐색", 공식 승인 화면의 차이 줄과 등급 표시 | shell, kernel, 서버 | A가 그룹에 공유 → B의 내비에 뜨고 B의 Scope로 그려진다 → B가 그룹에서 빠지면 사라진다 → 공식 신청, 승인, 회수가 E2E로 통과 | 1단계. 내비 구역은 새 셸 영역이라 변형 2~3종과 소유자 선택. 승인 권한 결정(D5) |
| 3. 분석 데이터셋 계층 | 데이터셋 설명, 지표 정의, 허용 집계·나누기·거르기, 닫힌 질의 `dataset.query`, 발행·버전·사용처, 카탈로그. 합성 데이터셋 2종 | 서버, contracts, 운영 콘솔 | #1704 수용 기준: 비율 평균, 권한 밖 필드, 승인 없는 관계, 비용 초과를 서버가 거절한다. 발행 → 카탈로그 → 회수가 통과 | #1704, #1711, #1705(보안). 사내 Provider는 내부에서 |
| 4. 데이터셋에서 만들기 | Host 메뉴, `analysis-menu` 저장 종류, 선택기 3단계, 매핑 구역의 필드 칩, `탐색` 등급 표시, 버전 변경 알림 | kernel, SDK, 서버 | #1761 §7의 E2E: 발행 → 카탈로그 → 내 메뉴 작성 → 재열기·복제 → 권한 회수. 사용자 집계가 지표 버전 없이 `탐색`으로 보인다 | 1, 2, 3단계. Host 메뉴는 새 화면이라 시안 필요 |
| 5. 넓히기 | 집계 사이 계산(비율), 행 단위 식, 피벗 표(ADR-0007 경계 안), 데이터셋 사이 관계, 보드 칸 간 연결(#1708) | SDK, 서버 | 항목마다 따로 | #1707, #163 재개 조건. 실제 사용 사례 |

- 0단계는 이미 이슈가 있다. 이 리뷰가 더하는 것은 4절의 계약 선택이다.
- 1단계와 3단계가 시작되려면 #1761과 #911의 `on-hold`를 소유자가 풀어야 한다.
- 3단계가 가장 길다. 2단계까지를 먼저 내면 그동안 사용자가 "내 메뉴"를 쓰면서 어떤 지표와 나누기 기준을 찾는지가 드러나고, 그것이 발행할 데이터셋의 우선순위가 된다.

### 6. 위험

#### 숫자 관리
- **사용자 집계가 공식처럼 읽힌다.** 캡처해서 보고서에 붙이면 `탐색` 표시가 유일한 방어다. 표시는 제목 줄 안에 있어야 하고 이미지 복사와 내보내기에도 찍혀야 한다.
- **공식 메뉴가 낡은 지표 버전에 머문다.** 승인자가 올리지 않으면 계속 옛 값이다. 운영 콘솔에 "낡은 공식 메뉴" 목록이 필요하다.
- **같은 질문에 메뉴가 열 개 생긴다.** 그룹 공유가 쉬우면 비슷한 메뉴가 쌓인다. 공유받은 메뉴 목록에 원본(복제 출처)과 마지막 사용 시각을 보이고, 오래 안 쓴 것은 목록 아래로 내린다.
- **선택이 걸린 값이 전체 값처럼 읽힌다.** 걸러진 패널의 `필터됨 · n`이 사용자 메뉴에서도 빠짐없이 붙어야 한다. 표준 조각이 붙이게 하고 설정으로 끌 수 없게 한다.

#### 성능과 비용
- **패널마다 조회가 따로 나간다.** 패널 8개가 같은 데이터셋을 다른 기준으로 물으면 8번이다. 같은 조건·같은 질의는 공유하고, 정의 하나의 패널 수와 질의 비용에 서버 한도를 둔다.
- **선택이 바뀔 때마다 연결 패널이 전부 다시 묻는다.** 끌기가 끝난 뒤에만 묻고, "강조만"은 서버에 묻지 않는다. "거르기"가 서버에 다시 묻는지 받은 행에서 거르는지는 패널의 `grain`과 측정의 `reaggregation`으로 정한다. `sum`이 아닌 것은 서버에 묻는다.
- **높은 카디널리티 나누기.** Lot이나 Wafer로 나누면 계열이 수천이다. 서버가 한도를 넘으면 잘린 결과와 이유를 주고, 화면은 Top N + 기타로 보인다.
- 위 항목의 수치는 재지 않았다. 3단계에서 합성 데이터셋으로 잰다.

#### 보안
- **저장된 정의는 신뢰할 수 없는 입력이다.** 서버가 저장할 때와 열 때 두 번 스키마로 검증한다. 클라이언트가 보낸 권한, 필드 목록, 한도는 권위가 아니다.
- **식 트리.** 문자열 식을 서버에서 SQL로 이어 붙이지 않는다. 닫힌 함수 목록, 타입 검사, 깊이와 노드 수 한도.
- **메타데이터 누출.** 공유받은 정의에 볼 수 없는 데이터셋의 필드 이름이 들어 있다. 권한 밖 패널은 필드 이름과 제목을 지우고 사유만 내려야 한다.
- **작은 모집단.** 거르기를 겹치면 한 건까지 좁혀진다. 행 권한이 그것을 막지 못하는 데이터셋은 발행할 때 최소 n을 선언하게 한다.
- **주소에 실린 선택.** 값 묶음에 설비 id가 들어간다. ADR-0175대로 행 묶음은 싣지 않고, 값 개수 한도를 둔다.
- **사내 데이터셋 이름.** 공개 저장소의 fixture에는 합성 이름만 둔다(#1761 §6).

#### 엔지니어에게 과한 UX
- **고르는 것이 너무 많다.** 대부분은 "이 화면에 패널 하나 더"와 "이 선택으로 다음"만 원한다. 그래서 1단계(완성 패널)가 팝오버 맨 위에 있고 한 번 누르면 들어간다. 서랍은 열어야 보인다.
- **편집 흔적이 분석 화면을 덮는다.** 편집 모드, 격자선, 손잡이를 상시로 두지 않는다. 손잡이는 패널 머리에 올렸을 때만, 설정은 ⋯에서만.
- **연결이 안 보인다.** 왜 이 패널이 바뀌었는지 모르면 믿지 않는다. 패널 머리의 `입력:` 칩과 `필터됨` 표시, 칩에 올리면 출처 패널 강조. 연결선을 그리지는 않는다.
- **빈 화면에서 시작하기.** 흐름 b의 빈 Host 화면은 막막하다. 데이터셋 발행자가 "시작 배치" 하나를 함께 발행하게 하고, 사용자는 그것을 고쳐서 시작한다.
- **말이 늘어난다.** 뷰, 내 메뉴, 공식 뷰, 보드, 데이터셋이 한꺼번에 나온다. 사용자에게 보이는 말은 "내 메뉴"와 "공식" 둘로 줄이고, 뷰와 정의의 구분은 화면에 내놓지 않는다.

### 소유자에게 갈 결정

6. #1761과 #911의 보류를 1단계 범위만큼 풀지.

## 1. `06` §6.1 — 식별자·URL 소유·직렬화

### 1.1 케이싱과 매핑 소유

- **결정:** URL·JSON 공개 필드명은 camelCase, DB는 스키마 관례(snake_case). 컬렉션은 URL 반복 키(`equipmentIds=A&equipmentIds=B`), JSON은 배열.
- **근거:** `06` §6.1 예시가 이미 camelCase(`scopeId`, `equipmentIds`, `metricVersion`)이고, 콤마 결합은 ID에 예약문자가 들어올 위험이 있어 배제.
- **결정:** 공개 계약(이름·타입·카디널리티·버전·지원 Context·page-owned 키 등록)은 플랫폼 Kernel이 소유하고, 클라이언트 라우터와 서버 검증이 같은 산출물을 소비한다. SQL 컬럼/조인 매핑은 서버 소비 계층 소유(1:1 컬럼 대응을 가정하지 않음). 구현 형식(OpenAPI/JSON Schema/codegen)은 Candidate.

### 1.2 집합 키 정규화와 공집합 표식

- **결정:** 키 부재 = 무제약(권한/Scope/조회량 제한 유지). ID 1개 이상 = 선택 집합(중복 제거, 정렬은 Unicode 코드포인트, trim/대소문자/NFC로 합치지 않음). 빈/공백 ID = 형식 오류(`equipmentIds=`는 빈 ID 1개이지 "0개"가 아님). **명시적 공집합**은 집합 키마다 등록된 단일값 표식(Candidate: `equipmentSelection=none`)으로 표현하고, ID 키와 동시 사용은 오류. 공집합 지원 메뉴는 검증 후 `outcome=empty`, 미지원 메뉴는 공집합을 미적용으로 보존만 하고 자기 결과를 강제로 비우지 않는다.
- **근거:** 반복 키는 항목 0개일 때 키 자체가 사라져 "부재"와 "명시적 공집합"을 URL에서 구별할 수 없다(실측 확인: `urlencode({'equipmentIds': []}, doseq=True)` → 빈 문자열). 부재=무제약만 두면 선택 해제가 스코프 전체 조회로 위험하게 이어진다.

### 1.3 단일값 키 중복

- **결정:** `scopeId`/`from`/`to`/`v`/`metricId`/`metricVersion`/목적지 ID 등이 반복되면 같은 값이어도 형식 오류(첫/마지막 값 해석 금지).

### 1.4 전역 지표 Context = `metricId` + `metricVersion` 쌍

- **결정:** v1 전역 지표 Context는 **단일 `metricId`와 단일 `metricVersion`의 쌍**으로 공개 스키마에 함께 등록하고, 함께 보존·적용·제거한다(전역 반복 키·지표별 맵 없음). 완성/초기화 불변식:
  - 둘 다 있음 → 완성 Context. 서버가 그 조합의 유효성 검증, 실패 시 오류(최신 대체 없음).
  - ID만 있음 → **명시적으로 선언된 초기화 진입점에서만** 서버가 확인한 게시 버전을 URL에 기록(Q17). 미지원 경로는 계약 오류.
  - 버전만 있음 → 목적지 경로 계약이 소유 `metricId`를 유일하게 정의할 때만 경로 ID를 복사해 완성. 아니면 오류.
  - 둘 다 없음 → Context 없음. 경로가 지표를 유일 식별하고 초기화를 선언했으면 물질화 가능, 아니면 선택 상태.
  - 목적지 객체의 지표 ID와 전역 `metricId`가 다를 수 있음(문맥 이동) — 전역 쌍을 목적지 ID로 몰래 덮지 않는다.
- **근거:** 기존 §6.1은 지표를 `metricId`+`metricVersion`으로 식별한다면서 URL 소유 목록에는 `metricVersion`만 적어, 메뉴를 넘어가면 버전 숫자만 남아 다른 지표로 재해석될 위험이 있었다(예: cycleTime v3 → occupancy v3로 오독). 쌍으로 묶어 이 공백을 닫는다.

### 1.5 줌 vs 명시적 구간 적용 (v1 소수초 처리 포함)

- **결정:** 단순 줌/브러시/시리즈 가시성은 로컬, 플랫폼 복원 보장 밖. v1 URL 적용 대상은 초 정렬 `[from, to)`뿐이다. 판정 기준은 "구간 길이"가 아니라 **양 경계가 초에 정렬돼 있는가**다. 미정렬이면 외향 정렬(시작↓ 이전 초, 끝↑ 다음 초) 미리보기를 보여주고 사용자 확인 후에만 URL/전역 Context를 바꾼다. 취소 시 로컬 브러시만 유지. v1은 정확한 소수초 구간 공유를 지원하지 않는다는 제한을 명시한다.

## 2. `06` §6.2 — Scope·권한 (계층은 범위 밖, 조회 가드만)

- **결정:** 요청 `scopeId`는 하나(복수 Scope 자체는 여전히 Open domain decision). 부재 = 명시적 선택 상태(임의 대체 없음). 명시된 무단 ID는 침묵 제거하지 않음. 전체 권한 실패는 `outcome=forbidden`.

## 3. `06` §6.3 — 시간 계약 (메커니즘만; TZ 값·다중 사업장 같은 날짜는 범위 밖)

### 3.1 구간 경계와 문자열

- **결정:** 공통 조회 경계는 half-open `[from, to)`, `from < to` 필수, 잘못된 날짜는 비보정 거부. v1 URL `from`/`to`는 정확히 `YYYY-MM-DDTHH:mm:ss`(naive). 날짜-only·소수초·`Z`/offset은 형식 오류. 원천값·anchor 정밀도는 축소하지 않고, 비교는 원천 전체 정밀도로 한다(`to=10:00:00`이면 `10:00:00.000`과 `10:00:00.500` 모두 제외).
- **근거:** `03`이 이미 `[from, to)`를 예시로 제시. UTC/`Z` 자동 변환은 2차 리뷰에서 이미 지적된 실수(`00`, `03`)의 재연이라 배제.

### 3.2 날짜-only 해석

- **결정:** URL에는 datetime만 허용. 달력에서 고른 포함 구간 `[D1, D2]`는 `[D1T00:00:00, (D2+1일)T00:00:00)`로 UI가 변환한다("다음 날"은 naive 달력 연산이지 UTC instant+24h가 아님). 교대일/영업일/다중 사업장 같은 날짜 의미는 범위 밖.

### 3.3 원천 시간대 미확인 시 fallback

- **결정:** 단일 설비, 또는 동일 wall-clock 기준이 확인된 집합은 TZ를 몰라도 naive 조회 가능. 기본 TZ 가정·UTC 파생·타 시간역 병합은 제공하지 않고 Data Trust에 "TZ 미확인"을 표시한다. 확인된 TZ 이름이 있어도 DST 등으로 변환이 불가능할 수 있어 자동 변환 가능을 의미하지 않는다.

### 3.4 복수 설비 시간축 병합 가드

- **결정:** 서로 다른 설비를 같은 시간축으로 합치는 조회는 **서버 소유 assertion**이 있을 때만 허용한다. 최소 계약: `(equipmentId, timeDomainId, validFrom, validTo)`, 범위 `[validFrom, validTo)`(naive, 해당 설비 wall-clock). 실제 조회 대상 설비 전체·전체 요청 구간이 빈틈없이 덮이고 그 구간의 `timeDomainId`가 하나로 같아야 병합 허용. 덮이지 않으면 `time_domain_unverified`, 서로 다른 도메인이 확인되면 `time_domain_mismatch` — 둘 다 `outcome=error` 요청 검증 오류(0건/Unknown으로 위장하지 않음). `scopeId`나 클라이언트가 보낸 시간역 id는 증명이 아니다. 이력 없는 현재 스냅샷으로 과거 구간을 소급 증명하지 않는다.
- **근거:** §6.3이 이미 "확정 전 축 병합 비보장"이라 선언했고, 이를 "경고 후 허용"으로 약화하지 않기로 함.

### 3.5 기본 구간 물질화 시계 (`defaultRangeTo`)

- **결정:** 브라우저 로컬 now, UTC 문자열 절단, "watermark = now = Data through" 등식을 모두 거부한다. 서버가 해당 시간역·데이터셋의 기본 조회 상한 `defaultRangeTo`(배타적 초 경계, wall-clock)를 제공한다. "포함"은 그 점이 필터로 잘리지 않는다는 뜻이지 데이터가 완전히 도착했다는 뜻이 아니다. 기본 구간은 `[defaultRangeTo − Δ, defaultRangeTo)`(naive 길이, 자정 비정렬, Δ 숫자는 Open). 산출 불가 시 기간 선택을 요구(L2)하고, 한 번 물질화한 URL 기간을 데이터 갱신만으로 자동 이동시키지 않는다.
- **`defaultRangeTo`와 워커 진행 경계 `R`(§6.3 재집계 창, 아래 §6.3 참조) 관계:** 서로 다른 계약 필드이며 항상 같은 값은 아니다. 같은 시간역·대상일 때 `T ≤ R`인 경우에만 자동 물질화하고, 만족하는 값이 없으면 마지막 점을 버리거나 `R`을 올리는 우회 없이 선택을 요구한다(L2). `R` 부재가 독립적으로 유효한 기본 범위까지 자동으로 막지는 않는다(그때는 물질화하되 자동 재집계만 보류).

## 4. `06` §6.4 — URL vs 세션, 버전, 복원, 확정 전 조회

### 4.1 우선순위와 누락값

- **결정:** URL에 있는 키는 항상 이긴다. 없는 키를 세션/최근방문으로 채우지 않는다(세션은 적용 시 URL에 기록하는 제안값일 뿐). 시간을 요구하는 메뉴에서 기간 양쪽 부재 → 기본 구간을 물질화(L1)하거나 불가 시 선택 요구(L2). **한쪽만 있으면 오류**(보정하지 않음). 상대 기간이 물질화되기 전의 URL은 시점 의존 진입점이지 재현 가능한 링크가 아니다.

### 4.2 URL 계약 버전 `v`

- **결정:** 양의 정수 query `v`, 생략 = v1. 인바운드는 지정 버전 디코더로만 해석하고 자동 rewrite하지 않는다(북마크 의미 보존). 새로 생성하는 정규 URL만 "동등 표현 가능함을 검증한 뒤" 현재 `v`를 명시한다. 미지원 `v`는 부분 추측 없이 전체 거부. `v` ≠ `metricVersion` ≠ DB 마이그레이션 ≠ 메뉴 구현 버전.

### 4.3 잘못된 값 / 미등록 키 / 미지원 Context

- **결정:** 등록 키의 형식 오류는 조회 거부(clamp/보정 없음). 없거나 권한 없는 객체는 자동 대체하지 않는다. **등록된** 미지원 전역 Context는 URL에 남기고 미적용 표시, 지원 메뉴 복귀 시 재검증 후 적용. **미등록** 키도 현재 URL에는 남기되 검증된 조회조건으로 넘기지 않고 전역 Context로 승격하지 않는다.

### 4.4 뒤로가기와 셸 내비게이션

- **결정:** 플랫폼이 보장하는 복원 범위는 "URL이 소유한 상태"(전역 Context + 그 페이지가 URL에 쓰기로 한 탭/뷰 id + 선언됐지만 미적용인 등록 Context + 공집합 표식)로 한정한다. 줌/브러시/시리즈 가시성은 보장 밖이다. **사이드바를 포함한 셸 메뉴 전환도 Context Link helper와 같은 규칙**을 따른다: 등록된 전역 Context는 지원 여부와 무관하게 보존하고, 적용은 대상이 지원·검증할 때만 한다. helper는 "보존할 Context"와 "적용할 Context"를 구분해야 하며, "지원 키만 골라 쓴다"는 것이 URL에서 나머지를 지운다는 뜻이면 안 된다.

### 4.5 복수 Scope/시간계약 확정 전 허용 조회

- **결정:** §2의 `scopeId` 단일 원칙 + §3.4의 시간역 가드로 충분히 닫힌다. TZ 매핑이 끝날 때까지 분석을 전면 금지하지는 않는다(단일 설비 naive 조회는 계속 허용).

## 5. `06` §19 — 상태 원천/응답 스키마 (taxonomy 이름 자체는 기존 Decided 유지)

### 5.1 두 층 계약

- **결정:** 위젯/조회 단위 응답은 두 층으로 구성한다.
  1. `outcome`(배타): `ok | empty | error | forbidden | too_large | timeout`. `empty` = 성공 0건. 본 조회 실패는 `empty`가 아니라 `error`.
  2. `assessments[]`(이름 Candidate): 그 조회 계약이 선언한 **적용 kind**를 빠짐없이 1회씩, 각 항목은 `state = confirmed | clear | unknown`.
- `Loading`/`Refreshing same context`는 이 페이로드에 없다(클라이언트 생명주기). `Partial widget failure`는 위젯 결과가 섞일 때 페이지가 도출한다.
- **근거:** 단일 배타 enum으로는 `07_app_shell_wireframe.md`가 요구하는 "0건 + 원인 Unknown 공존" 시나리오를 표현할 수 없다.

### 5.2 적용 목록과 3상태

- **결정:** 플랫폼이 kind 어휘를 소유하고, 각 조회 계약이 "적용 kind 목록"을 선언한다. **원천이 아직 미구현이라는 이유로 목록에서 빼지 않는다** — 그 경우 `unknown`으로 응답한다. `clear`는 "그 kind의 문제가 없음을 원천이 실제로 확인"했을 때만 쓰는 제한적 주장이며 전반적 건강 선언이 아니다(가짜 clear 금지, statusSource/observedAt 필수). `unknown`은 생략하지 않는다.
- **`explainsEmpty`(Candidate):** `outcome=empty`이고 해당 평가가 `confirmed`이며 원천이 "그 요청의 0건 원인"을 확인한 경우에만 true(기본 false). UI는 배열 순서/행 수로 인과를 추론하지 않는다.

## 6. `05` Open Questions (세션 범위 3항)

### 6.1 실시간성 기본 정책

- **결정:** 기본은 **폴링 + 서버가 제공하는 완료된 계산 세대/갱신 정보 기반 캐시 재검증**. 원천 watermark 이동 ≠ mart 재집계 완료(감지→재계산→정합 결과 제공을 구분). 웹소켓/SSE는 "열린 대시보드에 초 단위 갱신이 필요하다"거나 "동시 편집 presence가 필요하다"는 **문서화된 요구**가 생길 때만 재평가한다(이 두 조건이 영구히 유일하다고 못박지는 않음). 폴링/워커 감지 주기의 숫자는 Open으로 남긴다.

### 6.2 파서 DB 접근 기본 정책

- **결정:** Open 항목을 "mart 소스 인스턴스가 어디에 사는가"로 재정의한다. 기본 후보는 `03`이 이미 추천한 대로 **같은 Postgres 인스턴스, 파서 read-only 역할, 플랫폼 전용 스키마**다. API는 파서 원본 테이블을 직접 조회하지 않는다(`01` 재확인). replica/분리 인스턴스는 경합 또는 보안 격리 요구가 **실제로 확인될 때** 평가 대상으로 승격한다(경합 존재만으로 자동 승격하지 않음).

### 6.3 지연 완료 허용 시간의 정책 메커니즘 (구체 숫자는 범위 밖)

- **결정:** 필수 운영 설정 `lateArrivalAutoHorizon`이 있어야 자동 재집계가 동작한다(유효 설정 없이 자동 운영을 시작하지 않고, 0/무한을 암묵값으로 넣지 않는다 — 숫자 미정이면 "설정 미충족"으로 보고). 창 **안**의 지연완료는 자동 재집계, 창 **밖**은 자동으로 재개방하지도 조용히 버리지도 않고 **식별·조회 가능한 정정/backfill 후보**로 남겨 운영자가 명시적으로 실행한다(새 승인 워크플로 UI를 지금 만들지는 않음). `autoRefreshClosed`는 "자동 창이 닫혔다"는 뜻일 뿐 "완전/불변"을 의미하지 않는다. 마스터 소급·재분류·지표 정의 변경은 이 창과 별개의 트리거다.
- **워커 판정 시계:** 자동 창의 기준은 시간역별 **원천 진행 경계 `R`**(데이터 계층 소유, naive 배타 경계, 첫 mart 세대 생성 전에도 공급 가능 — mart 계산 완료 시각·클라이언트 now·UTC 문자열 절단과는 다른 값)과 **명시적 wall-clock 길이 설정 `H`**다. 자동 창은 `[R-H, R)`이며, 버킷 `[bFrom, bTo)`가 `bFrom < R && bTo > R-H`를 만족하면 전체가 자동 대상이다. `R`이 없으면 자동 재집계만 보류하고 지연완료 식별·후보 보존은 계속한다. 원천 진행이 멈추면 창도 멈춘다 — 이는 "현실 N일 후 반드시 닫힘"이 아니라 데이터 진행 기준의 창이다.
- **근거:** "horizon 밖은 영구히 재집계하지 않는다"는 초기 제안은 원천과 mart가 영구히 어긋날 수 있어(업무 근거 없음) 기각하고, "자동 처리 창"과 "정정 허용 정책"을 분리했다.

## 8. 미해결 (in-scope이지만 이번 세션에서 닫지 않음)

1. **권한 없는 ID의 존재 여부 누설**(403 vs 404) — 서버 노출 정책으로 별도 결정, 인증 방식(범위 밖)과 인접.
2. **필드/enum 이름 확정** — `equipmentSelection`/`lotSelection`, `outcome` 값 목록, `assessments`/`explainsEmpty`/`statusSource`, `defaultRangeTo`/`R`/`H`/`lateArrivalAutoHorizon`, `timeDomainId` 등은 모두 Candidate.
3. **Δ, H, 기본 기간, 폴링/워커 주기, sunset 기간의 구체 숫자** — 메커니즘만 닫혔다.
4. **웹소켓 도입 조건의 닫힌 목록** — 기본은 폴링, 문서화된 요구가 생기면 재평가.
5. **사업장 override / 지표별 horizon** — 지금 구현하지 않음(영구 금지 아님).
6. **확인된 TZ의 변환 가능성 판정 세칙**(DST gap/overlap) — 원칙만("불가능하면 추측 금지").
7. **별도 UTC 분석 API** — URL 필터는 UTC로 바꾸지 않지만, 미래의 별도 분석 API 자체를 영구 금지하지는 않는다.
8. **v>1에서의 소수초 구간 URL** — v1 미지원.
9. **정정(backfill) 실행 UI·승인 권한 세칙** — "자동 아님 + 기존 권한/감사"만 결정, 워크플로/화면은 미설계.
10. **assessment kind 확정 문자열 목록** — 어휘 소유권만 결정, 조회 유형별 적용 목록의 구체 엔트리는 저장소 반영 시 채운다.

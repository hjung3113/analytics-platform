# 2026-11-23 — 디자인 시스템 시각 리뷰 («너무 평평해 보인다»)

## 이 문서의 지위

점검 증거 기록이다. 권위 문서가 아니다. 결정은 [ADR-0175](../adr/0175-chart-selection-feeds-next-analysis.md)에, 할 일은 아래 표의 이슈에 있다. 토큰 값과 셸 프레임 변경은 UI 시험 B라서 변형 2~3종 중 소유자가 고른 뒤에만 구현한다(이슈마다 표시). 제안 값은 시작점이다. 대비 수치는 눈으로 읽은 근사값이라 적용 전에 도구로 다시 잰다.

## 방법

- **범위:** 데스크톱 1600×1000, 라이트 테마(다크 모드는 없음), mock 개발 서버, `main` 50373da6f. 캡처한 화면은 생산성 개요, 사이클타임 상세, 차트 카탈로그 11종, HW Time, Configuration, 설비 마스터와 상세 서랍, 지표 카탈로그, 공지, 권한/역할, 변경 감사, 로그 탐색, Top View, 홈이다. 접힌 상태와 빈·오류·일부 실패·로딩 상태도 찍었다.
- **범위 밖:** 업무 흐름 대시보드와 Task 목록(실서버 필요), Wafer Journey(예정). 차트 상호작용은 정지 화면으로만 판단했다.
- **리뷰:** 1차는 캡처만 보고 판단했다(코드와 문서는 보지 않음). 이어서 코드 조사 사실(토큰 원천, 차트 경로, 선택·패널·링크 구조)을 넘겨 기존 SDK 조각 위에서 권고를 다시 맞췄다(M절).

## 결정

- 선택을 URL과 메뉴 간 링크에 싣는 범위는 권고안 (나)로 정했다. 값 묶음과 범위만 싣고 행 묶음은 싣지 않으며, 메뉴 간 링크는 목적지가 선언할 때만 싣는다([ADR-0175](../adr/0175-chart-selection-feeds-next-analysis.md)).
- 토큰 값(면·선·강조색·차트 글자·팔레트)과 사이드바 접힘은 권고대로 변형부터 만든다. 소유자가 고른 뒤 구현한다.
- 노코드와 사용자가 만들어 공유하는 분석 메뉴는 소유자가 플랫폼 1차 최종 목적에 가장 가깝다고 본 영역이다(2026-11-23). 이 리뷰는 그중 패널 추가 단계(H절)만 다뤘다. 범위와 순서는 [#1761](https://github.com/hjung3113/analytics-platform/issues/1761)과 그 후속 리뷰에서 정한다.

## 리뷰 본문

본문의 현재 값은 1차에 화면에서 읽은 추정이다. 코드 기준 값과 기존 조각에 맞춘 판단은 M절이 우선한다.

### A. 진단

#### 1. 면이 한 겹이다
- 아이콘 레일, 사이드 메뉴, 상단 제목 줄, 필터 줄, 본문 바탕이 모두 같은 옅은 파랑(약 `#EEF3FB`)이다. 구분은 1px 선뿐이다. `home`, `notices`, `equipment-master` 어디서나 같다.
- 흰 카드만 한 단계 위인데 그림자가 거의 보이지 않고 테두리도 옅은 파랑이다.
- `equipment-detail-drawer`: 서랍이 본문과 같은 파란 바탕에 선 하나로 붙어 있다. 위에 뜬 층이라는 신호가 없다.
- `notices`: 목록과 본문 패널이 바탕과 같은 색이라 카드인지조차 흐리다.

#### 2. 파랑이 너무 많은 일을 한다
같은 계열 파랑이 맡은 역할: 바탕, 표 머리 행, 차트 아래 "구간 선택" 띠, "선택 없음" 띠, 선택된 메뉴, 선택된 표 행, 히트맵, 막대, 링크, 체크박스, 주 버튼. `productivity-overview`에서 눈이 갈 곳이 없다. 색이 "여기가 데이터다", "여기가 선택됐다"를 말해 주지 못한다. 중립 회색이 사실상 없다.

#### 3. 선의 강약이 거꾸로다
- 가장 진한 선이 입력 상자 테두리다. 날짜 선택, "대상 전체", Scope 상자, 차트 아래 시작/끝 드롭다운이 진한 남색 테두리라 항상 포커스된 것처럼 보인다.
- 카드 테두리, 표 행 구분선, 카드 안 구분선이 모두 같은 푸른 회색(토큰 `#cbd6e6`) 한 단계다. 선 사이에 위계가 없고, 입력 테두리만 그보다 진하다. (처음에는 "카드 테두리가 가장 옅다"고 적었으나 토큰 값을 받고 고쳤다. 문제는 옅음이 아니라 한 단계뿐이라는 점과 푸른 기다.)
- `equipment-master`, `log-explorer`: 행 구분선이 모든 행에 같은 진하기로 들어가 줄무늬 종이처럼 보인다.

#### 4. 글자 위계가 평평하다
- 차트 도구 글자("확대 · 구간 선택 · 초기화 · 표로 보기 · 내보내기")가 카드 제목과 같은 검정, 같은 크기, 같은 굵기다. `productivity-overview`의 "Job 처리량 추세"에서는 도구 줄이 제목보다 넓고 진하다.
- `cycle-time`에서는 반대로 패널 제목("사이클타임 추세")이 12px 회색 보통 굵기라 화면에서 가장 약하다. 같은 차트 카드인데 개요 화면과 위계가 다르다.
- 10~11px 회색 글자가 여러 곳에 깔려 있다(축 단위 "분", 막대 안 값, 원천 줄).
- 표에서 설비 ID(고정폭)가 옆 칸보다 작고 가늘다. 행의 열쇠인 값이 가장 약하다.
- 잘 된 곳: KPI 숫자(`85.7`, `39.4`).

#### 5. 조작부가 데이터보다 넓다
- `cycle-time`: 제목 줄 48 + 조회 조건 줄 48 + 요약·페이지 조건·배치 줄 40. 첫 패널이 y≈152에서 시작한다. 조건을 펼치면(`min-cycle-time-filter-collapsed`) 입력 2줄 + 적용 조건 요약 줄 + 안내 줄 + 배치 줄이 쌓여 첫 패널이 y≈330이다. 화면 높이의 1/3이 조작부다.
- 패널마다 머리가 두 줄이다(제목 줄 40 + 아이콘 도구 줄 36).
- 차트 아래 "시작/끝/선택/빠른 구간 선택/선택 구간 없음" 블록이 차트마다 약 150px다. 선택이 없어도 자리를 잡는다.
- `min-nav-collapsed`: 메뉴를 접어도 레일 두 개(52 + 56 = 108px)가 남는다. 접힌 메뉴 레일에는 이름 없는 아이콘만 있고, "차트 카탈로그"와 "생산성 개요"가 같은 아이콘이라 구분도 안 된다.
- `chart-catalog*`: 오른쪽 "집중" 열이 접힌 상태에서도 약 40px(버튼 32 + 간격 8)를 열로 잡아 차트 폭을 줄인다. (처음 적은 56px는 페이지 오른쪽 여백 16px를 함께 센 값이었다.)
- "숨긴 패널 0"이 0일 때도 버튼으로 남아 있다.

#### 6. 초점과 선택 표시
- `productivity-overview`: 가장 진한 요소가 우상단 "사이클타임 상세 보기", 선택된 KPI 카드의 2px 남색 테두리, 차트마다 든 남색 "선택" 버튼이다. 주 버튼 색이 한 화면에 세 번 이상 나온다.

#### 7. 차트
- 팔레트가 두 벌이다. `productivity-overview`, `cycle-time`, `hw-time`은 밝은 하늘색·청록·보라(약 `#3B9BFF`, `#00A6B4`, `#A070F0`), `chart-catalog-01~10`은 탁한 남청·자주·청록·회색(약 `#44679A`, `#73629A`, `#327D78`, `#667085`). `chart-catalog-09`는 한 화면의 위 차트와 아래 차트가 다르다. "계열 색은 모든 차트에서 일관"이라는 지침과 어긋난다.
- 막대가 가늘다. `chart-catalog-01`은 140px 간격에 18px, `productivity-overview`는 50px 간격에 18px. `chart-catalog-06` 파레토는 190px. 비율이 차트마다 다르다.

- 도구 줄이 차트 종류마다 다르게 보인다. 순서와 이름은 공유 메시지로 이미 통일되어 있고, 다른 것은 종류마다 내놓는 부분집합과 표시 방식(아이콘+글자 / 글자만 / 아이콘만)이다. 선·막대는 아이콘+글자 7개, 히트맵·산점도는 글자만 4개, 도넛·상자·파레토는 글자만 3개, Lane·순서 트랙은 또 다른 글자 묶음, `cycle-time`은 아이콘만. "모든 차트에서 같은 상호작용"이라는 지침과 어긋난다.

- 날짜 눈금은 줄인다. `2026-09-25 09:00:00` → `09-25 09:00`, 날짜가 바뀌는 눈금만 날짜를 적는다.
- 범례: 제목 아래 왼쪽 한 줄, 12px, 색 조각 8×8(선 계열은 12×2). 지금은 남색 체크박스 + 색 조각이 겹친다. 색 조각 자체가 토글이고 꺼지면 조각이 비고 글자가 옅어진다. 데이터 위에 올리지 않는다.

### E. 위험과 피하는 법

- **그림자 과용**: L2 그림자는 위 값보다 진하게 하지 않는다. 카드 안에 카드를 넣지 않는다.
- **바탕을 너무 밝게**: `#F8FAFC` 위 흰 카드는 대비가 약 1.04:1이다. 카드 간격 12px인 화면에서 카드가 한 장으로 붙어 보인다. 캔버스는 `#F1F4F8`에서 멈추고 더 어둡게도 하지 않는다(카드 밖 글자가 읽기 어려워진다).
- **채도 올리기**: 밝은 색은 막대 안 흰 글자를 죽인다. 흰 글자는 범주색 1·2번에만, 나머지는 라벨을 밖에 둔다.
- **모서리·채움·그라디언트**: 막대 모서리는 2px까지. 면 채움은 단일 계열, 10% 이하. 그라디언트 막대 금지.
- **상태색을 범주색으로**: `configuration`의 위반 표시와 충돌한다. 금지.
- **hover로만 나타나는 도구**: 키보드 사용자가 못 찾는다. 포커스가 카드 안에 들어오면 반드시 나타나고, "표로 보기"와 ⋯는 항상 보인다.
- **접힌 상태를 0px로**: 무엇이 숨었는지 모르게 되면 안 된다. 숨은 것이 있으면 개수 배지가 남는다(G).
- **구간 선택 블록 제거**: 키보드로 시작·끝을 고르는 경로가 사라지면 안 된다. 선택 칩을 누르면 같은 입력이 팝오버로 열린다.
- **점 숨김**: 결측 구간이 이어져 보일 수 있다. 결측은 끊고 외톨이 값은 점으로.
- **KPI 카드 축소**: 기준·분모 줄을 지우면 신뢰 정보가 사라진다. 한 줄로 남긴다.
- **선택이 숫자의 뜻을 바꾸는 것**: 선택으로 걸러진 패널의 P95는 전체의 P95가 아니다. 걸러진 패널 머리에 "필터됨" 표시와 모집단 n을 반드시 보인다(J).
- **보라 강조색**: 남색보다 밝아 2px 활성선이 약해 보일 수 있다. 활성 메뉴는 선 + 옅은 바탕 + 굵은 글자 셋을 함께 쓴다.

### F. Hex와 비교

#### F1. Hex의 차트가 빽빽한데도 좋아 보이는 이유
1. **쉬는 상태에 조작부가 없다.** 셀의 도구는 올리거나 고를 때 나타나고, 설정은 옆 편집기에 있다. 보이는 것은 제목과 차트뿐이다. 이 플랫폼은 도구 글자 7개, 범례 체크박스, 안내 문장, 시작/끝 입력, 원천 줄이 항상 차트를 둘러싼다.
2. **팔레트가 작업 공간 단위로 한 벌이다.** 어느 차트에서나 같은 값이 같은 색이다.
3. **마크가 주인공이다.** 막대가 간격을 충분히 채우고, 격자와 축 글자는 옅고 작고, 테두리·3D·그라디언트가 없다.
4. **글자 단계가 적다.** 제목, 본문, 축 글자 정도다. 큰 숫자는 단일 값 셀에서만 크다.
5. **상호작용이 차트 종류와 무관하게 같다.** 범례 hover, 끌어서 선택, 클릭 선택, 원본 보기, 드릴.
6. **선택이 값이다.** 고른 것이 다음 셀의 입력이 된다. 선택이 화면 장식이 아니라 분석의 한 단계다.

#### F2. SDK 조각으로 가져올 것
| Hex | 이 플랫폼의 조각 |
| --- | --- |
| 작업 공간 팔레트 | 차트 토큰 한 벌(C1) + 메뉴가 선언하는 "대상 → 색" 표 |
| 쉬는 상태에 숨는 셀 도구 | 차트 프레임: 머리 한 줄, hover·포커스 때 나타나는 도구(B6) |
| Data / Style 편집기 | 패널 옵션 팝오버: 한 팝오버 안의 두 구역 "데이터"와 "모양" (탭 아님) |
| 선택 → Create output | 선택 모델 + 선택 칩 + "다음 분석" 동작 (J) |
| Drill: 나눌 기준 고르기 | 드릴 때 메뉴가 선언한 나누기 기준을 평평하게 보여 주는 팝오버 |
| View data | 마크·선택에서 "원본 행" 서랍 |
| Single value의 비교 의미 | 단일 값 카드: 값 / 절대 변화 / % 변화, 증가가 좋은지 나쁜지 선언 |
| 기준선, 데이터 라벨, 쌓은 합계 | 차트 옵션 조각(이미 일부 있음: P95 선, 80% 선, 합계) |
| Top N + Other | 범주 축 공통 옵션 |
| Faceting | 작은 다중 차트(공유 축, 열 수) |
| 차트 설정 직렬화 | 패널 명세 JSON: 데이터 / 설정 / 그리기 / 상호작용 분리 |
| 범주별로 묶인 차트 종류 선택기 | 패널 추가 선택기 (H) |

#### F3. 가져오지 않을 것
- **세로로 이어지는 노트북·셀 흐름**: 이 플랫폼은 한 화면의 연결 패널이다. 셀을 아래로 쌓으면 선택과 결과가 한 화면에서 떨어진다.
- **편집기의 Data / Style 탭을 화면 구조로 올리는 것**: 차트 옵션은 옵션으로 남는다. 팝오버 안 구역으로 충분하다.
- **자유로운 열 → 축 매핑과 집계 변경(지금 단계)**: 이 플랫폼의 숫자는 지표 버전, 모집단, 원천이 붙은 관리되는 값이다. 사용자가 집계를 바꾸면 같은 이름의 숫자가 다른 뜻이 된다. H에서 범위를 정한다.
- **오른쪽 범례 기본값**: 폭을 60~120px 먹는다. 위 왼쪽 한 줄로 둔다.
- **hover로만 닿는 조작**: 키보드 경로가 없으면 가져오지 않는다.
- **게시 앱의 넉넉한 여백**: Hex 앱은 이 도구가 필요한 밀도보다 느슨하다. 간격은 B5를 따른다.
- **파이 차트의 격상**: 구성은 쌓은 막대가 더 정확하다. 도넛은 지금처럼 카탈로그의 한 종류로만 둔다.
- **차트 스타일 복사·붙여넣기**: 모양은 토큰이 정한다. 차트마다 다른 모양을 퍼뜨리는 기능은 일관성을 깎는다.

### G. 접힌 상태 설계

#### G1. 규칙
1. **접힌 영역은 자기 자리를 갖지 않는다.** 줄도 열도 예약하지 않는다. 손잡이는 이미 있는 줄(제목 줄, 컨텍스트 줄, 카드 머리)에 28px 아이콘이나 칩으로 얹힌다.
2. **접힌 상태가 남기는 것은 상태뿐이다.** 걸린 조건, 숨은 개수, 선택 개수처럼 사용자가 알아야 할 것만 칩이나 숫자 배지로 남긴다. 0이면 아무것도 남기지 않는다.
3. **예산**: 전부 접었을 때 화면 위 크롬은 88px(제목 줄 48 + 컨텍스트 줄 40), 왼쪽 크롬은 52px, 오른쪽 크롬은 0px. 패널 머리는 36px 한 줄.
4. **잠깐 볼 때는 덮고, 고정할 때만 민다.** 손잡이에 올리거나 누르면 L3 층으로 내용 위에 열린다. 핀을 누르면 자리를 차지하며 고정된다.
5. **찾을 수 있어야 한다.** 모든 손잡이에 툴팁(이름 + 단축키), `aria-expanded`, 포커스 가능. 열면 포커스가 안으로 들어가고 Esc로 닫으면 손잡이로 돌아온다. 접힘 상태는 사용자별로 기억한다. hover로 열리는 것은 클릭과 키보드로도 열린다.

### H. 패널(차트) 추가

#### H1. 범위에 대한 입장
지금은 노코드 BI로 가지 않는다. 사용자가 고르는 것은 **메뉴가 선언한 지표와 나누기 기준 안에서의 조합**까지다. 이유: 이 플랫폼의 숫자는 버전과 모집단이 붙은 관리되는 값이고, 자유 집계는 "기존 숫자의 뜻을 바꾸지 않는다"는 원칙을 깬다. 다만 패널 설정을 처음부터 선언형 명세로 저장하면, 나중에 자유 편집기는 같은 명세를 쓰는 편집기 하나를 더하는 일이 된다.

| 단계 | 사용자가 하는 일 | 시점 |
| --- | --- | --- |
| 1 | 메뉴가 선언한 완성 패널을 고른다(사이클타임 추세, 분포, 느린 실행 …) | 지금. `hw-time`의 "+ 패널 추가"가 이 단계 |
| 2 | 종류 × 지표 × 나누기 기준을 선언된 목록에서 고른다 | 다음 |
| 3 | 데이터셋·열·집계·계산 필드를 직접 고른다 | 나중. 지표 관리와 권한이 준비된 뒤 |

#### H2. 선택기 (SDK 조각)
- 여는 곳: 컨텍스트 줄의 "+ 패널", 격자의 빈 칸, 선택 동작 막대의 "새 패널"(J), 표 열 머리의 "이 열로 차트".
- 모양: 720×440 팝오버 하나. 위에 검색 칸, 그 아래 구역 두 개.
  - **이 메뉴의 패널**: 메뉴가 선언한 완성 패널. 이름 + 한 줄 설명 + 56×40 미리보기. 한 번 누르면 바로 들어간다.
  - **종류로 만들기**: 범주가 옆으로 나란히 놓인 열. 트리나 탭이 아니다.

| 추세 | 비교 | 분포 | 구성 | 시간·순서 | 값·표 |
| --- | --- | --- | --- | --- | --- |
| 선 | 막대 | 히스토그램 | 쌓은 막대 | 히트맵 | 단일 값 |
| 영역 | 묶음 막대 | 상자그림 | 100% 쌓은 막대 | Lane 시간선 | 표 |
| | 가로 막대 | 산점도 | 파레토 | 순서 트랙 | 피벗 |
| | TopN | | 도넛 | | |

- 검색어를 넣으면 맞지 않는 항목이 흐려진다. 열 구조는 그대로다(좁히기는 유지, 위계는 만들지 않음).
- 미리보기 그림은 실제 차트 토큰으로 그린다. 선택기가 곧 팔레트의 견본이 된다.
- 종류를 고르면 같은 팝오버 오른쪽에 두 줄이 나온다: **지표**(P50 · P95 · 실행 수 …)와 **나누기**(없음 · 설비 · 공정 · Recipe …). 메뉴가 선언한 것만, 칩으로 평평하게. 종류와 맞지 않는 조합은 흐려지고 이유가 툴팁에 나온다. "추가"를 누르면 끝난다.
- 선택에서 열었을 때는 팝오버 위에 `입력: 추세 14:00–16:00`이 칩으로 보이고, 새 패널은 그 선택을 입력으로 태어난다.

#### H3. 들어간 뒤
- 새 패널은 격자의 다음 빈 칸에 기본 크기(가로 6/12칸, 높이 기본 단계)로 들어가고, 페이지 조건과 현재 선택에 바로 연결된다.
- 종류 바꾸기(막대 ↔ 선 ↔ 표), 기준선, Top N, 정렬, 라벨은 패널의 옵션 팝오버에 있다. 팝오버는 "데이터"와 "모양" 두 구역으로 나뉜 한 장이다.
- 패널 구성은 지금의 배치 저장·공유 링크에 함께 실린다. "기본 배치"로 되돌릴 수 있다.
- 메뉴가 선언하는 것: 완성 패널 목록, 지표 목록, 나누기 기준, 종류별 허용 조합, 대상 → 색 표. SDK가 하는 것: 선택기, 명세 저장, 격자 배치, 연결.

| 빈·로딩·오류 상태 | 채택 | 이미 있다. 한 줄 요약 띠와 원인 묶기는 좋고, 패널 크기 유지와 패널별 구분이 모자라다(K2) |
| 노코드(데이터셋, 조인, 계산 필드, 끌어 만드는 대시보드) | 조정 | 방향은 맞지만 지금은 H의 2단계까지. 명세만 먼저 선언형으로 |
| 데이터 / 설정 / 그리기 / 상호작용 분리, 페이지 전용 차트 금지 | 채택 | 화면에서는 `productivity-overview`와 `chart-catalog`의 팔레트·도구 차이가 이 원칙이 아직 지켜지지 않는다는 증거다 |
| 품질 기준(긴 이름, 많은 계열, 큰 수, 결측, 음수) | 채택 | 카탈로그의 견본 데이터가 전부 짧고 깨끗하다. 카탈로그에 "험한 데이터" 견본을 종류마다 하나씩 둔다. `metric-catalog`의 `non_process_dwell_duration` 줄바꿈, 잘린 배지가 이미 보이는 사례 |


#### J2. 선택 → 다음 분석의 입력

지금은 선택이 차트 안의 일시적인 상태다. "선택 없음" 글자와 시작/끝 입력이 차트마다 따로 있고, 다른 화면으로 넘기는 길은 `productivity-overview` "확인할 항목"의 "사이클타임 상세 → / 다른 화면" 링크처럼 화면마다 손으로 만든 것뿐이다. 아래 다섯 조각으로 바꾼다.

**조각 1. 선택 모델** (SDK)
- 선택 하나 = 출처 패널 + 차원 + 값. 종류는 네 가지: 값 묶음(설비 = 0111, 0106), 범위(시간 14:00–16:00, 사이클타임 60–75분), 칸(설비 × 시간), 행 묶음(산점도·표에서 고른 행 키).
- 직렬화되어 주소에 실린다. 링크를 받은 사람이 같은 선택을 본다. 뒤로 가기가 선택을 한 단계 되돌린다.
- 행 묶음은 개수 상한을 둔다(주소 길이와 보안 경계 때문). 넘으면 "범위로 바꾸기"를 권한다.
- 메뉴가 선언하는 것: 패널마다 고를 수 있는 차원, 패널마다 받아들이는 차원(거르기 / 강조만 / 무시), 넘겨줄 수 있는 다른 메뉴.

**조각 2. 차트 위의 선택 표시** (차트 프레임)
- 고른 마크는 원래 색 + 1.5px 강조색 링, 나머지는 30%. 구간은 강조색 10% 띠.
- 다른 패널에서 온 선택은 띠나 링 없이 "거른 결과"로만 보인다. 그 패널이 강조만 받도록 선언했으면 해당 마크가 원래 색으로 남고 나머지가 흐려진다.
- 걸러진 패널은 머리에 `● 필터됨 · n=52` 표시가 붙는다. 올리면 어떤 선택이 걸렸는지 나온다. 패널 ⋯에 "선택 영향 받지 않기"가 있어 전체와 나란히 비교할 수 있다.

**조각 3. 선택 칩** (컨텍스트 줄 안, 새 줄 없음)

`조건: 기간 09-25→09-27 · 공정 PHOTO │ 선택: ◧ 추세 14:00–16:00 ✕ › ▥ 분포 60–75분 ✕ · 모두 지우기`

- 조회 조건 칩은 중립 테두리 칩(서버에 다시 묻는 조건), 선택 칩은 강조색 옅은 바탕 칩(화면 안에서 바로 걸리는 것). 한눈에 구분된다.
- 칩 = 출처 패널 아이콘 + 차원 + 값. 값이 여럿이면 `설비 3`으로 줄이고 올리면 전부 보인다.
- 칩에 올리면 출처 패널과 고른 마크가 강조된다. 칩을 누르면 편집 팝오버(범위는 시작/끝 입력과 빠른 구간, 값 묶음은 체크 목록). 지금 차트 아래 블록이 하던 일이고 키보드 경로다. ✕는 그 선택만 지운다.
- 앞 선택의 결과 안에서 고른 선택은 `›`로 이어 보인다. 이것이 사슬이다. 가운데 칩을 지우면 뒤 칩은 남되, 더는 해당하는 데이터가 없으면 회색 "해당 없음"으로 표시된다. 말없이 사라지지 않는다.
- 되돌리기: ⌘Z와 뒤로 가기가 마지막 선택부터 한 단계씩. "모두 지우기"는 선택만 지우고 조회 조건은 건드리지 않는다.
- 넘치면 `+2`로 접는다. 선택이 없으면 "선택:" 구역 자체가 없다.

**조각 4. "다음 분석" 동작 막대** (L3, 선택 바로 옆에 뜨는 28px 막대)

`설비 2 · 14:00–16:00 │ 나누기 ▾ │ 새 패널 │ 다른 분석 ▸ │ 원본 행 │ 조건으로 │ ✕`

선택을 마치면 뜬다. 같은 항목이 칩의 ⋯에도 있다. 클릭 한 번이면 연결 패널은 이미 갱신되어 있으므로, 이 막대는 "그다음"을 고르는 곳이다.

| 동작 | 일어나는 일 |
| --- | --- |
| (자동) 연결 패널에 적용 | 같은 화면의 히트맵, 막대, 표, 산점도, 추세가 그 자리에서 갱신된다. 단추 없음 |
| 나누기 ▾ | 메뉴가 선언한 기준(설비 · Recipe · Lot · 시간 …)이 평평하게 나온다. 고르면 출처 패널이 그 기준으로 한 단계 내려가고, 패널 머리에 `전체 › PHOTO › 설비별` 경로가 생긴다. 경로의 앞 단계를 누르면 올라간다 |
| 새 패널 | H의 선택기가 `입력: …` 칩과 함께 열린다. 새 패널은 이 선택을 입력으로 태어나고, 머리에 입력 칩이 보인다. 입력은 두 방식: **따라가기**(선택이 바뀌면 같이 바뀜, 기본) / **붙잡기**(지금 선택을 붙잡아 둠. 다른 것을 골라 나란히 비교할 때). 패널 추가 메뉴의 "추가하면 고정"과 다른 뜻이라 "고정"이라는 말은 쓰지 않는다 |
| 다른 분석 ▸ | 메뉴가 선언한 목적지(사이클타임 상세 · HW Time · Configuration · 설비 마스터 · 로그 탐색 …)가 평평하게 나온다. 각 줄에 넘어가는 것과 못 넘어가는 것이 보인다: `설비 2 · 기간 14:00–16:00` / ~~`Recipe`~~ 받지 않음. 새 탭 열기도 같은 줄에 |
| 원본 행 | 이 선택을 만든 행이 서랍 표로 열린다 |
| 조건으로 | 선택을 조회 조건으로 올린다(예: 끈 구간 → 기간). 서버에 다시 묻고, 선택 칩이 조건 칩으로 바뀐다 |

**조각 5. 넘겨받은 맥락** (도착한 화면의 컨텍스트 줄)

`← 생산성 개요에서: 설비 2 · 14:00–16:00 ✕`

- 다른 메뉴에서 넘어오면 컨텍스트 줄 맨 앞에 넘겨받은 칩 묶음이 보인다. `←`를 누르면 떠나온 화면이 떠날 때의 선택 그대로 돌아온다. ✕를 누르면 넘겨받은 것을 버리고 이 화면의 기본 조건으로 간다.
- 목적지 대상(어느 설비의 화면을 여는가)과 분석 맥락(기간, 선택)은 따로 실린다. 넘겨받은 칩은 분석 맥락만 보여 준다.

**차분함과 접근성**
- 강조색은 선택에만 나온다. 링 1.5px, 흐림 30%, 띠 10%. 깜박임이나 채움 변화 없음.
- 키보드: 1차 경로는 선택 칩의 편집 팝오버(범위 입력, 값 체크 목록)와 "표로 보기"의 행 선택이다. 둘 다 DOM이라 바로 된다. 차트 안에서 화살표로 마크를 옮기는 것은 캔버스(ECharts) 위에 포커스 대리 요소를 따로 만들어야 해서 비용이 크다. 2차로 미룬다. Esc 해제와 선택 칩 구역으로의 영역 이동은 1차에 넣는다.
- 숫자의 뜻: 걸러진 패널의 값은 항상 모집단 n과 함께 보이고, 원천 줄에 "선택 적용"이 적힌다. 걸러진 P95를 전체 P95로 읽는 일을 막는다.

**화면에서의 한 흐름** (`productivity-overview` → `cycle-time`)
1. "Job 처리량 추세"에서 02:00~04:00의 낮은 막대 셋을 끈다. 띠가 생기고, 컨텍스트 줄에 `◧ 추세 02:00–04:00 ✕`가 생기고, "공정별 점유 구성"과 "확인할 항목"이 그 구간으로 갱신되며 `● 필터됨`이 붙는다.
2. 동작 막대에서 "나누기 ▾ → 설비"를 고른다. 추세 패널이 설비별로 내려가고 머리에 `전체 › 설비별`이 생긴다.
3. 가장 낮은 설비 둘을 클릭한다. 칩이 `◧ 추세 02:00–04:00 › 설비 2`가 된다.
4. "다른 분석 ▸ → 사이클타임 상세"를 고른다. 도착한 화면 맨 앞에 `← 생산성 개요에서: 설비 2 · 02:00–04:00 ✕`가 보이고, 추세·분포·느린 실행 표가 이미 그 범위다.
5. `←`를 누르면 개요 화면이 3번 상태로 돌아온다. ⌘Z 두 번이면 1번 이전이다.

지금 화면의 "확인할 항목"의 링크 두 개, 차트 아래 시작/끝 블록, "선택 없음" 띠는 모두 이 다섯 조각으로 대체된다.


#### J3. 다섯 조각과 기존 SDK의 관계

| 조각 | 기존 조각 | 판단 | 할 일 |
| --- | --- | --- | --- |
| 1 선택 모델 | 차트 안의 점 선택과 `{from,to}` 범위(차트 안에만 있고 주소에 없음). `PanelDeclaration.outputs {key, action}`(지금은 표시용 정보) | 확장 | `outputs`를 실제 전달 통로로 만든다. 패널이 선택을 `outputs`의 key로 내놓고, 다른 패널의 `queryInputs`·`displayInputs`가 그 key를 받는다. 지금 메뉴가 손으로 쓰는 공유 페이지 키를 SDK가 선언을 보고 잇는다. `outputs`를 선언하지 않은 패널은 지금처럼 차트 안 선택으로 남는다(기본 동작 불변) |
| 2 차트 위 표시 | ECharts의 선택·흐림 상태, 제어형 `activeCategory` 행 강조 | 확장 | 링·30% 흐림은 테마 값. 다른 패널에서 온 선택의 "강조만" 방식은 `activeCategory`를 일반화한 것. `● 필터됨 · n` 표시는 한 줄 pane 머리의 신호 칩(ADR-0051)에 얹는다 |
| 3 선택 칩 | 접힌 QueryBar 줄(ADR-0160, 붙박이), PageFilterBar의 접힌 요약 줄(ADR-0029) | 확장 + 결정 필요 | 칩은 접힌 QueryBar 줄 안에 산다. 새 줄을 만들지 않는다. 다만 두 접힌 줄을 한 줄로 합치는 것은 두 ADR에 닿는다(M3) |
| 4 "다음 분석" 동작 막대 | `selectionActions`, `pointActions`, `onPointClick`, `useDrill` + 경로 막대, `PanelAddMenu`, `resolveLink`, "분석 기간으로 적용" | 새 껍데기, 속은 기존 | 막대 자체는 새 조각. 항목은 기존 훅을 표준 항목으로 채운다: 나누기 = `useDrill`, 새 패널 = `PanelAddMenu`, 다른 분석 = `resolveLink`, 조건으로 = "분석 기간으로 적용"을 일반화. 페이지가 넣던 `selectionActions`는 막대의 추가 항목으로 그대로 들어간다 |
| 5 넘겨받은 맥락 | `resolveLink`(전역 Context + 목적지가 선언한 페이지 키, 목적지 ID는 분리) | 확장 + 결정 필요 | 넘겨받은 칩 표시는 새 조각. 선택을 링크에 싣는 것은 계약 결정이다(M3) |

- **이름**: kernel의 "Selection"은 지금 설비 선택을 뜻한다. 차트 선택을 같은 말로 부르면 안 된다. 이 문서의 "선택 모델"은 "분석 선택" 같은 다른 이름이 필요하고, 용어집에 올릴 결정이다.
- **전역과 페이지의 경계**: 클릭으로 바로 걸리는 것은 페이지 안의 연결 패널까지다. 전역 기간이나 설비 선택을 바꾸는 것은 지금처럼 명시 동작("조건으로")으로만 한다. 차트에서 설비를 골랐을 때 kernel 설비 선택으로 올리는 것도 같은 명시 동작이다.
- **되돌리기**: 뒤로 가기로 선택을 되돌리는 것은 선택이 주소에 실릴 때만 된다. 주소에 싣지 않기로 하면 ⌘Z만 남는다.

### K. 다시 찍은 화면과 상태

#### K1. 화면
- `admin-roles`: 3행짜리 표다. "권한 수 31 / 25 / 4"와 "메뉴 85 / 54 / 35"가 왼쪽 정렬이다. 숫자 열은 오른쪽 정렬 + `tabular-nums`(B4). 고정 동작 열 왼쪽의 진한 세로선이 표에서 가장 진한 선이다. 열 고정 표시는 `#D5DBE3` 선 + 왼쪽으로 지는 옅은 그림자 4px로.
- `admin-audit`: "시각" 열이 좁아 모든 행이 두 줄(`2026-11-19` / `11:42`)이다. 행 높이가 약 45px로, 다른 표(33px)보다 한 화면에 6행쯤 덜 들어간다. 시각 열 최소 폭을 한 줄 폭(약 136px)으로 잡는 것이 표 조각의 기본이어야 한다. "사유" 칸이 고정 열에 말줄임표 없이 글자 중간에서 잘린다. "출처" 열은 모든 행이 같은 파란 "사용자" 배지다. 값이 한 가지뿐인 배지는 색을 빼고 일반 글자로(상태만 색, B6). "이름 미확인", 회색 "지표"처럼 비어 있는 값은 옅은 글자 + 기울임 없이 통일.
- `equipment-master`(관리자): 처음과 같다. 상태 배지가 여전히 고정 열에 가려 "사용중"이 잘린다. 왼쪽 메뉴 아래에 "기능 · MARS" 묶음이 생겼는데 구분선 하나로만 나뉘어 메뉴와 같은 무게다. 묶음 제목 규칙(B6)을 따른다.
- `eqv-topview`(설비 고르기 전): "설비 선택" 드롭다운 하나와 "위에서 설비를 고르세요" 한 줄이 바탕 위에 카드 없이 놓여 있고 나머지 900px가 비어 있다. 세 가지를 권한다. ① 고르는 칸은 컨텍스트 줄로 올린다. ② 본문은 L2 카드 한 장으로 틀을 미리 보여 주고, 그 안에 빈 상태를 둔다. ③ 빈 상태에 "최근 본 설비"와 "즐겨찾기 설비"를 칩으로 평평하게 놓아 한 번에 들어가게 한다. 처음 쓰는 화면이 가장 비어 보이는 화면이면 안 된다.

#### K2. 상태 (`state-*-productivity`)

**잘 된 것 (유지)**
- 같은 원인을 한 번만 말한다. 패널 넷이 각자 외치지 않고 위에 한 줄 띠가 "위젯 4개가 같은 이유로 열리지 않았습니다"라고 묶는다. 차분한 강조 원칙에 맞다.
- 빈 결과와 오류를 말로 구분한다. "조회는 성공했고 결과가 0건입니다"는 정확하다.
- 띠에 다음 행동이 있다(다시 시도, 조건 열기, 자세히).
- 부분 실패에서 성공한 패널(KPI, 추세)은 그대로 보인다.
- 로딩 중에도 카드 제목은 남는다.

### L. Hex 차트 종류와 비교

#### L1. Hex의 종류 → 이 플랫폼

| Hex | 여기 | 판단 | 넣는 방식 |
| --- | --- | --- | --- |
| Column · grouped | 캡처에서는 못 봄(세로 막대는 단일 계열과 쌓기만 보임) | 필요 | 막대의 옵션 `쌓기: 없음(묶음) / 쌓기 / 100%` |
| Column · stacked | 있음(`productivity-overview` "공정별 점유 구성") | — | — |
| Column · 100% stacked | 없음 | 필요 | 같은 `쌓기` 옵션의 100% |
| Bar · grouped | 있음(`chart-catalog-09` 묶음 막대) | — | — |
| Bar · stacked | 있음(`chart-catalog-09`, `hw-time`) | — | — |
| Bar · 100% stacked | 없음 | 필요 | 분해 막대의 `쌓기` 옵션 100%. 가동/대기/정지 비율 비교에 바로 쓴다 |
| Line | 있음 | — | — |
| Area | 없음 | 필요(작게) | 선의 옵션 `면 채움`. 단일 계열 기본값으로 권한 것(C3)과 같은 옵션 |

- **새 SDK 차트 종류는 하나도 필요 없다.** 빠진 것은 전부 기존 종류의 옵션이다: 막대·분해 막대·선에 공통인 `쌓기: 없음 / 쌓기 / 100%` 하나, 선의 `면 채움` 하나, 히스토그램의 카탈로그 등록.
- `쌓기`와 `100%`는 더할 수 있는 측정에만 허용한다. `chart-catalog-09`가 이미 "더할 수 있는 측정"과 "더하지 않는 측정·비율"을 나누고 있으므로 그 선언을 그대로 쓴다. 비율을 쌓거나 100%로 만들면 숫자의 뜻이 바뀐다. Hex에는 이 구분이 없다.
- 이 플랫폼은 막대 계열이 넷이다(막대, TopN 막대, 분해 막대, 파레토). Hex는 하나에 옵션이다. 지금 종류를 합치라고 권하지는 않는다(선언과 화면이 깨진다). 패널 추가 선택기(H)에서는 "막대" 한 묶음 아래 변형으로 보여 주고, 종류를 합칠지는 뒤에 판단한다.

- 둘 다 없는 것 중 팹에서 흔히 찾는 것: 관리도(중심선, 관리 한계, 규칙 위반 점)와 웨이퍼 맵. 관리도는 새 종류가 아니라 선 + 기준 띠 + 위반 점 링의 조합으로 된다(I의 6번이 그 조각). 웨이퍼 맵은 새 종류다. 필요한 메뉴가 범위에 들어오는지는 소유자가 정할 일이다.

#### M2. G와 H를 기존 조각 위에 다시 적기

**G (접힌 상태)**
- 컨텍스트 줄 = 접힌 QueryBar 줄. 새 줄이 아니다. 지금 두 줄로 보이는 것은 접힌 QueryBar 줄과 PageFilterBar 요약 줄이 따로 쌓이기 때문이다. 권고는 PageFilterBar 요약, 선택 칩, 배치·숨김·안내 손잡이를 접힌 QueryBar 줄에 함께 싣는 것이다.
- 한 줄 안에서 세 가지를 구분한다: 조회 조건(적용을 눌러야 서버에 물음, 중립 테두리 칩) │ 페이지 조건(바로 반영, 중립 채움 칩) │ 선택(차트에서 옴, 강조색 칩). 지금 두 막대가 나뉜 이유(적용이 필요한가)는 칩 모양으로 남는다.
- pane 머리 한 줄(ADR-0051)은 이미 결정이다. `cycle-time`에서 두 줄로 보이는 것은 pane 머리 아래에 차트 프레임의 도구 줄이 한 번 더 나오기 때문이다. 규칙 하나를 더한다: **pane의 내용이 차트 하나뿐이면 차트 도구는 pane 머리로 올라간다.** 차트 프레임은 머리 없이 그려진다.
- 접힌 메뉴 레일 56 → 0은 셸 프레임 변경이다. `[`는 그대로 쓴다.
- 차트 아래 선택 블록을 없애는 것은 선택 칩(J3 조각 3)이 들어온 뒤에 한다. 그전에는 블록을 "선택이 있을 때만 한 줄"로 줄이는 것까지만 한다.

**H (패널 추가)**
- 1단계 = 지금의 `PanelAddMenu`. 바꾸는 것은 선언에 선택 항목 `category`(와 미리보기용 종류)를 더하는 것뿐이다. 선언하지 않은 메뉴는 지금의 평평한 드롭다운 그대로다. 범주를 선언했거나 항목이 8개를 넘으면 범주가 옆으로 놓인 팝오버로 바뀐다.
- 2단계(종류 × 지표 × 나누기)는 선·막대가 `ChartSpec` 유니온 밖(props로 설정)에 있는 동안에는 만들 수 없다. 선택기가 선언만으로 선·막대 패널을 만들 방법이 없기 때문이다. Lane·순서 트랙도 같다. **선·막대를 `ChartSpec`에 넣는 것이 2단계의 선행 작업**이고, C5의 "모든 차트 같은 상호작용"도 같은 작업에 걸려 있다.
- "패널 명세 JSON"은 새 스키마가 아니라 `ChartSpec` + `PanelDeclaration`의 확장이다(지표·나누기 목록, 허용 조합, `outputs`의 실제 통로화). 저장은 지금의 배치 프리셋·저장 경로에 얹는다.
- "추가하면 고정"은 그대로 둔다. J2의 입력 방식 이름을 "붙잡기"로 바꿔 겹치지 않게 했다.

#### M3. 실제 충돌과 소유자에게 갈 결정

계약 결정 (소유자 승인 필요):
1. **선택을 주소에 싣기 = 새 URL 키.** 세 안: (가) 싣지 않는다. 공유 링크와 뒤로 가기로 선택이 되살아나지 않는다. (나) 값 묶음과 범위만 싣고 행 묶음은 싣지 않는다. 키 이름은 패널이 선언한 `outputs`의 key를 페이지 키로 쓴다. 장치는 지금의 페이지 키 그대로이고 새로 생기는 것은 메뉴별 키 이름이다. (다) 주소가 아니라 저장된 보기에만 싣는다. 권고는 (나). "선택이 다음 분석의 입력"이 링크를 받은 사람에게도 성립하려면 주소에 있어야 한다.
2. **선택을 메뉴 사이 링크에 싣기.** `resolveLink`가 싣는 것은 전역 Context와 목적지가 선언한 페이지 키다. 선택을 실으려면 목적지가 그 키를 받는다고 선언해야 한다. 장치는 같고 계약 범위가 넓어진다. 1번이 (가)면 이것도 안 된다.
3. **토큰 값 변경**(바탕, 선 세 단계, 강조색 `#1428a0` → `#635BCE`, 차트 기본 글자 11 → 12, 차트 팔레트). 모든 화면이 바뀐다. 변형 2~3종으로 고른다.
4. **셸 프레임**: 접힌 메뉴 레일 56 → 0.

설계 결정 (ADR에 닿음):
5. 접힌 QueryBar 줄(ADR-0160)과 PageFilterBar 요약 줄(ADR-0029)을 한 줄에 싣기. 두 결정의 방향(접으면 한 줄)과는 맞지만 두 줄이 한 줄이 된다.
6. 드릴에서 나누기 기준 고르기. 지금은 선언한 단계를 순서대로 내려간다. 한 단계에 대안을 여럿 선언하게 하는 확장이며, ADR-0025/0063과 맞는지는 내가 확인하지 못했다.
7. "Selection"이라는 말. 차트 선택의 이름을 따로 정해 용어집에 올린다.
8. 선·막대(그리고 Lane·순서 트랙)를 `ChartSpec`에 넣기. H 2단계와 C5의 선행 작업이며 이 목록에서 가장 큰 구조 작업이다.

충돌이 아닌 것으로 확인된 것:
- 클릭 즉시 연결 패널에 적용: `outputs`를 선언한 패널에만 켜지므로 기존 메뉴의 동작은 바뀌지 않는다.
- 전역 기간을 바꾸는 "분석 기간으로 적용": 그대로 남고 동작 막대의 "조건으로"가 된다.
- 목적지 ID와 분석 맥락의 분리: J2 조각 5가 같은 원칙이다.
- 내보내기를 manifest가 정하는 것, 배치 프리셋을 메뉴가 선언하는 것, 숨긴 패널을 세는 것: 그대로 쓴다.

#### M4. 우선순위에 미치는 영향 (D 보충)
- D의 3번(접힌 상태)은 새 조각이 아니라 기존 세 결정의 마무리라 비용이 "중간"에서 "작음~중간"으로 내려간다.
- D의 6번(선택)은 `outputs` 통로화가 핵심 작업이고, 주소에 싣는 결정(M3-1)이 먼저 나와야 범위가 정해진다.
- D의 7번(같은 상호작용)과 9번(패널 선택기 2단계)은 M3-8(선·막대의 `ChartSpec` 편입)에 묶인다. 이 작업을 6번 다음에 둔다.
- K2의 상태 다듬기는 작고 독립적이다. D의 4번(글자 역할)과 같은 묶음으로 넣을 수 있다.

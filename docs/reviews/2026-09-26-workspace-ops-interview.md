# 2026-09-26 워크스페이스·운영 메뉴·FeedbackOps 통합 인터뷰

통합 프로토타입(`prototypes/platform-app`, PR #13) 완성 후 진행한 사용자 인터뷰 기록이다. 이 문서는 근거 기록이며 authoritative source가 아니다. 결정 원본은 아래 반영 위치를 따른다.

## 배경

- 세부 메뉴 화면은 플랫폼 기능을 확인하기 위한 Consumer였다. 다음 목표는 플랫폼 틀, 메뉴 개발 환경, 공유 컴포넌트 설정이다.
- 개발자 내부 메뉴(시스템 모니터링, 메뉴 활용률, 가공 진행 상태), 사용자용 가공 트레이스(설비별로 가공이 안 된 이유를 VOC 관련해 확인), FeedbackOps(Task·Milestone은 내부, VOC·설문은 사용자도 확인)를 같은 플랫폼에 두되, 좌측 내비게이션이 무거워지지 않는 진입 구조가 필요했다.
- 06 §9는 평면적인 사이드바 확장을 금지하고 이미 7그룹을 쓰고 있었다.

### 정정: Milestone은 신규 기능이 아니다

인터뷰 중 "Milestone은 FeedbackOps에 없는 신규 기능"이라고 제시했으나 사용자가 정정했다. 확인 결과 FeedbackOps 설계(`docs/design/06-task-project-system.md` FR-TASK-004)와 디자인 프로토타입(`docs/design-prototype/screen-milestone-gantt.jsx`)에 Milestone과 하위 Task 간트 차트가 정의돼 있다. 고정 커밋 `6a0c7f8`에서는 백엔드가 "MVP에서는 보류" 상태로 `milestone_id` 자리만 있다. 사용자가 FeedbackOps 원본 저장소에서 구현하기로 했으며, 플랫폼은 그 구현을 참조한다.

## 참고: 작업량 추정 (일정 승인 아님)

시니어 1인 기준의 거친 추정이다. 실제 기간은 인증·권한 관련 미결 3건의 결정 속도에 가장 크게 좌우된다.

| 영역 | 내용 | 추정 |
| --- | --- | --- |
| 개발 환경 | pnpm 모노레포(kernel/ui/components/shell/메뉴 패키지), lint·테스트·CI, 메뉴 템플릿 생성기, URL 직접 조립 금지 lint | 1~1.5주 |
| Kernel | 레지스트리·URL 스키마 단일 산출물(클라이언트·서버 공유, §6.1), 라우터·쿼리 계층, 활용률 계측·감사 연동, 워크스페이스 층 | 2~3주 |
| 공유 컴포넌트 | 표 서버 API 계약, 드로어·Audit·Data Trust·상태 화면·차트 프레임 정식화, ECharts 테마, 폼 부품, Storybook, 접근성·시각 회귀 테스트 | 3~4주 |
| 서버 골격 (범위 밖) | 응답 envelope, 요청마다 Scope 재검증, 시간 계약 검증 | 2~4주 |
| 인증·권한 (범위 밖) | SSO 연동, room_name 권한 상속 | 1~2주 + 결정 대기 |
| 운영 콘솔 (별도) | 대부분 적재 워커 상태 보고 기반 서비스. 메뉴 활용률은 Kernel 계측이 이미 있음 | 3~5주 |
| FeedbackOps 1단계 (별도) | SSO·토큰·딥링크 연결, 사용자용 VOC·설문 읽기 전용 화면 | 1~2주 |
| FeedbackOps 2단계 (별도) | 셸 편입 | 4~8주 |

결정 4에 따라 다음 범위는 앞의 세 줄(약 6~9주)이다.

## 남은 Open

- 적재 워커 상태 기록 스키마, 원인 분류 목록, 보존 기간, `context_recognized_parser` 저장소 변경 범위.
- 레지스트리 `space` 필드명, 공간별 그룹 상한의 정확한 숫자, 06 §9.1 표 항목 중 그룹과 그 아래 화면의 구분.
- FeedbackOps 1단계에서 VOC 등록·설문 응답 제출을 원본 화면 딥링크로 처리하는 방식(Candidate)의 확정 여부.
- 운영 콘솔 권한 모델(개발자와 운영자를 다른 역할로 나눌지).
- FeedbackOps 2단계 시점(인증 프로토콜과 Scope↔Managed System 관계 결정 이후).

## 1. 요구사항과 사용자 작업

이 플랫폼은 **서로 다른 업무 시스템을 하나의 웹 진입점에서 사용**하게 한다. UI는 공통이지만 한 시스템의 개별 메뉴·작업 객체·조회 규칙이 다른 시스템 안으로 흡수되지는 않는다.

| 사용자 | 핵심 작업 | UI 요구 |
| --- | --- | --- |
| 생산성 분석 엔지니어 | 설비/기간별 분석 → 상세 → 관련 로그·개선 과제 | 분석 전용 메뉴, 컨텍스트 보존, 명시적 교차 링크 |
| 지표 관리자 | 지표 정의·버전·발행·영향도 조회 | 지표 전용 카탈로그/이력·관리 메뉴 |
| 표준 로그 개발 담당자 | 모델·개발 단계·검증 Round·결함·협력사 검토 | 내 검증 대기에서 모델 상세로, 검증용 고밀도 표·상세(ADR-0065) |
| 개선 담당자 | 분석 인사이트의 현장 적용, 과제·적용 이력·실적 | 개선 워크플로와 실적 비교 화면 |
| 개발·운영 담당자 | 서버 앱·적재 파이프라인·가공 상태·운영 설정 | 운영 전용 콘솔, 접근 권한 |
| 업무 시스템 사용자 | 시스템별 VOC·Task·설문 이용 | 현재 시스템으로 자동 범위를 좁힌 공통 협업 메뉴 |
| 협업 담당자 | 여러 시스템의 VOC·Task·설문 분류 및 추적 | 별도 권한으로 진입하는 전체 FeedbackOps 허브 |

메뉴 수가 많다는 전제 때문에 **모든 업무 메뉴를 하나의 사이드바에 평면적으로 나열하지 않는다**. 핵심은 시스템 전환(상위 IA)과 시스템 내부 메뉴 이동(하위 IA)의 분리다.

- 4개 업무 워크스페이스와 운영 콘솔은 **독립적 시스템 메뉴 집합**이다. 모든 팀원이 모두 접근하는 구조를 가정하지 않는다.
- `[이 시스템의 협업]`은 플랫폼 화면이 아니라 FeedbackOps를 새 탭으로 여는 링크다(ADR-0027). 전체 협업 허브는 FeedbackOps의 시스템 범위 없는 화면이고, 플랫폼은 진입 링크만 둔다.
- 기존 메뉴 귀속(Decided, ADR-0028): 운영 개요는 홈 런처, 설비관리·기준정보관리는 생산성 분석, 공지·내 VOC는 공간 밖 전역 유틸리티. 경로는 유지한다.
- FeedbackOps의 `Managed System`과 플랫폼의 `SpaceDef`는 서로 다른 식별 개념이다. 1:1 관계를 보장하지 않는다.

**불변 UI 원칙**

1. Rail은 플랫폼 레벨: 포털·접근 가능한 워크스페이스·통합 검색·프로필. 모든 워크스페이스에서 같은 위치다.
2. Sidebar는 *현재 워크스페이스*의 그룹·메뉴만 표시한다. 공간 밖 전역 화면은 예외로 플랫폼 사이드바를 쓴다(§3.2, ADR-0070). 그룹 접기, 최근/즐겨찾기, 검색은 [기존 셸](../wireframes/app-shell.md) 계약을 활용한다.
3. Sidebar의 VOC·Task·설문은 시스템별 **공통 협업 진입점**이고, 기능 내용은 FeedbackOps가 소유한다. 진입은 FeedbackOps를 새 탭으로 여는 링크다(ADR-0027). 메뉴 수가 많아도 쉽게 접근할 수 있는 구역에 둔다. 실제 상시 고정 위치는 화면 높이·권한·메뉴 밀도 검증 대상이다.
4. Main은 업무 유형에 따라 자유롭게 다르다. 분석 차트, 지표 카탈로그, 로그 검증 표, Task 보드·성과 폼을 하나의 보편적 레이아웃에 억지로 맞추지 않는다.
5. Right detail은 문맥이 필요한 조회·수정에서 재사용한다. 대용량 검증·원문 로그는 전체폭 Workbench/Drill로 예외 허용.
6. 색·서체·입력/버튼/배지·테이블 기본 규칙은 [FeedbackOps 디자인 시스템](../../DESIGN.md) 및 `@ap/ui`로 재사용한다. **워크스페이스마다 별도의 테마를 만들지 않는다.**
7. 실제 앱 치수는 **rail 52px, sidebar 240/56px, page header 50px, right panel 440px**의 현재 [06 §7](../contract/layout.md#7-application-shell) / ADR-0011·0013 계약을 유지한다. HTML 샘플의 56px rail·252px nav·56px 최상단 바는 별도 변경 승인 전 **픽셀 사양이 아니다**.

### 3.1 셸 배치 (Decided, 2026-10-09)

> 아래 **레일(로고 홈 링크·공간 버튼)**, 사이드바 머리·본문은 [§3.2](#32-시스템별-레일-decided-2026-10-19-adr-0042)가 대체한다(구현 #423). 홈·FeedbackOps 블록·접근성 규칙은 그대로다. 홈의 사이드바 없음·홈 순서·공간 0개 안내, FeedbackOps 블록의 `VOC 등록`은 [ADR-0070](../adr/0070-global-features-platform-menu-and-voc-drawer.md)이 대체한다(§3.2, 구현 #594).

[ADR-0028](../adr/0028-workspace-shell-launcher-pinned-feedbackops-global-utilities.md)이 실제 앱 위 시안(#250)에서 고른 배치다. 위 원칙 7의 치수를 그대로 쓴다.

**레일 (위 → 아래)**: 플랫폼 홈 링크(로고 자리, 툴팁 `플랫폼 홈`) → 공간 버튼(MARS · BRAVO · 표준 로그 개발 · 개선 실행 · 개발·운영 콘솔 순, 접근 가능 공간이 2개 이상일 때만, 최근 사용 순으로 바꾸지 않음) → 구분선 → 메뉴 검색(⌘/Ctrl K) → 여백 → (`FeedbackOps 전체`는 #764 p2에서 없앴다, ADR-0081 결정 6) → 앱 주입 도구 → 도움말 → 언어 → 사용자 메뉴.

**사이드바 (위 → 아래)**: 50px 머리(현재 공간 이름 + 접기, 이름은 전환 버튼이 아님) → Scope 선택기 → 독립 스크롤 구역(현재 공간 그룹·메뉴 → 즐겨찾기 → 최근 방문 5개) → 매핑된 공간에만 FeedbackOps 바닥 고정 블록(스크롤 밖). 접힘 56px에서는 즐겨찾기·최근을 숨기고, 메뉴 아이콘과 FeedbackOps 아이콘 셋(`VOC`·`Task`·`설문`)을 같은 순서로 남긴다. 키보드로 마지막 메뉴까지 가도 바닥 블록에 가리지 않는다.

**FeedbackOps 블록**: 머리 `FeedbackOps · <공간 이름>` → `VOC` → `Task` → `설문` → `새 탭에서 열립니다`. 각 행 끝 외부 링크 표시. 접근 이름과 접힘 툴팁 모두 `<항목> — <공간 이름>, FeedbackOps, 새 탭`. `aria-current`를 붙이지 않는다. 링크 모양은 ADR-0027·#251. `VOC 등록`은 레일로 옮긴다(ADR-0070).

**홈 `/home`** (`/`는 [별칭](../contract/kernel.md#64-url-계약-decided-필드명enum-문자열은-candidate)): 사이드바 없음. 업무 시스템 카드(이름 · 한 줄 목적 · 검증된 마지막 화면이 있으면 `이어서: <메뉴명>`) → 최근 방문(최대 5, 홈 자신 제외)·즐겨찾기 → 공지(권한 있는 실제 항목만). 머리 보조 링크 `내 VOC`. 카드에 메뉴 수·건강 상태 숫자를 두지 않는다. 공간 1개면 카드 하나로 들어가고 자동 이동하지 않는다. 공간 0개면 `접근 가능한 업무 시스템이 없습니다` + 권한 요청 안내 문장과 `권한 요청` 버튼(`권한 요청` 페이지로 가는 링크, 그 메뉴를 열 수 있을 때, ADR-0070 결정 8). 0개라고 다른 URL의 금지·미등록 오류를 이 화면으로 덮지 않는다.

**최근·즐겨찾기·복원 표시**: 저장값이 있다는 것만으로 보이지 않는다. 지금 들어갈 수 있는 공간·메뉴인지 확인한 뒤 보인다.

**접근성**: 레일 업무 시스템·주 메뉴·FeedbackOps 블록은 고유 이름의 `nav`. 레일을 toolbar로 만들지 않는다(Tab 이동). 현재 메뉴만 `aria-current="page"`. 팔레트 입력은 접근 이름 `메뉴 검색`, 업무 시스템별 묶음은 `role="group"` + 레이블, 방향키로 고른 항목은 늘 보이게 스크롤한다.

### 3.2 시스템별 레일 (Decided, 2026-10-19, ADR-0042)

> 상태: 전환기·섹션 레일·사이드바 머리·페이지 머리 시스템 이름·팔레트 전체 경로 구현(#423). 전환기 플랫폼 메뉴·전역 화면 플랫폼 사이드바·사용자 메뉴의 언어 구현(#594; `FeedbackOps 전체`는 #764 p2에서 없앴다). 레일 `알림` 종·팝오버·플랫폼 메뉴 `알림` 배지 구현(#652); 설문 전체 페이지(`/survey`, `/survey/:surveyId/respond`, `/surveys…`는 별칭, 제출 뒤 출발 화면 복귀) 구현(#653); 권한 요청 페이지(`/permission-requests`, 새 요청 폼·내 요청 상태·철회, mock은 `실서버 필요`) 구현(#657 1부); 홈 `내 할 일`(Kernel 슬롯 `homeTodo`) 구현(#657 2부); 내 VOC(`/voc` 목록 + 셸 상세 패널 `focus`, `/voc/:vocId` 전체 화면, 읽기 전용 — 답글·설명 수정은 백로그) 구현(#654). 레일 `VOC 등록` 도킹 드로어(Context 고정 칩·오른쪽 패널 하나·인라인 닫기 확인) 셸 구현(#655), 드로어 내용(`VocComposeScreen`)·앱 연결·사이드바 `VOC 등록` 항목 제거 구현(#656). 팝오버 `모두 읽음`과 설문·권한 요청 배지는 아직 없다(백로그).

[ADR-0042](../adr/0042-system-switcher-and-system-owned-rail.md)(Decided, 방향)가 3.1의 레일·로고 부분을 대체한다. FeedbackOps를 셸 안에서 여는 것은 ADR-0038을 따르고, 그 전까지 바닥 블록은 새 탭 링크다. 전환기 모양은 실제 앱 위 `?variant=` 시안 세 안(A 팝오버 카드 · B 펼침 패널 · C 검색형, 버리는 브랜치 `hjung3113/proto-423-switcher`)과 UX 리뷰(A + 기존 검색 유지 권고)를 본 뒤 사용자가 **A**로 정했다(2026-10-19, #423). 원칙 7의 치수는 그대로다.

**레일 (위 → 아래)**: 전환기(맨 위 50px 영역, 시각 32×32px, 대상 40×40px) → 구분선 → 현재 시스템 섹션(많으면 이 구역만 스크롤) → 공통 도구(메뉴 검색 → 분석 보드 → `VOC 등록` → `알림`) → 구분선 → 도움말 → 사용자. `언어`는 사용자 메뉴 안에 있다(ADR-0070). `FeedbackOps 전체`는 없앴다(#764 p2) — 전환기 카드가 대신한다(ADR-0081 결정 6). `VOC 등록`은 오른쪽 도킹 드로어를 연다(06 §8·§13). `알림`은 종 아이콘 + 읽지 않은 수 배지, 누르면 팝오버(최근 알림, `모두 읽음`, `모두 보기` → 알림 페이지)이고 읽음은 설문 완료와 별개다. 버튼 시각 32px, 세로 간격 6px. 공통 도구는 시스템을 바꿔도 움직이지 않는다. 플랫폼 홈·분석 보드 화면에서는 섹션 구역을 비우고 전환기는 플랫폼 표식을 쓴다.

**전환기**: 버튼은 현재 시스템 아이콘(또는 짧은 문자) + 작은 펼침 표시. 색만으로 시스템을 구별하지 않는다. 접근 이름과 hover/focus 때 보이는 툴팁도 `시스템 및 플랫폼 메뉴 · 현재: <시스템>`(접근 이름과 같은 문구, ADR-0070). 팝오버(약 520px, 2열): 제목 `시스템 및 플랫폼 메뉴`, 위쪽에 경계로 나뉜 `플랫폼 메뉴` 구역(`nav`, 글자 링크 `홈` · `알림` · `내 VOC` · `설문` · `권한 요청` · `공지`, 건수가 있으면 배지, 권한 있는 것만, 접힌 하위 메뉴로 숨기지 않음, 시스템 카드가 아님 — 플랫폼 홈 링크는 이 구역의 `홈`이다), 그 아래 사용 가능한 시스템 카드(시스템 이름 아래에 `subtitle`이 있으면 12/16px muted 한 줄, 현재 카드에 체크 + `현재`, 보조 문구 12/16px `이어서: <메뉴명>` 또는 기록이 없으면 `시작: <첫 화면>`), 아래 `준비 중` 영역(포커스는 가지만 이동하지 않는 행, 이름 + 같은 `subtitle` 줄 + 같은 12/16px 설명 `아직 사용할 수 없습니다`). 부제는 목록에서만 보이고 버튼 이름·툴팁·사이드바 머리·breadcrumb·팔레트 경로에는 쓰지 않는다(06 §9.1). 전환기 안에 검색 입력을 두지 않는다. 고르지 않은 안: B(사이드바 자리를 덮는 패널 — 늘 보이는 탐색 자리에 임시 모달을 놓는 새 패턴), C(전환기와 ⌘K 통합 — 빈 검색이 메뉴 대신 시스템 목록이 되어 기존 검색의 의미가 바뀜). 제품 화면에 모듈·레포·이슈 번호를 쓰지 않는다. 열면 현재 시스템 카드로 포커스(현재 시스템이 없는 플랫폼 홈·분석 보드에서는 첫 사용 가능한 시스템), Tab은 팝오버 안에서만 돈다(focus trap), Enter/Space로 고르면 새 화면 제목으로 포커스, Esc는 닫고 전환 버튼으로 돌아간다. 현재 선택과 키보드 포커스를 구별한다.

**사이드바 머리 (50px)**: 시스템 이름 14/20px semibold, 그 아래 섹션 이름 12/16px secondary, 오른쪽에 접기 하나. 머리를 또 다른 전환기로 만들지 않는다. 시스템 이름과 섹션 이름이 같으면(섹션이 하나뿐인 시스템 등) 둘째 줄을 생략하고, 섹션 이름과 그룹 제목이 같으면 본문 그룹 제목을 생략한다. 페이지 머리 50px에는 사이드바 접힘과 관계없이 `<시스템> › <메뉴>`를 늘 보인다(접힌 레일에서는 시스템 아이콘과 섹션 아이콘이 겹쳐 보일 수 있어서).

**업무 시스템 `FeedbackOps` (ADR-0081, Decided 2026-10-24, 일부 구현 — #595)**: **구현됨(#759): 전환기 카드·`대시보드` 섹션(`/feedbackops`, 머리 동작 `새로고침`)·사이드바 `목록 범위`(URL `managedSystem`, Kernel 슬롯 `scopeControl`; mock에서는 비활성 `전체` + `실서버 필요`). 구현됨(#761 1부): `VOC` 그룹의 `수신함`(`/feedbackops/vocs`)·`Triage`(`/feedbackops/triage`) — 선택은 페이지 키 `focus`(수신함은 셸 상세 슬롯), 대시보드의 큐·영역 미지정 링크가 이 메뉴로 연결된다. 구현됨(#761 p1b): 사이드바 보기(`연결 없음`·`높음`·`미배정`)와 개수 배지(Kernel 슬롯 `navCounts`, 현재 `managedSystem` 기준, mock에서는 배지 없음), `VOC 등록`의 Managed System 기본값(FeedbackOps 화면의 `managedSystem`이 UUID 하나이고 사용자 목록에 있을 때). 구현됨(#761 p2): `VOC` 그룹의 `Clusters`(`/feedbackops/clusters`) — 선택은 `focus`(셸 상세 슬롯), 개수 배지, 다른 화면의 Cluster 링크가 이 메뉴로 연결된다. 구현됨(#761 p3): 사이드바 `저장된 보기`(Kernel 슬롯 `spaceNavSection`, 원래 VOC 저장된 보기의 목록·적용·삭제와 수신함·Triage 현재 필터 저장; 후속 조치의 응답 선택은 `focus`) — 대시보드·복구·영역 보고서·알림의 Survey 링크가 이 메뉴로 연결되고, 바닥 블록의 `설문`이 `Survey 관리`를 셸 안에서 연다. `설문 참여`·`설문 응답`은 신고자 메뉴가 그대로 맡는다. 구현됨(#764 p2): `관리자` 그룹의 `Managed System`(`/feedbackops/managed-systems`)·`Analytics Area`(`/feedbackops/analytics-areas`, 상세는 `focus`로 연 셸 드로어, 화면 자체 필터는 `system`)·`권한 요청 검토`(`/feedbackops/permission-requests`)·`부여 목록`(`/feedbackops/permission-grants`)·`FeedbackOps 설정`(`/feedbackops/settings`, `section=coverage`가 `#coverage`) — 권한은 `console:access`(`workspace-admin` 규칙)라 `feedbackops:access`만 가진 사용자에게는 이 섹션이 없고, `목록 범위`는 꺼져 비활성이며, 화면의 자체 제목 줄은 플랫폼 머리가 대신한다. Coverage의 `설정` 링크·권한 요청 알림·복구 출처가 이 메뉴로 연결된다. 사용자 메뉴의 `FeedbackOps 전체` 링크는 없앴다.** 전환기 카드 `FeedbackOps` · 부제 `피드백 운영`, `feedbackops:access` 사용자에게만. 레일 섹션 `대시보드`(액션 큐) · `VOC` · `Findings` · `Tasks` · `연동` · `Surveys` · `관리자`. 사이드바는 FeedbackOps `NAV_TREE`에서 신고자 항목(`내 VOC`·`VOC 등록`·`설문 참여`)과 `연동 › Findings`를 뺀 것이고, Triage 보기·보기 항목은 부모 아래 하위 항목이다. 이름은 `권한 요청 검토`·`연동 액션 대시보드`·`FeedbackOps 설정`. 사이드바 Scope 자리에 `목록 범위` 선택기 하나(원본 의미: 모든 사용자에게 `전체` = 내 담당 합집합, 범위 밖 시스템은 흐리게 `범위 밖`, 관리자는 워크스페이스 전체; 원천은 URL `managedSystem` 하나; 섹션·메뉴 이동에도 유지; `관리자` 섹션 화면에서는 끔). 화면 머리는 플랫폼 페이지 머리 한 줄(`FeedbackOps › <메뉴>`, ☆, 원본 화면에 있는 동작만)이고 원본 제목 줄은 그리지 않는다. 확정 시안은 ADR-0081 Decider 줄. (위 `/feedbackops/…` 주소는 manifest `path`에 등록한 별칭이고 정규 URL은 `/feedbackops/<메뉴 id>`다 — 표는 `menus/AGENTS.md`).

**FeedbackOps 바닥 블록**: 메뉴 스크롤 밖, 위 경계 1px, 안쪽 여백 8–12px, 머리 `FeedbackOps · <시스템>`(12/16px), 항목 32px — `VOC` → `Task` → `설문` 중 권한 있는 것만(`VOC 등록`은 레일, ADR-0070). `feedbackops:access`가 없는 사용자에게는 블록을 그리지 않는다(슬롯 `permission`, ADR-0081 결정 8). **`VOC`는 셸 안 이동이다(#760)**: 같은 탭에서 `수신함`(`/feedbackops/vocs`)을 열고, 외부 링크 표시도 `새 탭` 이름도 없다(접근 이름 `VOC — <시스템>, FeedbackOps`). 링크는 `managedSystem`(그 공간의 Managed System)과 복귀 정보 `returnTo`만 싣는다 — 출발 화면의 기간·Scope·Condition은 싣지 않는다(ADR-0045, UX-9). FeedbackOps 주소(origin)가 없어도 열린다. **`Task`도 셸 안 이동이다(#763)**: 같은 탭에서 `Task 목록`(`/feedbackops/tasks/list`)을 열고 `managedSystem`과 복귀 정보만 싣는다(접근 이름 `Task — <시스템>, FeedbackOps`). **`설문`도 셸 안 이동이다(#764 p1)**: 같은 탭에서 `Survey 관리`(`/feedbackops/surveys`)를 열고 같은 두 값만 싣는다(접근 이름 `설문 — <시스템>, FeedbackOps`). 새 탭 항목은 지금 없지만 슬롯은 `href` 항목(`ExternalLink` 표시, 이름 끝 `, 새 탭`, 주소가 없으면 비활성)을 그대로 지원한다. 설명 줄은 셸 안 항목이 있으면 `FeedbackOps로 이동합니다`, 새 탭 항목이 있으면 그 아래 줄 `<ExternalLink 아이콘> 표시는 새 탭에서 열립니다`(보조 기술에는 `외부 링크 표시는 새 탭에서 열립니다`)다. 접힌 사이드바는 아이콘 셋을 같은 순서로 두고 접근 이름을 툴팁에 담는다. 높이 약 172–180px는 항목이 넷(`VOC 등록` 포함)일 때 잰 값이고 셋인 지금은 다시 재지 않았다. 사용자 문구는 `업무 시스템`이고 필요할 때 설명에 `Managed System`을 병기한다. 양식의 등록 대상과 목록 범위가 다르면 각각 `등록 대상`·`목록 범위`로 이름 붙이고, 같은 상태를 독립 선택기 둘로 만들지 않는다.

**복귀 줄 (구현됨, #760)**: FeedbackOps 페이지 머리 아래 본문 맨 위 32px(`PlatformPage`가 그린다), 링크 `← <출발 메뉴>로 돌아가기`, 옆 문구 `<시스템>에서 왔습니다`(출발 메뉴가 공간 밖이면 문구 없음). URL 페이지 키 `returnTo`가 `safeReturnTo`와 `canOpen`을 통과했을 때만 그리고(parent·홈 fallback이면 줄 없음), 돌아가면 출발 메뉴의 URL·Scope·기간·Condition/Selection·등록된 page 상태를 06 §6.4·§22 규칙으로 되살린다. `returnTo`는 FeedbackOps 공간의 `carriedPageKeys`라서 **줄이 남고 사라지는 규칙(UX-10)**은 이렇다: FeedbackOps 메뉴 사이를 옮기는 동안(레일 섹션·사이드바·대시보드 링크·FeedbackOps 안 필터 이동) 남고, 다른 시스템·전역 메뉴로 나가거나 전환기로 다른 시스템을 고르면 사라지며, 돌아가기 링크를 따라가면 사라진다. 저장된 보기를 적용하면 사라진다(새 목록을 여는 일이고, 적용 뒤 복귀 줄 유지는 사용자 요청이 있을 때 다시 연다 — 백로그). FeedbackOps 안의 링크는 이어받기만 하고 새 `returnTo`를 만들거나 덮어쓰지 않는다. **복원은 줄을 되살리지 않는다**: 공간 마지막 화면 복원(탭 세션)과 최근 방문은 저장할 때 `returnTo`를 뺀다. 그래서 전환기로 FeedbackOps에 들어오면 줄이 없다. 양식에서 고른 업무 시스템이 출발 화면의 조회 범위를 덮어쓰지 않는다. 미저장 입력이 있으면 이탈 확인 뒤 이동한다. 단순 시스템 전환(전환기)은 이 복귀와 다른 동작이다.

**전역 화면 사이드바 (ADR-0070)**: 홈을 포함한 공간 밖 전역 화면은 플랫폼 사이드바를 쓴다 — `홈` / 메뉴 그룹 `내 활동`(`알림` · `내 VOC` · `설문` · `권한 요청`) / `공지`. 접기(`[`)는 업무 사이드바와 같다. 각 항목은 자기 메뉴 권한으로 판정하고, 건수가 있으면 배지를 단다. 이 화면들은 공간이 아니고(`space: null`) 공간 수에 들지 않으며 전환기에 현재 표식이 없다. `내 활동`은 메뉴 그룹 이름이고 별도 페이지가 아니다. 설문은 레일 자리 없이 전체 페이지로 열리고(알림·홈·플랫폼 메뉴에서 진입), 미리 선택된 답이 없으며, 제출 뒤 출발 화면으로 돌아간다.

**권한 요청 페이지 (ADR-0070 결정 8, #657)**: `권한 요청` 전체 페이지는 먼저 업무 시스템 접근 권한은 플랫폼 관리자가 준다는 안내 한 줄을 보이고, FeedbackOps 기능 권한(필요하면 Managed System과 사유)을 요청하는 폼, 내가 보낸 요청의 상태 목록(대기 중·승인됨 등), 열린 요청의 `요청 철회`(줄 안 확인)를 둔다. 승인은 FeedbackOps 관리자 화면이 맡고(합류 설계 §3.3), 보완 제출·수정·만료일은 이 페이지에 없다(백로그).

**홈**: FeedbackOps 카드를 같은 권한·순서로 더한다. 순서는 업무 시스템 카드 → `내 할 일`(`응답할 설문` 마감 순 · `내 VOC` 지난 방문 이후 변경 · `권한 요청` 대기·결정됨, 빈 묶음은 숨김, 차트 없음) → `즐겨찾기` · `최근 방문` · `공지`다(ADR-0070, 3.1 홈 순서 대체). 구현(#657 2부, Kernel 슬롯 `homeTodo`): `마감 순`은 설문에 마감 필드가 없어 서버 순서(`opened_at` 내림차순)로 대신하고, `지난 방문 이후 변경`은 읽지 않은 공개 업데이트 알림(`voc.public_update_posted`, VOC당 한 줄)이다. `권한 요청`은 열린 요청과 7일 안에 결정된 요청(철회 제외)이다. 묶음마다 5줄까지 보이고, FeedbackOps 세션이 없거나 mock이면 구역이 없다([백로그](../../.planning/backlog.md)). 공간 0개면 `접근 가능한 업무 시스템이 없습니다` 아래 `권한 요청` 버튼을 둔다. FeedbackOps 자기 홈은 접근 이름 `FeedbackOps 홈`으로 플랫폼 홈과 구별한다(#595 구현 뒤에는 업무 시스템 `FeedbackOps`의 레일 섹션 `대시보드`, ADR-0081).

**검색**: 지금 전역 메뉴 검색(⌘K / Ctrl+K, 위쪽 640px 팔레트, 빈 입력이면 메뉴 목록)을 그대로 쓰고, 결과 보조 줄에 `<시스템> › <섹션> › <메뉴>` 전체 경로를 보인다. 플랫폼 메뉴의 목적지(홈·알림·내 VOC·설문·권한 요청·공지)도 같은 권한으로 찾는다(ADR-0070). 전환기는 작은 고정 목록, 검색은 숙련자의 직접 이동으로 역할을 나눈다.

**분석 보드 자리**: [16 §8](analysis-board.md#8-셸-결정에서-지금-정해-둘-것). 보드 화면에서만 main 열 맨 아래 40px + 위 경계 1px 시트 탭 띠를 쓰고, 일반 화면에서는 높이 0이다.

## 5. 메뉴 전환과 작업 복귀

### 5.1 워크스페이스 전환

- Rail 버튼으로 시스템을 바꾸면 **현재 Sidebar가 통째로 대상 Sidebar로 교체**된다. 포털 재진입을 강제하지 않는다.
- 같은 시스템으로 돌아오면 마지막으로 사용하던 화면으로 복귀한다. 요청한 URL과 권한은 다시 검증한다(06 §9.1).
- 포털에서는 시스템 설명·권한 상태·바로가기만 노출하고, 모든 메뉴를 중복 나열하지 않는다.
- 전역 검색(Command Palette)은 접근 가능한 **모든 시스템의 메뉴**를 대상으로 하며, 검색 결과에 시스템명을 표시한다.
- 사용자가 접근할 수 없는 워크스페이스는 레일/검색에 보이지 않고, 직접 URL 진입은 서버가 거절한다.
- 시스템별 마지막 화면은 사용자+공간별 탭 세션 범위에 저장한다(Decided, ADR-0028). 기기·세션 간 동기화는 없다.

### 5.2 시스템 간 이동

~~~text
생산성 분석 (설비/기간)
  └─ 명시적 링크: 관련 로그 검증 →
       표준 로그 개발 (대상 모델/검증 Round)
         └─ '생산성 분석으로 돌아가기' (원래 메뉴·지원 가능한 컨텍스트)

지표관리 (Metric ID + Version)
  └─ 해당 지표가 사용된 생산성 분석 →

개선 실행 (개선 과제/적용)
  └─ 관련 분석 결과 보기 →

각 시스템의 VOC/Task 상세
  └─ 원래 생성된 시스템의 업무 객체로 이동 →
~~~

- 딥링크는 **대상 식별자 + 발신 화면의 안전한 복귀 참조 + 지원 가능한 컨텍스트**로 구성한다. 목적지 객체 ID를 전역 필터인 것처럼 사용하지 않는다(06 §6·§22).
- **다른 시스템으로 넘어갔다고 사용자의 전역 Scope·권한이 바뀌지 않는다.** 대상 화면은 지원·권한 검증된 컨텍스트만 적용한다.
- 지원하지 않는 필터는 조용히 사용하지 않고 '이 화면에서 미사용' 등 구분하여 표시한다. 임의로 기존 범위의 데이터를 보여주는 것처럼 속이지 않는다.
- 각 워크스페이스의 로컬 페이지 상태(탭, 정렬, 테이블 열, 검색어 등)는 전역 Scope와 분리한다. 공간의 마지막 화면 복원은 사용자+공간별 탭 세션으로 Decided다([ADR-0028](../adr/0028-workspace-shell-launcher-pinned-feedbackops-global-utilities.md), [06 §9.1](../contract/kernel.md#91-업무-시스템-decided-2026-09-26)). 표 열 같은 다른 사용자 설정의 저장 위치는 아직 정하지 않았다.
- 안전한 딥링크·Back/Forward·새로고침·직접 진입은 기존 플랫폼 URL/Context 계약을 유지한다.

## 6. FeedbackOps UX 통합

### 6.1 시스템 안의 FeedbackOps

공간별 `VOC`·`Task`·`설문` 진입은 셸 안 메뉴로 열리고 `managedSystem`과 `returnTo`만 전달한다. 진입·권한·목록 범위·복귀 UX는 §3.2와 [06 §8](../contract/layout.md#8-shell-slots)이 소유한다. 화면과 역할별 기능의 권한·상태 규칙은 FeedbackOps가 판정한다. VOC 보고자 상태와 내부 Task 상태는 자동 매핑하지 않는다(FO ADR-0005).

SDK가 제공하는 외부 FeedbackOps 링크의 생성·검증·`platformReturn` 계약은 [딥링크 계약](../integration/feedbackops-deeplink.md)을 따른다.

### 6.2 전체 협업 허브

범위 없는 FeedbackOps 진입은 `feedbackops:access` 사용자의 업무 시스템 전환기 카드가 맡는다. 사용자 메뉴에는 `FeedbackOps 전체` 링크가 없다(ADR-0081 결정 6). 실제 데이터 접근 권한은 FeedbackOps 서버가 판정한다.

### 6.3 도메인 경계

- **FeedbackOps Task**: 제품 개선/개발 요청 등의 공통 실행·협업 객체.
- **로그 검증 Defect / Validation Round**: 표준 로그 개발 시스템이 소유.
- **현장 적용 과제 / 개선 실적**: 개선 실행 시스템이 소유.
- **지표 정의 / 지표 버전**: 지표관리 시스템이 소유.

같은 이름의 'Task'나 '이슈'가 있더라도 백엔드 객체를 강제 병합하지 않는다. 필요한 관계만 링크한다.

### 6.4 매핑·보안(기술 계약 Open)

플랫폼의 `SpaceDef.id`(UI 탐색), FeedbackOps의 `Managed System`(협업 스코프), 설비의 `Site/room_name/EquipmentID`(데이터 스코프)는 **서로 다른 식별 계층**이다. `workspaceId → managedSystemId`는 기본적으로 1:1이라고 가정하지 않는다. 명시적 매핑 모델, 호출 시 범위 검증, SSO/세션 위임/권한 설명을 #81·#150·#213에서 해결한다.

FeedbackOps 화면은 플랫폼에 합류하고 독립 앱은 은퇴한다([ADR-0066](../adr/0066-feedbackops-merges-into-platform.md)). 백엔드와 업무 객체는 FeedbackOps가 소유한다.

## 7. 컴포넌트 맵(소유권)

| 계층 | 책임 | 기존/추가 |
| --- | --- | --- |
| `@fops/ui` → `@ap/ui` | 토큰·Button·Badge·Shell형 primitives 등 | 기존 재사용, 도메인 코드 의존 금지 |
| `@ap/kernel` | SpaceDef/GroupDef/MenuEntry, Registry, 권한·Context·URL·전환 | 기존 계약 확장 |
| `@ap/shell` | AppRail·AppSidebar·Portal·CommandPalette·복귀 UX | 기존 셸 확장 |
| `menus/*/*` | 각 워크스페이스의 고유 업무 메뉴/화면 | 메뉴 그룹별 Consumer 유지 |
| FeedbackOps | VOC·Evidence·Finding·Task·설문 화면과 API | 플랫폼에 합류하며 업무 객체와 API는 FeedbackOps가 소유한다(ADR-0066) |
| 각 독립 백엔드 | 로그·분석·지표·개선·운영 도메인 규칙/DB | 합치지 않음 |

워크스페이스별로 새로운 FE를 복제하지 않는다. **동일한 FE shell/runtime이 등록된 도메인 메뉴를 조립**한다. 서로 다른 서버·DB를 합치거나 도메인 테이블을 공유 DB로 이동시키지 않는다.

## 8. 화면 스펙과 상호작용

### 플랫폼 홈(Directory)

- 목적: 업무 공간을 빠르게 고르기.
- 입력: 접근 가능한 Workspace 목록, 즐겨찾기/최근 메뉴, 공지(선택).
- 출력: 해당 공간으로 진입.
- 오류·빈 상태: 공간 0개면 `권한 요청` 버튼으로 권한 요청 페이지를 연다(ADR-0070); 로딩 시 업무 카드 자체를 재배치하지 않는다.
- 금지: 도메인 원천 없이 시스템별 건강 상태·성과 수치 집계.

### 업무 시스템 안의 FeedbackOps 진입

- 목적: 현재 업무 시스템의 VOC·Task·설문을 FeedbackOps에서 바로 열기.
- 입력: 현재 공간, 공간 → Managed System 매핑, FeedbackOps origin.
- 출력: 그 시스템으로 좁힌 FeedbackOps 화면(새 탭).
- 오류·빈 상태: 매핑이 없으면 진입을 그리지 않는다. origin이 없거나 잘못되면 링크를 비활성으로 보이고 화면은 그대로 둔다(1단계 딥링크와 같은 규칙).
- 금지: 시스템 범위 없이 FeedbackOps를 열면서 "이 시스템의 협업"이라고 표시하는 것.

### 전체 협업 허브 진입

- 목적: 권한자가 FeedbackOps의 전체 화면으로 가기.
- 입력: `feedbackops:access` 권한(ADR-0045), FeedbackOps origin.
- 출력: FeedbackOps의 시스템 범위 없는 화면(새 탭).
- 금지: 링크 노출을 다른 시스템 내용의 열람 권한처럼 다루는 것.

## 9. 프로토타입과 실제 구현의 차이

[HTML](../prototypes/multi-workspace-v2/index.html)은 **UI 상호작용 검토용 Mock**이다. 실제 백엔드, SSO, 서버 권한, 정확한 표준 로그 검증 결과, 실데이터, 정식 XLSX는 포함하지 않는다.

| 항목 | v2 HTML 표현 | 실제 앱 계약/과제 |
| --- | --- | --- |
| 좌측 rail | 56px | 기존 52px 확정 |
| Sidebar | 252px | 기존 240px/56px 확정 |
| 최상단 바 | 별도 56px | 기존 '상단바 없음 + 페이지 머리 50px' 확정. 프로토타입 차이를 임의 반영하지 않음 |
| Sidebar 검색 트리거 | 샘플 UI 있음 | 플랫폼 Command Palette 1개 |
| 협업 데이터 | 샘플 배열·브라우저 임시 등록 | FeedbackOps API·서버권한·SSO |
| 로그인·접근 가능성 | 모두 접근 가능한 샘플 사용자 | 공간/메뉴/객체별 권한 재검증 |
| 협력사 검토 파일 | 예시 CSV 생성 | 업무 요구 기준 XLSX 내보내기, 보안메일 연동 제외 |
| 작업 복귀/최근 | 브라우저 메모리 상태 | 마지막 화면 복원은 사용자+공간별 탭 세션(Decided, ADR-0028). 표 열 등 다른 사용자 설정 저장은 미정 |
| 설비/모델/지표 예시 | 가상 값 | 실제 도메인에서 제공 |

`main`의 앱 셸을 바꾸는 코드 작업은 **별도 이슈·실제 앱 `?variant=` 비교 프로토타입 승인·회귀 검증**을 거친다(루트 AGENTS.md). 이 문서는 해당 작업의 제품 방향이며 기능 완료 증거가 아니다.

## 10. 단계별 이행

1. **설계 기준 고정:** UX·IA·예외·Open 문서/ADR/HTML 승인안 저장. 이 단계에서는 서비스 코드·서브모듈을 수정하지 않는다.
2. **셸/Registry 확장:** 포털·워크스페이스 메뉴·전용 Sidebar·통합 검색/탐색·권한 기반 노출·기존 라우트 호환.
3. **업무 워크스페이스 등록:** 분석/지표 분리, 로그 개발·개선 실행·운영 콘솔 추가; 기존 설비/기준정보 귀속 확정.
4. **FeedbackOps 진입:** 공간 → Managed System 매핑(#81, Decided — ADR-0045)과 링크 계약 확장 뒤 공간별 진입과 허브 링크를 단다(#251 완료). 화면의 플랫폼 합류는 ADR-0066과 #595를 따른다.
5. **시스템 간 링크 UX/회귀:** 출발 화면 복귀, 무권한, 필터 미지원, 새로고침·Back/Forward·직접 URL, 시스템 0개/많음, 좁은 데스크톱 폭 검사.

## 11. 구현 수용 기준

- [ ] 4개 핵심 + 운영 콘솔이 각자 **메뉴 그룹·전용 Sidebar·독립 기본 화면**을 가진다.
- [ ] 포털과 rail은 도메인 메뉴 수가 늘어도 1층 탐색으로 유지된다.
- [ ] 권한 없는 워크스페이스는 rail/검색/URL에서 접근이 거부된다.
- [ ] 공간의 FeedbackOps 진입은 **현재 시스템**의 Managed System으로 좁혀 열고, 매핑이 없으면 그리지 않는다.
- [x] 전체 허브 링크(사용자 메뉴 `FeedbackOps 전체`)는 없앴다(#764 p2). 전환기 카드가 `feedbackops:access` 사용자에게만 보이고, 내용 판정은 FeedbackOps가 한다.
- [ ] FeedbackOps 백엔드/객체를 복제하거나 로그 결함·개선 실적을 강제 통합하지 않는다.
- [ ] 교차 링크는 대상+발신 맥락을 보존하고, 대상이 지원하지 않거나 권한 없는 필터를 적용하지 않는다.
- [ ] 이전 분석·지표·설비·기준정보 라우트/딥링크를 단계적으로 호환 처리한다.
- [ ] 실제 앱에서 기본 셸 치수·디자인 토큰·고정 상세 슬롯 계약을 유지한다.
- [ ] Kernel/셸/FeedbackOps 접근 테스트와 데스크톱 UX 캡처·회귀를 추가한다.

## 12. Open / Risk

- **Open:** 여러 시스템 매핑 정책과 필터 불변식(공간당 하나는 Decided — ADR-0045, #213).
- **Open:** SSO·세션 공유(#150). 세션 공유 전에는 FeedbackOps에서 로그인을 한 번 더 거칠 수 있다.
- **Decided:** 공간 0개 사용자의 권한 요청 안내 목적지는 `권한 요청` 페이지다(ADR-0070 결정 8이 #250을 닫았고 #657이 구현했다).
- **Risk:** 한 화면에서 시스템을 바꾸는 동안 이전 시스템의 캐시·상세 패널이 보일 수 있음. 현재 Scope/permission이 변경되면 이전 결과를 새 결과처럼 보여주지 않는 06 §11 계약 준수.

# 18. 사용자 분석 메뉴 — 제품 방향 (#2906)

상태: **Candidate (방향, 소유자 2026-11-25).** 결정의 원본은 [ADR-0176](../adr/0176-user-analysis-menu-one-definition-two-homes.md)이고 계약 문구는 구현 이슈가 [06](../contract/platform-ui-contract.md)의 해당 절에 넣는다. 이 문서는 그 결정이 향하는 제품 모습, 하지 않는 것, 단계 순서를 한곳에 적는다. 구현 승인이나 보류 해제가 아니다. 근거 기록은 [노코드 사용자 분석 메뉴 리뷰](../reviews/2026-11-23-nocode-user-menu-review.md), 에픽은 [#1761](https://github.com/hjung3113/analytics-platform/issues/1761)이다.

## 1. 방향

개발자가 완성 메뉴만 주던 것에서, **개발자가 검증된 패널을 공급하고 사용자가 그 패널을 조합해 다른 사람이 다시 열 수 있는 메뉴로 만드는** 쪽으로 넓힌다. 소유자는 Hex의 분석 → 조합 → 공유 흐름을 가장 가까운 참고로 꼽았다(2026-11-25).

| 누가 | 하는 일 |
| --- | --- |
| SDK 개발자(이 저장소) | 패널 선언·연결·저장·공유의 계약과 범용 차트 조각을 제공한다 |
| 사내 메뉴 개발자(저장소 밖 메뉴 패키지) | 도메인 분석 패널을 만들어 패널 선언으로 내놓는다 |
| 사내 백엔드 | 닫힌 질의를 실제 DB에서 실행하는 핸들러와 실행 환경을 맡는다(#2916) |
| 데이터 책임자 | 분석 데이터셋과 공식 지표를 발행한다(3단계부터) |
| 사용자 | 기존 화면에서 패널을 더하고, 잇고, 저장하고, 공유한다 |
| 시스템별 승인자 | 공식 신청을 검토한다 |

차트는 표현 수단이고, 패널은 분석 질문 하나에 답하는 재사용 단위다. 패널 인스턴스의 `source`는 `declared`와 `chart` 둘이다(ADR-0176).

## 2. 되는 것과 하지 않는 것

| 범위 | 판단 | 근거 |
| --- | --- | --- |
| 기존 화면에서 패널 조합 → 저장 → 공유 → 공식 | 한다(1·2단계) | 패널 선언, 패널 빌려주기, 분석 선택, 작업 영역, 저장된 뷰의 ACL·승인이 이미 있다 |
| 차트 종류 × 메뉴가 선언한 지표 × 나누기 | 한다(1단계) | #2761. 메뉴가 선언한 범위 안에서만 고른다 |
| 분석 데이터셋에서 새 메뉴 만들기 | 한다(3·4단계) | 분석 데이터셋 계층(#1704)이 먼저다. 이 저장소는 계약과 합성 데이터까지 만들고, 실행은 사내 핸들러가 한다(#2916) |
| 피벗, 사용자 계산식 | 조건부(5단계) | 피벗은 닫힌 질의의 두 축 묶기와 서버 집계를 먼저 본다. 계산은 분자 합 ÷ 분모 합부터다. #1707, #163의 재개 조건을 따른다 |
| 사용자 SQL·Python·임의 조인 | 하지 않는다 | 데이터 무결성과 권한: 서버가 승인된 관계와 닫힌 질의만 실행한다. SQL·Python은 분석 데이터셋 초안을 만드는 길로만 쓰고, 데이터 책임자가 발행한 뒤에 사용자에게 보인다(#1762) |
| 정기 실행, AI 조합 | 이 방향의 비목표 | 정기 실행은 #1713이 소유한다 |
| 공식 승인으로 코드 메뉴 자동 생성 | 하지 않는다 | 승인된 정의는 개발 요청의 명세다(ADR-0176) |

분석 보드는 메뉴 화면 여러 개를 나란히 놓고, 사용자 분석 메뉴는 화면 하나 안에서 패널을 조합한다. 한 차트 안에서 겹쳐 비교하는 것은 차트 계약의 Compare(06 §16)이고, 조건이 다른 두 조회를 나란히 보는 것은 같은 패널의 두 인스턴스다.

## 3. 대표 흐름

기존 화면에서 원인을 찾다가 재사용할 분석으로 남기는 흐름이 첫 번째다. 검증 화면은 HW Time이고 빌린 패널 사례는 Configuration이다.

1. HW Time에서 조회 조건을 적용한다.
2. 차트에서 구간이나 항목을 고른다. 분석 선택이 칩으로 남고 «다음 분석»이 나온다.
3. 현재 분석 선택이 필수 입력을 채우는 패널 가운데 하나를 더한다. 추천은 선언 기반 거름이고 순위 모델이 아니다.
4. 상위 요약은 그대로 두고 더한 패널만 좁힌다. 비교할 패널 하나는 붙잡고 나머지는 따라간다.
5. 메뉴가 선언한 지표·나누기로 기본 차트를 더한다.
6. 이름을 붙여 저장한다. 다시 열면 패널, 연결, 배치가 복원된다. 공유받은 사람은 자기 권한 범위에서 본다.
7. 자주 쓰이면 공식 신청을 한다.

기본 조작은 끌어 놓기다(소유자 2026-11-25, #2917): 패널 목록에서 화면으로, 필드 칩을 매핑 칸으로, 분석 선택 칩을 패널 위로. 끌기마다 키보드와 메뉴로 같은 결과를 내는 길을 둔다(접근성). 끌기는 입력 방식이고 저장되는 정의는 같다.

공유받은 사람이 고치면 저장된 뷰의 `수정됨`, «저장본으로 되돌리기», «새 뷰로 저장»을 쓴다. 편집 모드와 열람 모드를 따로 두지 않는다.

## 4. 단계

단계 이름은 리뷰 §5의 번호를 쓴다. 단계별 수용 기준은 각 이슈가 소유한다.

| 단계 | 목표 | 이슈 |
| --- | --- | --- |
| 0. 기반 계약 | 분석 선택 전달, 패널 추가 메뉴 범주, 저장되는 차트 설정 | #2732–#2735(끝남), #2744, #2745 |
| 1. 패널 구성 저장 | 패널 추가·설정·연결·저장, 빌린 패널 출력, 붙잡기, 끌어 놓기 | #2760–#2763, #2862, #2917 |
| 2. 내 메뉴와 공유 | 내 메뉴 내비, 공유, 공식 승인, 복제, 감사와 사용 계측 | #2764, #2765 |
| 3. 분석 데이터셋 계층 | 분석 데이터셋, 공식 지표, 닫힌 질의, 카탈로그 | #1704, #1711, #1762. 사내: #2915, #2916 |
| 4. 데이터셋에서 만들기 | Host 메뉴, `analysis-menu` | #1763 |
| 5. 넓히기 | 데이터셋 사이 비교, 보드 칸 간 연결, 피벗, 계산 | #911, #1708, #1707, #163, #1709 |

3단계는 1·2단계와 나란히 간다(소유자 2026-11-25). 가장 오래 걸리는 단계이고, 사내가 닫힌 질의 핸들러와 데이터셋 발행을 맡는다. 합성 데이터셋의 모양은 사내에서 넘겨받는 마스킹 명세(#2915)를 따른다.

1·2단계가 끝났다는 시험은 하나다: HW Time과 Configuration의 mock에서 3절의 흐름 1–7을 코드 변경 없이 끝낸다. 입력 누락, 차원·shape·grain 불일치, 연결 순환, 범위 확대, 권한 회수, 패널 선언 삭제는 그 자리만 실패하고 나머지 패널은 그려진다. 실제 사용자를 관찰하는 사용성 실증은 사내 파일럿의 일이다.

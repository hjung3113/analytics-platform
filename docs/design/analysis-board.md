# 16. 분석 보드 — 하단 시트 탭 · 그리드 칸 · 칸별 조건

상태: **Decided — 1차 범위의 동작(사용자, 2026-10-19 #421 설계 질의 Q1–Q25)** / **Decided — 칸 머리·선택 표시([ADR-0051](../adr/0051-analysis-board-pane-header-signal-chips-numbered-selection.md), 2026-10-19)** / **Deferred — §10**. 구현은 나눠 진행했다: Kernel 칸 Context(#496), 보드 골격(#497a: `/board` 플랫폼 화면·시트 탭 띠·그리드·칸 선택·Context 바·저장·되돌리기·레일 진입), 칸 머리 차이 칩·`⋯` 동작·일괄 적용/복사·`분석 보드에 열기…`·상세 슬롯 공유·`이전 화면`(#497b), 메뉴 보드 지원·E2E(#498)를 이 사양대로 구현했다. 1차 분석 보드 구현 완료(#496·#497·#498). 추적: [#421](https://github.com/hjung3113/analytics-platform/issues/421). 용어는 [GLOSSARY](../../GLOSSARY.md) "분석 조건과 분석 보드".

> 분석 Context의 범위 계약은 [06 §6.5](../contract/kernel.md#65-분석-context의-범위--칸-decided-adr-0049)와 [ADR-0049](../adr/0049-analysis-context-belongs-to-a-pane.md)가 소유한다. 이 문서는 보드 화면과 동작을 적는다.

## 1. 문제

분석은 한 메뉴만 보지 않는다. 엔지니어는 관련된 여러 메뉴(사이클타임 상세 + 설비 Top View + 지표 상세)를 함께 보거나, 같은 메뉴를 다른 조건(지난달 vs 이번 달, PHOTO vs ETCH)으로 나란히 본다. 지금 플랫폼은 화면 하나 = URL 하나라서, 그때마다 브라우저 창이나 탭을 새로 연다. 창마다 셸과 사이드바가 반복되고, 창 사이의 배치는 저장되지 않으며, 다음 날 같은 비교를 다시 만들어야 한다.

## 2. 범위

- **1차(이번 구현, §9의 1·2단계)**: 보드 화면, 시트 탭 띠, 시트마다 1×1 · 1×2 · 2×1 · 2×2, 칸마다 메뉴 하나와 독립 분석 Context, 칸 조건 편집과 일괄 적용·복사, 보드 지원 선언, 좁은 칸 점검. 저장은 브라우저(§7).
- **뒤로 미룸(§10)**: 서버 저장·공유, 여러 보드, 시트 복제, 칸 묶음, 서버 동시 실행 상한.
- **빠짐**:
  - 칸끼리 값을 합치는 계산(이 칸의 P95 − 저 칸의 P95). 서로 다른 시스템의 데이터를 합치는 교차 분석이라 별도 결정이다(사이트 비전 ③ 사용자 비정형 분석).
  - 메뉴를 누르면 기본으로 보드에 여는 동작(§7).
  - 본 화면 레이아웃 변경. 보드를 쓰지 않는 사람에게는 지금 화면 그대로다.
- **재개 조건 처리**: 처음 적은 다시 볼 조건 중 셸 구조 결정은 [ADR-0042](../adr/0042-system-switcher-and-system-owned-rail.md)로 충족됐다. "실제 메뉴 2–3곳에서 나란히 보기 요구 확인"은 소유자 방향(2026-10-18)으로 갈음했다(사용자, 2026-10-19). 보드는 메뉴 사이 반복 UI 패턴이 아니라 Kernel·레이아웃 계약이라 06 §24의 공통화 기준이 그대로 해당하지 않는다.

## 3. 용어

[GLOSSARY](../../GLOSSARY.md)의 분석 Context · 본 화면 · 분석 보드 · 시트 · 칸 · 기본 조건을 쓴다. 칸을 "패널"이라 부르지 않는다(상세 패널과 섞인다). 분석 보드는 Page Archetype(06 §12)이 아니다. 칸 안의 메뉴 화면은 자기 아키타입을 유지한다.

## 4. 화면 구조 (Decided)

- **진입**:
  - 레일 공통 도구의 `분석 보드`(메뉴 검색 아래, 모든 시스템에서 같은 자리, ADR-0042). 보드 지원 메뉴를 하나라도 열 수 있는 사용자에게만 보인다.
  - 보드 지원 메뉴의 페이지 머리 `⋯`에 `분석 보드에 열기…`. 누르면 대화상자에서 넣을 곳을 고른다: **새 시트**(1×1, 기본 선택) / 기존 시트의 빈 칸 / 기존 칸 바꾸기(바꾼다는 확인). 넣은 뒤 보드로 이동한다. 사용자가 고르기 전에는 어떤 칸도 덮어쓰지 않는다.
  - 메뉴 클릭의 기본 동작은 지금처럼 본 화면 이동이다.
- **최소화·복원·닫기([ADR-0087](../adr/0087-board-minimize-restore-history.md), #893)**: 보드는 열린 뒤 한 React 인스턴스로 남는다(숨은 보드는 일반 화면의 Suspense와 경계를 나눈다 — 지연 로드 화면이 suspend해도 보드가 가려지거나 차트가 다시 만들어지지 않는다). 보드에서 홈·일반 메뉴로 이동하면 그 이동이 곧 최소화다(사전 조작·확인 없음). 최소화 중에는 main 아래 왼쪽의 한 줄 칩 `분석 보드 · <시트 이름>`(버튼 하나)과 레일 `분석 보드(최소화됨, 눌러 복원)`이 한 번에 같은 시트·칸·선택·초안·차트 확대로 되돌린다. 레일 버튼은 닫힘 `분석 보드` / 열림 `분석 보드(열림)` / 최소화 세 이름과 아이콘 표지로 구분한다. 보드 폭(뷰포트 아님)이 760px보다 좁으면 머리의 `이 브라우저에만 저장`·`최소화`·`보드 닫기`는 글자를 숨기고 아이콘만 남기며(접근 이름·`title`은 그대로) 머리 버튼이 겹치지 않게 한다. 보드 머리 오른쪽의 `최소화`는 마지막 일반 경로(없으면 홈)로 돌려보내되 그 경로의 상세를 여는 `focus` 키는 뗀다(복귀 주소는 상세를 여는 키를 떼므로 도착한 화면의 상세가 보드 상세를 교체하지 않는다). 포커스는 칩으로 옮기며, `보드 닫기`는 열린 보드만 끝내고 저장된 시트는 남긴다. 열기·최소화·복원은 모두 history replace다(전이표는 ADR-0087). 숨은 보드는 도착 포커스를 가져가지 않고 주소를 쓰지 않으며, 0으로 측정되는 숨김 크기를 좁은 폭으로 보지 않는다. 숨은 보드의 상세·overlay·토스트·권한 처리는 893c2. 숨은 보드는 일시 UI만 정리한다: 보드 소유 menu·popover·dialog와 끌기·지연 포커스 핸드오프를 닫고 되돌리기 토스트를 닫으며(숨은 보드는 새 토스트를 만들지 않는다), 칸이 연 상세는 자리를 지킨 채 보이지 않는다(소유 표면 중지, [ADR-0088](../adr/0088-surface-pause-detail-slot.md)). 분석 선택·초안·드릴·행 선택·차트 확대·스크롤은 지우지 않는다. 최소화 중 일반 화면이 새 상세를 열면 보드의 상세는 기존 교체 규칙으로 끝나고, 복원해도 되살리지 않는다(ADR-0088 우선권 표). 사용자가 바뀌면 열린 보드·초안·복귀 주소·칩이 함께 사라지고, 최소화 중 권한이 회수되면 복원 직후에도 그 칸은 권한 상태로만 보인다.
- **창으로 보기([ADR-0091](../adr/0091-board-floating-window.md), #893 893d)**: 최대화한 보드의 머리 `창으로 보기`(`최소화` 옆)는 보드를 일반 화면 위에 뜨는 비모달 창으로 보인다(시안 A 자유 창). 배경 차단막·포커스 가두기·바깥 클릭 닫기·`Esc` 닫기 의미가 없고, 레일·사이드바·페이지 머리·칩 행은 덮지 않는다(창의 영역은 main을 감싼 위치 지정 상자이고, 아래쪽 토스트 띠 — 토스트 스택 `bottom` 오프셋에서 도출 — 는 영역에서 뺀다). 표시 모드는 저장하지 않고 파생한다: 주소가 `/board`면 최대화(`floating`은 `/board` **도착** 때만 지운다), 아니고 `live`이며 `floating`이면 창, 아니고 `live`면 최소화. 보드는 `FloatingWindow`의 자식으로 모든 표시에서 같은 React 자리에 있어(`off`/`window`/`fill`) 모드가 바뀌어도 다시 마운트하지 않는다. 창에서는 보드 자체 머리의 최소화·닫기 대신 창 제목줄 `분석 보드 · <시트 이름>`의 `최소화`·`최대화`·`닫기`와 `창 메뉴`(위치 5·크기 3)를 쓰고, 보드 제목은 페이지 제목이 아니며 도착 포커스를 가져가지 않는다. 이동·크기는 끌기 외에 제목줄 방향키(Alt = 크기)와 메뉴로 한다.

  | 전이 | 주소 | 저장소 |
  | --- | --- | --- |
  | 최대화 → 창으로 보기 | 복귀 일반 경로로 **replace** | `floating=true`, `lastMode='floating'` |
  | 창 → 최소화 | **변경 없음** | `floating=false`, `lastMode='floating'`, 포커스는 칩 |
  | 최소화 → 복원(칩·레일) | `lastMode='floating'`이면 변경 없음, 아니면 `/board?sheet=` replace | 창이면 `floating=true` |
  | 창 → 최대화 | `/board?sheet=` **replace** | `floating=false`, `lastMode='maximized'` |
  | 창 → 닫기 | 변경 없음(배경 주소 유지) | `live=false`, `floating=false` |
  | 창 중 일반 메뉴 이동 | 배경만 push, **창 유지**(최대화 중 이동은 기존 자동 최소화) | 변경 없음 |
  | 창 중 Back/Forward가 `/board`에 도착 | `/board` | 도착 때 `floating=false`(최대화) |

  `lastMode`는 최소화 직전 가시 모드로 항상 최신이다(자동 최소화 포함). 창은 주소를 읽지도 쓰지도 않는다: 시트 선택은 보드 세션의 활성 시트만 바꾸고 주소·history는 그대로다(주소를 소유하는 것은 최대화뿐). 창의 위치·크기(`geometry`)는 사용자 조작(끌기·핸들·키·메뉴)만 저장소에 쓰고 이번 실행 동안만 기억하며 새로고침·사용자 교체 뒤에는 사라진다. 영역이 줄면 표시만 clamp하고 저장값은 건드리지 않는다. 영역 폭이 900 미만이거나 창의 최소 크기(640×420)를 담지 못하면 창 대신 같은 인스턴스를 영역 전체에 채운 최대화 표시(`fill`)로 열고 `창 대신 최대화 표시로 열립니다`를 보이며, 주소는 `/board`로 바뀌지 않고 저장된 `geometry`는 그대로다. 레이어: 창(`z-40`)은 모달·팝오버·메뉴(`z-50`)와 토스트(`z-100`)보다 아래다. 모달이 열리면 Radix가 형제를 처리하므로 창에 수동 `inert`를 걸지 않는다. 토스트가 제목줄을 가려도 레일 버튼(`분석 보드(창으로 열림, 눌러 앞으로)`)이 제목줄로 포커스를 보낸다. 최소화는 893c 칩 그대로다.
- **보드 화면**: 업무 시스템 사이드바를 붙이지 않는다(홈·전역 유틸리티와 같은 취급, ADR-0028). 페이지 머리 50px에 보드 이름, 레이아웃 선택(1×1 · 1×2 · 2×1 · 2×2), 선택된 칸의 Context 바.
- **선택된 칸**: 시트에는 늘 선택된 칸이 하나 있다. 처음 열 때(저장된 값이 없거나 깨졌을 때)만 첫 칸이 선택된다. 새로고침·새 탭·다음 세션은 마지막 선택 칸과 묶음별 활성 탭을 되살린다(선택이 시트의 칸이 아니면 첫 칸). 칸을 누르면 선택이 옮겨 간다. Context 바는 선택된 칸의 분석 Context를 편집하고, 빈 칸이 선택되면 바는 비활성이다.
  - **표시(ADR-0051)**: 모든 칸(빈 칸 포함)에 번호 배지 `칸 N`이 늘 보인다. Context 바 앞머리·상세 머리·토스트·팝오버도 같은 번호를 쓴다. 선택된 칸은 번호 배지가 강조색이 되고, 칸 전체 높이의 왼쪽 2px 강조 막대와 머리 선택 표면(공유 selected 표면)을 가진다. 색만으로 선택을 나타내지 않는다.
  - **키보드**: 칸 머리 제목이 "칸 N 선택" 버튼이고, 칸 안으로 포커스가 들어가면(focus-within) 그 칸이 선택된다. 숫자 키 단축키는 두지 않는다.
  - **머리 동작은 먼저 선택한다**: `⋯`·`같음 N`·칩 등 칸 머리의 어떤 동작이든 열 때 그 칸을 먼저 선택한다(바가 다른 칸을 보이는 동안 다른 칸의 조건이 퍼지지 않게).
- **시트 탭 띠**: main 열 맨 아래, 높이 40px + 위 경계 1px, 본문 스크롤 밖(§8). 시트 추가(+), 이름 바꾸기(더블클릭), 끌어서 순서 바꾸기, 삭제(실행 취소 제공), `이 시트 조건을 다른 시트에 복사`. 시트는 최대 20장. 시트 탭은 ←/→로 이동하고(`role=tab`), 시트 동작은 탭 밖 메뉴로 연다(탭 안에 버튼을 넣지 않는다).
- **칸 머리(ADR-0051, 한 줄)**: 번호 배지, 업무 시스템 이름 칩, 메뉴 이름, 같은 시트의 다른 칸과 **다른 키만** `키 값` 칩(강조색), 같은 키는 `같음 N`(누르면 그 칸의 조건 전체 Popover — 정의 목록과 `Context 바에서 편집`), 동작 `⋯`(`@ap/ui` DropdownMenu): `이 조건을 시트의 모든 칸에 적용`, `본 화면에서 열기`(그 칸의 조건으로 본 화면을 연다), `바꾸기`, `복제`(같은 메뉴·같은 조건의 칸을 빈 자리에), `비우기`.
  - **넘침**: 메뉴 이름의 최소 폭은 기본 96px이고 차이 칩은 줄바꿈하지 않는다. 넘침 배치를 쓰면서 차이 칩이 하나 이상 있으면 차이 칩에 공간을 먼저 주도록 메뉴 이름의 최소 폭을 64px로 줄이고 이름은 말줄임한다(결정자: 콘덕터, 사용자 결정 BX-3 A 적용). 넘침이 없거나 다른 조건이 없으면 96px를 유지한다. 차이 칩이 모두 들어가면 기존처럼 `같음 N` 버튼을 보이고 넘침 버튼은 두지 않는다. 차이 칩이 다 들어가지 않으면 차이 칩을 먼저 배치하고 `같음 N`을 넘침에 합쳐 `+N`으로 보인다(N = 숨은 차이 조건 + 같은 조건). 누르면 그 칸의 모든 조건과 기존 `다름` 표식, `Context 바에서 편집`을 보여 준다.
  - **접근 이름**: `칸 2 동작`, `칸 2의 같은 조건 3개`, `칸 2의 조건 4개 더 보기`처럼 칸 번호와 개수를 보인다. 넘침 문구는 숨은 조건의 수를 사용한다.
- **빈 칸과 저장 범위**: 각 빈 칸에 번호와 `분석 화면 넣기`를 보이고, 누르면 해당 칸의 기존 화면 선택기를 연다. 시트의 모든 칸이 비었을 때만 그리드 위에 한 번 `분석 화면 두 개를 넣어 나란히 비교하세요`와 시트·칸 설명을 보인다. 보드 머리에는 아이콘과 `이 브라우저에만 저장`을 항상 표시하고, 누르면 `보드와 배치는 이 브라우저의 저장 공간에 보관됩니다. 다른 컴퓨터나 기기에서는 보이지 않습니다.`를 설명한다. 이는 저장 범위 안내이며 저장 성공 표시가 아니다.
- **패턴 근거**: [보드 다듬기 사례 조사](../research/2026-10-20-board-polish-patterns.md).
- **칸 크기([ADR-0060](../adr/0060-analysis-board-pane-sizing-collapse-maximize.md), 사용자 2026-10-21, D)**: 페이지 머리 50px·Context 바 48px·시트 띠 40px+경계·본문 padding·빈 시트 안내를 뺀 영역에 그리드를 맞추고 칸 본문만 스크롤한다. 칸 머리는 기존 한 줄 40px이며 바깥 경계를 포함한 접힌 칸 높이는 42px다. 펼친 본문은 최소 120px, 열은 최소 340px이다. 높이가 부족하면 보드 본문을 스크롤해 안내·칸·조건·탭에 계속 닿을 수 있다.
  - 1×1에는 구분자·접기·최대화가 없다. 1×2에는 열 구분자만, 2×1에는 행 구분자 하나, 2×2에는 열 구분자와 **열마다 독립된** 행 구분자를 둔다. 드래그는 pointer capture를 쓰고, 구분자 방향키는 5%, Home/End는 실제 픽셀 최소·최대 비율까지 조절한다. 이름은 `열 너비 조절` / `칸 a과 칸 b 높이 조절`, role=separator·orientation·현재/최소/최대 값·실제 칸 DOM id를 연결한 controls·포커스 링을 제공한다.
  - 두 칸 이상이면 `칸 N 접기` / `칸 N 펼치기`(aria-expanded)와 `칸 N 최대화` / `원래 크기로`를 둔다. 접으면 본문만 숨기고 inert로 두며 같은 논리 열의 다른 칸에 높이를 준다. **논리 열마다 하나는 펼쳐야 한다**: 마지막 펼친 칸의 접기는 사유와 함께 꺼진다. 1×2는 각 열에 칸이 하나라 두 접기 버튼 모두 꺼진다(세로 쌓기에서도 같다).
  - 최대화는 다른 칸 루트를 숨기고 inert로 두며 저장하지 않는다. 접힌 칸도 최대화 중에는 본문을 임시로 보이되 저장된 접힘은 바꾸지 않고 접기 버튼은 끈다. 복원하면 원래 접힘과 비율로 돌아간다. 숨길 칸의 메뉴·Popover·선택기·확인창·화면 소유 transient overlay와 지연 포커스 핸드오프를 취소한다. 공유 상세는 기존 칸 소유로 유지한다.
  - Escape는 메뉴·Popover·대화상자·선택기·상세의 처리부터 존중하고, 처리되지 않은 이벤트만 최대화를 끝낸다. 상세가 열려 있어도 보드 안의 Escape는 최대화만 복원한다. 숨김/inert를 제거한 뒤 최대화 트리거로 포커스를 돌리고, 없으면 보이는 칸/보드 머리로 간다. 상세 닫힘도 숨겨진 opener를 건너뛴다.
  - `크기 초기화`는 현재 시트·현재 레이아웃의 비율과 접힘만 초기화하고 실행 취소 토스트는 만들지 않는다. 저장 비율과 유효 크기는 분리한다: 폭·높이가 줄면 렌더만 clamp하고 공간이 돌아오면 저장 비율을 다시 적용한다.
- **레이아웃 줄이기**: 2×2 → 1×2처럼 줄여 내용이 있는 칸이 넘치면, 바꾸기 전에 "칸 N개가 비워집니다"를 확인하고(첫 포커스는 `취소`) 바꾼 뒤 토스트로 실행 취소를 준다. 빈 칸만 넘치면 확인 없이 바꾼다. 넘친 칸을 숨겨 보관하지 않는다.
- **좁은 뷰포트**: 기존 동일 배분 기준으로 그리드 content box가 `2×340 + 12 = 692px`보다 좁으면 행 우선 순서로 한 열에 쌓는다(뷰포트 폭 기준 아님). 구분자·최대화는 숨기고 접기는 유지한다. 저장 비율은 바꾸지 않는다. 1280 + 실제 상세 440px에서는 2×2가 두 열로 남고 1120 + 상세에서는 쌓인다. 세로 쌓기에서는 펼친 칸 전체를 최소 400px(머리·경계 포함, 본문 약 358px)로 두고 보드 본문을 스크롤한다. 접힌 칸은 머리·경계 42px만 유지한다(콘덕터 결정, 되돌릴 수 있음). 쌓기 밖의 본문 최소 120px은 유지한다. 서로 다른 저장 열 비율은 쌓기 전 각 열 340px 이상으로 먼저 clamp한다.

- **dock 렌더러([ADR-0067](../adr/0067-dockview-layout-engine-board-v2.md), 설정 `platform:board-layout-engine`, 기본값은 `dock`이고 `grid`는 한 릴리스 동안 대체 렌더러)**: 같은 저장 모델 V2를 탭·도킹으로 그린다. 기본값을 `dock`으로 바꾼 것은 2c(칸 머리 C, Opus 판정 2026-10-22: 본문 높이·칸마다 메뉴 하나·보이는 최대화 토글).
  - **탭**: 칸 하나가 탭 하나이고 이름은 `칸 N · 메뉴명`(빈 칸은 `칸 N · 빈 칸`)이다. N은 칸 번호(순서 + 1)라 탭을 옮겨도 바뀌지 않는다. 탭은 `칸 N` 배지(Context 바와 같은 부품: 선택된 칸은 강조색으로 채우고 다른 칸은 중립)·메뉴 이름(한 줄 말줄임, 64–160px, 전체 이름은 툴팁, 빈 칸은 `빈 칸`)·X 순서다. 선택된 칸은 늘 자기 그룹의 활성 탭이다 — 끌기나 명령으로 다른 탭이 앞에 오면 선택이 그 탭으로 옮겨 간다. 내용이 있는 칸의 탭에는 X가 있어 첫 클릭에 `비우기`(+ 실행 취소, 선택 여부와 무관, 그 칸도 선택)와 같다. 탭에서 Delete/Backspace도 `비우기`이고 빈 칸에서는 아무 일도 없다. 비운 뒤 포커스는 그 칸의 탭에 남는다. 엔진 닫기는 어디에도 없다. 보조기기에는 선택된 칸의 탭이 `편집 대상 칸`(설명)이고 탭마다 쓰는 키(`Delete Shift+F10`, 빈 칸은 `Shift+F10`)를 `aria-keyshortcuts`로 알린다. 탭 제목은 탭 높이 가운데에 두고 왼쪽 여백은 탭이 하나든 여럿이든 같다. 탭 줄은 넘치지 않거나 끝에 닿으면 세로 휠을 바깥 스크롤로 넘긴다(`overscroll-behavior: auto`, 넘치는 줄은 dockview의 가로 탭 스크롤이 우선, #700).
  - **칸 머리(한 줄 띠, C)**: 그룹마다 40px 띠 하나다. 왼쪽이 탭 목록(`role=tablist`, 탭만)이고, 남는 공간 뒤 오른쪽 끝이 **활성 탭 칸의 영역**이다(tablist 밖의 형제, `role=group` 이름 `칸 N 머리`): 업무 시스템 칩·차이 칩·`같음 N`/`+N`·`이전 화면`·**최대화 토글**(28px, `칸 N 최대화` ↔ `원래 크기로`, grid와 같은 이름·아이콘)·`⋯` 하나(`칸 N 동작`). 영역은 그룹의 활성 탭이 바뀌면 그 칸 기준으로 다시 그려지고 열려 있던 `같음 N` Popover·`⋯` 메뉴는 닫힌다. 활성 탭이 여럿인 그룹은 활성 탭에 2px accent 아래 막대와 semibold를 둔다(탭이 하나면 막대 없음). 선택된 칸이 있는 그룹의 띠에는 선택 표면과 왼쪽 2px accent 막대가 깔린다(배지 채움·막대·`편집 대상 칸` 설명이 함께 선택을 나타낸다). 칸 안에는 머리 행이 없다.
  - **`⋯`(`칸 N 동작`, 탭에서 Shift+F10·ContextMenu 키·오른쪽 클릭)**: 하나의 메뉴가 활성 칸을 대상으로 한다. 내용 묶음(`이 조건을 시트의 모든 칸에 적용`·`본 화면에서 열기`·`바꾸기`·`복제`·`비우기`, 빈 칸은 `칸 N 닫기`이고 칸이 하나뿐이면 없음) 뒤 구분선, 배치 묶음(`칸 N 최대화`/`원래 크기로`, 그룹에 칸이 둘 이상이면 활성 칸을 `오른쪽으로 나누기`·`아래로 나누기`, 다른 그룹마다 `칸 M 묶음으로 옮기기` — M은 그 그룹의 가장 작은 칸 번호, 오름차순)이다. 끌기와 같은 결과를 키보드로 낸다. 최대화 중에는 배치 묶음이 `원래 크기로`만 남는다. 나누기·옮기기 뒤 포커스는 옮겨 간 칸의 탭에 놓는다. 탭에서 Shift+F10을 누르면 메뉴의 첫 항목에 포커스가 있고, 배경 탭이면 그 탭을 활성으로 만들고 칸을 선택한 뒤 연다(머리 동작은 먼저 선택한다). 그 메뉴를 선택 없이 Esc로 닫으면 포커스는 `칸 N 동작` 버튼이 아니라 연 탭으로 돌아온다.
  - **좁은 띠(최소 340px 포함)**: 띠가 넘치면 차례로 ① 모든 탭의 이름을 64px까지 말줄임(Dockview 탭 넘침 드롭다운은 쓰지 않는다) ② 배경 탭을 뒤에서부터 하나씩 배지만 남김(넘치는 만큼만, 줄일 때마다 넘침을 다시 잰다; 활성 탭은 줄이지 않는다; 이름은 툴팁과 접근 이름에 남고 X는 hover·focus 때만) ③ 차이 칩을 ADR-0051 규칙대로 `+N`에 합침 ④ 그래도 넘치면 활성 칸 영역을 둘째 줄(40px, 오른쪽 정렬)로 내림. 배경 탭을 모두 줄이고도 칩이 들어가지 않을 때만 ③·④로 넘어간다. 차이 칩이 있는 칸(칩 하나 107px가 서로 다른 경우)의 340px에서 탭 하나는 ③까지, 둘은 배경 탭 하나를 줄이는 ②·③, 셋 이상은 배경 탭을 모두 줄여도 칩이 들어가지 않아 ④다. 탭 넷이 한 그룹인 700px 띠에서 뒤 배경 탭 하나만 배지가 되는 것은 목 기하(fixture 내용, 탭 바닥 136·배지 46)로 계산한 수치 예이고 렌더 측정이 아니다(`BoardDock.test.tsx`). 340px 예는 내용으로 구분한다: 위는 차이 칩이 있는 경우이고, 칩이 같거나 이웃 칸이 비어 차이 칩이 없는 경우는 340px에서 탭 둘이 이미 둘째 줄(④)로 내려갈 수 있어 다르다. 활성 탭이 바뀌면 줄임 대상을 다시 정한다(사용자 승인 2026-10-27, #978).
  - **구분자**: 그룹 사이마다 `role=separator`(`칸 a와/과 칸 b 너비 조절` / `칸 a와/과 칸 b 높이 조절` — 와/과는 칸 번호 읽기의 받침으로 고른다, 구분자마다 이름이 다르다), 방향키 5%·Home/End. Esc는 열린 메뉴·Popover·상세를 먼저 닫고 남은 Esc가 최대화를 푼다. 토글·Esc·메뉴 어느 쪽으로 풀어도 포커스는 최대화 토글로 돌아간다(없으면 칸, 보드 머리). 최대화한 채 창 크기를 바꾸고 풀어도 열 비율은 최대화 전과 같다. 메뉴 작업 영역의 `아래로 쌓기` 모드의 최상위 줄 경계는 이 계약의 예외이고 06 §12.8 "높이 방식"이 정한다(보드 자체는 해당 없음, [ADR-0077](../adr/0077-workspace-stack-mode-rows-keep-own-height.md)).
  - **칸 수**: 머리에 `1×1…2×2`와 `크기 초기화`가 없고 `칸 추가`(시트당 분석 화면은 8개까지라 8칸이면 `시트당 분석 화면 8개까지 둘 수 있습니다.`와 함께 꺼지고, 누르면 포커스가 새 칸의 탭으로 간다. 표시 그룹이 4개 미만일 때: 배치가 지금 칸들의 기본 배치 그대로면 새 칸을 더한 기본 배치가 되어 3칸 기본 배치에 더하면 4칸 2×2가 되고, 그 밖이면 면적이 가장 큰 그룹을 긴 쪽으로 나눠 새 칸을 두며, 표시 그룹이 이미 4개이면 새 그룹을 만들지 않고 선택된 칸의 그룹에 탭으로 더한다. 새 칸을 선택하고 활성으로 둔다. 최대화 중이면 크기를 되돌린 뒤 더한다)와 `기본 배치`(칸 수에 맞는 기본 트리, 실행 취소 없음)가 있다. 빈 칸의 `⋯`에는 `칸 N 닫기`가 있다(칸이 하나뿐이면 없음, 위 `⋯` 참조). 닫은 칸이 선택돼 있었으면 그 묶음에 탭이 남을 때 선택은 그 묶음에서 새로 앞에 서는 탭(닫은 탭 바로 뒤, 마지막이었으면 바로 앞)으로 가고, 묶음이 사라지면 그 번호를 이어받는 칸(마지막이었으면 마지막 칸)으로 간다. 뒤 칸 번호가 하나씩 당겨지고 토스트가 그 변화를 말하며 실행 취소가 칸·위치·번호를 되돌리되 닫은 뒤 사용자가 바꾼 다른 그룹의 크기는 그대로 둔다. 모든 실행 취소는 칸을 번호가 아니라 슬롯으로 가리켜, 앞 칸을 닫아 번호가 당겨진 뒤에도 다른 칸을 고치지 않는다. `복제`는 빈 칸이 없고 8칸 미만이면 새 칸을 만든다. **표시 그룹은 4개까지**다: 나누기(`오른쪽으로 나누기`·`아래로 나누기`)와 끌어서 만드는 분할이 새 그룹을 만들게 되는 경우, 그룹이 4개이면 메뉴 항목은 꺼지고 `표시 영역은 4개까지입니다. 나누려면 먼저 칸을 다른 묶음으로 옮기세요.`를 보이며, 끌기 결과는 거절한다(저장 모델이 5번째 그룹을 받지 않는다). 그 분할 위치(다른 그룹의 가장자리, 이동이 그룹 수를 줄이지 않는 경우)에는 드롭 미리보기도 그리지 않고(이유는 메뉴의 안내가 맡는다), 그룹 가운데에 놓아 탭으로 합치는 위치는 그대로다(`DockLayout`의 선택 prop `canDropAt`). 칸 합계 상한(분석 화면 8개)과 표시 그룹 상한(표시 영역 4개)은 서로 다른 한도이고 문구도 섞지 않는다([ADR-0089](../adr/0089-board-tab-cap-split.md)). 브라우저 설정이 `grid`여도 칸이 4개를 넘는 시트가 있는 보드는 dock으로 열고 `격자 보기는 4칸까지라 이 보드는 도킹 보기로 엽니다.`를 한 번 알린다(4칸 이하 보드는 그대로 grid. 격자 렌더러의 5칸 이상 지원은 `.planning/backlog.md`). `기본 배치`는 5칸 이상이면 4개 그룹의 2×2에 5번째 이후 칸을 마지막 그룹의 탭으로 둔다(칸을 버리지 않는다). 격자 레이아웃 전환은 4칸 이하 시트에서만 의미가 있고 모델은 5칸 이상 시트를 바꾸지 않는다.
  - **묶음 `+`**: 모든 그룹(탭이 하나뿐이어도)의 마지막 탭 바로 뒤에 `이 묶음에 분석 탭 추가` 버튼이 고정으로 있다. 탭 목록 밖의 별도 버튼이라 `role=tab` 안에 들어가지 않고, Tab 순서는 활성 탭 → 이 `+` → 머리 → 칸 본문이다. 누르면 분석 화면 선택기가 먼저 열리고, 취소하면 아무것도 바뀌지 않으며(저장 없음) 포커스는 그 `+`로 돌아온다. 고르면 눌린 그룹의 **저장된** 트리 그룹에 새 칸을 마지막 번호로 더하고 활성·선택하며(나누지 않고, 다른 칸의 ID·순서·번호·내용·분할 비율은 그대로) 새 탭이 포커스를 받는다. 좁은 폭의 합친 표시 그룹에서 눌러도 눌린 시점의 활성 칸이 속한 저장 그룹에 들어가므로 폭을 넓히면 원래 분할 그대로 새 탭만 그 그룹에 있다. 새 칸의 기본 조건은 새 칸의 기본 조건 규칙(최근 본 화면의 조건)을 따르며 `바꾸기`(교체)와 같지 않고 눌린 탭의 조건을 물려받지 않는다. 선택기 제목은 `칸 N 묶음에 추가할 분석 화면`이다(N은 그 묶음의 가장 작은 칸 번호, `칸 N 묶음으로 옮기기`와 같은 규칙). 누른 시점에 사용자·시트·눌린 칸·그 칸이 속한 저장 그룹의 구성원을 기억해 두고, 고르는 순간 이것이 그대로이고(사용자가 바뀌었거나 그 칸이 다른 그룹으로 옮겨졌거나 그룹 구성원이 달라졌으면 아무것도 쓰지 않고 다시 누르도록 안내) 칸이 8개 미만이며 고른 화면을 마운트할 수 있는지 다시 확인하고, 어긋나면 다른 곳에 더하지 않고 사유를 알린다. 시트당 분석 화면은 8개까지(표시 그룹은 4개, 5번째 탭부터는 기존 그룹 안에서 늘어난다)이며 상한이면 `+`는 꺼지지 않고 눌렀을 때와 설명(`aria-describedby`)으로 `시트당 분석 화면 8개까지 둘 수 있습니다.`와 `칸을 먼저 닫으세요(내용이 있는 칸은 비운 뒤 닫습니다)`를 알린다(비우기만으로는 칸 수가 줄지 않는다). 탭이 하나뿐인 그룹에서도 `+`는 마지막 탭 바로 뒤에 붙는다(탭 줄의 남는 폭은 그 뒤 빈 영역이 차지한다). 그룹 최대화 중이면 최대화를 풀지 않고 새 탭이 그 최대화된 그룹에 활성으로 보인다. 엔진 쪽은 도메인 중립 `@ap/components/dock`의 `renderGroupTabsEnd`, 보드 쪽 모델 연산은 `addPaneInGroup`이다.
  - **키보드 순서**: Tab은 그룹의 활성 탭 → 묶음 `+` → 활성 칸 영역의 버튼(`같음 N`·`이전 화면`·최대화 토글·`⋯`) → 그 칸 안(첫 포커스 요소, 없으면 칸 내용의 포커스 대상 — `tabindex=-1`인 첫 하위 요소, 곧 칸 루트라 선택이 따라온다) → 다음 그룹의 활성 탭 순서이고 Shift+Tab은 거꾸로다(칸 안 첫 컨트롤 → 같은 칸의 머리 버튼 → 같은 그룹의 묶음 `+` → 같은 칸의 탭 → 앞 그룹의 마지막 정지점). 읽기 순서의 마지막 그룹 뒤 Tab은 레이아웃 밖의 다음 포커스 요소로, 첫 그룹 탭 앞 Shift+Tab은 밖의 이전 요소로 나간다. 그룹은 화면 읽기 순서(위쪽 좌표, 다음 왼쪽 좌표)라 기본 2×2는 1→2→3→4다. 같은 그룹의 다른 탭은 방향키로 옮긴다(탭 모양). 엔진의 DOM 순서(탭 띠 전체 뒤에 칸 본문, 트리 순서)는 바꾸지 않고 `DockLayout`의 키 처리로 이 순서를 만든다.
  - **좁은 폭**: 692px 미만이면 모든 칸을 한 탭 그룹으로 표시만 한다(저장은 그대로). 탭은 칸 번호 순(1·2·3·4)이고 보이는 탭은 보드의 선택된 칸을 따르며(Context 바와 같은 칸) 거기서 탭을 고르면 그 칸이 선택된다. 배경 탭의 칸은 마운트된 채 `inert`이고 열린 Popover·메뉴는 닫힌다. 이동·합치기·탭 전환·최대화·기본 배치에서 칸은 다시 마운트되거나 다시 조회하지 않는다.

- **실행 취소**: 칸 비우기·시트 삭제·레이아웃 줄이기·일괄 적용·복사는 `@ap/ui` `UndoToast`(포커스·호버 중 멈춤, Escape)로 실행 취소를 준다. 실행 취소는 그 동작이 바꾼 시트·칸만 되돌린다(토스트가 떠 있는 동안의 다른 편집은 그대로). 동작 뒤 포커스는 트리거로 돌아가고, 칸 머리는 다시 그려도 같은 요소를 유지한다.

- **구현에서 정한 세부(#497b, 사양이 열어 둔 곳)**:
  - 차이 칩 값은 기간 `분 단위 시작 ~ 끝`, 집합은 `, `로 이은 ID(명시적 빈 집합은 `없음`), 조건은 이름, 지표는 `지표 v버전`이다. 다른 칸에는 있고 이 칸에는 없는 키는 `미설정`으로 칩이 된다. 비교는 이 사용자가 실제로 마운트하는 칸(`canMountPaneScreen`) 중 주소가 읽히는 칸끼리만 한다 — 거부된 칸의 조건은 다른 칸 칩에 나오지 않는다.
  - `같음 N`·`조건 N` 팝오버는 그 칸에 설정된 키와 다른 칸과 다른 키를 모두 정의 목록으로 보이고 다른 키 옆에 `다름`을 붙인다. 비교 대상이 없으면 `조건 N`(N = 설정된 키 수)이다. 0개면 버튼을 그리지 않는다.
  - `이 조건을 시트의 모든 칸에 적용`은 받을 다른 칸(내용 있고 마운트 가능)이 없으면 사유 `조건을 받을 다른 칸이 없습니다`와 함께 꺼진다. 이미 모두 같으면 바꾸지 않고 안내 토스트만 띄운다. 적용·복사는 대상의 page 키를 두고 메뉴의 `contextResetKeys`만 지운다(Kernel 도우미 `withPaneContext`, Context 쓰기와 같은 규칙).
  - `바꾸기`의 새 화면은 이 칸의 Context로 시작하고 page 키는 없다. 열 수 없는(권한 거부 등) 칸의 저장 Context는 읽지 않는다 — 그 칸의 `바꾸기`는 새 칸과 같은 기본 조건으로 시작하고, 일괄 적용·복제·시트 복사는 그 칸을 원본으로 쓰지 않는다(사유와 함께 꺼짐). `복제`·`바꾸기`·일괄 적용·복사 모두 실행 취소 토스트를 주며, 되돌릴 칸이 그 동작이 남긴 그대로일 때만 복원한다(아니면 오래된 토스트 문구).
  - `이전 화면`은 칸 슬롯의 `previous`(칸마다 한 단계, 없으면 `null`, 저장 모델 V2)에 저장한다. 다른 메뉴로 `push`할 때만 채우고 비우기·바꾸기·복제·되돌린 뒤에는 비운다.
  - `분석 보드에 열기…` 대화상자는 라디오 목록으로 시트·칸을 고른다(`새 시트` / `기존 시트의 빈 칸` / `기존 칸 바꾸기`). 20장이면 `새 시트`가 사유와 함께 꺼지고, 빈 칸이 없으면 `기존 시트의 빈 칸`이 꺼진다. 확인 때 저장소를 다시 읽고 고른 칸이 그대로(빈 칸 / 같은 화면)인지 확인한다. 달라졌으면 쓰지 않고 `그 칸이 바뀌었습니다 — 다시 고르세요`를 보인다. 대화상자는 사용자별이다.

시안: 세 안(A 신호형 · B 전부 펼침 · C 제목형)을 아티팩트로 만들어 UX 리뷰로 골랐다(사용자 요청으로 실제 앱 `?variant=` 대신, #421 코멘트). 결과는 A 머리 + C 선택 표시(ADR-0051). 배치(아래 시트 띠, 그리드)는 소유자 방향으로 고정이었다. 시안 칸 내용은 예시 데이터라, 실제 메뉴가 좁은 칸에서 어떻게 보이는지는 구현 때 확인한다.

## 5. 조건 모델 (Decided)

계약은 [06 §6.5](../contract/kernel.md#65-분석-context의-범위--칸-decided-adr-0049). 보드에서 보이는 모습만 적는다.

- **칸마다 자기 분석 Context를 통째로 가진다.** 새 칸은 기본 조건을 복사해 시작한다. `분석 보드에 열기`로 넣으면 누른 화면의 조건, 보드에서 `분석 화면 넣기`로 넣으면 마지막으로 본 본 화면의 조건이다. `복제`는 원래 칸의 조건을 복사한다. 그 뒤로 칸끼리, 그리고 본 화면과 연결이 없다. 상속은 없다.
- **일괄 맞추기는 명시적 동작뿐**: `이 조건을 시트의 모든 칸에 적용`, `이 시트 조건을 다른 시트에 복사`. 한 번 복사하고 이후 연결은 남지 않는다.
- **`이 시트 조건을 다른 시트에 복사`는 같은 칸 번호로 복사한다**(화면 위치가 아니라 번호, dock 렌더러의 배경 탭 칸도 포함): 원본 시트 칸 i의 조건을 대상 시트 칸 i에 넣는다. 양쪽 모두 메뉴가 있는 칸끼리만 복사하고, 짝이 없는 칸은 그대로 둔다. 비교 시트의 칸별 차이를 지우지 않기 위해서다. 메뉴와 토스트는 "칸 1–3의 조건을 '<대상>'의 같은 칸에 복사했습니다"처럼 원본·대상 칸을 적는다(코디네이터 결정 2026-10-19, UX 리뷰 지적, 되돌릴 수 있다).
- 칸 머리에 조건 요약을 늘 보이고, 같은 시트에서 칸끼리 다른 키를 강조한다.
- UX 리뷰(2026-10-18)의 "보드 조건 따름 / 이 칸만" 연결은 쓰지 않는다(소유자, 2026-10-18).
- 칸 하나는 단일 Scope다. 칸마다 서버가 권한을 다시 판정하고, 거부된 칸만 권한 상태가 된다.
- 보드에서 무엇을 해도 본 화면의 분석 Context나 마지막 화면 복원(ADR-0028)이 바뀌지 않는다.

## 6. 메뉴 쪽 요구 (Decided)

- **보드 지원 선언**: manifest `features.board: boolean`(기존 `features`의 `compare`·`annotate` 옆). 선언하지 않은 메뉴는 `분석 화면 넣기`·`분석 보드에 열기…`에 나오지 않는다. 1차 지원 메뉴와 이유:
  - `productivity-overview`: 기간·room_name Context를 적용하고 KPI·요약 그리드가 컨테이너 폭에 따라 재배치된다.
  - `cycle-time`: 기간·조건 Context를 적용하고 차트 레이아웃이 화면 자체 폭에 따라 재배치된다.
  - `equipment-master`: room_name·조건 Context를 적용하고 ManagementLayout이 필터와 목록을 컨테이너 폭에 따라 재배치한다.
  - `operation-time`(CLAS): 기간·room_name Context를 적용하고 요약 카드와 차트가 화면 자체 폭(`@container/analysis`)에 따라 재배치된다. page 키 `eqp`는 칸 상태에 산다.
  - `metric-catalog`(BRAVO): 지표 Context를 적용하고 목록 표가 칸 폭 안에서 스크롤한다. 경로 파라미터가 없다. `metric-detail`은 `:metricId` 경로 파라미터가 있어 선언하지 않는다.
  - 칸 머리의 업무 시스템 이름 칩이 칸마다 붙으므로 한 시트에 MARS·CLAS·BRAVO 메뉴가 섞여도 칸이 어느 시스템의 화면인지 구분된다.
- **칸에는 원래 메뉴 화면이 들어간다.** 보드용 작은 화면을 따로 만들지 않는다. 화면은 자기 컨테이너 폭으로 반응해야 한다(뷰포트 기준 아님). 좁은 칸에서 깨지는 메뉴는 보드 지원을 선언하지 않는다. 메뉴 화면은 좁은 칸에서 깨지는 부분만 고친다.
- **page 상태**: 칸의 page 키(탭·정렬·페이지·드릴 단계)는 칸 상태에 산다. 메뉴는 Kernel의 page 상태 API로만 읽고 쓴다.
- **칸 안에서 다른 메뉴로 가는 링크**(드릴다운·메뉴 간 연결 `navigateTo`): 대상이 보드를 지원하면 그 칸의 화면을 대상 메뉴로 바꾸고 칸 조건을 링크가 넘긴 값으로 갱신한다. 칸 머리에 `이전 화면`을 한 단계만 둔다. 대상이 보드를 지원하지 않으면 본 화면으로 이동한다(보드 상태는 저장돼 있다).
- **상세 패널**: 보드 전체에 오른쪽 상세 슬롯 하나(ADR-0013·0047)를 칸들이 나눠 쓴다. 칸마다 드로어를 붙이지 않는다(1280에서 상세가 열리면 main 788px). 상세 머리에 어느 칸·메뉴의 상세인지 보인다. 다른 칸의 상세가 열리면 앞 칸의 상세는 닫힌다(× 한 번으로 슬롯이 닫힌다). 다른 칸을 선택해도 상세는 그대로 두고, 시트를 바꾸거나 상세를 연 칸의 조건·화면이 바뀌거나 그 칸을 비우면 닫는다.
- **모듈 화면**(ADR-0038·0039): 기능·EV 모듈 화면도 호스트 포트로 Context·page 상태를 받으므로 같은 규칙으로 칸에 들어갈 수 있다. 1차 검증 대상은 아니다.

Apply 메뉴의 조회 바는 기존 48px Context 행에 접힌 요약·동작만 놓고 앵커 패널로 편집한다([06 §11](../contract/kernel.md#11-global-context-bar)). 패널은 가용 viewport 높이 안에서 스크롤하며 닫아도 Kernel 칸 초안은 유지한다. 칸·메뉴·세션 전환은 열린 편집기와 검색 상태를 닫는다. page 요약·오류는 같은 칸의 본문과 바가 공유하며 다른 칸으로 넘어가지 않는다. 적용 결과 스트립은 칸 본문에 있고 본 화면의 제목·동작 머리는 복제하지 않는다.

## 7. 저장·URL·조회 (Decided, 1차)

- **저장**: 브라우저 localStorage `platform:board:v2:${userId}`(즐겨찾기·표 설정과 같은 방식, 저장 모델 V2 — [ADR-0067](../adr/0067-dockview-layout-engine-board-v2.md)). 새로고침·새 탭·다음 날에도 남는다. 시트마다 선택된 칸과 묶음별 활성 탭도 보드 문서와 함께 저장돼 다시 열 때 그대로 되살아난다. 읽는 순서는 V2 키 → V1 키(`platform:board:${userId}`, 메모리에서 V2로 이행하고 첫 저장 때 V2를 쓴다). V1 키는 쓰지도 지우지도 않으며, 첫 저장 때 V1 원문을 `platform:board:v1-backup:${userId}`에 한 번 복사한다(그 키가 비어 있을 때만). 더 새 버전(`v > 3`)의 V2 값은 이 세션에서 새 보드로 열되 V2 키를 쓰지 않고(편집은 메모리에만) 토스트 `더 새 버전에서 저장한 보드라 이 화면에서는 저장하지 않습니다.`를 보인다. 읽을 수 없는 값(JSON 오류·검증 실패)은 키마다 원문을 `platform:board:corrupt-backup:v2:${userId}`·`platform:board:corrupt-backup:v1:${userId}`에 복사해 두고(이미 있으면 덮어쓰지 않는다. 칸이 5개 이상인 `v:2` 값도 깨진 값이다) V2가 깨졌으면 V1로 넘어가며, 어느 키에서도 보드를 얻지 못하면 새 보드로 시작해 `저장된 보드를 읽을 수 없어 새 보드로 시작했습니다. 원래 값은 따로 보관했습니다.`를 보인다. 어느 경우도 편집 전에는 쓰지 않는다. 서버 저장은 §10.
- **세션 저장소**: 보드를 읽고 쓰는 길은 하나다. 사용자별 보드를 모듈 수준 세션 저장소 하나(`boardSession`)가 쥐고, 보드 화면과 `분석 보드에 열기…`를 포함한 모든 작성자가 같은 저장소를 거쳐 읽고 쓴다. 두 구독자는 같은 보드 객체를 보고, 저장소에는 보드 문서만 있다(무엇이 화면에 있는지는 담지 않는다). `분석 보드에 열기…`는 확인 직전에 다른 탭의 저장값을 다시 읽어 메모리에 반영한 뒤(저장 안 된 이동이 없을 때만) 대상 확인·변경·저장을 한 번의 update 안에서 한다. 그래서 보드가 열려 있는 채 추가한 시트·칸이 이후 보드 편집에 덮이지 않는다. 새로 읽기는 저장값만 들이고 선택 칸·활성 시트는 메모리 값을 지킨다(최초 진입 정규화는 새 세션만 — 저장된 선택이 묶음 활성 탭과 어긋나거나 칸이 아니면 맞춘다). 읽기 전용(더 새 버전) 세션은 새로 읽어도 문서·안내·쓰기 거부가 그대로이고, 저장 안 된 이동이 있는 세션에서의 확인은 쓰지 않고 `boardBusy`(「보드를 편집하는 중입니다…」)로 멈춘다. 구독자 없는 세션은 변경 없음·거절을 포함해 모든 반환에서 폐기한다. 마지막 구독자가 빠진 세션은 한 틱 뒤에 폐기하므로, 같은 틱의 재구독(StrictMode 효과 재생, 한 커밋 안의 보드 교체)은 저장 안 된 이동과 읽기 전용 래치를 그대로 잇는다.
- **열림 상태**: 보드가 열려 있는지(`live`), 돌아갈 일반 경로, 칩에 쓸 마지막 시트는 실행 세션 범위의 표시 상태 저장소(`boardPresentation`)가 쥔다. 보드 문서(`boardSession`)에는 담지 않고 저장하지 않는다. 최대화 여부는 URL이 정본이다(ADR-0087).
- **보드 수**: 사용자당 하나. 비교 묶음은 시트로 나눈다.
- **URL**: `/board?sheet=<시트 ID>`(플랫폼 소유 화면 — Registry 메뉴가 아니고, 어떤 메뉴도 `/board`나 그 아래 경로를 쓸 수 없다. 이 화면은 최근 방문·공간 마지막 화면·메뉴 사용 계측에 남지 않는다). 칸 상태(메뉴·조건·page 키)는 URL에 넣지 않는다. 새로고침하면 같은 시트로 돌아온다. 뒤로가기는 시트 전환만 되돌리고, 칸 안의 조건·page 변경은 기록에 남기지 않는다. 이 URL은 그 브라우저 안에서만 의미가 있고 공유 링크가 아니다.
- **열 수 없게 된 칸**: 저장된 칸의 메뉴가 Registry에서 빠졌거나 보드 지원이 꺼지면 "더는 보드에서 열 수 없는 화면"과 `비우기`를 보인다. 메뉴·Scope 권한을 잃으면 그 칸만 권한 상태다. 어느 경우도 자동으로 지우지 않는다.
- **저장 버전([ADR-0089](../adr/0089-board-tab-cap-split.md))**: 같은 V2 키에 어느 시트라도 칸이 4개를 넘으면 `v:3`, 아니면 `v:2`로 쓴다(시트당 칸 상한: `v:2` 4개, `v:3` 8개, 둘 다 표시 그룹 4개). 이 변경 이전 빌드는 `v>2`를 더 새 버전으로 읽어 `v:3` 값을 손상으로 격리하지 않고 읽기 전용으로 연다(덮어쓰지 않는다). 칸을 4개 이하로 줄이면 다음 저장부터 `v:2`로 내려간다(롤백 경로).
- **배치 저장**: `Board { v: 2 | 3, activeSheetId, sheets }`, `Sheet { id, name, panes: { id, screen, previous }[], selectedPaneId, tree, gridMemory? }`. `panes` 배열 순서가 화면의 칸 번호(`칸 n` = 인덱스 + 1)이고 칸 id는 시트 안에서 유일한 불투명 값이다(`v:2` 1–4칸, `v:3` 1–8칸). `tree`는 `group { panes, active }`(한 셀의 탭) 또는 `branch { dir, sizes, children }`이며 모든 칸이 정확히 한 그룹에 한 번 나오고, `sizes`는 유한 양수로 합이 100(±0.01)이며 자식마다 하나, 빈 그룹은 없고 분기는 자식이 둘 이상이다. `gridMemory?: Partial<Record<BoardLayout, { columns: number[]; rows: number[][]; collapsed: number[] }>>`는 격자 렌더러 전용 기억이다. 현재 레이아웃을 포함해 레이아웃마다 마지막 열 비율·열별 행 비율·접힌 칸(0부터 시작하는 행 우선 인덱스)을 독립 저장한다. 격자 화면은 `gridOf(sheet)`(트리 → `{ layout, arrangement, order }`)로 읽고 `withGrid`로 트리와 `gridMemory`를 함께 쓴다. 접힌 열은 같은 열 두 칸을 한 그룹으로 두고 펼친 칸이 활성 탭이며, 접힌 열의 행 비율은 `gridMemory`에만 있어 펼치면 되돌아온다. 격자 모양이 아닌 트리는 칸 수의 기본 격자로 투영하고(3칸은 2×2에 빈 칸 하나로 표시만 하며 저장하지 않는다) 격자 렌더러는 3칸을 만들지 않는다. `selectedPaneId`는 그 시트의 칸 id이고 1단계에서는 그룹의 활성 탭과 독립이다(접힌 칸이 선택될 수 있다). 각 벡터는 해당 논리 열/행 수와 길이가 같고 유한 양수의 합이 100(허용 오차 0.01), 단일 트랙은 [100]이다. 접힌 칸은 중복 없는 유효 정수이며 논리 열 전체를 접을 수 없다. V2 검증은 모양·칸 id·트리가 하나라도 어긋나면 보드 전체를 거절하고(부분 복구 없음 — 되돌리기 뒤 `normalizeBoard`의 사후 복구만 예외), `gridMemory`만 잘못된 레이아웃 항목/알 수 없는 키를 버리고 정상 형제 항목과 보드는 유지한다. 객체가 아닌 `gridMemory`는 생략한다. 기본 항목은 정규화해 지우고 모두 기본이면 필드 자체를 생략한다. V1 값(`Board.v: 1`, `Sheet.layout`·`selected`·`panes[]`·`previous[]`·`arrangement`)은 순수 함수 `migrateV1`으로 읽는다. 칸은 행 우선 순서대로 새 id를 받고 `previous[i]`는 그 칸의 `previous`, `selected`는 `selectedPaneId`가 되며, 현재 레이아웃의 배치는 `withGrid`로 트리가 되고 다른 레이아웃의 배치는 `gridMemory`로 간다. 서버 직렬화·endpoint 변경은 없다.
- **보존 범위**: 이름·순서·선택·조건·화면 편집·시트 간 조건 복사·레이아웃 전환·외부 `분석 보드에 열기…` 쓰기는 모든 배치 항목(`gridMemory`)을 유지한다. `분석 보드에 열기…`도 같은 읽기·쓰기 경로로 V2를 쓰고, 더 새 버전의 V2가 저장돼 있으면 쓰지 않고 대화상자에 같은 문구를 보이며 닫지 않는다. 칸 번호 기준 일괄 적용·시트 간 조건 복사는 계속 칸 번호(인덱스)를 따른다. 새 시트/마지막 시트 삭제의 대체 시트는 기본 배치다. 레이아웃 실행 취소는 이후 배치 편집을 보존하며, 대체 시트의 배치가 편집되면 오래된 삭제 실행 취소는 실패한다.
- **조회·인스턴스 수명**: 활성 시트의 칸만 마운트한다. 접기/펼치기·최대화/복원·세로 쌓기 전환은 BoardPane·머리·Provider·화면 인스턴스와 입력·스크롤·Context/page·상세 소유 관계를 유지한다. 활성 시트의 숨겨진 칸도 기존 요청 수명주기(취소·세대)를 계속 유지하며 가시성 때문에 취소·재시작하지 않는다. 시트/사용자 전환은 이전 칸을 언마운트하고, 레이아웃 축소는 기존 확인·실행 취소 경로로 넘친 칸을 제거한다. 최대화·지연 포커스·드래그는 사용자+시트+레이아웃 수명에 속하며 그 변경·칸 제거에 취소한다. 세로 쌓기 진입은 최대화 표시만 멈추고(칸 본문은 쌓여 보인다) 최대화 의도는 지우지 않아, 다시 넓어지면 그 칸이 다시 최대화된다(최소화 중 창이 좁아졌다 복원돼도 같다). 동시 조회의 최대는 마운트된 칸 수(시트당 최대 8)다: 칸마다 첫 조회가 한 번이고 탭을 더해도 다른 칸을 다시 조회하지 않는다(`BoardDock.test.tsx` E7: 서로 다른 조건의 조회 칸 4개와 조회 없는 칸 3개 시트 → 어댑터 호출 4회, `칸 추가` 뒤에도 4회). 20·50개 같은 더 큰 상한은 약속하지 않는다. 보드의 최소화·복원도 같은 인스턴스라 칸의 조회 identity·세대를 바꾸지 않는다: 숨기기 전에 시작한 요청의 응답은 숨은 동안 도착해도 자기 칸에만 반영되고, 복원이 다시 조회하지 않으며, 숨은 동안 다른 일반 메뉴를 조작해도 칸의 요청 소유가 바뀌지 않는다(`BoardHidden.test.tsx`).
- **계측**: 칸이 열리면 그 메뉴의 사용으로 센다(`recordUsage`, 출처 `board` 표시). 보드 열기·시트 수·칸 수는 보드 사용으로 따로 센다. 이 부분은 `UsageEvent`가 메뉴 사용 모양(`menuId`·`path` 필수)이라 계약 변경 없이는 못 넣는다 — 구현하지 않고 [백로그](../../.planning/backlog.md)에 둔다(#497a).
- 메뉴 클릭으로 바로 보드에 여는 방식을 쓰지 않는 이유: 지금은 화면 하나 = URL 하나라 새로고침·뒤로가기·링크 복사가 그대로 된다(06 §6.4). 기본을 보드로 바꾸면 뒤로가기가 무엇을 되돌리는지를 새로 정해야 한다.

## 8. 셸 결정에서 지금 정해 둘 것

셸 구조 ADR(#249)에 함께 적어 보드를 막지 않게 한다.

- **진입 자리**: 레일 도구 영역(메뉴 검색 아래)에 플랫폼 소유 도구 하나. 셸 안이 시스템 전환 아이콘 방식(시안 D안)이든 공간 레일 방식이든 같은 자리다.
- **하단 띠 공간**: 보드 화면에서만 main 열 맨 아래 40px + 위 경계 1px을 쓰고, 일반 화면에서는 높이 0이다. 띠는 main 열에서 끝나고 오른쪽 상세 슬롯 아래로 지나가지 않는다. 표 높이 맞춤(`tableFit`)이 본문 영역(`data-platform-page-content`)을 관찰하므로 띠는 그 영역 밖(아래)에 둔다. 사이드바 바닥 기능 블록과 공간을 나누지 않는다(보드 화면에는 시스템 사이드바가 없다).
- **머리와 칸**: 페이지 머리 50px·Context 바 48px의 역할을 유지하고, 칸 안에 셸 머리·Context 바를 다시 넣지 않는다.
- **본 화면과의 경계**: 보드에 들어갈 때 본 화면 Context를 기본 조건으로 복사할 뿐, 이후 양방향으로 동기화하지 않는다. 보드에서 무엇을 해도 본 화면의 조건이나 마지막 화면 복원(ADR-0028)이 바뀌지 않는다.
- **전역 Context 바와의 관계**: 보드 화면의 Context 바는 지금 고른 칸의 조건을 편집한다. 셸 ADR은 Context 바를 "현재 칸의 Context 편집기"로 적어 두어, 보드가 생겨도 바의 의미가 바뀌지 않게 한다(본 화면은 칸이 하나).
- **Context를 읽는 길은 Kernel 훅 하나**: 지금 메뉴 코드는 URL을 직접 읽지 않고 Kernel 훅(`usePlatform`의 전역 Context·`pageParam`·`setPage`)만 쓴다(2026-10-18 확인). 이것을 메뉴·모듈 규칙으로 유지한다. 깨지면 칸 범위 Context를 Kernel 한 곳에서 바꿀 수 없다.

## 11. 백엔드에 생기는 일

- **보드 저장소**: 보드·시트·레이아웃·칸별 메뉴 ID·칸 조건·page 상태를 사용자별 문서로 저장한다. 공유하면 소유자·공유 대상·감사 기록이 필요하다.
- **쓰기 포트**: 지금 `PlatformAdapter`는 읽기 중심이다(쓰기는 주석 등 일부). 보드 저장은 새 쓰기 포트와 서버 저장소 소유자 결정이 필요하다.
- **동시 조회 부하**: 2×2 시트는 한 화면 질의가 네 배다. 시트를 바꿀 때 보이지 않는 시트의 칸은 조회하지 않는다(화면에 보이는 시트만 마운트).
- **시스템마다 다른 서버**: 칸 하나는 플랫폼 마트, 다른 칸은 기능·EV 서버를 부른다. 모듈이 자기 서버를 부르는 구조(ADR-0038) 그대로면 보드는 배치만 하고 데이터를 합치지 않는다.

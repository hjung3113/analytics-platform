# 14. 드릴다운 — 플랫폼 기능과 레이아웃 (#225)

상태: **Decided (2026-10-08, [ADR-0025](adr/0025-drilldown-level-page-keys-path-bar-layout.md)).** 계약의 원본은 [06](06_platform_ui_contract.md)이다: 단계 URL은 §6.4, 레이아웃은 §12.7, 다른 메뉴로 갔다 돌아오는 복귀는 §22. 이 문서는 사용자 과업·정보 구조·와이어프레임과 견본 소비자를 남긴다. 대표 왕복 경로(사이클타임 → 실행 상세)의 화면 계약은 [12](12_cycle_time_drilldown_wireframe.md)가 소유한다.

## 1. USER TASK

공정·설비 엔지니어가 요약 숫자에서 시작해 **단계별로 좁혀 들어가며** 원인을 찾는다. 예: 생산성 개요의 점유 구성에서 공정(room_name) PHOTO → 그 공정의 StGroup → 그 StGroup의 설비 → 설비 하나의 상세. 레시피 → 설비 → 설비 상세처럼 주제마다 단계는 다르다(사용자, 2026-10-05).

- 지금 어느 단계인지, 각 단계에서 무엇으로 좁혔는지 보인다.
- 앞 단계 어디로든 한 번에 돌아간다.
- 링크를 공유하면 같은 단계가 열린다. 브라우저 뒤로가기는 한 단계씩 돌아간다.
- 다른 메뉴로 넘어갔다가 돌아오면 출발한 단계가 그대로 복원된다.

메뉴는 이것을 직접 만들지 않고 **플랫폼 기능 + 레이아웃**으로 조립한다.

## 2. IA

```text
메뉴 화면 (예: 생산성 개요)
├─ 0단계: 요약 (KPI · 추세 · 구성 표)          ← 단계 키 없음
├─ 1단계: 공정 = PHOTO 의 StGroup 구성        ← drillRoom
├─ 2단계: StGroup = STG-PHOTO-A 의 설비 목록   ← drillStgroup
└─ 3단계: 설비 = ICH-PHOTO-0103               ← drillEquipment
     ├─ 오른쪽 상세 슬롯 (같은 화면 안, ADR-0013)
     └─ 다른 메뉴로: 설비 상세 (linkTo + returnTo)
          └─ "← 생산성 개요 (PHOTO › STG-PHOTO-A › ICH-PHOTO-0103)" 로 복귀
```

- 단계 순서는 메뉴가 manifest에 선언한다. 단계 상태·URL·경로 바·레이아웃·복귀 버튼은 플랫폼이 소유한다.
- 메뉴 위치(고정 breadcrumb), 단계 경로(경로 바), 이동 기록(복귀 버튼)은 서로 다른 요소다.

## 3. WIREFRAME — 경로 바 + 단계마다 본문 교체

```text
┌ Page header: 생산성 개요 ───────────────────── [새로고침] ┐
├ Context bar (전역) ──────────────────────────────────────┤
├ 페이지 소유 컨트롤 (집계 단위 등) ─────────────────────────┤
├ 경로 바: [전체] › [공정: PHOTO ▾] › [StGroup: STG-PHOTO-A ▾] ┤
│                                                          │
│  현재 단계 본문 (StGroup STG-PHOTO-A 의 설비 목록)         │
│  이 단계 범위 KPI 한 줄                                    │
│  ┌ 설비 표 ──────────────────────────── 행 끝 › ┐        │
│  │ ICH-PHOTO-0103  99.5%  69  57.0분          › │        │
│  └──────────────────────────────────────────────┘        │
└──────────────────────────────────────────────────────────┘
   3단계(설비 하나)는 표를 남기고 오른쪽 상세 슬롯을 연다.
```

시안에서 비교한 다른 두 안(브랜치 `hjung3113/proto-225-drill-layout`, ADR-0025 Considered Options):

- **2–3열 나란히**: 공정 | StGroup | 설비 목록을 옆으로 둔다. 형제 사이를 빨리 오가지만 열이 좁아 값과 점유율만 들어가고, 상세 슬롯까지 열면 비좁다.
- **아래로 쌓는 섹션**: 요약 아래에 지난 단계를 한 줄로 접고 현재 단계를 펼친다. 깊어지면 스크롤이 길고, 상세 슬롯이 열리면 위쪽 표가 찌그러진다.

## 4. COMPONENT MAP

| 층 | 책임 |
| --- | --- |
| Contracts | manifest `drill.levels`(단계 page key와 표시 이름) 타입 |
| Kernel | Registry가 단계 선언을 검사(키가 `pageKeys`·`contextResetKeys`에 있음, 최대 4개, 중복 없음). 현재 단계·경로 읽기, 형식 오류 판정, 들어가기·올라가기·형제 바꾸기(push, 뒤 단계 지움). 채택한 `returnTo`에서 출발 메뉴 이름과 단계 값 읽기 |
| 공통 컴포넌트 | `DrillPath`(경로 바, ▾ 형제 메뉴, 깊이 4에서 가운데 접기), `DrillLayout`(경로 바 + 본문, 형식 오류·없는 값 상태), `ReturnLink`(복귀 버튼) |
| 메뉴 | 단계 선언, 단계마다 본문과 조회, 행 끝 들어가기 버튼, 형제 목록, 마지막 단계 상세 슬롯 |

견본 소비자: 생산성 개요(공정 → StGroup → 설비). `ReturnLink`는 설비 상세·실행 상세·지표 상세의 복귀 버튼이 쓴다.

## 5. DATA REQUIREMENTS

- 단계마다 메뉴의 조회 엔드포인트(`useMenuQuery`)를 앞 단계 값으로 좁혀 부른다. 서버는 단계마다 권한·Scope를 다시 검증하고, 받은 범위 밖의 값을 만들지 않는다(§17).
- 단계 값은 ID·마스터 값이다(room_name, StGroup, EquipmentID). 번역하지 않는다(§23). 경로 칩의 값은 URL 값 그대로이며 표시용 라벨을 따로 조회하지 않는다.

## 6. DEFERRED / RISKS

- 단계 이동의 활용률 계측(ADR-0020) — 지금은 메뉴 진입·체류만 센다.
- 깊이 4 초과.
- 단계마다 조회가 따로 돌아 로딩이 쌓일 수 있다. 앞 단계 결과를 보존(캐시)할지는 소비자가 늘면 본다.

# 08. 운영 개요(랜딩) 요구사항·와이어프레임

상태: 설계 산출물. `.agents/skills/analysis-platform-wireframe/SKILL.md`의 설계 단계에서 종료한다. 프로토타입이나 시각 스타일 검증 결과가 아니다.

이 문서는 `07_app_shell_wireframe.md` §4 WIREFRAME의 "하위 화면 content slot"에 들어가는 첫 화면 — 운영 개요(랜딩) — 만 소유한다. 셸 자체의 배치·헤더·내비게이션·전역 Context Bar는 07의 범위이며 여기서 재정의하지 않는다. 전역 계약 원본은 `06_platform_ui_contract.md`다.

## 1. USER TASK

- 주 사용자: 로그인 후 처음 진입하는 전체 사용자(공정/설비 엔지니어, 마스터데이터·지표 관리자, 운영 관리자, 현업 문의자).
- 주 작업: 접근 가능한 메뉴 확인 → 즐겨찾기/최근 방문으로 이전 작업 복귀 → (있다면) 공지 확인.
- 분석 대상 객체: 메뉴 레지스트리 항목, 사용자별 즐겨찾기/최근방문 기록, 공지.
- 이 화면에서 내리는 결정: 어떤 메뉴로 이동할지. 데이터 자체를 분석하는 화면이 아니다.
- 데이터 규모: 메뉴 수십 개 이하, 즐겨찾기/최근방문 수십 건(Candidate, `07` §1과 동일 가정).
- 이용 빈도: 세션당 진입점이자 자주 되돌아오는 앵커 화면(하루 종일 상주하는 화면은 아님).
- Desktop-first(프로젝트 기본값).

## 2. IA / SCREEN INVENTORY

`06_platform_ui_contract.md` §9의 "운영 개요" 그룹 랜딩 화면 1개. 하위 화면 없음(공지 목록/상세는 `공지·VOC` 그룹 소유이며 이 화면은 진입 링크만 제공).

```
운영 개요(랜딩)               [이 문서]
├── 메뉴 그룹 바로가기 → 그룹의 대표 목적지로 즉시 이동   [Decided 2026-09-24, §4/§8]
├── 즐겨찾기 항목 → 저장된 목적지 화면(저장된 Context 없이 진입, 전달 Context는 별개로 보존)    [추가는 목적지 화면 소유]
├── 최근방문 항목 → 이전에 방문한 화면(읽기 전용 이력)
└── 공지 배너 → 공지 목록 → 공지 상세          [별도 그룹, 이 문서 범위 아님. 배너에서 상세로 바로 가지 않고 목록을 거친다]
```

"수집 상태/데이터 최신성" 위젯은 이 화면에 배치하지 않는다. 파서 적재 상태를 판정할 근거 서비스(statusSource)가 없는 상태에서 분석 결과 0건을 수집 중단·지연으로 추론하지 않는다(`06` §19, `07` §2). 이 조건이 해소되기 전까지는 Deferred.

| 항목 | 내용 |
| --- | --- |
| Purpose | 접근 가능한 메뉴 요약과 개인화된 재진입 경로 제공 |

| Output | 선택한 메뉴의 URL. 즐겨찾기는 목적지 ID만 저장하므로 저장된 마지막 조회 Context는 복원하지 않는다(Decided 2026-09-24) — 단 그 시점에 실제로 전달되는 Context가 있으면 §7의 보존 규칙에 따라 별도로 적용된다 |
| Primary action | 메뉴/즐겨찾기/최근방문 항목 클릭 → 이동 |

| Navigation | 로그인 직후 기본 진입 지점. 다른 화면에서 로고/운영개요 메뉴 클릭으로도 복귀 |
| Data requirements | §6 참조 |
| Empty state | 즐겨찾기 없음 / 최근방문 없음을 각각 안내. 접근 가능한 메뉴가 하나도 없으면 별도 접근 안내(권한없음과 데이터없음 구분, `06` §19). 게시 중인 공지가 없으면 배너 자체를 노출하지 않는다(조회 실패와 다른 상태) |
| Loading state | 메뉴 그리드·즐겨찾기·최근방문·공지 배너 각 영역 독립 스켈레톤. 권한 재검증 중에는 세션 후보값을 확정 노출로 표시하지 않음 |
| Error state | 영역별 실패는 서로 격리한다 — 아래 §7 상태 매트릭스 참조. 메뉴 노출 판정 실패는 전체 화면 오류로 취급하고(권한 근거 없이는 메뉴를 보여줄 수 없음), 즐겨찾기·최근방문·공지 실패는 해당 영역만 오류 표시로 격리하며 나머지 영역은 정상 동작한다. 모든 오류는 Correlation ID를 포함한다(`06` §4 전역 Error Boundary/Correlation ID 표시, §19 응답 스키마) |

## 4. WIREFRAME (Candidate)

`07` §4 셸 프레임의 "하위 화면 content slot"을 아래로 채운다. 셸의 헤더·내비게이션·Breadcrumb·전역 Context Bar는 변경하지 않는다. 이 화면은 Context Bar를 **숨기거나 비우지 않는다** — 다른 화면에서 넘어온 전역 Context가 있으면 셸이 그대로 보존하고 "이 화면에서는 미적용"으로 표시한다(`06` §6.4). 이 화면 자체가 Context를 필터로 소비하지 않을 뿐이다.

```text
┌─────────────────────────────────────────────────────────────────────┐
│ [Logo] Scope ▾                  메뉴 검색              사용자 ▾    │  ← 07 소유
├───────────────┬─────────────────────────────────────────────────────┤
│ 운영 개요 ◀   │ 운영 개요                                           │  ← Breadcrumb, 07 소유
│ 설비관리     ├─────────────────────────────────────────────────────┤
│ 기준정보관리 │ (전달된 Context가 있으면) Equipment: EQP-013 · Not used on this page │ ← 07 소유, §6 재사용
│ 생산성 분석  ├─────────────────────────────────────────────────────┤
│ 지표관리     │ 📢 공지 배너 (게시 중인 공지 있을 때만) [전체 공지 보기 →] [✕ 닫기]│
│ 공지·VOC     ├─────────────────────────────────────────────────────┤
│ 관리·감사    │ 내 메뉴 바로가기                                     │
│               │ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ │
│               │ │설비관리  │ │생산성분석│ │지표관리  │ │공지·VOC  │ │
│               │ └──────────┘ └──────────┘ └──────────┘ └──────────┘ │
│               │ (Kernel의 메뉴 노출 판정 결과를 그대로 렌더링. 클릭 시 그룹 대표 목적지로 즉시 이동) │
│               ├───────────────────────────┬─────────────────────────┤
│               │ 즐겨찾기                  │ 최근 방문                │
│               │ - 설비 마스터 목록  [★ 제거]│ - 사이클타임 상세 (12분전)│
│               │ - 사이클타임 개요   [★ 제거]│ - 설비 상세 EQ-0231      │
│               │ [+ 즐겨찾기 없음일 때 안내, │ [최근방문 없음일 때 안내]│
│               │  다른 화면의 ☆ 버튼으로 추가]│                        │
├───────────────┤                                                     │
│ 즐겨찾기     │  ← 07 사이드바 영역(동일 데이터의 축약 노출, 07 소유) │
│ 최근방문     │                                                     │
└───────────────┴─────────────────────────────────────────────────────┘
```

- 공지 배너(닫기/전체보기 링크 포함)와 "내 메뉴 바로가기" 그리드, 즐겨찾기(제거 컨트롤 포함)/최근방문 2열 목록이 이 문서가 추가하는 content slot 내용이다. 즐겨찾기 **추가** 컨트롤(☆)은 각 목적지 화면(예: 설비 상세, 사이클타임 개요)에 있으며 이 랜딩 화면이 소유하지 않는다 — 이 화면은 이미 추가된 항목의 목록·제거만 다룬다.
- 사이드바의 즐겨찾기/최근방문(07 소유, 상시 축약 노출)과 이 화면 본문의 즐겨찾기/최근방문(전체 목록)은 같은 데이터를 다른 밀도로 보여준다 — 별도 데이터 소스가 아니다.
- 메뉴 바로가기 카드는 그룹 단위다. **그룹 클릭 시 그 그룹의 대표 목적지로 즉시 이동한다(Decided, 2026-09-24)** — 하위 메뉴 펼침은 채택하지 않았다. 대표 목적지는 사용자가 접근 가능한 메뉴 중 임의로 고르지 않고, Menu Registry에 그룹당 정확히 1개씩 등록된 고정 항목을 따른다. **구현 전제(신규 Open):** 현재 Menu Registry 필드 목록(`06` §5)에는 그룹의 "대표 목적지" 플래그가 없다 — 그룹별 primary 메뉴 항목을 레지스트리 스키마에 추가하는 작업이 이 결정의 선행 조건이며, 이 문서가 그 스키마 세부를 정하지는 않는다.

## 5. CONCEPTUAL COMPONENT MAP

| 영역 | 책임 |
| --- | --- |
| 공지 배너 | 공지 도메인이 판정한 게시기간·대상 메뉴·Scope 타게팅 결과를 표시·닫기(판정 로직 자체는 공지 도메인 소유, 이 화면은 결과 소비자). 닫기의 세션 내 지속은 Decided(2026-09-24); 어떤 공지를 언제 노출할지(노출 조건 자체)와 재노출 세부는 Open |

| 즐겨찾기 목록 | Kernel의 즐겨찾기 공통 기능(`06` §4)을 소비해 사용자별 목적지 표시·제거·빈 상태 안내. 추가는 각 목적지 화면 소유 |
| 최근방문 목록 | Kernel의 최근방문 공통 기능을 소비해 이력 표시(읽기 전용)·빈 상태 안내 |

## 6. DATA REQUIREMENTS

- 이 화면은 메뉴 레지스트리를 직접 조회·필터링하지 않는다. Kernel이 현재 사용자·Scope 기준으로 이미 판정한 "접근 가능한 그룹" 목록을 소비해 그대로 렌더링한다(`06` §4/§5). 페이지가 별도로 권한 로직을 구현하는 것은 금지된 패턴이다(`06` §5 금지 목록).
- 진입 시 권한 재검증은 이미 Decided다(`06` §6.2 "재적용 전에 현재 Scope에서 ... 권한의 유효성을 다시 검증", §17 매 요청 재검증). 이 문서에서 Open인 것은 재검증 **결과의 화면 표현**(항목을 숨길지 비활성 표시할지)뿐이다.
- **즐겨찾기는 목적지 ID만 저장한다(Decided, 2026-09-24, [07 §6](07_app_shell_wireframe.md#6-data-requirements)도 같이 갱신함)** — 즐겨찾기 자체에는 마지막 조회 Context(기간·설비·필터 등)를 저장하지 않으므로, 클릭 시 그 화면이 자체적으로 물질화하는 기본 Context로 진입한다(예: 기간 화면이면 `defaultRangeTo` 기준 기본 구간, `06` §6.3). **이는 다른 화면에서 지금 들고 온 전달 Context를 지운다는 뜻이 아니다** — Context Link helper의 보존 규칙(`06` §6.4)은 즐겨찾기 클릭에도 그대로 적용되며, 전달된 Context가 있으면 그 목적지가 지원하는 한 계속 적용된다. 서버 권한 재검증도 그대로 적용된다(§6 재검증 규칙).
- 공지는 게시기간·대상 메뉴·Scope 타게팅 필드로 판정된 결과를 참조한다(`02_domain_menus.md` 공지 항목). 공지의 게시·타게팅 판정 로직 자체는 공지 도메인이 소유하고, 이 화면은 그 결과를 표시만 하는 소비자다. **Scope 타게팅은 현재 요청 `scopeId` 기준이다(Decided, 2026-09-24)** — 사용자가 접근 가능한 다른 Scope의 공지는 그 Scope를 선택했을 때만 보인다.
- Scope는 전역 Context Bar가 대표하는 Context 중 하나다(`06` §11). 다만 Scope **선택기 UI**는 Context Bar 스트립이 아니라 헤더에 위치한다(`06` §7, `07` §4 — "헤더 Scope 선택기와 중복 배치 금지"). 이 화면이 "전역 Context를 분석 필터로 소비하지 않는다"고 선언한 것과 무관하게, Scope 자체의 재검증·전환·이전 결과 숨김은 계속 셸이 수행한다(`06` §6.2/§11). Scope 전환·재검증 **중**이면 이 화면의 Scope 의존 콘텐츠(공지 타게팅 등)도 셸의 로딩 상태를 그대로 따른다(별도 로딩 상태를 만들지 않음). Scope가 아직 한 번도 **선택되지 않은** 경우는 로딩이 아니라 `06` §6.2의 "명시적 선택 상태"다 — 이때 Scope 의존 콘텐츠는 선택 요구 안내를 따르고, 로딩 스피너로 표현하지 않는다.
- **사이드바 축약과 본문 전체 목록은 같은 정렬 기준을 쓴다(Decided, 2026-09-24)** — 최근 사용/방문순으로 동일하게 정렬하고, 사이드바는 그중 상위 N개만 잘라 보여준다(N은 구현 시 정함). 별도의 사이드바 전용 정렬을 두지 않는다.

## 7. INTERACTION RULES

| 규칙 | 근거 |
| --- | --- |
| 접근 불가 그룹/메뉴는 그리드에 노출하지 않는다(서버 재검증 없이 클라이언트 캐시로만 숨기지 않음) | `06` §17 |
| 즐겨찾기·최근방문 클릭 시 목적지 진입 전 권한 재검증, 실패 시 조용히 대체하지 않고 오류/선택 상태 표시 | `06` §6.2/§17 |
| 즐겨찾기 없음/최근방문 없음/접근 가능한 메뉴 없음은 서로 다른 안내 문구를 쓴다(권한없음 vs 데이터없음 구분) | `06` §19 |
| "수집 상태" 류 위젯은 statusSource가 생기기 전까지 이 화면에 추가하지 않는다 | `06` §19, `07` §2 |
| 공지 배너 닫기는 세션 동안만 유지한다(영구 dismiss 아님) — 다음 로그인/재접속에서는 다시 노출된다 | 이 문서, Decided(2026-09-24, §8) |
| 이 화면은 전역 Context를 **분석 필터로 적용하지 않는다.** 그러나 Context Bar는 숨기지 않고, 다른 화면에서 전달된 Context를 보존한 채 "이 화면에서는 미적용"으로 표시하며, 지원 화면으로 복귀하면 재검증 후 다시 적용한다(조용한 폐기 금지) | `06` §6/§6.4 |
| 그룹 바로가기 클릭은 그 그룹의 Menu Registry 등록 대표 목적지로 즉시 이동한다. 대표 목적지가 등록되지 않은 그룹은 클릭 가능한 카드로 렌더링하지 않는다(임의 첫 메뉴로 대체 금지) | 이 문서, Decided(2026-09-24, §8) |
| 대표 목적지 자체는 권한이 없지만 같은 그룹의 다른 메뉴는 접근 가능한 사용자에게 그 그룹 카드를 어떻게 다룰지는 **Open**이다(카드 자체를 숨길지, 클릭 시 그룹 내 접근 가능한 다른 메뉴로 대체할지는 정하지 않음) — 이 문서는 이 경우의 동작을 확정하지 않는다 | 이 문서, Open(§8) |

## 9. UX REVIEW (문서 단계)

- 밀도: 카드형 메뉴 바로가기는 그룹 개수(7개 이하)로 제한돼 있어 `wireframe-rules.md`의 "과도한 카드 그리드 지양" 원칙과 충돌하지 않는다. 그룹 수가 늘어나면 리스트형으로 전환을 재검토한다.
- 숨은 Context 없음: 이 화면은 전역 Context를 분석 필터로 쓰지 않지만, 전달된 Context를 지우거나 숨기지 않고 미적용 상태로 계속 보여준다 — 다른 화면에서 설정한 기간/설비 필터가 조용히 사라지거나 조용히 재적용되는 일이 없어야 한다(§7 규칙 참조).
- Traceability: 즐겨찾기/최근방문 항목은 항상 실제 목적지 URL로 연결되며, 요약 카드에서 그치지 않는다.

## OPEN QUESTIONS / RISKS

- 공지 배너 노출 조건(언제 어떤 공지를 보여줄지) 자체가 아직 정해지지 않아 이 화면의 세로 레이아웃이 배너 유무에 따라 흔들릴 수 있다(닫기 지속 범위는 2026-09-24 결정으로 해소).
- 메뉴 그룹이 실제로 몇 개까지 늘어날지(현재 7그룹 고정이지만 하위 확장 가능성)에 따라 그리드 레이아웃이 리스트형으로 바뀔 수 있다.
- **그룹 클릭 = 대표 목적지 즉시 이동 결정(2026-09-24)은 Menu Registry에 그룹당 1개 primary 필드가 있어야 성립한다.** 이 필드가 구현되기 전까지는 그룹 카드를 클릭 가능하게 만들 수 없다 — 스키마 작업이 이 화면 구현의 선행 조건이다.
- 대표 목적지가 아직 등록되지 않은 그룹(과도기)을 카드에서 완전히 숨길지, 비활성 상태로 보여줄지가 Open이다.
- 대표 목적지만 권한이 막힌 사용자(그룹 내 다른 메뉴는 접근 가능)에게 그룹 카드를 어떻게 보여줄지가 Open이다 — "그룹 접근 가능 = 대표 목적지 접근 가능"을 전제하면 안 된다.
- 즐겨찾기가 목적지 ID만 저장하기로 결정(2026-09-24)했으므로, 마지막 조회 조건으로 되돌아가고 싶은 사용자는 매번 필터를 다시 설정해야 한다 — 사용성 트레이드오프로 인지하고 넘어간 결정이다.

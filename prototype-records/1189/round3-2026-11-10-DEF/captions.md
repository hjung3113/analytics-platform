# #1189 2차 시안: 시스템이 합쳐지는 방향 (2026-11-10)

A·B·C는 모두 반려. 다듬기가 아니라 개념이 다른 세 안이다. 디자인 시스템(토큰·부품·글자 규칙)은 그대로이고 구조는 자유롭게 바꿨다.

실제 앱(mock, admin) 1440×900 @2x. 지난 시안과 같은 준비 상태: MARS 생산성 개요 방문 후 즐겨찾기, CLAS 방문, 홈. 이동 화면은 MARS 생산성 개요에서 열었다.

| 파일 | 내용 |
| --- | --- |
| `home-{current,D,E,F}.png` | 홈 (지금) |
| `home-{D,E,F}-merged.png` | 홈 (합쳐진 뒤) |
| `home-empty-…` | 첫 방문 홈, 지금과 합쳐진 뒤 |
| `nav-{current,D,E,F}.png`, `nav-…-merged.png` | 이동 화면 열림. current는 지금 전환기 |
| `nav-D-source-CLAS.png` | D에서 출처를 CLAS로 고른 상태. 없는 메뉴도 흐리게 남음 |
| `collapsed-…` | 사이드바 접힘. E는 사이드바가 없어 해당 없음 |

## 세 안 공통

- 합쳐지는 것은 MARS·CLAS·BRAVO뿐이다. 표준 로그 개발, 업무 흐름, 도구, 운영 콘솔은 별도 목적지로 남는다.
- 주소, 메뉴 id, 권한, 이어서, 조회 조건 유지는 시안에서 바꾸지 않았다.
- 합쳐진 뒤 화면은 표시만 바꾼 모의 화면이다. 실제 데이터, 서버 이전, 저장값 변환은 없다.
- 단계별 메뉴 배치는 **시안용 임시안**이다(2/9/1/1로 치우침). 실제 배치는 소유자가 정한다. `공정`·`StGroup`·`설비`·`설비 기준`·`조직 기준`은 별도 메뉴가 아니라 화면 안의 드릴이라 넣지 않았고, `실행 상세`는 사이드바 숨김 메뉴라 빠졌다.

## D 분석 순서 (추천)

- **개념.** 분석이 하나의 목적지가 되고, 사이드바와 홈의 기본 구조가 분석 순서다. 시스템은 사이드바 위 `출처` 선택과 메뉴 옆 작은 태그로 내려간다.
- **지금 화면.** 출처를 고르면 그 시스템에 없는 메뉴도 `미제공`으로 흐리게 남아, 합쳐지는 진행 상황이 보인다. 홈은 네 단계를 가로로 펼친다.
- **합쳐질 때.** 출처 선택과 태그만 사라진다. 나머지는 그대로다(`home-D` ↔ `home-D-merged`).
- **새로 익힐 것.** 지금 한 번. 합쳐질 때는 없다.
- **위험.** 합병 전에 메뉴 구조가 먼저 바뀐다. 단계 배치가 현장 인식과 다르면 찾기 어려워진다.

## E 메뉴판

- **개념.** 전환기 없음. `메뉴` 하나를 열면 볼 수 있는 모든 메뉴가 한 판에 나온다. `시스템별 / 분석 순서별` 묶음을 바꿔 볼 수 있고, 홈도 같은 판이다.
- **합쳐질 때.** 기본 묶음이 분석 순서가 되고 토글이 사라진다.
- **새로 익힐 것.** 적다. 사이드바가 사라지는 것은 지금 익혀야 한다.
- **위험.** 메뉴 66개가 한 화면에 나열되어 시선이 머물 곳이 약하다. 조사에서도 경계가 사라지면 홈은 목록이 아니게 된다고 나왔다.

## F 내 작업에서 시작

- **개념.** 홈은 마지막 화면과 조건을 이어가는 곳이고 시스템 목록이 없다. 다른 곳으로는 `이동` 하나로 간다(검색, 최근 방문, 목적지).
- **합쳐질 때.** 홈은 변화 없음. 시스템 이름이 사라지고 사이드바가 분석 순서가 되며, 옛 이름은 검색어로 남는다.
- **새로 익힐 것.** 가장 적다.
- **위험.** 처음 쓰는 사람이나 평소 안 쓰는 메뉴를 찾을 때 단서가 적다. 분석 순서가 합병 전까지 화면에 드러나지 않는다.

## 합쳐질 때 옮길 것 (세 안 공통, 구현 안 함)

| 항목 | 할 일 |
| --- | --- |
| 주소 | 옛 경로를 유지한다. 대표 경로를 바꾸면 허용된 조회 키를 보존하는 별칭을 둔다 |
| 저장된 뷰 | 메뉴 id와 필터를 유지한다. 메뉴를 합치면 id·필터 대응표를 버전과 함께 만든 뒤 옮긴다 |
| 즐겨찾기 | id가 그대로면 변환 없음. 합치면 대응·중복 제거, 순서 유지 |
| Registry | 단계·출처·옛 이름 선언을 권한·목적지 식별과 분리해 승인한다. D 단계, E 대체 묶음, F 옛 이름과 통합 분석 목적지 |
| 이어서 | 통합 분석 이어서 키를 만들고 유효한 최신 옛 기록으로 채운다. 호환 기간엔 옛 기록을 유지한다 |
| 조회 조건 | 출처가 Scope로 바뀌지 않게 하고 기존 Scope·기간 의미를 유지한다 |

## 사례 조사 (`../research-delta.md` Round 2)

- 페이지를 공유하게 될 단위는 범위 또는 구분 없음으로 간다. Vercel, Google Cloud, Fabric, Grafana, Datadog.
- 작업 순서만을 유일한 기본 내비게이션으로 삼은 제품은 찾지 못했다. 가장 가까운 Fabric도 작업 단계를 필터로 쓴다. 그래서 D에 출처 선택을 남겼다.
- 이름을 바꿔도 주소는 살린다. GitHub, Grafana, Microsoft, Data Studio.
- 전환은 선택 → 기본 → 종료 순이 흔하다. Vercel 35일, GitHub 약 6개월, Atlassian 약 9개월.
- 경계가 사라지면 홈은 이어서 일하는 곳이 되고 전체 목록은 다른 곳으로 간다. Google Cloud, Atlassian, Fabric, AWS.
- 공식 문서로 확인했고 실제 콘솔은 열어 보지 않았다.

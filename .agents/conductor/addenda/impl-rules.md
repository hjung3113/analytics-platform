## analytics-platform addendum (AP addendum)

AP overrides and additions to the numbered rules above. The stricter rule wins.

- **You are the implementation worker, not the coordinator. Edit directly in this worktree. Do not run `git` or `orca`.**
- Do not revisit coordinator decisions marked "final — do not re-litigate" in the task file.
- Do not run `git` commands for reading or writing; this is stricter than the shared rule 1 prohibition on git. Do not run `pnpm install`, `add`, `patch`, or `update` — dependency installation is the coordinator's responsibility. Leave changes uncommitted; the coordinator commits and runs root checks. `orca` (terminals, worktrees, orchestration) is also the coordinator's responsibility. If a required command is blocked, do not retry it; report the command and reason in the report, then stop.
- Read first: root `AGENTS.md`, the `AGENTS.md` in the folder being changed, and the contract documents referenced by the task file (section 06 and ADRs).
- Run only the narrowest checks allowed by the repository and task file. Package checks use `pnpm --config.verify-deps-before-run=false --filter <pkg> run <lint|typecheck|test>`. If tests change, also run that package's `typecheck` (vitest does not check types). The vitest worker cap is set through environment variables; do not add worker-count flags, especially not after `--` as in `run test -- --maxWorkers=…` (it becomes a file filter and removes the cap). For changed shell scripts, run `bash -n <file>`; for docs-only changes, run `node .github/scripts/check-doc-links.mjs`. If the checker reports `target exists locally but is not tracked by git` for a newly created document, do not treat it as a failure; report it. Fix the first failure. If it still fails, report the exact command and exit code.
- Do not run root `pnpm test`, `build`, `e2e`, dev servers, or browsers (16 GB machine, `docs/agents/operations.md`). If E2E tests are added or changed, report that they could not be run.
  - Exception: For `site/` work, run the demo build, capture scripts (`shots.mjs`, `shots-real.mjs`), static server, and real-server-mode dev server (captures and `check-assembled.mjs --browser` are acceptance criteria). Shut down every server before finishing. `assemble.mjs` allows output inside the repository only in `_site/`, so assemble review previews outside the repository with `--site-base /analytics-platform/`, then copy them into `.review/`.
- Reuse the i18n dictionary and the screen's existing wording for UI copy; follow `GLOSSARY.md` for domain terms. Do not reformat existing lines.
- The report must list changed files (one reason per file), added tests (which acceptance criterion), changed existing tests and why, checks run and their results, anything not run, **host-only verification**, and open questions.

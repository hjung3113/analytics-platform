# Traps (read when writing a brief or when the topic comes up)

Append new traps at the end, one bullet each: the symptom, then what to do. No dates or stories. When a path changes, fix or delete its stale line.

- Use [`docs/agents/operations.md`](../../../docs/agents/operations.md) for worker setup pitfalls: new worktree installation, pnpm 11, CSS selector CI, captures, and mock registration.
- A baseline worktree created with plain `git worktree add` cannot host an Orca terminal reviewer; run previews there only — the Orca terminal is unavailable.
- Write an ADR number only after commenting `ADR-NNNN 예약` on #598. Before reserving, check both `origin/main` and open PRs. A reservation does not stop another session from using the same number: recheck `origin/main`'s `docs/adr` before ship.
- If `gh pr merge` rejects a merge by recommending `--auto`, check state with `gh pr view <n> --json state` before deleting the remote branch — deleting it closes the PR.
- Before final checks, run `pnpm install --frozen-lockfile` in the main checkout — `node_modules` can become stale as merges accumulate.
- Resolve relative `addenda/` paths from `$CONDUCTOR`, not the repository root — otherwise they resolve to “No such file.”
- If a task has no issue number, `launch-worker.py` cannot create a worktree because `--issue` requires a number. Create one manually: `orca worktree create --setup skip` (without `--issue`) → install → close the configuration shell → write TASK → shared runner.
- Do not edit source in a worktree while host root tests or E2E are running — Vite HMR may cause spurious E2E failures — and never run a host check in a worktree a fix worker is editing (stop the worker or wait for its report first). If a change is needed, wait for the checks to finish, edit, and rerun them.
- E2E uses `--strictPort` and defaults to port 4190 (`E2E_PORT`; base path defaults to 4191 via `E2E_BASE_PATH_PORT`). Use the flow-specific port in [`LANES.md`](../LANES.md) when another session uses the same port; do not touch another session's process. Find the PID with `lsof -nP -iTCP:<port> -sTCP:LISTEN`, then check cwd with `lsof -a -p <PID> -d cwd`. A full local E2E run takes `heavy.lock` and is announced to the lead (LANES §Machine resources).
- If `ship-pr.sh --issue` fails with `Could not close the issue` because the PR's `Closes #n` already closed the issue, verify merge with `gh pr list --head <branch> --state all`, manually archive the worktree's `.review/`, then remove the worktree — the script skips `--worktree` cleanup and `--archive-review`, and omits `merged` from JSON ([conductor-engine#58](https://github.com/hjung3113/conductor-engine/issues/58)).
- After applying `css-removal-ok`, wait for reruns to finish with `gh pr checks <n> --watch`. `ship-pr.sh --ci` may still report `ci_failed` (exit 21) for an earlier run on the same head after checks finish. Confirm every check passes with `gh pr checks <n> --json name,bucket`, then merge with `gh pr merge <n> --squash` under `merge.lock` ([conductor-engine#144](https://github.com/hjung3113/conductor-engine/issues/144)); see Verify step 7.
- Do not run file-writing commands such as `node tooling/gen-menu/scripts/probe.ts` in a reviewer preview worktree; stop the preview first because transient file changes can make Vite show import errors.
- Put “Do not read the clipboard” near the start of UX review briefs. `navigator.clipboard.readText()` transfers control of the Ego Lite task space to the user; judge link copying from its success toast and the address bar.
- Before launching a worker, resolve any item in a brief-check patch marked “coordinator decision before start” by recording the decision in the brief — otherwise the worker may stop on an open policy question.
- Start `worker-wait.sh` with `run_in_background` in the same turn that launches workers and reviewers — without a wait, completion notifications do not arrive.
- If a shared component is wrong or missing, the conductor files an `upstream` issue with the provider's `engine/scripts/upstream-file.sh`; record any local workaround here with that issue link instead of putting it only in memory or `HANDOFF.md`.
- Include a `?variant=` value in menu `pageKeys` so changing the address redraws the screen — otherwise the previous variant can remain visible.
- For conductor-host Playwright captures, import `@playwright/test` from `apps/platform-e2e` and add `v=1&scopeId=MEM` to the URL. Without Scope, the page shows only “Scope를 선택하세요” and the canvas wait times out.
- Compare domain hierarchies and groupings in briefs with `GLOSSARY.md` first (for example, “Maker → Module”) — use the glossary and the root `AGENTS.md` principle “SDK provides general-purpose building blocks.”
- For IA and menu-structure prototype captures, capture each space rail section; the sidebar shows only the selected section's menus. Clear that origin's localStorage and sessionStorage before each variant so recent visits do not contaminate captures.
- Wait for the 200ms fade-in of popovers and menus to finish before capture or visual review — an intermediate frame can look like a transparency defect.
- When public types (including union extensions) in `@ap/contracts` or SDK packages change, also run `pnpm sdk:api` after root checks. For intended changes, use `--update` and add one change-record line to `docs/integration/sdk-git-tag-consumption.md` — root checks do not cover this gate.
- Do not close slice or wave Epics during release cleanup; close only issues named by the PR body's `Closes` — cleanup may otherwise close an Epic.
- `launch-worker.py <n>` requires the brief report and sentinel to be `.review/W-<n>-REPORT.md` and `<!-- W-<n>-DONE -->`. Use the same names for a second stage in a new worktree; names such as `-STEP1-DONE` are rejected.
- After `app-preview.py stop --all`, confirm with `status`; if a preview remains, stop it by label ([conductor-engine#63](https://github.com/hjung3113/conductor-engine/issues/63)).
- Do not switch branches in a checkout where `ship-pr.sh` is running, especially `$MAIN`; run ship from a `git worktree add` for that branch — otherwise concurrent branch creation can include unmerged commits.
- Do not pipe `ship-pr.sh` through `| tail -1`; write output to a file and check the exit code separately. Re-run root checks from the beginning after resolving a rebase conflict, since tests may have changed on the newly merged branch ([conductor-engine#64](https://github.com/hjung3113/conductor-engine/issues/64)). Exit code 20 may otherwise be reduced to `{"pr": null, "merged": false}`.
- For UX reviews on the real server (`dev:real` + issue database), specify a Context-capable screen and a persona able to open it in advance. Seed personas (Mock User and Mock Admin) lack analytics-space access, so the analysis menu shows “이 메뉴에 대한 권한이 없습니다”; the operations console's “변경 감사” (actor filter + time range) has Context. Platform “로그아웃” is inactive, so switch users by selecting again at `/auth/login`.
- The real-server assembly (`dev:real` + issue database) cannot show the zero-space home: the log-dev space menu requires only `platform:view`, so every logged-in user has a space. Verify the zero-space state with the home unit test and do not specify a “zero-space persona” in UX briefs.
- If observed behavior differs from an assertion, compare the brief and contracts (06, ADR) before weakening the assertion — if they conflict, fix the code to match the contract.
- Verify release and tag state remotely with `gh release list`, then `git fetch --tags` and `git tag`; local tags may be stale.
- If a site capture (`site/scripts/shots.mjs`) is described as showing asynchronously loaded content, wait for that content in the capture preparation step — `go()`'s `aria-busy` wait does not wait for it.
- A test may pass locally while a delayed timer runs after the test in CI and calls an API missing from jsdom, causing vitest to exit 1 after all tests pass. When stubbing a global absent from jsdom, leave the stub installed if there was no original value; treat CI `Unhandled Errors` as failures.
- UX rechecks after changing `PanelWorkspace` presets or ratios: values persisted in `platform:workspace:v1:*<persistKey>*` by earlier reviews hide the new preset (the persisted value wins, per contract). Put in the recheck brief: “before measuring, press `기본 배치` at each stage or clear that key”. The shell sidebar default also depends on width (collapsed below 1440, `packages/sdk/shell/src/frame/AppShell.tsx`): record the measured viewport width in the brief.
- When adding a feature bridge entry, update all four shared locations: `apps/feature-screens/package.json` `exports`, `tooling/eslint/src/index.js` `FEATURE_BRIDGE_ENTRIES`, the entry array in `tooling/eslint/src/boundaries.test.ts`, and the describe in `packages/adapters/feature-bridge/src/feature-entry-graph.test.ts`. After rebase, preserve main's lines and add only this node's lines and describes; verify the describe count is main plus this node — manual block merging can truncate a describe.
- In briefs for code that rewrites URL keys, specify each key's type. Do not prescribe `String(previous[key]) === value ? previous[key] : value` to preserve types; if reusing a previous value is required, start with `previous[key] !== undefined &&`.
- To review another persona alongside a reviewer on `dev:real`, open the same Vite server at `http://[::1]:5186` — Vite binds to `localhost`, not `127.0.0.1`. Cookies are host-specific, so this does not change the UX reviewer's `localhost` login.
- Before accepting worker results, compare `git status --short | wc -l` with the report's changed-file count. Put in every brief and fix brief, for files in the residual Biome scope (documentation roots, ops): “`biome check --write <changed file paths>` — never pass a directory or `.`” (a wider run rewrites unrelated files). Files under `apps/platform-api`, `apps/feature-screens`, `packages/feature-shared` and `packages/feature-ui` take their package `lint` (ESLint) instead and never Biome (#1102 a+b).
- For moves or renames in SDK packages (`packages/sdk/{contracts,ui,kernel,components,shell}`), run `pnpm sdk:pack --out <dir> && pnpm sdk:consumer-check <dir>` on the host in addition to the four root checks — CI runs this gate, but the root checks do not.
- A node that changes a public export or type of `packages/sdk/{contracts,ui,kernel,components,shell}` runs `pnpm build` (not just the cached turbo build) before `pnpm sdk:api --update`, then `pnpm sdk:api` and `pnpm sdk:test`; CI also runs `pnpm sdk:api` and the tarball/consumer checks, which the four root checks skip. The snapshot reads `dist` declarations, so a stale `dist` after a rebase writes outdated lines for other packages' types.
- A PR that renames a button or changes a toast must also update `site/scripts/shots.mjs` and `site/SOURCES.md`. The intro-site capture job is not part of the root checks, and #1042 failed CI twice on this.
- Workers may not run git or use the network (`00-IMPL-RULES.md`), so a brief never tells them to `git fetch`/`git show` an input: put every file they must read (prototype source, approved screenshots, captures) under the worktree's `.review/` before dispatch. Otherwise the worker silently builds without the spec.
- `worker-wait.sh` can report `failed` while a codex browser worker is still mid-task (no report yet). Read the terminal screen before closing it; closing it kills the run.
- `$ENGINE` is `~/.agents/skills/issue-wave-conductor/scripts`; use that path directly and never search the home directory for the engine, which can select a stale Trash copy.
- Codex lane sessions cannot publish claude.ai Artifacts. For prototypes and captures requiring owner confirmation, the lane creates only the files (capture directory), and the lead publishes them as an Artifact. Never use Orca share links (`share.onorca.dev`) as owner-confirmation links. (#1099)
- Codex workers under workspace-write cannot edit protected `.agents/` files. Have the conductor apply permitted agent-asset edits before dispatch and exclude those writes from the worker brief; keep product and test changes in the worker, and preserve host edits on resume ([conductor-engine#153](https://github.com/hjung3113/conductor-engine/issues/153)).
- The feature Biome gate selects committed merge-base..HEAD paths. When verifying an uncommitted implementation, do not infer that root lint checked those feature files; use bounded file checks when needed. A shorter renamed literal can make a previously wrapped array require one-line formatting (#1099a).
- The lead must not fast-forward `AP_MAIN` while a lane review tripwire is armed; ff only when no review is running — an ff trips the review's tripwire and the review loses its base.
- One issue DB (`env.verify.<n>`) serves one integration run at a time: a conductor run and a worker run on the same DB at once fail time- and grant-dependent cases (expired session/grant) that pass alone. Wait for the worker to end before the host integration run.
- `ship-pr.sh --ci`: the default 600 s CI wait is shorter than AP CI (2026-11-04: median 11.7 min, p90 17.8, max 27.4; it timed out twice on #1305). Pass `--ci-timeout 2700` on every ship, and `--ci-timeout 3000` on a PR that runs full E2E (`packages/**` changes).
- `archive/kernel-platform-table/tests/table.browser.test.ts` reads `docs/contract/components.md` and `DESIGN.md` table values (row/header height, cell padding) and the prototype's CSS; when a contract value changes, update that check and the prototype class in the same PR (archive rule: minimal fix).
- A stacked node (PROFILE §Launch) whose base merges by squash: rebase it with `git rebase --onto origin/main <old base tip>` (the base commits are not on main), then compare the tree with the verified head (`git diff --stat <verified> HEAD`); only main's own changes may differ.
- `ship-check.sh` reads review records from `$WAVE_BRIEFS` (`W-<n>-FINAL*.md`, `W-<n>-UX.json`, a `review-plan:` line in VERIFY), while reviewers write in the worktree's `.review/` and state JSON goes to `$WAVE_STATE`: copy the reports and JSON into `$WAVE_BRIEFS` and append `review-plan: $(python3 $ENGINE/review-plan.py <worktree> | tail -1)` before running it.
- `with-lock.sh` does not wait for a held lock: it prints `merge.lock held by …` and the wrapped `ship-pr.sh` never runs. Behind `| tail -1` that looks like a finished ship; read the output for the JSON before assuming a PR exists, and ship again after the holder ends. `ship-pr.sh --merge` also needs `SHIP_AUTOMERGE=1` in the environment (exit 31 otherwise).
- A capture worker can report 1440×900 while saving 1200×962 files (window size wins over its viewport claim). Check every file with `sips -g pixelWidth -g pixelHeight` before using it, and put that check in the capture brief.
- Gate a commit on the checks' exit status (`ok=1; pnpm lint || ok=0; …; [ $ok = 1 ] && git commit …`), never `vitest … | grep 'Tests ' && git commit` (grep succeeds when tests fail) nor `(pnpm x && echo OK || echo FAIL); git commit` (each `|| echo` returns 0). A round that adds or edits tests also runs the package `typecheck`, because vitest does not typecheck.
- A menu that gains `src/endpoints.ts` declarations (or changes them) must regenerate `packages/sdk/contract-schemas/endpoints.json` (`pnpm --filter @ap/contract-schemas gen:endpoints`) and commit it: only CI's "Platform static" (`tooling/sdk/sdk-schemas.test.mjs`) checks it, local `verify-root.sh` does not (#1194 node r).
- `ship-check.sh` reads everything after `ux-skip:` as the evidence path: put the reason on another VERIFY line, never after the path (#1194).
- A node that adds a migration runs the FULL backend `test:integration` on its recreated DB before push, not only the touched module dirs: repo-wide suites such as `role-grants.integration.test.ts` (the workspace-first index convention of [FO ADR-0015](../../../docs/adr/history/feedbackops/0015-operational-safety-rate-limit-headers-migrations-idempotency.md)) catch what targeted dirs miss (#1266 b5a).
- Reproduce a CI shell step with the YAML's exact quoting, and pass explicit worktree paths into subshells: `$PWD` inside `(cd …)` is the new directory, so `verify-db.sh create --migrate-from "$PWD"` once migrated from main. zsh does not word-split `$var` (`set -- $n`, `$P up` with `P='docker compose …'`): put multi-word commands in a script or `bash -c`.
- Chain the merge on ship-check: `bash .agents/conductor/scripts/ship-check.sh <n> <wt> && <with-lock merge>`. Running them as separate statements once merged a PR whose ship-check had failed on a missing `review-plan:` line (#1276).
- A worker may run a formatter the repo does not use (double quotes, reflowed files it did not need to touch). Check `git diff --numstat` for files outside the task's list and revert formatter-only churn before committing (#1275).
- Integration files run one at a time and share the unauthenticated per-IP rate-limit bucket (50/min). A suite that logs in must clear `core.rate_limits where key like '127.0.0.%'` before its first `loginAs`; adding any test file changes the order and exposes suites that do not (#1275).
- Rehearsing the compose-based ops scripts (`scripts/backup/*`, `upgrade.sh`) on a disposable project: put `RELEASE_POSTGRES_VOLUME` / `RELEASE_MINIO_VOLUME` in that project's env file, not only in a helper's exported environment — the scripts call compose themselves, and without the variables compose falls back to the pinned production volume names (#1266 b6).
- `gh pr checks <n> --watch` exits at once with «no checks reported» while the head's runs are still queued (a concurrency group waiting on the previous push), so a chained merge silently does nothing. Wait for the head's runs instead: loop `gh run list --branch <br> --json headSha,status` until none for the head SHA is unfinished, then require `gh pr checks --json bucket` to have more than zero entries and no `fail`/`pending` before `ship-check && merge`.
- A root verify counts only when its summary prints `step=test` and `step=build`. Exit 75 means `heavy.lock` was held and test/build never ran; wait and rerun instead of reading the lint/typecheck lines as a pass.
- If the bundled Playwright Chromium will not launch locally, run E2E on installed Chrome with a throwaway config in `apps/platform-e2e`: `import base from './playwright.config'; export default { ...base, use: { ...base.use, channel: 'chrome' } };`, then `E2E_PORT=<port> pnpm exec playwright test -c <that file> <specs>`, and trash the file afterwards.
- `ship-pr.sh` stops with a GraphQL 503/504 from `gh`: the PR may already exist. Wait for its checks over REST (`gh api repos/<o>/<r>/commits/<sha>/check-runs`), run `merge-precheck.sh`, then merge with `gh api -X PUT repos/<o>/<r>/pulls/<n>/merge -f merge_method=squash -f sha=<sha>` under `merge.lock`.
- Workers and prototype agents never stop shared containers (`platform-verify` on 5439): a stopped one breaks every lane's verify DB. If it happens, `verify-db.sh up` and recreate the DBs that were in use.
- Changing the order of `GROUPS` in `apps/platform-web/src/menus.ts` breaks the E2E sidebar-order asserts (`features-navigation`, `contract-shell`, `contract-features`); update them in the same change.
- A copy rename is done only when tests, E2E specs and menu `description`/`label` `ko:` strings are swept too (`git grep` the old word under `platform/`, `apps/feature-screens/src`, `apps/platform-e2e`), not only the screens.
- A test whose first query waits for a lazily loaded slot body (`lazy(() => import(...))`) passes `LAZY_MOUNT_WAIT` (`@ap/feature-bridge/testing`); the 1 s default passes locally and fails under CI load.

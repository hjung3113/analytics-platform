# Traps (read when writing a brief or when the topic comes up)

Append new traps at the end, one bullet each: the symptom, then what to do. No dates or stories. When a path changes, fix or delete its stale line.

- Worker setup pitfalls (new worktree install, pnpm 11, CSS selector CI, captures, mock registration): [`docs/agents/operations.md`](../../../docs/agents/operations.md).
- ADR numbers: comment `ADR-NNNN 예약` on #598 (still the reservation thread) after checking `origin/main` and open PRs; recheck `origin/main`'s `docs/adr` before ship, because a reservation does not stop another session.
- If `gh pr merge` rejects a merge by recommending `--auto`, check `gh pr view <n> --json state` before deleting the remote branch: deleting it closes the PR. Merge commands: [`merge.md`](merge.md).
- Resolve `addenda/` paths from `$CONDUCTOR`, not the repository root.
- A task with no issue number cannot use `launch-worker.py` (`--issue` needs digits). Create the worktree with `orca worktree create --setup skip`, install, write TASK, use the shared runner.
- Do not edit source in a worktree while host root tests or E2E run there (Vite HMR causes spurious E2E failures), and never run a host check in a worktree a fix worker is editing.
- E2E uses `--strictPort`; take your lane's port (LANES §Lanes) and never touch another session's process. A full local run takes `heavy.lock` (LANES §Machine resources).
- After `css-removal-ok`, wait for the reruns before ship (`ship-pr.sh --ci` judges the latest run of each check).
- Do not run file-writing commands such as `node tooling/gen-menu/scripts/probe.ts` in a reviewer preview worktree; stop the preview first (Vite shows import errors).
- Put "Do not read the clipboard" at the start of UX review briefs: `navigator.clipboard.readText()` hands the Ego Lite task space to the user. Judge link copying from the success toast and the address bar.
- Resolve every brief-check item marked "coordinator decision before start" in the brief before launch; otherwise the worker stops on an open policy question.
- Include a `?variant=` value in menu `pageKeys`, or the previous variant stays visible.
- Compare domain hierarchies and groupings in briefs with `GLOSSARY.md` first (for example "Maker → Module") and the root `AGENTS.md` principle "SDK provides general-purpose building blocks".
- IA and menu-structure prototype captures: capture each space rail section (the sidebar shows only the selected section's menus) and clear that origin's localStorage and sessionStorage before each variant.
- Wait out the 200ms fade-in of popovers and menus before a capture; an intermediate frame looks like a transparency defect.
- Do not close slice or wave Epics during release cleanup; close only issues named by a PR body's `Closes`.
- `launch-worker.py` appends the sentinel rule itself; for a second stage in a new worktree reuse `.review/W-<n>-REPORT.md` and `<!-- W-<n>-DONE -->`.
- Do not switch branches in a checkout where `ship-pr.sh` runs, especially `$MAIN`; ship from a `git worktree add` for that branch, or concurrent branch creation includes unmerged commits.
- After a rebase conflict, rerun the root checks from the beginning; the newly merged branch may have changed tests. Write `ship-pr.sh` output to a file and read the exit code separately, not through a pipe.
- UX reviews on the real server (`dev:real` + issue DB): name a Context-capable screen and a persona that can open it in the brief. Seed personas (Mock User, Mock Admin) have no analytics-space access, so the analysis menu shows "이 메뉴에 대한 권한이 없습니다"; the operations console's "변경 감사" has Context. "로그아웃" is inactive: switch users by selecting again at `/auth/login`.
- The real-server assembly cannot show the zero-space home (log-dev space needs only `platform:view`); verify it with the home unit test and do not request a "zero-space persona".
- If observed behavior differs from an assertion, compare the brief and contracts (06, ADR) before weakening the assertion; if they conflict, fix the code to match the contract.
- Verify release and tag state with `gh release list` and `git fetch --tags`; local tags may be stale.
- A `site/scripts/shots.mjs` capture of asynchronously loaded content waits for that content in its own preparation step; `go()`'s `aria-busy` wait does not.
- A delayed timer can run after a test in CI and call an API missing from jsdom, so vitest exits 1 after all tests pass. When stubbing a global absent from jsdom, leave the stub installed if there was no original; treat CI `Unhandled Errors` as failures.
- UX rechecks after changing `PanelWorkspace` presets or ratios: persisted `platform:workspace:v1:*<persistKey>*` values hide the new preset. The brief says "press `기본 배치` at each stage or clear that key before measuring" and records the viewport width (the shell sidebar collapses below 1440, `packages/sdk/shell/src/frame/AppShell.tsx`).
- A new feature bridge entry updates four places: `apps/feature-screens/package.json` `exports`, `tooling/eslint/src/index.js` `FEATURE_BRIDGE_ENTRIES`, the entry array in `tooling/eslint/src/boundaries.test.ts`, and the describe in `packages/adapters/feature-bridge/src/feature-entry-graph.test.ts`. After a rebase keep main's lines and add only this node's; the describe count must be main's plus this node's.
- In briefs for code that rewrites URL keys, state each key's type. Do not prescribe `String(previous[key]) === value ? previous[key] : value`; reuse a previous value only after `previous[key] !== undefined &&`.
- To review another persona beside a reviewer on `dev:real`, open the same Vite server at `http://[::1]:5186`; cookies are host-specific, so the reviewer's `localhost` login is unaffected.
- Before accepting worker results, compare `git status --short | wc -l` with the report's changed-file count, and check `git diff --numstat` for files outside the task list (formatter churn). Briefs for files in the residual Biome scope (documentation roots, ops) say "`biome check --write <changed file paths>` — never a directory or `.`". `apps/platform-api`, `apps/feature-screens`, `packages/feature-shared` and `packages/feature-ui` take their package `lint` (ESLint), never Biome.
- SDK gates that only CI runs (`packages/sdk/{contracts,ui,kernel,components,shell}`): a public type or export change runs `pnpm build` (not the cached turbo build), then `pnpm sdk:api --update`, `pnpm sdk:api`, `pnpm sdk:test`, because the snapshot reads `dist` declarations; a move or rename also runs `pnpm sdk:pack --out <dir> && pnpm sdk:consumer-check <dir>`. See PROFILE §Verify step 7.
- A PR that renames a button or changes a toast also updates `site/scripts/shots.mjs` and `site/SOURCES.md`; the intro-site capture job is not in the root checks.
- Briefs never tell workers to `git fetch`/`git show`; put every input file (prototype source, approved screenshots, captures) under the worktree's `.review/` before dispatch.
- `worker-wait.sh` can report `failed` while a codex browser worker is still mid-task. Read the terminal screen before closing it; closing kills the run.
- Codex lane sessions cannot publish claude.ai Artifacts: the lane creates the capture files and the lead publishes them. Never use Orca share links (`share.onorca.dev`) as owner-confirmation links.
- Codex workers under workspace-write cannot edit `.agents/` files. The conductor applies those edits before dispatch and keeps them out of the worker brief; preserve host edits on resume (conductor-engine#153, open).
- The feature Biome gate selects committed merge-base..HEAD paths; for an uncommitted implementation use bounded file checks, not root lint. A shorter renamed literal can make a previously wrapped array require one-line formatting.
- The lead must not fast-forward `AP_MAIN` while a lane review tripwire is armed; an ff makes the review lose its base.
- `archive/kernel-platform-table/tests/table.browser.test.ts` reads `docs/contract/components.md` and `DESIGN.md` table values and the prototype's CSS; when a contract value changes, update that check and the prototype class in the same PR.
- `ship-check.sh` reads review records from `$WAVE_BRIEFS` (`W-<n>-FINAL*.md`, `W-<n>-UX.json`, a `review-plan:` line in VERIFY), while reviewers write in the worktree's `.review/` and state JSON goes to `$WAVE_STATE`: copy them over and append `review-plan: $(python3 $ENGINE/review-plan.py <worktree> | tail -1)` first.
- `with-lock.sh` does not wait for a held lock: it prints `merge.lock held by …` and the wrapped command never runs (exit 75). Read the output for the JSON before assuming a PR exists. `ship-pr.sh --merge` needs `SHIP_AUTOMERGE=1` (exit 31 otherwise).
- A capture worker can report 1440×900 while saving 1200×962 files. Check every file with `sips -g pixelWidth -g pixelHeight` and put that check in the capture brief.
- Gate a commit on the checks' exit status (`ok=1; pnpm lint || ok=0; …; [ $ok = 1 ] && git commit …`), never on `grep` of output or `(cmd && echo OK || echo FAIL); git commit`. A round that adds or edits tests also runs the package `typecheck`.
- A menu that gains or changes `src/endpoints.ts` declarations regenerates and commits `packages/sdk/contract-schemas/endpoints.json` (`pnpm --filter @ap/contract-schemas gen:endpoints`); only CI's "Platform static" checks it.
- `ship-check.sh` reads everything after `ux-skip:` as the evidence path; put the reason on another VERIFY line.
- A migration node runs the FULL backend `test:integration` on its recreated DB before push: repo-wide suites such as `role-grants.integration.test.ts` (workspace-first index convention of [FO ADR-0015](../../../docs/adr/history/feedbackops/0015-operational-safety-rate-limit-headers-migrations-idempotency.md)) catch what targeted dirs miss.
- Reproduce a CI shell step with the YAML's exact quoting and pass explicit worktree paths into subshells (`$PWD` inside `(cd …)` is the new directory). zsh does not word-split `$var`: put multi-word commands in a script or `bash -c`.
- Chain the merge on ship-check: `ship-check.sh <n> <wt> && <with-lock merge>`, never as separate statements.
- Integration files share the unauthenticated per-IP rate-limit bucket (50/min). A suite that logs in clears `core.rate_limits where key like '127.0.0.%'` before its first `loginAs`.
- Rehearsing compose-based ops scripts (`scripts/backup/*`, `upgrade.sh`) on a disposable project: put `RELEASE_POSTGRES_VOLUME` / `RELEASE_MINIO_VOLUME` in that project's env file; without them compose falls back to the pinned production volume names.
- CI wait on a PR (short-lock path): `gh pr checks <n> --watch` exits at once with "no checks reported" while the head's runs are still queued. Loop `gh run list --branch <br> --json headSha,status` until no run for the head SHA is unfinished, then require `gh pr checks --json bucket` to list more than zero checks and none `fail`/`pending`. Locked path: `ship-pr.sh --ci`.
- Workers and prototype agents never stop shared containers (`platform-verify` on 5439): a stopped one breaks every lane's verify DB. Recover with `verify-db.sh up` and recreate the DBs in use.
- Changing the order of `GROUPS` in `apps/platform-web/src/menus.ts` breaks the E2E sidebar-order asserts (`features-navigation`, `contract-shell`, `contract-features`); update them in the same change.
- A copy rename is done only when tests, E2E specs and menu `description`/`label` `ko:` strings are swept too (`git grep` the old word under `platform/`, `apps/feature-screens/src`, `apps/platform-e2e`).
- A test whose first query waits for a lazily loaded slot body passes `LAZY_MOUNT_WAIT` (`@ap/feature-bridge/testing`); the 1 s default fails under CI load.
- If bundled Playwright Chromium will not launch, run E2E on installed Chrome with a throwaway config in `apps/platform-e2e`: `import base from './playwright.config'; export default { ...base, use: { ...base.use, channel: 'chrome' } };`, then `E2E_PORT=<port> pnpm exec playwright test -c <that file> <specs>`, and trash the file afterwards.
- `ship-pr.sh` stopping on a GraphQL 503/504: the PR may already exist. Check `gh pr view`, wait for its checks, then merge per [`merge.md`](merge.md).
- Pass `worker-wait.sh --state` the exact state file of the worker you launched, never a `W-<n>*.json` glob: an older sibling state (`W-<n>-CAP.json`) matches first and the lane waits on a finished worker while the live one ends unseen.

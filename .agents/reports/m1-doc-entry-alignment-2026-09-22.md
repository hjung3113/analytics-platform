## 대표 작업 재검증

### V1 새 메뉴의 Kernel 소비 준비

INDEX → 06 §4–6/8/17–19/26/28–29 → 02 설비관리 → 07/해당 화면 설계 → 04 후보 경로를 실제로 따라갔다. 01 필드 원천과 DESIGN/설계 스킬도 도달 가능하다. Registry 선언, 요청 Scope의 서버 검증, 목적지 equipment ID와 occurrence 키 분리, 미지원 Context 보존, 원인 미확인 상태와 성공 0건 구별을 먼저 확인할 수 있다. 새 Sidebar/개별 Date Picker 규칙을 임의로 만드는 것은 여전히 06 §5 금지다.

결과: 진입점 수용 기준 충족. Registry 실제 schema·등록 코드·필드별 쓰기 원천·화면 구현은 완료하지 않았다. Domain Done만으로 Platform Done을 주장할 수 없다.

### V2 URL·시간 변경 영향

03 → 06 §6.3 → 05 R/H 상세, 04 → 06 §6.1/6.4, 07 §6–8의 소비 관계를 대조했다. 다음 반례를 원문으로 확인했다.

- R 없음 + 독립적으로 유효한 defaultRangeTo: 기본 기간 물질화 허용, 자동 재집계만 보류.
- R 있음: 같은 시간역·대상 조건에서 defaultRangeTo≤R, 불가능하면 기간 선택. 마지막 포함할 점과 배타적 상한은 다르다.
- TZ 미확인 단일 설비: naive 조회 가능. 복수 시간축 병합은 서버 assertion의 모든 설비·요청 전 구간 빈틈 없는 동일 시간역 증명이 필요하다.
- URL은 초 단위 naive datetime과 half-open, 원천 정밀도는 유지. 날짜만 고른 UI 입력 변환과 날짜-only URL 거부는 다른 규칙이다.
- 집합 키 중복 제거와 단일값 키 반복 오류를 합치지 않는다. page-owned/미등록 키와 등록된 전역 Context의 전달 범위도 다르다.
- 시간 기본 Δ, assertion 공급자, 다중 사업장 같은 날짜·교대일/영업일은 미결. H=1시간과 한국 우선 TZ, 명시적 1일/7일 프리셋은 이미 결정돼 있으며 다시 Open으로 내리지 않는다.

결과: 확정 메커니즘을 재결정 대상으로 보내던 안내를 수정했다. 07 §7의 10개 문서 검토 시나리오와 06 §6/11/17/19 연결도 유지했다. 이것은 문서 워크스루이며 제품 런타임 통과가 아니다.

## 검증과 다음 작업

주 에이전트 확인: 네 파일 모든 기존 Markdown 제목 동일, 07 §7 본문 동일, 로컬 inline 링크 37개(경로 및 사용한 fragment) 검사 오류 0, `git diff --check` 통과. 링크 검사는 제한된 Markdown 추출기로 로컬 대상과 제목 slug를 검사한 것이며 외부 URL·렌더러 전체·의미 정합성을 자동 보장하지 않는다. source diff는 직접 읽어 검토했다. 플랫폼 런타임·브라우저·성능·외부 서비스 검증은 실행하지 않았다.

FeedbackOps gitlink `b5dd614ac8da3792cb1627e7daeffb8fc9c4944e`와 내부 작업 트리, 독립 parser, 역사 보고서는 보존한다. 원본 전체를 전수 정독한 작업은 아니다. 네 대상 파일 전체, 05 결정/정책, 06 관련 계약, CONTEXT/ADR를 읽었고 01/02/DESIGN/REQUIREMENTS는 판단에 필요한 절만 대조했다.

다음 문서 이행은 M2 한 계약 연결 시범이지만 이번에 착수하지 않았다. 시작 시 06 §6.3과 05의 현재 R/H를 다시 읽고 실제 의존 포인터 하나와 작업별 검증 기록을 시범 적용한다. 과거 계획의 H/TZ/Scope Open 가정을 복사하지 않는다. 01/02의 Phase 표현, DESIGN의 오래된 설명, REQUIREMENTS의 결정/구현 증거 구분, 05 상세 원본 이관은 이번 완료 범위 밖이다. 현재 원문에 남은 Open을 HANDOFF의 “인증 하나” 요약으로 덮어쓰지 않는다.

되돌릴 때는 이 작업의 네 문서 diff만 역적용하고 HANDOFF 완료 안내도 같이 조정한다. 다른 변경이 추가된 뒤 전체 파일 checkout/reset으로 되돌리지 않는다. 이 실행 기록은 실제 수행 이력으로 남긴다.

마감 확인: 새 실행 기록의 링크 5개와 HANDOFF 상단 링크 4개도 존재하며, 기존 HANDOFF 전체가 접미부에 원문 그대로 남아 있다. FeedbackOps 내부 Git 상태는 깨끗하고 gitlink 동일, 역사 보고서 변경 없음. 최종 변경은 기존 파일 5개와 새 실행 기록 1개이며 미커밋 상태다.

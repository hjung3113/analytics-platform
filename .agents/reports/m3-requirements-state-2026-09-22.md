# M3 — 파생 요구사항의 상태·증거 구분

2026-09-22. 기준 커밋: `d20efe0` (M2). M3 본문 수정은 `PLATFORM_REQUIREMENTS.md`만이며 이 보고서와 HANDOFF는 작업 기록이다. 새로운 제품 결정·구현 승인·폴더 이동은 없다.

## 변경과 근거

- REQUIREMENTS를 파생 작업/제안 목록으로 명시했다. Must/Should/Nice와 모델 표수는 조사 이력이며 채택 권위가 아니다. 상태가 불명확한 추천은 승인된 요구가 아니다.
- §0의 체크는 문서 결정 반영이다. 구현 완료 체크에는 원본 revision, 구현 파일/commit, 검증 명령·환경·결과, 미검증 범위를 담은 작업/PR 링크를 요구한다. 후보 검토 완료와 제품 구현 완료를 구별한다.
- UI 프리미티브는 04의 Candidate, 다크모드는 DESIGN의 Deferred, 반응형 breakpoint는 06 §25의 Candidate로 구분했다.
- 05의 H=1시간, 사내 SSO 존재/프로토콜 Open과 06 §6.2의 Site→Line·단일 Scope/상속 Open을 요약에 반영했다. 계약 원본은 수정하지 않았다.
- 06 §6.1을 직접 대조해 metric 쌍의 ID-only 초기화·version-only 경로 완성 예외가 요약에서 사라지지 않도록 했다. 06 §6.3에 따라 국내 복수 설비도 시간축 병합 전 assertion 근거가 필요함을 정정했다.
- 미결이면 모든 구현을 금지하던 제목을 바꿨다. 미결 입력에 의존하는 동작을 구체화하고 독립 작업은 계속할 수 있다. 변경한 두 제목의 기존 fragment는 명시 anchor로 보존했다.

## 수행한 검증

- HEAD와 비교해 체크박스 107개의 순서/상태, 기존 [x] 두 줄 전체, 모델 표수 출처 순서가 동일하다. 질문 번호 1–15를 보존했다.
- REQUIREMENTS의 로컬 inline 링크 31개에 대해 파일 및 fragment를 검사했고 오류가 없다. 제목 fragment와 명시 anchor 기준 검사이며 의미 정합성 보증은 아니다.
- `git diff --check` 통과. 변경 범위는 REQUIREMENTS·이 보고서·HANDOFF다. 05/06/DESIGN 및 과거 보고서, FeedbackOps gitlink는 변경하지 않았다.
- 주 에이전트가 직접 수행했다. M3에서 별도 모델 토론이나 런타임/브라우저 시험은 실행하지 않았다. 기존 다중 모델 표기는 최초 조사 참여 기록이다.

## 확인 범위와 다음 단계

REQUIREMENTS 본문과 변경에 필요한 03/04/05/06/DESIGN의 관련 문단을 대조했다. 모든 체크리스트 항목의 모든 외부 근거를 전수 감사한 결과는 아니다. 현재 플랫폼 구현 증거가 없는 항목을 완료로 올리지 않았다.

M4에서는 필요한 내용만 남기려는 사용자 의도를 반영해 중복 요약과 상세 원본의 실제 정리를 작은 단위로 수행한다. 원본/요약/과거 근거를 먼저 구분하고 old→new 문단 대응, 소비 참조·옛 anchor 유지, 예외 역대조를 한 묶음으로 검증한다. DESIGN의 낡은 preset 문구와 integration 후보2의 OIDC 표현은 후속 대조 대상으로 남아 있다. 이번에는 이동·통합·삭제하지 않았다.

되돌림은 이 M3의 REQUIREMENTS diff와 작업 기록을 함께 검토해 복귀한다. M2의 시간 계약 링크나 기존 사용자 결정을 되돌리지 않는다. 다음 Grok 호출은 사용자 요청에 따라 4.7을 사용하며, 실제 가용성 확인 전 참여를 주장하지 않는다. 과거 4.6 실행 기록은 그대로 보존한다.

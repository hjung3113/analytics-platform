### 실행 확인의 한계

- `gh issue view 172`는 GitHub API 연결 실패로 이슈 본문을 직접 확인하지 못했다. 로컬 spec/report에 적힌 세 변형의 요구사항을 기준으로 검토했다.
- 우선 사용해야 하는 `ego-browser`는 sandbox에서 `ego_cli bootstrap` 연결에 실패했다. 지시문에 허용된 로컬 Playwright 방식으로 확인하려 했으나, 허용된 개발 서버 명령이 `listen EPERM: operation not permitted 127.0.0.1:5191`로 종료됐다. 실행 중인 리뷰용 개발 서버는 없다.
- 따라서 실제 키보드 이동, 메뉴 종료 후 포커스 복귀, 스크린리더 발화, 좁은 화면 렌더링, 다운로드·클립보드 동작은 이번 리뷰에서 재검증하지 못했다. 아래에서 스크린샷으로 관찰한 사항과 소스로 판단한 사항을 구분한다.
- 기존 보고서의 선택 3행/필터 결과 전체 38행 다운로드·복사 성공은 이전 실행 기록이며, 이번 리뷰의 실행 결과로 취급하지 않았다.

## A — 단일 내보내기 메뉴

근거: `A-1-noselection.png`, `A-2-selected.png`, `A-3-menu-open.png`; `packages/components/src/prototypeTableExport.tsx:129`.

### 잘 되는 점

- 세 안 중 툴바 공간을 가장 적게 사용한다. 기존 내보내기 위치를 유지해 기존 사용자에게 변화가 작다.
- 메뉴 안에서 `선택 3행`과 `필터 결과 전체 38행`을 구분한다. Excel/CSV/복사가 동일한 대상을 사용하는 구조도 일관된다.
- `Excel (.xlsx)`와 CSV가 별도 항목이어서 형식 선택이 명확하다.

### 발견성과 대상·형식의 혼란

- 복사를 찾으려면 먼저 “내보내기”를 열어야 한다. 파일 다운로드를 기대하는 메뉴 아래에 복사가 있어 발견성이 낮다.
- 트리거에 펼침 표시가 없고 선택 건수도 표시하지 않는다. 선택 전후 버튼 모양이 같아 대상이 전체 결과에서 선택 행으로 바뀌었다는 사실을 메뉴를 열기 전에는 알기 어렵다.
- 선택이 없을 때 메뉴 복사는 필터 결과 전체를 복사한다. B/C의 선택 전용 복사와 정책이 다르다. 사용자가 세 안을 비교할 때 UI 위치뿐 아니라 복사 기능의 범위까지 달라지는 점을 설명해야 한다.
- 선택 상태에서 필터 결과 전체를 받으려면 선택을 해제해야 한다. 현재 구조에서는 그 경로를 사용자가 추론해야 한다.

### 키보드·포커스·스크린리더

- 네이티브 Button과 Radix 메뉴를 사용한 것은 적절하다. 실제 메뉴 이동·Escape·포커스 복귀는 이번 실행에서 미확인이다.
- 대상 문구는 `DropdownMenuLabel`로 보이지만 트리거나 개별 항목의 접근 가능한 설명에 연결되지 않았다. 항목만 탐색할 때 “선택 3행”이라는 대상이 함께 전달되는지 보장하지 않는다.
- 공통 메뉴의 포커스 스타일 문제와 Ctrl/⌘+C 처리 문제는 아래 필수 수정 2번에 해당한다.

### 밀도·DESIGN.md·줄바꿈

- 추가 대상 줄이 없어 가장 경제적이다. 선택 전후에도 내보내기 버튼 위치는 유지된다.
- 기존 선택 바와 별도의 대상 줄을 중복하지 않는 점이 좋다.
- 툴바의 바깥 영역과 필터 영역은 줄바꿈을 허용한다. 폭이 좁아질 때 실제 위치와 메뉴 충돌 처리는 미확인이다.
- A의 긴 복사 항목은 짧은 Excel/CSV 항목보다 메뉴 폭을 크게 만든다. 작은 데스크톱 폭과 영어에서 확인이 필요하다.
- 메뉴 그림자는 DESIGN.md의 그림자 없는 규칙과 충돌한다. 공통 밀도·토큰 평가는 아래 공통 평가를 따른다.

### 한국어 문구

- “클립보드에 복사 (엑셀 붙여넣기용)”은 목적을 설명하지만 길다. 별도 버튼이라면 “선택 행 복사”가 더 직접적이다.
- “필터 결과 전체 38행”은 현재 페이지와 전체 결과를 구분하는 좋은 표현이다. 다른 안에도 같은 표현을 적용하는 편이 좋다.
- 메뉴·선택 바·완료 알림 사이의 `행·개·건` 단위와 `Excel` 표기를 통일해야 한다.

## B — 선택 작업 바

근거: `B-1-noselection.png`, `B-2-selected.png`; `packages/components/src/prototypeTableExport.tsx:149`, `:170`.

### 잘 되는 점

- 선택 후 복사·Excel·CSV가 선택 건수 바로 옆에 나타난다. 선택 대상과 동작의 시각적 연결이 가장 강하다.
- 선택 행에 대한 세 동작을 메뉴 없이 한 번 클릭으로 실행할 수 있다. 반복 작업에는 효율적이다.
- 기존 선택 바를 활용해 별도 대상 줄을 늘리지 않는다.

### 발견성과 대상·형식의 혼란

- 선택 전에는 툴바의 Excel 분할 버튼, 선택 후에는 아래 선택 작업 바로 위치와 형태가 바뀐다. 동작을 찾는 위치가 안정적이지 않다.
- 선택이 없을 때 전체 내보내기 대상은 실행 전에 명시되지 않는다. `Excel`이라는 버튼 이름만으로 현재 페이지인지 필터 결과 전체인지 알기 어렵다.
- CSV는 선택 전 화살표 메뉴 안에 숨고, 선택 후에는 직접 버튼이 된다. 형식 선택 방식도 상태에 따라 달라진다.
- 선택이 없을 때 복사는 보이지 않는다. 행 선택이 복사의 선행 조건이라는 안내가 필요하다.

### 키보드·포커스·스크린리더

- 분할 화살표에 접근 가능한 이름은 있다. 다만 `CSV로 내보내기`는 즉시 내보내기처럼 들리지만 실제 동작은 메뉴 열기다. “내보내기 형식 선택”처럼 동작을 설명하는 이름이 적절하다.
- 선택 건수와 작업 버튼은 시각적으로 가까우나 프로그램적으로 연결되지 않았다. 버튼이나 작업 그룹에 선택 대상 설명을 연결해야 한다.
- 선택 전후 작업 요소가 교체된다. 선택·선택 해제 과정에서 포커스가 사라진 요소에 남지 않는지 실제 키보드 확인이 필요하다.
- 공통 메뉴 포커스와 단축키 문제도 적용된다.

### 밀도·DESIGN.md·줄바꿈

- 제공된 1440px 스크린샷에서도 선택 전후 필터가 아래 줄에서 제목 오른쪽으로 이동한다. 선택 시 툴바의 Excel 분할 버튼이 제거되면서 너비가 달라져 재배치되는 구조다.
- 선택 바에는 복사·Excel·CSV·분석·선택 해제·설명이 모인다. 좁은 데스크톱 폭에서는 여러 줄이 될 가능성이 높다. 실제 줄바꿈 배치는 미확인이다.
- 추가 대상 줄이 없는 것은 장점이지만, 상태에 따른 필터 이동은 밀도 절약보다 사용자의 위치 기억을 더 크게 해친다.
- 선택 작업 버튼은 28px 높이로 주 툴바의 32px 버튼보다 작다. 데스크톱 최소 타겟과 전체 밀도 안에서는 검토할 수 있으나, 같은 동작의 시각적 크기가 상태별로 달라진다.

### 한국어 문구

- “복사”는 짧지만 “선택 행 복사”가 대상을 더 명확히 설명한다.
- `Excel`만 표시하면 파일 형식 설명이 부족하다. A/C와 같은 `Excel (.xlsx)` 표기를 권한다.
- 무선택 상태에는 “필터 결과 전체 38행”을 실행 전에 표시해야 한다.

## C — 별도 버튼과 상시 대상 표시

근거: `C-1-noselection.png`, `C-2-selected.png`, `C-3-menu-open.png`; `packages/components/src/prototypeTableExport.tsx:181`, `:203`.

### 잘 되는 점

- 복사가 항상 보여 발견하기 쉽다. 내보내기에는 펼침 표시도 있어 메뉴 동작을 예상할 수 있다.
- 대상 줄이 선택 행과 필터 결과를 명시한다. 선택 전후 버튼 위치가 유지되는 점도 좋다.
- 대상 줄에 `aria-live="polite"`가 있어 대상 변경을 알릴 수 있는 기반이 있다.
- 내보내기 메뉴는 `Excel (.xlsx)`와 CSV만 제공해 형식 선택이 간결하다.

### 발견성과 대상·형식의 혼란

- 선택이 없을 때 복사가 비활성화되는 이유가 설명되지 않는다. “복사하려면 행을 선택하세요”와 같은 설명을 보여야 한다.
- 무선택 대상의 “필터 결과 38행”에는 “전체”를 넣어 현재 페이지와 구분해야 한다.
- 선택 상태에서는 대상 줄의 `선택 3행`과 선택 바의 `3개 선택`이 반복된다. 설명은 명확하지만 정보가 중복된다.
- 열린 형식 메뉴 안에는 대상이 없다. A처럼 메뉴 안에서도 대상과 건수를 다시 확인할 수 있으면 좋다.

### 키보드·포커스·스크린리더

- 대상 변경 알림은 세 안 중 가장 좋은 기반이다. 실제 발화는 미확인이다.
- 버튼 이름만 읽으면 대상이 빠진다. 대상 줄을 버튼의 `aria-describedby`로 연결해야 한다.
- 비활성 복사 버튼은 일반 Tab 탐색에서 건너뛰므로, 비활성 이유를 버튼에만 숨기지 말고 보이는 설명으로 제공해야 한다.
- 메뉴 종료 시 트리거가 비동기 작업 때문에 비활성화된 상태일 수 있다. 포커스 복귀 동작을 실제로 확인해야 한다.
- 공통 메뉴 포커스와 단축키 문제도 적용된다.

### 밀도·DESIGN.md·줄바꿈

- 선택 후 대상 줄·선택 바·결과/신뢰 줄이 연속으로 쌓인다. 기존 선택·결과 표시와 대상 정보를 합쳐 세로 공간을 줄이는 편이 좋다.
- 복사·내보내기 묶음은 내부 줄바꿈이 없어 폭이 좁아지면 묶음 전체가 이동하는 구조다. 필터 위치를 유지하면서 어느 영역이 다음 줄로 내려갈지 정해야 한다.
- 대상 줄은 최소 높이만 지정되어 있으므로 긴 문구에서 높이가 늘어날 수 있다. 실제 1024–1439px 및 영어 렌더링은 미확인이다.
- A보다 툴바 폭과 정보 줄을 더 사용하지만, 발견성과 대상 명확성의 이점이 있다.

### 한국어 문구

- “선택 3행 (필터 결과 38행 중)”은 이해하기 쉽다.
- 버튼은 “선택 행 복사”, 무선택 대상은 “필터 결과 전체 38행”을 권한다.
- 완료 알림의 “내보내기”는 실행 중인지 완료인지 모호하다. “선택 3행을 Excel 파일로 내보냈습니다”처럼 완료된 결과를 설명하는 편이 좋다.

## 공통 평가 — 밀도, 토큰, 접근성, 기준 화면

- 세 안 모두 색·테두리·버튼 크기는 대체로 DESIGN.md 방향에 맞는다. 새 툴바는 의미 기반 토큰과 기존 Button·Radix primitive를 사용한다.
- 표의 행 최소 높이와 셀 패딩은 `32px`, `4px 12px`를 유지한다. 스크린샷의 기존 데이터 행은 약 41px로 보이지만 32px는 최소값이며, `none.png`에서도 같은 행 밀도가 관찰되므로 이 변경의 계약 위반으로 판단하지 않았다.
- 내보내기 메뉴는 공통 `DropdownMenuContent`의 `shadow-md`를 그대로 상속한다. A/C의 열린 메뉴 스크린샷에서도 그림자가 보인다. DESIGN.md의 그림자 없는 규칙과 충돌하며 B의 CSV 메뉴에도 같은 primitive가 적용된다. 프로토타입 전환 바의 허용된 그림자와는 별개다.
- 메뉴 항목은 `outline-none`을 쓰면서 포커스 배경을 기본 메뉴 배경과 같은 흰색으로, 글자색도 기본색으로 설정한다. 소스 검토상 명확한 포커스 표시가 부족하다. 실제 키보드 렌더링으로 확인해야 한다. 위치: `packages/ui/src/components/shadcn/dropdown-menu.tsx:88`.
- 새 대상 문구·버튼은 `useI18n`의 언어를 읽지만 문구를 직접 분기한다. 실제 구현에서는 문구·단위·완료 알림을 공통 번역 원본으로 관리하는 편이 일관성을 유지하기 쉽다.

## 추천

**C를 바탕으로 A의 메뉴 내부 대상 표시를 결합하는 방식을 권한다.**

- 복사와 내보내기 위치를 선택 전후 고정한다. 복사는 “선택 행 복사”로 명명하고 무선택 상태의 비활성 이유를 제공한다.
- 내보내기는 펼침 표시가 있는 메뉴로 유지하고, 메뉴 내부에 `선택 3행` 또는 `필터 결과 전체 38행`을 표시한다.
- 상시 대상 정보는 기존 선택·결과 표시와 합쳐 별도 정보 줄이 중복되지 않게 한다. 선택 대상과 필터 결과 전체 건수는 구분해서 유지한다.
- B의 빠른 직접 동작은 장점이지만, 현재 구조의 필터 재배치와 작업 위치 변경 때문에 우선안으로 권하지 않는다.
- A는 공간 효율이 가장 좋지만 복사 발견성이 부족하다. 복사 사용 빈도가 낮다는 사용자 근거가 없다면 C의 별도 복사 버튼을 유지하는 편이 낫다.

이 추천은 새로운 플랫폼 공통 툴바·선택·내보내기 계약에 반영할 결정이다. throwaway 코드를 그대로 승격하거나 메뉴 전용 로직을 공통 컴포넌트에 남기는 것을 뜻하지 않는다.

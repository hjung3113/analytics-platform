## 질문에서 제외한 추가 조사

- 공개 schema 형식(OpenAPI/JSON Schema/codegen), Base UI/Radix, ECharts/Plotly, CJK 폰트: I4의 팀/환경 제약을 받은 뒤 기술 담당이 원문·fixture·실렌더로 비교한다. 사용자가 먼저 도구명을 골라야 모든 문서 정비가 진행되는 구조를 만들지 않는다.
- parser 지원 revision·필드 사전·실제 dump, 상태 공급 서비스의 응답·권한: 근거 조사/담당자 확인 항목. 소스 열람만으로 운영 가용성을 단정하지 않는다.
- 소유 문서 충돌, 잘못된 anchor, 과거 감사 stale 여부: 문서 원문으로 해결할 조사이며 사용자 재결정이 아니다.
- Donut/Gauge: 06 §24는 업무 판단에 기여하지 않는 장식 시각화를 금지한다. 특정 화면의 분모·업무 목적을 먼저 조사하고 실제 가치 충돌만 I1 업무 담당에게 올린다. 전체 차트 취향 질문으로 확장하지 않는다.
- URL sunset: 지원 기간과 외부 북마크 현실은 I4/I5 운영 입력이 필요하다. decoder/별칭의 기술 설계는 기존 06 §6.4를 따라 담당자가 제안한다.

## 미결 항목 기록의 완료 조건

질문마다 현재 상태 Open, 원문 위치, 영향받는 작업, 필요한 자료, 제안된 담당 역할(미지정이면 명시), 다음 행동, 재검토 계기를 기록한다. 답변 부재에 임의 날짜·값을 넣지 않는다. 답변을 받으면 원문 해당 계약/질문에 결정 근거를 반영한 뒤 파생 질문 목록은 포인터로 갱신한다. 이 인터뷰 문서는 질문 준비 자료이며 영구적인 두 번째 결정 대장이 아니다.

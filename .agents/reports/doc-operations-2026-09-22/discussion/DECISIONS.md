# 다중 모델 토론 판단 기록

상태: 문서 운영 체계 권고. **표결이 아니라 현재 계약·반례·유지 비용으로 판단했다. 제품/기술 결정을 새로 Decided로 승격하지 않았다.**

## 과정과 원문

공통 [BRIEF](BRIEF.md)와 동일 source snapshot에서 독립 분석을 먼저 작성했다. root는 상대 R1이 나오기 전에 독립안을 남겼고 각 모델에는 다른 신규 초안을 읽지 말도록 지시했다. 저비용 Luna 조사에는 사실·출처 추출만 맡겼으며 단일 추천 구조를 공통 자료로 배포하지 않았다.

[R2 질문](ROUND2.md)으로 상대 전제·실패 사례를 검토하고 [R3 질문](ROUND3.md)으로 수정된 입장에 다시 응답했다. [EXECUTION](EXECUTION.md)에 실제 도구·모델/추론 metadata·세션을 기록했다. 토론은 비동기이며 모든 라운드가 동시 blind였다고 주장하지 않는다. R1의 독립성 이후에는 상대 보고서와 root 반론을 공개했다.

## 실패하면 재검토할 조건

M2/M6에서 소비자 누락, 같은 관계의 중복 갱신, 상태 토큰의 파생 원본화, 잘못된 원본 탐색, 감당 못할 metadata 비용을 기록한다. 두 구조 중 하나가 언제나 우월하다고 가정하지 않는다. 소비자 목록은 완전성 보장이 아니므로 task의 rg/원문 영향 점검을 제거하지 않는다. 파일 hash 변경도 전면 재검토 명령이 아니라 영향을 찾는 신호다.

팀 evidence 위치와 담당 지정(I7), 첫 업무(I1), Scope/시간/운영 입력(I2–I6)은 아직 사용자 답변이 없다. 모델 합의가 이를 대신하지 않는다. 첫 네 파일 M1의 문서 안내 정정은 이 답변 없이 구체화할 수 있지만 실제 구현 범위/수치 승인으로 읽지 않는다.

## 최종 재응답을 반영한 마감 판정

GLM R3는 원본 인접 시범과 감사용 분리 샘플을 조건부 수용했다. 따라서 초안 간 위치 선호를 아직 그대로 대립한다고 보고하지 않는다. **최종 위치의 운영 적합성은 여전히 미검증**이며 I7/M6에서 확인한다. GLM의 ‘3건 중 2회 누락’은 측정 기준 후보이지 승인된 정책 숫자가 아니다. 초기에는 누락 원인과 실제 갱신 비용을 기록하고 팀이 기준을 정한다.

Grok R3는 샘플 삭제/대체를 허용 조건으로 제안했다. 주 에이전트는 역사·반례 보존을 위해 **현재 계약으로 운영하지 않고 snapshot 증거로 보존**하는 방식을 선택했다. R3 참가자들은 명료화 전 도입문의 ‘유지하지 않는다’를 인용했다. §6.3 본문과 기존 의도는 같지만 삭제로 오해할 수 있어 최종 도입문은 ‘동기화하지 않는 역사 증거’로 명료화했다. 토론 원문을 소급 수정하지 않는다.

GLM R3의 ‘작업 중 INDEX 등 원본이 움직였다’는 주장은 **근거 불충분으로 기각**했다. 최종 source-snapshot 대조에서 471개 내용 해시 변경이 없고 Git 원본 diff도 없다. 수정시각 관찰은 내용 변경의 증거가 아니다. 다음 세션 M0 재확인은 여전히 필요하지만 이번에 원본 변경이 있었다고 기록하지 않는다.

GLM의 07 §7 시나리오 참조 확인은 M1 좁은 검증에 포함한다. 01/02에 남는 Phase 표현은 부분 이행 범위로 보고하되 첫 정정 작업을 막지 않는다. 이것을 새로운 제품 Phase로 승격하지 않는다. DESIGN 숫자나 라이브러리 문구의 충돌에도 자동 강등/새 결정 규칙을 만들지 않고 현재 승인 근거를 확인한다.

# 주 에이전트 R2 — 상대 독립안 반박

세 R1을 읽었다. 원본 06 §6.3/§6.4/§19, 05 R/H, 07 §6/§8, DESIGN Navigation/Open, REQUIREMENTS 본문과 대조했다. 원문 재확인 없이 새 제품 결정을 채택하지 않는다.

## GLM에 대한 반박

- 05 3열 추가는 빠른 탐색에는 유리하다. 그러나 원본 상태+05 요약+07 표를 인정한 채 05에 evidence까지 쌓으면 문서 상태와 release 증거가 같은 행에서 독립적으로 늙는다. 예: 시간 메커니즘은 Decided지만 TZ 공급자만 미구현이고 decoder만 검증된 상태를 '증거 있음' 한 칸으로 표현하기 어렵다. **수정 제안:** 05는 source와 질문/결정 이력 경로, evidence는 실제 작업 기록 링크. 전체 계약이 한 번 검증됐다고 새 revision을 자동 Verified로 유지하지 않는다.
- 06§6.3-time처럼 좌표를 ID로 쓰고 섹션 재번호를 금지하면 참조는 유지되지만 합리적 문서 편집을 막는다. **대안:** 초기엔 현행 section path, 최초 변경할 고위험 계약만 semantic anchor 추가. 이전 heading anchor는 alias. 모든 문장 ID는 불필요.
- '행 단위 마지막 갱신 승리'는 반대한다. A가 집합 equipmentIds 중복 제거를 구현하고 B가 단일 scopeId 중복 거부를 고칠 때 잘못된 공통 요약 '중복 키 모두 오류'가 마지막 기록이면 06 §6.1을 바꿔버린다. 같은 값 단일 중복과 집합 중복 제거를 별도로 보존해야 한다. 충돌은 승인된 source revision과 조건/예외로 해결하고 불명확하면 변경 보류.
- source 없이 재정의 탐지나 소유권 위반 판정을 구조 검사로 반려한다는 서술은 과하다. grep은 후보 탐지만 한다. semantic review가 실제 판정자다.
- 과거 리뷰 갱신 또는 신규 기록 중에는 신규 정정/후속 기록이 기본이어야 한다. 과거 당시 근거를 지우면 감사가 반복된다.

## Grok에 대한 반박

- INDEX 행렬은 현황 길찾기에 좋지만 상태+delivery를 포함한 대형 표는 제4 원본이 된다. source pointer 중심으로 줄이고 계약의 상태는 원문에서 읽는다. sample은 검증 뒤 유지하지 않는다는 수명도 필요하다.
- '둘 다 원본이면 더 구체적인 금지/예외 임시 우선'은 반대한다. R 없음 때 전체 분석을 금지하는 연구 문구가 더 구체적이어도 06/05의 허용 예외보다 우선할 수 없다. 권위를 판단할 수 없으면 현행 승인 baseline 유지·새 의미 변경만 보류.
- HANDOFF의 과거 문장을 지워 운영 규칙을 바로잡기보다 새 운영 안내에서 현재 source를 지정한다. 기록 수정 필요가 생겨도 당시 문장과 현재 안내를 구분한다.
- DESIGN을 '페인트만'으로 줄이면 focus/disabled/busy·키보드/렌더 상호작용 책임까지 잃는다. 데이터 의미/전역 행동은 06, render interaction은 DESIGN 유지.
- 메뉴 등록이 06 변경을 요구하면 무조건 Kernel 실패라는 표현은 과하다. 새 소비 요구가 진짜 계약 공백을 드러낼 수 있으며, 이 경우 명시적 플랫폼 변경 제안이 맞다. 단순 새 메뉴마다 Sidebar 수정하는 것은 금지.

## 자기 수정

- R1의 별도 운영 표도 완전한 dependency graph처럼 보일 수 있다. **권고 수정:** 최초 적용에는 INDEX의 책임/작업 경로 + 소수 원본의 직접 소비자 포인터 + 작업별 영향 판정만. 별도 영구 manifest는 만들지 않는다.
- 설계 상태의 단일 원본은 개별 계약 문단, 05는 상태 추적 index/이력으로 수렴. 현행 05의 R/H 상세는 이동 전 현 원본으로 인정한다. 이관은 운영 체계 설치의 선결 조건이 아니다.
- '사람 승인'은 모든 engineering 문서 정정 때 다시 사용자 허락을 받으라는 뜻이 아니다. 세션/조직의 명시적 위임을 따른다. 이번 과업은 제안까지만이므로 어떤 제품 선택도 새로 Decided로 하지 않는다.
- 파일 전체 해시 drift는 재검토 신호; 영향 섹션이 그대로라면 관련 소비 검토를 전면 무효화하지 않는다.

## 남은 이견

05 중심 관리가 실제 팀에 더 쉬울 수 있다. I7 운영 흐름을 확인하기 전 INDEX/05/원본 중 관계 표의 영구 위치를 과도하게 확정하지 않는다. 다만 동일 관계를 세 곳에 복제하지 않는 조건은 권고한다. 검증에서는 현재 source를 사용한 탐색·예외 대조·동시 변경 시뮬레이션만 주장한다.

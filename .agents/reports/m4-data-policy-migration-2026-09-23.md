# M4 — 데이터 운영 정책 원본 이관

기준 `c09c101`(M3 커밋). 주 에이전트 단독 수행. 다중 모델 검토·제품 구현·런타임 검증은 수행하지 않았다. M4 적용 단위는 기존 이행 계획의 05 세 정책→01 이관이다. 파일 삭제나 전체 문서 축약은 수행하지 않았다. DESIGN recipe 분할은 필요성이 확인되지 않아 보류했다.

## 소비 경로와 검증

- INDEX → 06 CTX-TIME → 01 R/H로 현재 원본을 찾는다. defaultRangeTo는 06, R/H는 01이다.
- 06의 R 부재 예외 본문은 참조만 바꿨다. 독립적으로 유효한 defaultRangeTo 물질화는 계속 가능하다.
- 02 재집계 소비 기능, 03 시간 요약, REQUIREMENTS, 05 결정 표의 경로를 함께 갱신했다. 체크리스트 완료 상태는 변경하지 않았다.
- 변경한 본문 7개 파일의 로컬 inline 링크/fragment 87개 오류 없음. 기존 세 제목 유지 검사와 git diff --check 통과. 구조 검사만으로 의미 정합성을 보장한다고 해석하지 않는다.
- 폴링·DB·R/H 예외는 위 문단 역대조로 확인했다. parser upstream·FeedbackOps 내부 및 gitlink는 수정하지 않았다.

## 남은 범위와 되돌림

01의 기존 멀티테넌시 Open/site-plant 추천은 현행 Scope 원본과 후속 정렬이 필요하다. DESIGN preset 안내와 integration 후보2 OIDC 문구도 기존 잔여 과제다. 이 이관에 섞어 제품 정책을 정하지 않았다. 모든 문서의 중복/내용 충실도를 전수 재검토한 것은 아니다.

후속 정리는 위 잔여 요약을 원본과 대조하는 작은 묶음으로 진행할 수 있다. 과거 근거·예외를 지우거나 후보를 승인으로 올리지 않는다. 되돌릴 때는 01 본문·05 원본 복구·02/03/06/INDEX/REQUIREMENTS 참조를 같은 묶음으로 복귀한다. 한 파일만 되돌리면 원본 안내가 어긋난다. M3 이전 변경과 사용자 변경은 보존한다.

## 후속 정렬 — 2026-09-23

사용자의 계속 진행 요청으로 기존 잔여 3곳을 정정했다. 01의 Scope 요약은 05 결정 상태·06 §6.2·ADR-0001을 직접 확인해 초기 1Site/Line·2단계·v1 단일 선택으로 맞췄다. 구체 행 스코핑/RLS를 채택하지 않았다. DESIGN의 preset anchoring Open 문구는 같은 파일 Date preset meaning 및 06의 확정 rolling 메커니즘으로 연결했고 초기 자동 Δ·교대일/영업일 Open은 유지했다. integration 후보2의 OIDC 전제는 05의 프로토콜 Open에 맞춰 인증 주체/caller 매핑으로 정정했다. 매 요청 Scope 재검증·무단 ID 명시 거부 문장은 보존했다. 후보를 채택하거나 외부 구현을 재검증한 것은 아니다.

위 ‘남은 범위’의 세 정정 후보는 이 후속 작업으로 처리됐다. 전체 문서 전수 정리 완료를 뜻하지 않는다. 사용자 모델 선호는 HANDOFF에 GPT-6(Luna/Sol 포함), Grok 4.7로 기록했다. 이번 작업에 별도 모델 호출은 없었다.

후속 검증: 변경 문서의 로컬 링크 155개를 검사했다. 일반 anchor 검사에서 기존 GitHub 행 범위 링크 4개가 탐지되어 별도로 대상 파일과 행 범위를 확인했다(실제 렌더러 이동은 미검증). 나머지 경로/제목 anchor 오류 없음. 이관한 세 정책 본문 동일성과 diff 공백 검사도 다시 통과했다.

# 분석 플랫폼 구축 요구사항 및 체크리스트

작성 모델/관점: Codex GPT-6 Astra — Platform Kernel 우선, 계약 정합성·데이터 신뢰·메뉴 확장성 중심의 구현 전 요구사항 검토.

작성일: 2026-09-20. 지정된 `docs/INDEX.md`, `docs/00`~`07`, `DESIGN.md` 전체와 `analysis-platform-wireframe/SKILL.md`를 읽고 작성했다. 이 문서는 구현·POC·라이브러리 채택을 승인하거나 완료를 주장하지 않는다. 외부 웹·파서 저장소·실제 데이터는 이번에 검증하지 않았으며, 파서 관련 내용은 이 저장소에 기록된 계약 요구를 인용한다.

## 읽는 법과 출처

- **Decided**는 기존 플랫폼 책임·행동 규칙이며 구현 완료가 아니다. **Candidate**는 기존 후보, **Open**은 기존 미결, **Deferred**는 기존 유보 범위다. `docs/02`처럼 상태 태그가 없는 도메인 요구는 **기존 문서 요구**로 표시해 임의로 확정하지 않았다.
- **신규 제안**은 이 보고서의 추가 요구다. 기존 기능을 구체화한 경우 기존 부분과 추가 부분을 함께 구분한다.
- **Must**는 플랫폼 성립·정합성·권한 또는 해당 기능 도입 시의 필수 조건, **Should**는 주요 운영·개발 효율, **Nice**는 수요 확인 후 확장 힌트다. 우선순위는 작성자의 판단이며 일정·Phase·전체 메뉴 구현 의무가 아니다.
- 모든 체크박스는 미구현 체크리스트다. 메뉴는 커널을 검증하는 소비자이며, 전체 카탈로그를 한 번에 구축할 필요가 없다. 초기 검증은 대표 분석 흐름과 독립된 관리 메뉴로 시작하고, 반복이 확인된 책임만 공통화하는 편이 적절하다.

## 1. 디자인

- [ ] D01 의미 기반 토큰을 실제 스타일 산출물에 연결 — 화면별 임의 색·간격이 늘지 않도록 primitive/semantic/component 관계와 CSS·차트 소비 경로를 일관되게 만든다. — **Must**, 공통 UI의 기반 — **출처: 기존 Candidate**, 06 §23; DESIGN YAML·Open Decisions의 Component library binding.
- [ ] D02 기존 시각 기준 적용 — 밝은 캔버스·어두운 내비게이션, 4px 간격 체계, 4/6/8px radius, 제한된 강조색을 기본으로 사용한다. 수치는 제품 기능 결정과 분리하고 화면별 카드 과잉을 피한다. — **Should**, 시각 일관성 — **출처: 기존 디자인 기준/Candidate**, DESIGN Colors·Typography·Layout·Shapes; 06 §23~24.
- [ ] D03 다크모드 별도 설계 — 요청이 확인되면 표·차트·상태·포커스·어두운 사이드바까지 대체 토큰과 선호 설정을 설계한다. 현재는 라이트 전용이며 색 반전으로 완료 처리할 수 없다. — **Nice**, 교대·장시간 사용 수요 확인 필요 — **출처: 기존 Open**, DESIGN Open Decisions / Dark mode; 설정 저장 방식은 **신규 제안**.
- [ ] D04 차트 라이브러리 테마 바인딩 — 제목·축·범례·툴팁·선택·시리즈·상태 색을 디자인 토큰에서 공급한다. ECharts는 후보이며 실제 테마와 렌더 검증은 아직 없다. — **Must**, 차트 도입 시 UI 의미 일치 — **출처: 기존 Candidate/Open**, 04 차트/도식 자유도; 06 §16; DESIGN Open Decisions / Chart library token mapping.
- [ ] D05 아이콘 체계 확정 — 한 outline 계열, 크기·stroke·chip 사용처·접근 가능한 이름을 통일한다. Lucide 등 특정 라이브러리는 후보일 뿐이다. — **Should**, 메뉴 증가 시 식별 일관성 — **출처: 기존 Candidate/Open**, DESIGN Reference component bindings / Icons/navigation·Open Decisions / Icon set.
- [ ] D06 UI primitive 조합 확정 — shadcn/ui와 Base UI/Radix 후보의 합성·포커스·키보드 동작을 비교하고 채택 조합을 명시한다. 토큰 이름을 라이브러리 props로 오인하지 않는다. — **Must**, 공통 컨트롤 도입 전 기반 결정 — **출처: 기존 Candidate**, 04 프론트엔드 기술 스택; DESIGN Component library binding; 06 §13의 표현은 04의 후보 상태와 함께 해석.
- [ ] D07 전체 인터랙션 상태 구현 — hover/pressed/selected/focus/disabled/read-only/busy를 실제 동작에 연결하고 중복 제출 차단과 비활성 이유를 제공한다. 색 토큰만 있는 것을 상태 구현으로 세지 않는다. — **Must**, 안전한 조작 — **출처: 기존 디자인 요구**, DESIGN Shared interaction and data states.
- [ ] D08 접근성 검증 — 키보드 탐색, Dialog/Drawer 포커스 제어·복귀, 이름 있는 아이콘, 색 외 텍스트·형태, 동일 데이터 표와 차트 요약을 확인한다. 대비는 렌더에서 확인해야 하며 토큰만으로 통과를 주장하지 않는다. — **Must**, 핵심 조작 가능성 — **출처: 기존 Decided/디자인 요구**, 04 제품 제약; 06 §26; DESIGN Shared interaction and data states.
- [ ] D09 한글·긴 ID·수치 표시 검증 — CJK fallback, 긴 설비명, 단위·소수점·숫자 우측 정렬, 확대 시 줄바꿈을 실제 표본으로 확인한다. 고정 높이로 필수 내용을 잘라내지 않는다. — **Should**, 현업 정보 가독성 — **출처: 기존 요구/검증 공백**, DESIGN Typography·Layout; 04 확인 한계; 한글 표본 묶음은 **신규 제안**.
- [ ] D10 밀도·반응형 기준 적용 — Desktop-first를 유지하며 좁은 폭에서는 내비게이션 접기·보조 Drawer·표 내부 스크롤을 사용한다. 25px 참조 행은 기본 강제값이 아니며 포인터·포커스 요구에 맞춰 커진다. — **Should**, 고밀도와 조작성을 함께 보장 — **출처: 기존 Decided 방향/Candidate 배치**, 06 §25; DESIGN Layout.
- [ ] D11 공통 상세 표면 제공 — 간단 확인은 Modal, 맥락 유지 상세는 Drawer, 복잡한 편집·딥링크 상세는 Full Page로 구분한다. 큰 폼을 모달에 몰아넣지 않는다. — **Should**, 메뉴마다 상이한 탐색 부담 감소 — **출처: 기존 계약 요구**, 06 §20.
- [ ] D12 Data Trust·오류 시각 표현 통일 — Updated/Data through/계산 기준/coverage/지표 버전/Unknown을 공통 언어로 보여준다. 초록색이나 Live 라벨이 완전성 증명이 되지 않도록 한다. — **Must**, 숫자 오해 방지 — **출처: 기존 Decided**, 06 §19 및 §18; DESIGN Shared interaction and data states.
- [ ] D13 기간 선택 UI를 하나의 전역 컨트롤로 연결 — 초안과 Apply를 분리하고 취소 시 현재 구간을 보존한다. 7D/30D/90D의 달력일·rolling 의미는 미결이므로 문구만으로 계산하지 않는다. — **Must**, 기간 재현성 — **출처: 기존 Decided + Open**, 06 §6.3·§11; DESIGN Reference component bindings / Page header/period·Date preset meaning.
- [ ] D14 모션과 실시간 표현 제한 — 기본 Live dot은 정적이고 실제 freshness 근거가 있을 때만 선택적 pulse를 사용한다. reduced-motion과 freshness 상실 시 중단을 반영한다. — **Should**, 신뢰성과 피로도 — **출처: 기존 Candidate/디자인 요구**, DESIGN Shared interaction and data states·P2 breadcrumb / pulse.
- [ ] D15 디자인 상태 갤러리와 시각 회귀 기준 — 공통 컴포넌트의 정상·빈값·권한없음·긴 한글·부분실패 화면을 모아 비교한다. 특정 도구 도입보다 메뉴 간 회귀를 발견할 수 있는 검토 자산이 필요하다. — **Should**, 반복 UI 변경의 검증 비용 감소 — **출처: 신규 제안**, 근거 06 §13·§19·§28.

## 2. 메뉴 카탈로그

다음은 capability 후보 목록이다. 새 최상위 그룹을 추가하지 않고 06 §9의 7그룹 안에서 배치를 검토하며, 하위 메뉴 이름·도입 시점은 별도 결정한다.

- [ ] M01 운영 개요 — 접근 가능한 메뉴·즐겨찾기·최근방문으로 업무 시작점을 제공한다. 상태 근거 서비스 없는 수집 현황 위젯은 포함하지 않는다. — **Should**, 빠른 재진입 — **출처: 기존 Candidate/Deferred 경계**, 07 §2; 06 §9·§12.1.
- [ ] M02 설비 마스터·유효구간 상세 — 파서에 실재하는 equipment_id를 발견하고 business 속성을 부여하며 사용중지/복원과 이력을 보존한다. 물리 삭제·속성 유효기간 종료·사용중지를 같은 동작으로 취급하지 않는다. — **Should**, 첫 관리 소비자 후보 — **출처: 기존 문서 요구**, 02 도메인 capability catalog / 설비관리; 01 마스터 데이터 수정 권한의 원천.
- [ ] M03 기준정보관리 — 공정·레시피·자재 등의 목록·상세·변경 이력을 제공하되 외부 소유 필드와 직접관리 필드를 구분한다. 실제 대상 엔티티와 편집 범위는 확정이 필요하다. — **Should**, 분석 기준의 일관성 — **출처: 기존 문서 요구/Open 세부**, 02 기준정보관리; 04 설비·기준정보 CRUD.
- [ ] M04 물리 점유율·비Process 체류 분석 — 실제 계산 가능한 지표부터 제공하고 기간·설비·버전·coverage와 원천 상세 이동을 붙인다. 파서만으로 SEMI E10 가동률이나 수율을 계산할 수 있다고 표시하지 않는다. — **Should**, 대표 분석 가치 검증 — **출처: 기존 문서 요구**, 00 1차 리뷰; 02 생산성 분석.
- [ ] M05 사이클타임 P50/P95·느린 실행·Job 처리량 — 집계에서 실행 목록과 occurrence 상세로 내려가 숫자의 원인을 검증하게 한다. 구현한다면 평균 P95 같은 잘못된 재집계를 금지한다. — **Should**, end-to-end 검증 후보 — **출처: 기존 요구/Candidate**, 02 생산성 분석; 05 대표 분석 시나리오; 01 집계 가능성 계약.
- [ ] M06 Wafer Journey·공정 타임라인 — 설비·Lot 맥락에서 이송 분포와 실행 근거를 연결한다. 업무 ID만으로 occurrence를 조인하지 않는다. — **Should**, 분석 드릴다운 — **출처: 기존 문서 요구**, 02 생산성 분석; 07 §2; 06 §6.1.
- [ ] M07 지표 카탈로그·정의·버전·사용처 — grain·단위·분자/분모·원천·coverage·발행 이력을 표시한다. 초안/발행/폐기 상태와 별도 승인 워크플로를 혼동하지 않는다. — **Must**, 지표를 제공할 때 의미·버전 고정 — **출처: 기존 문서 요구**, 02 지표관리; 04 지표 카탈로그; 06 §6.1.
- [ ] M08 공지 목록·상세·게시 관리 — 게시기간·대상 메뉴·Scope에 따라 배너/목록을 노출한다. 배너 위치는 Open이며 범용 알림 엔진을 선행 조건으로 만들지 않는다. — **Should**, 변경·장애 안내 — **출처: 기존 문서 요구/Open**, 02 공지; 07 §4·§8.
- [ ] M09 VOC 접수·담당·상태·댓글 — 자체 도메인 모델로 접수→처리중→완료를 관리하고 관련 분석 링크를 보존한다. VOC 열람과 원본 설비·Lot 열람은 각각 권한 검증한다. — **Should**, 분석에서 개선 요청까지 연결 — **출처: 기존 문서 요구/Decided 권한**, 02 VOC; 04 공지·VOC; 06 §17.

## 3. 메뉴 간 연결

- [ ] L01 목적지와 Context 분리 — occurrence는 `(equipmentId, entityType, anchor)`, 설비 마스터는 equipment_id, VOC는 vocId처럼 각 식별 계약으로 연다. 목적지 객체에 분석 Context를 억지로 식별키로 사용하지 않는다. — **Must**, 잘못된 객체 이동 방지 — **출처: Decided**, 06 §6.1.
- [ ] L02 공통 Context Link 경로 — destination·권한·보존할 Context·적용할 Context를 helper가 처리하고 사이드바도 같은 규칙을 사용한다. 메뉴끼리 URL 문자열을 직접 조립하지 않는다. — **Must**, 새 메뉴 확장성 — **출처: Decided/기존 계약**, 06 §6.4·§22.
- [ ] L03 미지원 Context 왕복 보존 — 분석의 Lot을 설비관리에서 미적용으로 표시하고 다시 지원 메뉴로 가면 재검증 후 적용한다. 미지원이라는 이유로 URL에서 삭제하거나 결과 필터로 몰래 적용하지 않는다. — **Must**, 문맥 손실 방지 — **출처: Decided**, 06 §6·§6.4.
- [ ] L04 전역·페이지·차트·주석 상태 분리 — 메뉴 이동은 등록된 전역 Context만 자동 전달하고 page-owned 키·미등록 키는 자동 복사하지 않는다. 줌·brush·series는 뒤로가기 보장 대상과 다르다. — **Must**, 공유 링크의 의미 안정 — **출처: Decided**, 06 §6·§6.4.
- [ ] L05 URL과 세션 우선순위 — URL 누락값을 과거 세션으로 채우지 않고 제안값을 명시 적용할 때 URL에 기록한다. 필수 Scope가 없으면 선택을 요구한다. — **Must**, 동일 링크의 조건 재현 — **출처: Decided**, 06 §6.2·§6.4.
- [ ] L06 URL 스키마·카디널리티·공집합 — 반복 집합 키 정규화, 단일값 중복 거부, 공집합 표식과 ID 동시 입력 거부를 공통 검증한다. 공집합도 권한/기간 오류를 성공으로 덮지 못한다. — **Must**, 클라이언트·서버 해석 일치 — **출처: Decided**, 06 §6.1; 표식 필드명은 Candidate.
- [ ] L07 지표 ID·버전 쌍 보존 — 전역 metricId/metricVersion은 함께 적용·제거하고 목적지의 다른 지표로 덮어쓰지 않는다. 초기화 선언 경로에서만 서버가 게시 버전을 확인해 URL을 완성한다. — **Must**, 지표 오해 방지 — **출처: Decided**, 06 §6.1.
- [ ] L08 URL 버전 수명주기 — v 생략은 1, 미지원 버전은 전체 거부하며 과거 링크를 자동 최신 의미로 바꾸지 않는다. sunset 일정은 별도 정책으로 정한다. — **Must**, 북마크 호환성 — **출처: Decided/Open 일정**, 06 §6.4.
- [ ] L09 wall-clock 구간 유지 — naive `YYYY-MM-DDTHH:mm:ss`와 `[from,to)`를 사용하고 offset·소수초 URL·한쪽 경계만 있는 입력을 거부한다. occurrence anchor와 원천 정밀도는 줄이지 않는다. — **Must**, 조회 경계 정합성 — **출처: Decided**, 06 §6.1·§6.3~6.4.
- [ ] L10 기본 기간 물질화 — 서버 defaultRangeTo와 명시된 길이로 절대 구간을 만들며 브라우저 now를 쓰지 않는다. R이 있으면 defaultRangeTo≤R을 확인하고, R이 없더라도 독립적으로 유효한 기본 구간은 허용한다. — **Must**, 기본 링크의 정확성 — **출처: Decided/Open 길이**, 06 §6.3; 05 지연 완료.
- [ ] L11 다중 설비 시간역 가드 — 요청 전체 구간·모든 설비의 동일 timeDomainId를 서버 assertion으로 증명할 때만 축을 병합한다. 증거 부족과 불일치는 오류로 처리하고 분리 조회는 허용한다. — **Must**, 잘못된 시간 비교 방지 — **출처: Decided**, 06 §6.3.
- [ ] L12 명시적인 선택 구간 드릴다운 — 차트 선택은 로컬로 유지하다 Analyze selected range에서 승격한다. 미정렬 경계는 시작 내림·끝 올림 미리보기와 확인을 거쳐 URL에 적용한다. — **Must**, 조용한 필터 변경 방지 — **출처: Decided**, 06 §6.1·§11.
- [ ] L13 비동기 응답과 Context 전환 — 기간·설비 변경 시 이전 요청 결과를 새 조건 결과로 채택하지 않고 Scope/권한 변경 시 기존 결과를 숨긴다. 동일 Context 재조회에만 Refreshing과 기존 값을 함께 허용한다. — **Must**, 데이터 혼동·노출 방지 — **출처: Decided**, 06 §11·§19.

- [ ] L15 연결 행렬을 메뉴 계약에 첨부 — 출발/목적지별 적용·보존·미지원·page-owned 상태와 필수 권한을 표로 관리한다. 메뉴가 늘어도 링크 예외를 화면 코드에 숨기지 않게 한다. — **Should**, 연결 누락 검토 — **출처: 신규 문서화 제안**, 기존 06 §5·§6·§22 구체화.

## 6. 기타 제안

- [ ] X01 소비 계층과 DB 권한 분리 — API는 호환 view/mart를 읽고 파서 원본에는 직접 접근하지 않으며 플랫폼 전용 스키마·마이그레이션을 운영한다. 기본 소스는 같은 인스턴스의 파서 read-only 역할이다. — **Must**, 원천 보호·책임 분리 — **출처: 기존 Decided/문서 요구**, 05 파서 DB 접근; 01 전체 아키텍처; 03 기술 스택.
- [ ] X02 지연완료·정정 재집계 정책 — 필수 H 설정과 원천 진행 경계 R로 `[R-H,R)` 자동 창을 운용하고 창 밖 후보를 보존한다. R 부재는 자동 재집계만 보류하며 마스터 소급·재분류·지표 변경 트리거는 별도다. — **Must**, 과거 데이터 정정의 유실 방지 — **출처: Decided**, 05 지연 완료; 01 mart 재계산 트리거.
- [ ] X03 계산 세대 일치와 숫자 근거 — 여러 mart를 사용하는 차트·표·CSV가 서로 다른 계산 세대를 섞지 않게 기준을 연결한다. 분자/분모 재집계와 화면 다운샘플링을 구분한다. — **Must**, 수치 정합성 — **출처: 기존 문서 요구**, 01 mart 재계산·집계 가능성; 05 대표 분석 시나리오.
- [ ] X04 마스터 소유권·시간역 근거 운영 — 필드별 외부/플랫폼 소유자와 timeDomain assertion의 공급자·정정 절차를 정한다. 현재 스냅샷으로 과거 구간을 증명하지 않는다. — **Must**, import 충돌·시간 병합 오류 방지 — **출처: 기존 요구/Decided**, 01 마스터 데이터 수정 권한; 06 §6.3; 구체 공급 조직은 Open.
- [ ] X05 성능 예산과 조회 제한 — 동시 사용자·최대 기간·반환 행/점·timeout·대량 작업 한도를 실측 목표로 정한다. 숫자는 현재 Open이며 원본 전체를 브라우저로 보내는 설계는 피한다. — **Must**, 운영 가능한 첫 릴리스 — **출처: 기존 요구/Open + 신규 예산 명문화 제안**, 01 확장성; 05 Open Questions; 06 §27.
- [ ] X06 복구·백업·마이그레이션 검증 — 메타데이터와 재생성 가능한 mart를 구분하고 백업 복원·버전 전환·실패 복구 절차를 검증한다. 복구 목표시간·허용 데이터 손실은 운영자가 정해야 한다. — **Must**, 운영 도입 전 복구 가능성 — **출처: 신규 제안**, 기반 01 소유 계층; 03 플랫폼 DB 마이그레이션.

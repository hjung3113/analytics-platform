# M2 실행 기록 — 시간 계약의 변경 영향 연결 시범

기준 revision: `ce4687f`(M1 커밋). 사용자 요청에 따라 M1을 먼저 커밋하고 M2를 실행했다. 시작 작업 트리는 깨끗했다. 주 에이전트가 직접 원문 대조·수정·검증했으며 M2에서 별도 워커나 다중 모델 검토를 실행하지 않았다. 이 기록은 해당 작업의 증거이며 현행 계약 원본이나 상시 상태 대장이 아니다.

## 전체 이행 흐름과 이번 범위

목적은 사람과 에이전트가 원본·결정 상태·변경 영향을 찾고 구현 증거와 구별하도록 만드는 것이다. 폴더 구조는 현재 유지한다.

| 단계 | 실제로 하는 일 | 현재 상태 |
| --- | --- | --- |
| M0 | 현재 Git·지침·원문을 재확인 | 매 작업 시작 시 수행 |
| M1 | 진입점과 낡은 결정 상태 정정 | `ce4687f` 커밋 완료 |
| M2 | 한 계약의 고정 참조·원본/소비 관계·변경 검토 기록 시범 | 이번 작업 완료, 미커밋 |
| M3 | 파생 체크리스트의 계약/후보/미결과 구현 증거 구분 | 미착수. REQUIREMENTS의 H 요약 정정부터 작은 단위로 가능 |
| M4 | 실제 필요가 확인된 상세 원본만 이관·분할 | 미착수. 전체 폴더 재배치가 필수는 아님 |
| M5 | 실제 구현 작업에 계약 revision·코드·테스트 증거 연결 | 미착수. 존재하지 않는 코드/테스트 경로를 만들지 않음 |
| M6 | 실제 변경 3건에서 누락·탐색 비용을 평가 | 미착수. 메타데이터/검색 도구 확대는 효과를 본 뒤 판단 |

M1/M2 완료는 문서 운영의 작은 적용 완료다. 모든 제품 결정 완료나 구현 착수 승인이 아니다. M3–M6 전체를 끝내야만 어떤 제품 작업도 할 수 있다는 뜻도 아니다. 제품 작업은 해당 범위의 결정·입출력·실패 조건과 별도 실행 지시에 따라 판단한다.

이번 원본 수정: [INDEX](../../docs/INDEX.md) 작업 진입 경로 1행, [06 §6.3](../../docs/06_platform_ui_contract.md#ctx-time) 고정 anchor·직접 의존/소비자 안내, [05 R/H](../../docs/05_roadmap_and_open_questions.md#late-arrival-policy) 현 원본 표시와 연결 안내. 별도 계약 사본/frontmatter/manifest/자동 생성기는 추가하지 않았다. 수동 작성 Markdown과 Git diff/검색으로 시범 적용했다. 계약 본문·숫자·상태·예외는 그대로다.

## 원본과 참조 방식

- `CTX-TIME` / `#ctx-time`: 06 §6.3 전역 Context·URL 시간 계약. 문서 참조 ID이며 공개 API·URL 버전이 아니다.
- `#late-arrival-policy`: 05의 R/H·지연완료 정책 상세. 이번에도 01로 이관하지 않았다.
- 과거 샘플이 가리키던 06 제목 anchor를 별칭으로 보존했다. 샘플 자체는 수정하지 않았다. 현행 제목 anchor도 유지하며, 향후 제목 변경 때 명시 anchor를 보존한다.
- 원문 안내에는 상세 결정 상태를 새 표로 복제하지 않고 해당 문단을 읽도록 했다. 알려진 직접 의존성만 적고 추가 검색을 요구한다. 검색·발췌 시 `source path + #ctx-time + 작업 기준 revision`에서 전제와 예외까지 돌아온다.
- 이번 두 파일의 연결을 전역 의존 그래프나 자동 동기화로 주장하지 않는다. source→consumer 포인터는 수동이고 의미 검토는 사람이 수행한다.

## 변경 시 운영 순서의 실제 적용

1. 시작: `ce4687f`, 쓰기 범위 INDEX/05/06와 작업 기록/HANDOFF를 한정했다. 제품 변경 대신 탐색 안내 추가로 분류했다.
2. 원본 확인: 06 시간 메커니즘, 05 R/H, 소비자 관련 절을 읽고 위 표에 수정/대조/후속 정정을 각각 남겼다. 파일 수정시각이나 다수결로 우선순위를 정하지 않았다.
3. 반영: 원본에 안내만 추가하고 INDEX 진입 경로를 연결했다. 코드 생성 산출물이 없으므로 재생성 작업도 없다.
4. 검증: 구조와 본문 보존을 기계적으로 검사하고 아래 반례를 수동 대조했다. 링크 검사는 의미 검증을 대체하지 않는다.
5. 인계: 기존 불일치는 숨기지 않고 후속 위치·이유를 남겼다. 향후 같은 계약을 병렬 수정하면 각 담당이 원본 revision과 쓰기 범위를 공유하고 원본 변경 후 영향받는 검토만 다시 수행한다. 단순히 더 엄격한 규칙이나 마지막 수정으로 충돌을 해결하지 않는다.

가상 변경 “R이 없으면 기본기간도 막는다”를 이 경로에 넣어 검토했다. 06의 R 부재 예외 → 05의 자동 재집계만 보류 → 07 초기 입력·DESIGN 기간 control 순으로 영향을 찾았다. 현행 계약 변경이므로 채택하지 않았다. 원본 소유자가 명시적인 변경 근거를 검토하기 전에는 기존 예외가 기준이다.

## 경계 반례 대조 — 실행 테스트 아님

| 사례 | 원문에서 확인한 결과 |

## 검증 증거와 한계

- `git diff --check` 통과. INDEX/05/06의 모든 기존 Markdown 제목 불변.
- 추가된 anchor 3개(06 안정 참조+과거 alias, 05 안정 참조) 중복 없음. 새 로컬 링크 15개 경로/fragment 검사 오류 0(INDEX 2, 05 4, 06 9). Markdown 제목 slug와 명시 anchor를 확인했으며 실제 브라우저 렌더러 검증은 하지 않았다.
- Python으로 새 안내 block과 anchor만 제거한 05/06 **전체 문자열이 ce4687f 원본과 동일**함을 확인했다. 기준 SHA-256: 05 `1ba45440d53a1a60dd214ab77676c13e89a00a4d5b9892318e87ce8c03485914`, 06 `c77dd4f963a55d7664b53117fdd4e1305d3f2f5f4ea669f71daba717b50920fe`.
- 역사 샘플의 원문 사본과 현재 기준을 문단별 비교했다. 9개 단위 중 6개 동일, 차이 3개는 제목·한국 우선 TZ 전제·명시적 프리셋/최초 Δ 분리다. 모두 M2 이전 인터뷰 반영이며 이번에 예외를 삭제한 것이 아니다. 샘플을 최신 계약으로 재작성하지 않았다.
- 위 12개 반례는 현행 원문 수동 대조 결과다. 제품 코드·API·시간 변환·성능 시험은 실행하지 않았다. 계약 자동 검증기가 구현됐다고 주장하지 않는다.

완료 판단: INDEX에서 시간 원본 및 R/H 원본으로 이동하고, 그 자리에서 소비자와 수정 필요 요약을 찾아 작업별 검토 결과를 기록할 수 있다. 개선율·탐색 시간은 측정하지 않았다. 운영 비용은 추가 안내 16줄이며 다음 실제 변경에서 포인터 누락·관리 비용을 관찰한다. 이 형식을 모든 문서에 확대하지 않는다.

되돌림: M2의 세 원본 파일에 추가한 안내/anchor/INDEX 행만 함께 제거하고 HANDOFF를 조정한다. 기존 링크가 새 anchor를 소비하기 시작했다면 먼저 사용처를 검색·갱신한다. 계약 본문이나 이전 M1 변경을 되돌리지 않고 이 실행 기록도 삭제하지 않는다.

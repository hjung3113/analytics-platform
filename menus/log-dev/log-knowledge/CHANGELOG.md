# @ap/menu-log-knowledge 변경 기록

내부 버전이며 발행하지 않는다. SDK 범위는 package.json의 ap.sdk를 따른다.

## 0.8.0 — 2026-11-06

- 모델 명세(#1196 d, 로직 보정 2차): 텍스트 저장 뒤 다음 저장이 처음 읽은 초안으로 되돌리던 문제, Event 표가 갱신 응답 도착 전에 다시 읽던 문제, Event 클릭이 편집 중 초안을 확인 없이 버리던 문제를 고쳤다. 서버의 행·칸 단위 오류(TSV 줄/열, 대체 변경점 경로)를 해당 입력 칸에 위치와 사유로 보여 주고, 저장 중에는 `aria-busy`와 «저장 중…» 표시를 둔다. mock은 잘못된 종류에 필드 오류를, TSV에 2,000행 상한과 20건 오류 요약을, 대상 이름에 서버와 같은 정규화·키를 쓴다.

- 모델 명세(#1196 d, A안 시각 보정): Event 표 영역의 가로 넘침을 내부로 제한하고, 변경점 전후 비교·원본 JSON 펼치기·대상별 JSON 예시를 추가했다. 모델 이름·코드·제조사와 발행 확인의 초안 Revision·원본 문서 버전을 표시하고, Event 상세에 필드·관계 빈 상태와 연결 변경점 근거를 보여 준다.

- 모델 프로파일의 명세 링크와 숨김 모델 명세 화면(#1196 d, 확정 A안): 접히는 Module 트리·Event 표/상세, SW 실효 명세 표시, 변경점·Revision 이력 탭, 초안 작성·저장·발행·반려와 변경점 추가·닫기/대체·재검토 확인. 서랍의 저장·확인 버튼은 SDK 선택 footer 슬롯에 둔다. 권한 안내·충돌 입력 보존·URL 상태·한영 문구와 결정적 mock 읽기 4종·쓰기 7종을 추가했다. 개념 매핑·Item 대상 연결은 후속 노드다.

## 0.7.2 — 2026-11-05

- 이전 리비전에서 수정 서랍을 연 채 「최신 보기」로 돌아와도 화면이 반복 갱신되며 실패하지 않고, 입력한 초안이 남는다.(#1365 수정 라운드 2)

## 0.7.1 — 2026-11-05

- 다른 리비전을 불러오는 동안은 수정·판단 변경·보관·관련 Item 신규 작성을 쓸 수 없다(이유를 title로). 이미 열린 파생 작성 서랍은 연 시점의 원본 리비전을 고정하고, 나중에 도착한 응답으로 다시 만들어지지 않는다.(#1365 수정 라운드)

## 0.7.0 — 2026-11-05

- Item 상세에서 리비전을 고르면 이전 리비전이 «갱신 중»으로 남고 로딩 뼈대가 뜨지 않는다(#1365, [ADR-0114](../../../docs/adr/0114-opt-in-keep-previous-for-page-input-params.md)). 다른 Item으로 가면 화면이 새로 열린다. 카탈로그 선택 목록 조회는 params가 바뀌지 않아 해당 없음.

## 0.6.0 — 2026-11-04

- 카탈로그 가져오기 마법사(#1195 c, A안): 제조사·공정·모델 탭 표 도구 줄의 「가져오기」가 목록 영역을 네 단계로 바꾼다 — 목록 붙여넣기(엑셀 복사 또는 CSV 열기, 메이커명·공정명·모델명) → 검사 결과(상태별 건수, 새로 만들 메이커·공정, 서버 페이징 행 표) → 확인 필요 행 정리(있을 때만, 건너뛰기만) → 적용 결과(`importApply` 반복 호출, 진행률, 전체 행 내보내기, 실패 행 다시 적용). 적용 전에는 아무것도 저장되지 않으며 나가면 작업을 취소한다. 서버 코드는 화면에 나오지 않고 모두 한국어 문장이다. mock에 가져오기 액션 5종과 `importDetail`(`src/mock/imports.ts`)을 추가했다. 카탈로그 manifest의 `features.export`를 켰다(내보내기 함수가 없는 카탈로그 표는 그대로).

## 0.5.0 — 2026-11-02

- 전체 기술 Item 목록·Item 상세 화면(#1197 s2, A안, 읽기 전용): 메뉴 `log-knowledge-items`(표·필터·검색)와 숨김 상세 `log-knowledge-item`(본문 4블록, 근거, 연결 Item, 리비전 `?rev=`, 판단 변경 이력). 조회 2종(`logKnowledge.items`·`itemDetail`) 선언·mock 저장소(`src/mock/items.ts`)·서버 drift 검사.
- 기술 Item 쓰기 5종 선언(`itemCreate`·`itemRevise`·`itemAssess`·`itemDerive`·`itemSetArchived`, 권한 `ITEM_PUBLISH_PERMISSION`=`knowledge:item-publish`)과 mock 쓰기(`src/mock/itemActions.ts`, Item 저장소 변경 함수), 서버 drift 검사(#1197 s3a, 화면 없음).
- 기술 Item 쓰기 화면(#1197 s3b, A안, 권한 `knowledge:item-publish` 보유자에게만): 전체 기술 Item의 「새 기술 Item」 서랍(소유 종류 모델|SW 버전 선택, 근거 포인터 ≤ 20, 주소 `focus=new`·`owner`), Item 상세의 「수정」(최신 리비전 기준, 변경 사유 필수, 주소 `drawer=revise`)·「판단 변경」·「관련 Item으로 신규 작성」(`drawer=assess|derive`, 근거·판단 상태 미승계)·`보관`/`보관 해제` 확인, 서버 `invalid` 경로(`evidence.<i>.<field>` 포함)를 칸에 연결, 충돌 시 새로 불러오기. 모델 프로파일 «모델 공통 Item»은 개수 한 줄 대신 모델 소유 게시 Item 5건과 `모두 보기 (N)`(Item 목록 `ownerModelId` 필터)로 바뀌었다. 선택 목록 `useOptionPicker`가 추가 필터(SW 버전의 `modelId`)를 받는다.

# 백로그 — 이슈로 올리지 않은 것

우선순위가 낮거나 수요가 확인되지 않은 일이다. 착수하려면 먼저 GitHub 이슈로 올리고 이 줄을 지운다.

## 작은 후속 (확인된 것)

- **구현 안 함 — platform-api의 plain Node 시작과 feature-shared 런타임 산출물:** `@ap/feature-shared`는 `src/index.ts`를 export하고 build가 `--noEmit`인 반면 소스 barrel은 `.js`를 참조해 `node dist/index.js`가 `src/enums/index.js`를 찾지 못한다. main `a1ab81ecb`와 #1098 r 직전 `9e1239d9f` 모두 frozen install·백엔드 build 뒤 같은 오류를 재현했다(2026-10-29); r 회귀가 아니다. 이유: #1104 설정 영속화 범위 밖인 기존 패키지 런타임 구성이다. `tsx` 로더를 쓴 실행은 가능하다. 다시 여는 조건: 백엔드 운영 배포 또는 plain Node 시작을 사용하는 작업에서 feature-shared의 emitted JS export·의존 빌드 순서를 함께 맞출 때.

- **구현 안 함 — 통합 계획 조사 기록 이동(v0.20 문서 점검 A1):** `docs/integration/framework-unification-plan.md`의 유효한 #396 전략·미구현 범위를 현행 소유 문서와 backlog에 연결하고 조사 본문을 `docs/research/`로 옮기는 일은 하지 않았다. 이유: 릴리스 문서 PR 범위 밖이다. 다시 여는 조건: #396 다음 작업 또는 해당 문서를 다시 고칠 때.

- **구현 완료 — `build:real-prod` CI 성공 검사(#1098 r, v0.20 마감 리뷰 Q7):** `ci.yml`의 static Job이 mock lazy/SDK 검사 뒤 DB-free 운영 빌드를 실행한다. 강제 mock graph/build 실패 guard도 유지한다.
- **구현 안 함 — `endpoints.json` 수집 완전성 게이트(v0.20 마감 리뷰 Q8):** 선언 수집은 `menus/*/*/src/endpoints.ts`의 정해진 export 모양만 보며 glob 밖 파일·배열·두 단계 중첩 선언을 놓칠 수 있고, `MOCK_ENDPOINTS`의 비모듈 id 집합과 대조하지 않는다. 이유: 현재 선언은 수집 범위 안에 있고 v0.20 범위가 고정돼 있다. 다시 여는 조건: 선언 파일·export 모양을 넓히거나 다음 엔드포인트 등록 작업에서 비모듈 `MOCK_ENDPOINTS` id와 산출물 id 집합을 대조하는 게이트를 넣을 때.

- **구현 안 함 — #764 실서버 확인(dev:real, 계획 D13):** Surveys·관리자 묶음의 실서버 흐름(설문 만들기→빌더→결과→후속 조치, 권한 요청 승인·부여·회수, Managed System 등록·수정, Coverage 설정 이동, 관리자 목록 범위 끔, 비관리자 메뉴 숨김)을 플랫폼 조립 위에서 실서버로 돌려 보지 않았다. 이유: mock에서는 FeedbackOps 화면이 마운트되지 않고, 화면별 동작은 FO 프런트 전체 테스트·다리 하네스·E2E가 덮으며 실서버 조립은 백엔드·이슈 DB·로그인이 필요한 별도 준비다. 다시 여는 조건: 첫 실서버 합류 점검(#593 이후) 또는 이 화면에서 실서버 전용 결함 보고.
- **구현 안 함 — Saved View 선택한 기존 뷰의 공유 대상 변경 진입(#1011):** 저장 흐름의 공유 대상 선택은 있지만, 이미 저장된 뷰를 골라 `ShareTargetPicker`로 대상을 바꾸는 진입은 셸에 연결하지 않았다. 이유: 이번 노드는 저장 흐름만 조립했다. 다시 여는 조건: 저장된 뷰의 공유 변경을 요구하는 이슈.
- **구현 안 함 — Saved View 선택기 필터를 드롭다운·검색으로(#1011 UX-4):** 공개 대상 필터가 그룹마다 단추 하나라 그룹이 늘면 줄바꿈과 Tab 정지점이 는다. 이유: 시드 그룹 3개 규모에서는 문제가 크지 않고 UX 구조를 바꾸는 일이다. 다시 여는 조건: 사용자 그룹이 5개 이상 보이는 화면이 생길 때.
- **구현 안 함 — Saved View 뷰 관리 승인 뒤 포커스와 보조줄 이름표(#1011 UX-8):** 승인으로 행이 사라지면 포커스가 대화상자 컨테이너로 가고(이웃 행이 아님), 행 보조줄 `이름 · 시각 · 이름 · v1`에 이름표가 없다. 이유: minor, 동작은 막히지 않는다. 다시 여는 조건: 접근성·관리 UX 라운드.
- **구현 안 함 — Saved View 패널 개수 표시와 소유자 이름 조회(#1011):** 패널 개수는 `panels`가 배열일 때만 센다(형식은 #911이 정한다). 소유자 이름은 본인과 그룹 멤버만 찾고 그 밖은 ID로 남는다. 사람 조회 포트 `lookupPeople`은 #1103이 내서 사용할 수 있지만 저장된 뷰 화면 연결과 서버 구현은 #1105·#1104–#1106 몫이라 이 줄은 그대로 구현 안 함이고, 패널 개수는 #911이 정한다. 다시 여는 조건: #1105(화면 연결), #911 계약.
- **구현 안 함 — 설정 이전 런타임·Kernel 배선(#1103 → #1104):** `readPreferences`·`patchPreferences`·`importPreferences` 포트와 mock·HTTP 어댑터는 있지만 Kernel은 여전히 localStorage를 읽고 쓰며 브라우저 → 서버 1회 이전(인증된 첫 읽기 뒤 가져오기, 확인 전 로컬 보존)을 실행하지 않는다. 이유: 서버 모듈이 없고 이 이슈 범위는 계약·대역이다([ADR-0098](../docs/adr/0098-adapter-preferences-people-notices-ports.md) §2). 다시 여는 조건: #1104 착수.
- **구현 안 함 — 공지 포트 직접 호출 뒤 Home 배너 갱신(#1103 → #1106):** `saveNotice`·`deleteNotice`를 직접 부르는 것만으로는 `home.notices` 캐시가 갱신되지 않는다. 이유: Home은 `menuQuery`로 읽고 갱신 연결은 서버·화면과 함께 만든다. 다시 여는 조건: #1106 착수.
- **구현 안 함 — Saved View 1280+상세 슬롯 확인(#1011):** 사이클타임 상세의 `상세`는 별도 실행 화면으로 이동해 이 화면에서 상세 슬롯을 열 수 없어 UX 리뷰에서 보지 못했다. 다시 여는 조건: 상세 슬롯이 열리는 화면이 저장된 뷰를 옵트인할 때.

- **구현 안 함 — Saved View 서버 저장·ACL·감사·실어댑터(#294 → #1011):** 1단계는 브라우저 로컬 mock 저장소와 `SavedViewStore` 포트 계약까지다. 이유: 사내 백엔드(#155) 합의 전이다. 다시 여는 조건: #155에서 저장 위치·ACL·감사 방식이 정해질 때(그때 `PlatformAdapter`/HTTP 계약 이슈로).
- **구현 안 함 — Saved View 쓰기 실패·이행·늦은 응답의 브라우저 확인(#1105 SDK Q6, 검증 공백):** 공유 실패 뒤 재시도, 마이그레이션 확인·적용 실패, 세대가 바뀐 뒤의 늦은 응답은 단위 테스트(`useSavedViews.test.tsx`, `SavedViewControl.test.tsx`)로만 덮였다. Q6 동작 자체는 구현됐다. 이유: mock 저장소에 장애 주입이 없고 유효한 마이그레이션 미리보기를 주는 fixture가 없으며, viewer는 사이클타임 메뉴가 권한 거부되어 뷰 관리를 열 수 없다. 다시 여는 조건: #1105 플랫폼 서버 저장소와 실패 fixture가 생길 때 그 브라우저로 같은 분기를 다시 확인한다.
- **구현 안 함 — Saved View 패널 좁히기 저장·복원(#294 → #1011):** 메뉴 뷰의 `panels` 슬롯과 읽기 전용 요약만 만든다. 이유: 패널 설정 계약이 #911(재사용 패널, 보류)에 있다. 다시 여는 조건: #911이 패널 설정 계약을 낼 때.
- **구현 안 함 — Saved View 공식 회수 뒤 공개 대상·관리자 부재 시 소유권(#294 → #1011):** 시안의 임의 재게시는 폐기했고 정책은 비워 둔다. 이유: 서버 ACL 결정(#155)과 함께 정해야 한다. 다시 여는 조건: #155 계약 확정.
- **구현 안 함 — Saved View 낡은 뷰 자동 이행(migration)(#294 → #1011):** 지금은 진단·안내와 사용자가 확정하는 갱신까지다. 이유: 첫 메뉴 스키마 변경 사례가 아직 없다. 다시 여는 조건: 저장된 뷰를 깨뜨리는 메뉴 스키마 변경이 처음 생길 때.
- **구현 안 함 — 보드 시트(C 단위) 저장과 `savedViewToken`(#294):** 보드 시트는 메뉴 뷰 여러 개의 배치라 새 형식이 없고, 보드 쪽 저장은 보드 이슈에서 다룬다. `savedViewToken`(긴 URL 대체)은 예약만이다. 다시 여는 조건: 보드 시트를 서버에 저장하거나 URL 길이가 문제가 될 때.

- **구현 안 함 — `sdk:consumer-check` CSS probe의 선택자 매칭 한계(#713 713f 점검 F2):** `hasCssSelector`(`tooling/sdk/sdk-css-probes.mjs`)는 원문 CSS를 정규식으로 보므로 복합 선택자(`.cls.other`, `.cls[attr]`)를 못 잡고(오탐), 이스케이프 식별자·선언 문자열 안의 선택자 모양 텍스트를 구분하지 못한다. 713f는 `>`·`+`·`~`·`)`만 더했다. 이유: probe는 패키지 전용 클래스 3개를 고르는 단순 검사라 CSS 파서를 들일 만큼의 수요가 없다. 다시 여는 조건: probe가 복합 선택자 클래스를 골라 CI가 오탐으로 실패할 때.

- **구현 안 함 — slice v0.17.0 마감 리뷰 Q2 나머지(보드 apply 칸 `QueryBar`의 `label.visible`):** 보드 apply 칸의 `QueryBar`가 `label.visible`을 트리거 글자로 그린다. 지우면 보이는 글자가 바뀐다. 결정: 팀장 2026-10-26, 현행 유지(문구 변경은 v0.17.0 완성도 범위 밖). 다시 열 조건: Context 바/`QueryBar` 문구를 손보는 이슈가 생길 때.

- **구현 안 함 — 소개 사이트(`site/`) 갱신(v0.17.0 릴리스):** 앱 v0.17.0과 `sdk-v0.17.0`에서 `site/`의 문구·캡처를 새로 맞추지 않았다(사용자 2026-10-26). 이유: 이번 릴리스는 완성도(버그·UX·성능) 범위라 소개 내용이 바뀐 기능이 없고 갱신을 건너뛰기로 했다. 다시 여는 조건: 다음 앱 릴리스.
- **구현 안 함 — #1057 P2(부록 #why/#status/#ask/#extend/#appendix-a~h 제목·요약 정비):** #1053·#957과 묶은 PR은 첫 화면과 본문(P0·P1)만 다뤘다. 이유: 부록은 정확성이 먼저인 기술 내용이고 사용자 요청은 첫 화면이었다. 다시 여는 조건: 다음 사이트 문구 라운드 또는 사용자 요청.

- **구현 안 함 — HW Time 비교 차트 안 선택 구간 강조(#912 조건 d):** 고른 Module(요약)·Motion(구성) 구간을 차트 안에서 색이 아닌 방식(윤곽·굵은 라벨 등)으로 강조하지 않았다. 지금은 패널 제목의 `· <값> 선택`과 경로 바가 비색상 단서다. 이유: `StackPanel`/`AnalysisChartFrame`에 시리즈 하나를 강조하는 계약이 없고 이번 릴리스는 새 계약을 열지 않으며, HW Time은 한동안 보류다(사용자 2026-10-26). 다시 여는 조건: Frame 시리즈 강조 계약을 넣는 릴리스.
- **구현 안 함 — 메뉴·차트 청크 미리 받기(#915):** 분석 보드 첫 로드에 남은 대기는 dock → 칸 메뉴 청크(약 300 ms, React fallback 스로틀)와 칸 → 차트 청크다. #915는 이미 받은 청크를 바로 그리고(`lazyChunk.ts`) 칸마다 경계를 둔 것까지만 했다. 이유: 받기 전에 시작하려면 메뉴 manifest의 preload 선언이나 차트 청크 preload API 같은 새 계약이 필요하고, 이번 릴리스는 새 계약을 열지 않는다. 다시 여는 조건: 미리 받기 계약을 릴리스 범위에 넣을 때 — #923·#915 코멘트의 측정 방법으로 전후를 잰다.
- **구현 안 함 — `selection-port-cache`를 Kernel 조회 엔진으로 옮기기(#825, ADR-0086):** 설비 검색·선택 포트는 자기 06 §6.5 계약(소유자별 LRU 50, 커서)을 가진 별도 캐시로 남겼다. 이유: 계약이 달라 옮기면 06을 함께 바꾸고 칸 소유(retain) 규칙을 다시 짜야 한다. 다시 여는 조건: 이 캐시의 버그가 나거나 세 번째 캐시되는 포트가 생길 때.
- **구현 안 함 — FeedbackOps와 Kernel이 QueryClient 하나를 쓰기(#825, ADR-0086):** Kernel 내부 클라이언트와 FO의 `foQueryClient`는 따로다. 이유: 키 공간·세션 세대 처리·GC 정책이 다르고 `QueryClientProvider` 공유는 메뉴가 Kernel 캐시를 읽게 만든다. 다시 여는 조건: FO 다리 화면과 플랫폼 메뉴가 같은 엔드포인트를 읽어 중복 요청이 측정될 때.

- **구현 안 함 — `useMenuFetch` 표 쪽을 `useInfiniteQuery`로(#825, ADR-0086):** 표 쪽 조회는 호출자가 신원을 소유하는 호출형 그대로다. 이유: 표 신원(Context·사용자·revision)과 내보내기가 이 모양에 묶여 있다. 다시 여는 조건: 표 쪽에도 SWR(뒤로 가기 때 이전 쪽 유지)이 필요해질 때.

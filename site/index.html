ANALYTICS PLATFORM · 사내 분석 메뉴 공통 기반

분석 메뉴는 업무 화면만 만들고, 공통 기능은 플랫폼이 맡습니다.

메뉴 등록과 검색, 조회 조건과 공유 링크, 권한·Scope·감사, 표와 차트, 화면 배치, 메뉴 사이 이동을 플랫폼이 한 번 만들고 모든 메뉴가 같이 씁니다. 그래서 설비·생산성·지표 메뉴가 같은 방식으로 동작하고 서로 이어집니다.

읽는 사람
  1. 메뉴마다 따로 만들던 탐색·조회 조건·권한·감사·표·차트를 플랫폼이 한 번 만들고, 모든 메뉴가 같은 규칙으로 씁니다.
  2. 메뉴를 오갈 때 기간·Site·선택 설비가 링크에 담겨 이어지고, 링크를 받은 사람의 권한으로 서버가 다시 검증합니다.
  3. 플랫폼 기반은 릴리스 7개(v0.1.0–v0.6.1)로 준비됐고, 사내 SSO·인프라·백엔드 답을 받으면 화면 코드를 고치지 않고 어댑터를 바꿔 실제 서버에 연결합니다. 효과는 파일럿에서 기준선부터 잽니다.

02 · 문제

메뉴마다 따로 만들면, 같은 기능이 메뉴 수만큼 생깁니다.

메뉴 등록·필터·딥링크·권한·데이터 상태·감사를 메뉴마다 구현하면, 메뉴가 늘수록 동작과 의미가 갈라지기 쉽습니다. 아래 네 가지는 설계 문서가 정의한 구조적 문제이고, 비용은 아직 측정하지 않았습니다.

문제 메뉴가 따로 만들면 플랫폼 규칙
조건이 끊긴다 다른 메뉴로 가면 기간·Site·설비를 다시 고른다 전역 조건이 URL에 담겨 메뉴 사이에서 이어진다 (계약 §6·§22)
같은 링크, 다른 숫자 늦게 들어온 데이터나 마스터 정정 때문에 같은 링크도 값이 달라진다 계산 기준 시각과 신뢰 정보(갱신 시각·coverage·지표 버전)를 함께 보인다 (§18)
0건의 뜻이 모호하다 결과 없음·수집 누락·파서 지연을 구분하지 못한다 0건·권한 거부·조회 과대·시간 초과·오류를 구분하고, 근거가 없으면 '미확인'으로 둔다 (§19)
권한·감사가 메뉴마다 다르다 메뉴마다 권한 검사와 변경 이력 표시가 달라진다 메뉴와 직접 URL이 같은 게이트를 지나고, 서버가 요청마다 다시 판정하며, 감사는 공통 형식으로 본다 (§13·§17)

처리 시간·건수 같은 효과는 지금 주장하지 않습니다. 사내 적용 파일럿에서 기준선부터 잽니다(#233).

공통 계약이 없을 때 예시

  1. 설비 목록에서 설비 ID 몇 개를 복사한다
  2. 분석 화면을 따로 열고 기간과 Site를 다시 고른다
  3. 설비 ID를 붙여 넣어 조건을 맞춘다
  4. 동료에게는 화면 캡처와 조건 설명을 같이 보낸다
  5. 받은 사람은 열어 봐야 권한이 있는지 안다

설명용 예시이며 사내에서 측정·관찰한 흐름이 아닙니다.

  4. 링크 복사로 조건이 담긴 주소를 보낸다 ① Kernel 기능
  5. 받는 사람의 권한으로 서버가 다시 검증한다 ① Kernel 기능
